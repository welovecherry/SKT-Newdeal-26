### 왜 필요한가

1. PC 는 패킷을 보내기 전에 **목적지가 같은 망인지**부터 계산합니다. 같으면 스위치로 바로, 다르면 **기본 게이트웨이**로 보냅니다.
2. 관제에서 「같은 층 PC 끼리는 되는데 다른 부서로만 안 된다」 같은 문의는 대부분 이 판정(목적지가 같은 망인가, 다른 망인가)에서 원인이 나옵니다.
3. 게이트웨이를 다른 망 주소로 잘못 설정하면 **물리적 연결(랜선 · Wi-Fi)이 정상이어도** 다른 망(인터넷)으로 패킷을 보내지 못합니다. 오류 메시지 없이 통신만 안 되는 장애의 대표 사례입니다.

### 5.1 두 장비가 하는 일

**여기 나오는 말**

- **MAC 주소 표 (MAC address table)** (맥 주소 테이블)
  - 스위치가 기억하는 「**이 MAC 주소는 몇 번 포트에 있다**」 표
  - 프레임이 들어오면 보낸 쪽 MAC 과 들어온 포트를 적어 둡니다
  - 다음부터는 그 MAC 으로 가는 프레임을 그 포트로만 보냅니다
- **스위치 포트**
  - 스위치에 **랜선을 꽂는 구멍**. 1번 · 2번 … 번호가 붙어 있습니다
  - 10/12 의 포트 번호(프로그램을 가리키는 번호)와 이름만 같고 다른 것입니다

| | 스위치(switch) | 라우터(router) |
|---|---|---|
| 층 | 2층(데이터링크) | 3층(네트워크) |
| 보는 주소 | **MAC 주소** | **IP 주소** |
| 잇는 범위 | **같은 망**의 장비들 | **다른 망** 사이 |
| 기억하는 표 | MAC 주소 표 — 「이 MAC 은 몇 번 포트」 | 라우팅 표(routing table) — 「이 망으로 가려면 다음은 누구」 |

### 5.2 같은 망이면 스위치로, 다른 망이면 게이트웨이로

**여기 나오는 말**

- **다음 홉 (next hop)** (넥스트 홉)
  - 지금 장비가 패킷을 **바로 넘겨줄 다음 장비**
  - 패킷은 목적지까지 장비를 하나씩 건너가는데, 장비마다 「다음은 누구」만 알면 됩니다
  - PC 의 다음 홉은 보통 기본 게이트웨이(공유기)입니다
- **ARP (Address Resolution Protocol)** (에이알피)
  - IP 주소를 보고 그 장비의 **MAC 주소를 알아내는** 방법
  - 내 PC 가 알아 둔 「IP 주소 → MAC 주소」 목록을 **ARP 캐시**라고 하고, `arp -a` 로 봅니다

오후에는 이 회사를 씁니다. 부서마다 `/24` 망 하나를 줬습니다 — **셋째 마디가 부서**를 가리킵니다.

| 부서 | 망 | 게이트웨이 |
|---|---|---|
| 개발팀 | `192.168.10.0/24` | `192.168.10.1` |
| 운영팀 | `192.168.20.0/24` | `192.168.20.1` |
| 보안팀 | `192.168.30.0/24` | `192.168.30.1` |

`/24` 는 앞 세 마디가 망 부분입니다(오전 3교시). 회사 주소는 앞 두 마디 `192.168` 이 모두 같으니, **셋째 마디가 같은가**만 보면 같은 망인지 압니다.

개발팀 PC `192.168.10.25` 가 보낼 곳은 이렇게 정합니다.

| 목적지 | 셋째 마디 | 보낼 곳 | 프레임의 목적지 MAC |
|---|---|---|---|
| `192.168.10.30` (개발팀) | `10` = `10` — 같은 망 | **스위치로 직접** | `.30` PC 의 MAC |
| `192.168.30.5` (보안팀) | `10` ≠ `30` — 다른 망 | **게이트웨이** `192.168.10.1` 로 | 게이트웨이의 MAC |
| `8.8.8.8` (인터넷) | 첫째 마디부터 다르다 — 다른 망 | **게이트웨이** `192.168.10.1` 로 | 게이트웨이의 MAC |

다른 망 `192.168.30.5` 로 보낼 때 패킷의 두 주소는 이렇게 됩니다.

| 필드 | 값 | 바뀌나 |
|---|---|---|
| 목적지 **IP** | `192.168.30.5` (최종 목적지) | 끝까지 **그대로** |
| 목적지 **MAC** | **게이트웨이의 MAC** | 장비를 하나 지날 때마다 **바뀐다** |

- PC 는 ARP 로 **같은 망의 장비**에게만 MAC 을 묻습니다. 다른 망으로 보낼 때는 게이트웨이의 MAC 만 알면 됩니다.

#### 명령 상자 · `arp -a` 화면 읽기

`arp -a` 는 내 PC 의 ARP 캐시를 보여 줍니다. 아래는 **예시 화면**입니다 — 주소는 PC 마다 다릅니다.

```
인터페이스: 192.168.1.57 --- 0x7
  인터넷 주소           물리적 주소           유형
  192.168.1.1           a0-b1-c2-d3-e4-f5     동적
  192.168.1.23          3c-52-82-11-22-33     동적
  192.168.255.255       ff-ff-ff-ff-ff-ff     정적
  224.0.0.22            01-00-5e-00-00-16     정적
```

| 열 | 뜻 | 이 문제에서 |
|---|---|---|
| `인터넷 주소` | IP 주소 | 이 열에서 **내 기본 게이트웨이 주소**와 `8.8.8.8` 을 찾는다 |
| `물리적 주소` | 그 IP 의 **MAC 주소** | 게이트웨이 줄의 이 열을 읽는다 |
| `유형` | `동적` = ARP 로 물어서 배운 것 · `정적` = Windows 가 미리 넣어 둔 것 | 읽지 않는다 |

- `224.` · `255` 로 끝나는 줄은 여러 장비에 한꺼번에 보내는 주소용 줄입니다. 이 문제와 상관없습니다.

### 5.3 스위치가 프레임을 받으면 — 하나 풀어 보기

**여기 나오는 말**

- **프레임 (frame)**
  - 2계층에서 주고받는 데이터 묶음
  - 맨 앞에 보낸 쪽 · 받는 쪽 **MAC 주소**가 적혀 있고, 스위치는 이 MAC 을 보고 포트를 고릅니다
- **플러딩 (flooding)**
  - 목적지 MAC 이 MAC 주소 표에 없을 때 **들어온 포트를 뺀 모든 포트로** 복사해 보내는 것
  - 답이 돌아오면 스위치가 그 MAC 의 포트를 배우고, 그다음부터는 그 포트로만 보냅니다

스위치는 프레임이 들어올 때마다 아래 세 단계를 합니다.

1. **① 출발지를 적는다** — 보낸 MAC 과 들어온 포트를 MAC 주소 표에 적습니다.
2. **② 목적지를 찾는다** — 받는 MAC 이 표에 있는지 봅니다.
3. **③ 내보낸다** — 표에 **있으면** 그 포트 하나로만, **없으면** 들어온 포트를 뺀 모든 포트로(플러딩) 보냅니다.

**예** — 포트 네 개짜리 스위치, MAC 주소 표는 비어 있습니다. `CC` 는 2번, `DD` 는 4번 포트에 꽂혀 있습니다.

| 들어온 프레임 | ① 표에 적는 것 | ② 받는 MAC 이 표에 있나 | ③ 내보내는 포트 | 그 뒤 MAC 주소 표 |
|---|---|---|---|---|
| 2번 포트로 `CC → DD` | `CC` 는 2번 | `DD` 없음 | 플러딩 — 1 · 3 · 4번 | `CC`:2 |
| 4번 포트로 `DD → CC` | `DD` 는 4번 | `CC` 있음(2번) | 2번 하나로만 | `CC`:2 · `DD`:4 |

- 스위치가 배우는 것은 **출발지**입니다. 첫 줄의 `DD` 는 목적지라 배우지 못했고, 둘째 줄에서 `DD` 가 보냈을 때 배웠습니다.

⚠ `mac_table["BB"]` 처럼 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">없는 키를 바로 꺼내면 `KeyError`</mark> 입니다. 먼저 `in` 으로 확인합니다.

#### 🐍 문법 상자 · 딕셔너리 `{}` · `d[키] = 값` · `키 in d` — MAC 주소 표 만들기

딕셔너리는 **키**와 **값**을 함께 담습니다. `키 in 딕셔너리` 로 키가 있는지 먼저 확인한 뒤 `딕셔너리[키]` 로 값을 꺼냅니다.

```python
mac_table = {}                    # {} 는 빈 딕셔너리다. 여기에 키와 값을 함께 담는다
mac_table["CC"] = 2               # 딕셔너리[키] = 값 으로 키 CC 에 값 2 를 넣는다
print(mac_table)                  # 딕셔너리 전체를 출력한다

print("CC" in mac_table)          # 키 in 딕셔너리 는 그 키가 있으면 True 다. CC 가 있으므로 True 를 출력한다
print("DD" in mac_table)          # DD 는 넣은 적이 없으므로 False 를 출력한다
print(mac_table["CC"])            # 딕셔너리[키] 로 키 CC 의 값을 꺼내 출력한다

# {'CC': 2}
# True
# False
# 2
```

| 쓰는 것 | 뜻 |
|---|---|
| `{}` | 빈 딕셔너리를 만든다 |
| `d["CC"] = 2` | 키 `"CC"` 에 값 `2` 를 넣는다. 키가 이미 있으면 값을 바꾼다 |
| `"CC" in d` | 키 `"CC"` 가 있으면 `True`, 없으면 `False` |
| `d["CC"]` | 키 `"CC"` 의 값을 꺼낸다. 없는 키면 `KeyError` |

### ✍️ 문제 5-2 · 스위치의 MAC 주소 표 읽기

**할 일** — 5.3 의 ① ~ ③ 을 코드 일곱 줄로 실행하고, 목적지 한 줄을 바꿔 다시 실행해 두 출력이 다른 이유를 보고서에 적습니다.

**왜 중요한가** — 스위치가 MAC 주소 표를 보고 포트 하나로만 보낼지, 플러딩할지 정하는 판단입니다. 관제에서 의심 PC 가 꽂힌 포트를 MAC 주소 표로 찾는 근거가 이 동작입니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `warmup_5_2.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 파일에 붙여 넣고, 실행하기 전에 **줄마다 주석을 읽어** 각 줄이 무엇을 하는지 이해합니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 로 복사합니다.
   ```python
   mac_table = {}                              # 빈 딕셔너리로 MAC 주소 표를 만든다. 처음에는 아무 MAC 주소도 모른다
   mac_table["AA"] = 1                         # ① AA 가 1번 포트로 프레임을 보냈다. 출발지 AA 를 1번 포트로 적는다
   dest = "BB"                                 # 이 프레임의 목적지 MAC 주소 BB 를 dest 에 담는다

   if dest in mac_table:                       # ② dest 가 MAC 주소 표의 키에 있으면 아래 줄을 실행한다
       print("포트", mac_table[dest], "로만")  # ③ 표에서 꺼낸 포트 번호를 넣어 출력한다
   else:                                       # else 는 위 if 의 조건이 False 일 때 아래 줄을 실행한다
       print("모든 포트로")                    # ③ 표에 없으면 플러딩한다고 출력한다
   ```
3. **[터미널]** 실행합니다. 터미널의 줄 위에 `…/network_zt` 가 보여야 합니다. 아니면 먼저 `cd network_zt` 를 입력합니다.
   ```bash
   python warmup_5_2.py
   ```
   맥북: `python3 warmup_5_2.py`
4. **[VS Code]** `dest = "BB"` 의 `"BB"` 를 `"AA"` 로 **한 곳만** 바꿉니다.
5. **[터미널]** **↑(위 화살표)** 를 눌러 방금 입력한 명령을 다시 실행합니다.
6. **[보고서]** `day02_subnet_design.md`의 `## 5교시` › `### 문제 5-2` 아래를 채웁니다.
   - (가) 바꾸기 전 출력 · `"AA"` 로 바꾼 뒤 출력:
   - (나-1) 두 출력이 다른 이유는 무엇인가요?
   - (나-2) 둘째 출력에 `AA` 가 아니라 숫자가 나온 이유는 무엇인가요?
   - (다-1) 플러딩은 언제 일어나나요?
   - (다-2) 플러딩이 많아지면 망에 어떤 문제가 생기나요?

**💡 힌트**

1. MAC 주소 표에 적힌 것은 둘째 줄의 `AA` 하나뿐입니다.
2. `mac_table[dest]` 는 키 `dest` 로 꺼낸 **값**입니다.
3. 5.3 예시 표의 첫 줄(`DD` 없음)과 둘째 줄(`CC` 있음)을 견줍니다.

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">6교시 (15:00–15:50) · VLAN · 라우팅 표 · 기본 경로</mark>

### 왜 필요한가

1. 부서마다 스위치를 따로 사면 비쌉니다. **스위치 하나를 여러 망으로 나누는 것**이 VLAN 입니다.
2. VLAN 이 다르면 **같은 스위치에 꽂혀 있어도** 직접 못 주고받습니다. 개발팀 PC 가 감염돼도 보안팀 망으로 바로 퍼지지 않습니다.
3. VLAN 사이를 오가려면 라우터가 필요하고, 라우터는 **라우팅 표**를 보고 경로를 고릅니다. 내 PC 에도 라우팅 표가 있습니다.

**여기 나오는 말**

- **홉 (hop)** (홉)
  - 패킷이 목적지까지 가면서 **거쳐 가는 라우터 하나**를 홉 하나로 셉니다
  - 예: 내 PC → 공유기 `192.168.1.1` → 통신사 라우터 → … → `8.8.8.8` 이면 공유기가 **1번 홉**, 통신사 라우터가 **2번 홉**입니다
  - 5교시의 **다음 홉**은 지금 장비가 패킷을 바로 넘겨줄 장비입니다. 내 PC 의 다음 홉은 1번 홉, 곧 기본 게이트웨이입니다

### 6.1 VLAN — 스위치 하나를 여러 망으로

**여기 나오는 말**

- **LAN (Local Area Network)** (랜)
  - 건물 · 층처럼 **가까운 곳의 장비를 묶은 망**
  - 같은 LAN 의 장비끼리는 스위치가 MAC 주소로 프레임을 전달합니다
- **VLAN (Virtual LAN)** (브이랜)
  - 스위치 포트마다 번호를 정해 **스위치 하나를 여러 망으로** 나눈 것
  - VLAN 이 다르면 같은 스위치에 꽂혀 있어도 서로 다른 망이라 직접 통신하지 못합니다
  - 부서마다 VLAN 을 나누면 브로드캐스트가 그 부서에만 퍼집니다
  - 부서마다 VLAN 하나에 서브넷 하나를 맞춥니다. 예: VLAN 10 = 192.168.10.0/24
- **액세스 포트 (access port)**
  - PC · 프린터 같은 장비를 꽂는 포트
  - 포트마다 VLAN 번호가 **하나씩** 정해져 있습니다. 예: 1번 포트는 VLAN 10(개발팀), 2번 포트는 VLAN 20(운영팀)
  - VLAN 번호는 **스위치에서만** 설정합니다. PC 에서는 따로 설정하지 않습니다
  - 그래서 PC 를 VLAN 10 포트에 꽂으면, 그 PC 는 자동으로 VLAN 10(개발팀 망)에 속합니다

이 회사는 VLAN 번호를 셋째 마디와 같게 맞췄습니다 — 개발팀 VLAN 10 · 운영팀 VLAN 20 · 보안팀 VLAN 30.

- 개발팀 PC 가 보낸 브로드캐스트는 VLAN 10 포트에만 퍼지고, VLAN 20 · 30 포트에는 가지 않습니다.
- VLAN 이 다른 장비끼리는 같은 스위치에 꽂혀 있어도 **라우터를 거쳐야** 오갑니다.

⚠ 서로 다른 VLAN 에 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">같은 서브넷</mark>을 주면, PC 는 같은 망이라 생각해 게이트웨이로 안 보내고, 스위치는 VLAN 이 달라 막습니다 — 라우터가 있어도 안 됩니다.

### 6.2 라우팅 표와 기본 경로

**여기 나오는 말**

- **라우팅 표 (routing table)** (라우팅 테이블)
  - 「**이 망으로 가려면 다음 홉은 누구**」를 적은 표
  - 라우터와 내 PC 모두 가지고 있습니다
  - 패킷의 목적지 주소에 맞는 줄을 찾아 그 줄의 다음 홉으로 보냅니다
- **기본 경로 (default route)** (디폴트 라우트)
  - 라우팅 표의 `0.0.0.0/0` 줄. `/0` 은 비교할 마디가 하나도 없다는 뜻이라 **모든 주소에 맞습니다**
  - 어떤 목적지로 갈 때 쓰이는지는 6-1 (다) 에서 직접 찾아 적습니다

개발팀 PC `192.168.10.25` 의 라우팅 표는 이렇게 생겼습니다.

| 목적지 망 | 다음 홉 | 뜻 |
|---|---|---|
| `192.168.10.0/24` | 직접 연결 | 내 망 — 스위치로 바로 |
| `0.0.0.0/0` | `192.168.10.1` | 기본 경로 — 다음 홉이 게이트웨이 |

내 PC 의 기본 경로 다음 홉은 `ipconfig` 의 「기본 게이트웨이」 줄에 있습니다. Windows 의 `tracert`(트레이스 라우트) 는 목적지까지 거쳐 가는 홉들을 차례로 보여 줍니다.

#### 명령 상자 · `tracert` 화면 읽기

`tracert -d -h 5 8.8.8.8` 은 `8.8.8.8` 까지 가는 길의 라우터를 **다음 홉 순서대로 한 줄에 하나씩** 보여 줍니다. `-d` 는 이름 찾기를 빼서 빨리, `-h 5` 는 최대 홉 수를 5 로 정한다는 뜻입니다. 아래는 **예시 화면**입니다.

```
최대 5홉 이상의
8.8.8.8(으)로 가는 경로 추적

  1    <1 ms    <1 ms    <1 ms  192.168.1.1
  2     2 ms     1 ms     1 ms  10.10.0.1
  3     *        *        *     요청 시간이 만료되었습니다.
  4     5 ms     4 ms     4 ms  112.188.0.1
  5     6 ms     5 ms     6 ms  112.174.0.1

추적을 완료했습니다.
```

| 부분 | 뜻 |
|---|---|
| 맨 앞 숫자 `1` · `2` … | 몇 번째 다음 홉인가 — `1` 은 내 PC 가 처음 넘겨준 장비 |
| 가운데 `ms` 세 개 | 같은 홉에 세 번 보내 답이 오기까지 걸린 시간 |
| **맨 끝 주소** | 그 홉의 **라우터 주소** — 이 주소를 읽는다 |
| `*  *  *` · `요청 시간이 만료되었습니다.` | 그 장비가 답하지 않도록 막아 둔 것. 길이 끊긴 것이 아니다 |

### 6.3 회사 라우터의 라우팅 표 — 회사 망 줄 아니면 기본 경로

회사 라우터는 이런 라우팅 표를 가집니다. 부서 망 셋은 라우터에 VLAN 으로 **직접 연결**돼 있고, 나머지는 기본 경로로 인터넷 쪽 라우터에 넘깁니다.

| 목적지 망 | 다음 홉 |
|---|---|
| `192.168.10.0/24` | 직접 연결 VLAN 10 |
| `192.168.20.0/24` | 직접 연결 VLAN 20 |
| `192.168.30.0/24` | 직접 연결 VLAN 30 |
| `0.0.0.0/0` | 인터넷 쪽 라우터 |

- 목적지가 들어가는 **회사 망 줄**(위 세 줄)이 있으면 그 줄로 보냅니다.
- 회사 망 줄에 하나도 맞지 않으면 **기본 경로 `0.0.0.0/0` 줄**로 인터넷 쪽 라우터에 보냅니다.

#### 🐍 문법 상자 · 튜플 리스트 · `for 변수1, 변수2 in 리스트:` — 라우팅 표 줄 꺼내기

튜플은 `( , )` 처럼 괄호로 묶은 값 여러 개입니다. 리스트에 튜플을 넣고 `for 변수1, 변수2 in 리스트:` 로 쓰면 튜플의 값을 차례로 두 변수에 나눠 담습니다.

```python
routes = [("192.168.10.0/24", "VLAN 10"),   # 리스트 안에 튜플을 넣는다. 튜플 하나가 (목적지 망, 다음 홉) 한 줄이다
          ("192.168.20.0/24", "VLAN 20")]   # 둘째 튜플을 넣고 리스트를 닫는다

for net, hop in routes:                     # 튜플을 하나씩 꺼내 첫 번째 값은 net, 두 번째 값은 hop 에 나눠 담아 반복한다
    print(net, "→", hop)                    # 목적지 망과 다음 홉을 출력한다

# 192.168.10.0/24 → VLAN 10
# 192.168.20.0/24 → VLAN 20
```

| 쓰는 것 | 뜻 |
|---|---|
| `("192.168.10.0/24", "VLAN 10")` | 튜플. 괄호로 묶은 값 두 개 |
| `for net, hop in routes:` | 튜플마다 첫 번째 값을 `net`, 두 번째 값을 `hop` 에 담아 반복한다 |

#### 🐍 문법 상자 · `ipaddress.ip_address()` · `주소 in 망` — 주소가 망에 들어 있는지

`import` 와 `ip_network()` 는 오전 3.4 아래 문법 상자에서 봤습니다. `ip_address()` 는 주소 하나를 **주소 객체**로 만들고, `주소 in 망` 은 그 주소가 망에 들어 있으면 `True` 입니다.

```python
import ipaddress                                   # import 로 IP 계산 모듈 ipaddress 를 불러온다

net = ipaddress.ip_network("192.168.30.0/24")      # 보안팀 망을 망 객체로 만들어 net 에 담는다
pc = ipaddress.ip_address("192.168.30.5")          # ip_address() 는 주소 글자로 주소 객체를 만들어 리턴한다. 그 객체를 pc 에 담는다
web = ipaddress.ip_address("8.8.8.8")              # 8.8.8.8 도 주소 객체로 만들어 web 에 담는다

print(pc in net)                                   # 주소 in 망 은 주소가 그 망에 들어 있으면 True 다. pc 는 들어 있으므로 True 를 출력한다
print(web in net)                                  # web 은 보안팀 망에 들어 있지 않으므로 False 를 출력한다

# True
# False
```

| 쓰는 것 | 뜻 |
|---|---|
| `ipaddress.ip_address("주소")` | 주소 하나를 나타내는 주소 객체를 리턴한다 |
| `주소 in 망` | 주소가 그 망에 들어 있으면 `True`, 아니면 `False` |

#### 🐍 문법 상자 · `found = False` → `found = True` — 찾았는지 적어 두는 변수

반복 전에 `False` 를 담아 두고, 찾으면 `True` 로 바꿉니다. 반복이 끝난 뒤 이 값을 보면 한 번이라도 찾았는지 알 수 있습니다.

```python
found = False                     # 아직 찾지 못했으므로 found 를 False 로 시작한다

for vlan in [10, 20, 30]:         # VLAN 번호를 하나씩 vlan 에 담아 반복한다
    if vlan == 30:                # vlan 이 30 이면 아래 줄을 실행한다
        found = True              # 찾았으므로 found 를 True 로 바꾼다

print(found)                      # 반복이 끝난 뒤 found 의 값을 출력한다. 30 을 찾았으므로 True 다

# True
```

| 쓰는 것 | 뜻 |
|---|---|
| `found = False` | 반복 전에 「아직 못 찾음」으로 시작한다 |
| `found = True` | `if` 아래에서 찾았을 때만 바꾼다 |
| `if found == False:` | 반복이 끝나도 한 번도 못 찾았으면 아래 줄을 실행한다 |

### ✍️ 문제 6-2 · 회사 망 줄인가, 기본 경로인가

**할 일** — 6.3 표의 회사 망 세 줄에서 목적지가 들어가는 줄을 찾고, 없으면 기본 경로로 보내는 코드를 실행합니다. 목적지 한 줄을 `8.8.8.8` 로 바꿔 다시 실행해 달라진 출력을 보고서에 적습니다.

**왜 중요한가** — 라우터가 목적지마다 회사 망 줄로 보낼지, 기본 경로로 보낼지를 코드로 확인합니다. 7-1 에서 개발팀 PC 가 보안팀 PC 로 가는 경로를 적을 때 이 판단을 씁니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `warmup_6_2.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 파일에 붙여 넣고, 실행하기 전에 **줄마다 주석을 읽어** 각 줄이 무엇을 하는지 이해합니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 로 복사합니다.
   ```python
   import ipaddress                                     # import 로 파이썬에 들어 있는 IP 계산 모듈 ipaddress 를 불러온다

   routes = [("192.168.10.0/24", "직접 연결 VLAN 10"),  # 회사 망 줄을 리스트로 만든다. 튜플 하나가 (목적지 망, 다음 홉) 한 줄이고, 이 줄은 개발팀 망이다
             ("192.168.20.0/24", "직접 연결 VLAN 20"),  # 운영팀 망 줄을 넣는다. 라우터에 VLAN 20 으로 직접 이어져 있다

   dest = ipaddress.ip_address("192.168.30.5")          # ip_address() 는 주소 글자를 주소 객체로 바꿔 리턴한다. 목적지 주소 객체를 dest 에 담는다
   found = False                                        # 맞는 회사 망 줄을 찾았는지 적어 두는 변수다. 아직 못 찾았으므로 False 로 시작한다

   for net, hop in routes:                              # 회사 망 줄의 튜플을 하나씩 꺼내 목적지 망은 net, 다음 홉은 hop 에 나눠 담아 반복한다
       if dest in ipaddress.ip_network(net):            # 주소 in 망 은 주소가 그 망에 들어 있으면 True 가 된다. True 이면 아래 두 줄을 실행한다
           print("맞는 줄:", net, "→", hop)             # 맞는 줄의 목적지 망과 다음 홉을 출력한다
           found = True                                 # 맞는 줄을 찾았으므로 found 를 True 로 바꾼다

   if found == False:                                   # 반복이 끝났는데 found 가 아직 False 이면 회사 망 줄에 하나도 맞지 않은 것이다
       print("회사 망 줄에 없음 → 기본 경로 0.0.0.0/0 (인터넷 쪽 라우터)")  # 그래서 기본 경로 줄로 보낸다고 출력한다
   ```
3. **[터미널]** 실행합니다. 터미널의 줄 위에 `…/network_zt` 가 보여야 합니다. 아니면 먼저 `cd network_zt` 를 입력합니다.
   ```bash

   ```
   맥북: `python3 warmup_6_2.py`

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">7교시 (16:00–16:50) · 2일 차 설계서 완성</mark>

### 왜 필요한가

1. 부서마다 망에 **VLAN 번호 · 게이트웨이 · PC 범위**를 붙이면 실제로 장비에 넣을 수 있는 설계가 됩니다.
2. 설계서는 사람이 읽는 문서입니다. 「개발팀 PC 가 보안팀 PC 로 갈 때 어디를 거치나」를 **경로로 적을 수 있어야** 합니다.
3. 다 채운 설계서를 깃허브에 올려 오늘의 산출물로 남깁니다.

### 7.1 오늘의 회사 설계표

**여기 나오는 말**

- **첫 호스트**
  - 네트워크 주소 바로 다음 주소(네트워크 주소 + 1)
  - 회사 설계에서는 보통 그 망의 **게이트웨이**에 이 주소를 줍니다. 예: `192.168.10.0/24` 이면 `192.168.10.1`
- **망 구성도**
  - 라우터 · 스위치 · 부서가 어떻게 이어지는지 그린 **그림**
  - 패킷이 어느 장비를 거쳐 가는지 따라갈 때 씁니다
- **설계서**
  - 주소 · VLAN · 게이트웨이 · 경로를 **장비에 바로 넣을 수 있게** 적은 문서
  - 현장에서는 이 문서를 보고 스위치 · 라우터를 설정합니다

5.2 의 세 부서에 VLAN 번호를 붙이고, 서버 10대를 둘 **서버망**을 더했습니다. 서버망은 부서가 쓰지 않은 **다음 셋째 마디** `40` 을 씁니다.

| 부서 | 망 | VLAN | 게이트웨이 | PC 에 줄 범위 |
|---|---|---|---|---|
| 개발팀 | `192.168.10.0/24` | 10 | `192.168.10.1` | `192.168.10.2` ~ `192.168.10.254` |
| 운영팀 | `192.168.20.0/24` | 20 | `192.168.20.1` | 7-1 에서 적는다 |
| 보안팀 | `192.168.30.0/24` | 30 | `192.168.30.1` | 7-1 에서 적는다 |
| 서버망 | `192.168.40.0/24` | 40 | `192.168.40.1` | 7-1 에서 적는다 |

- **게이트웨이** — 첫 호스트, 곧 넷째 마디 `1` 입니다.
- **PC 에 줄 범위** — 게이트웨이 다음 `.2` 부터 브로드캐스트 주소 `.255` 바로 앞 `.254` 까지입니다.

```
              ┌──────────── 라우터 (부서마다 게이트웨이 하나 · 6.3 의 라우팅 표) ────────────┐
              │
         ┌────┴──── 스위치 ────────────────────────────────────────┐
         │ VLAN 10 포트  │ VLAN 20 포트  │ VLAN 30 포트  │ VLAN 40 포트  │
       개발팀 PC      운영팀 PC      보안팀 PC      서버
```

### 7.2 경로 따라가기 — 하나 풀어 보기

통신 하나가 지나는 장비는 아래 네 단계로 따라갑니다.

1. **① 부서 찾기** — 출발지 · 목적지 주소의 셋째 마디로 7.1 표의 부서 · VLAN 을 찾습니다.
2. **② 같은 망인가** — 셋째 마디가 같으면 **스위치만** 거쳐 바로 갑니다(5.2). 끝입니다. 다르면 **출발지의 게이트웨이**(라우터)로 갑니다.
3. **③ 라우터가 줄 고르기** — 목적지가 들어가는 회사 망 줄이 있으면 그 줄, 없으면 기본 경로 줄을 고릅니다(6.3 · 6-2).
4. **④ 그 줄로 내보내기** — `직접 연결 VLAN ○○` 이면 스위치의 그 VLAN 포트로, 기본 경로면 인터넷 쪽 라우터로 보냅니다.

**예** — 운영팀 PC `192.168.20.30` → 개발팀 PC `192.168.10.25`

| 단계 | 하는 일 | 결과 |
|---|---|---|
| ① | 부서 찾기 | 출발 운영팀(셋째 마디 `20` · VLAN 20) · 도착 개발팀(`10` · VLAN 10) |
| ② | 같은 망인가 | `20` ≠ `10`, 다르다 → 출발지 운영팀의 게이트웨이 `192.168.20.1` 로 |
| ③ | 라우터가 줄 고르기 | `192.168.10.0/24` → 직접 연결 VLAN 10 |
| ④ | 내보내기 | 스위치의 VLAN 10 포트로 → 개발팀 PC |

```
운영팀 PC .30 ──▶ 스위치 (VLAN 20 포트로 들어옴)
                    │
                    ▼
                  라우터 — 게이트웨이 192.168.20.1 로 받음 · 줄 192.168.10.0/24 → 직접 연결 VLAN 10
                    │
                    ▼
                  스위치 (VLAN 10 포트로 나감) ──▶ 개발팀 PC .25
```

**경로** — 운영팀 PC → 스위치(VLAN 20) → 게이트웨이 `192.168.20.1`(라우터) → 스위치(VLAN 10) → 개발팀 PC

### 정답 5-1

💻 **터미널에 입력합니다.**

```bash
ping -n 1 8.8.8.8
arp -a
```
맥북: `ping -c 1 8.8.8.8` → `arp -a`

**결과**

- (가) 기본 게이트웨이 IP(학원 PC 는 `192.168.1.1`) 줄에 물리적 주소(`a0-b1-c2-d3-e4-f5` 꼴)가 있고, `8.8.8.8` 줄은 **없습니다**.
- (나) ARP 는 같은 망의 장비에게만 MAC 을 묻습니다. `8.8.8.8` 은 다른 망이라 PC 는 그 MAC 을 묻지 않고 게이트웨이의 MAC 으로 보냈습니다.
- (다) MAC 주소는 랜카드를 만든 회사가 정해 넣는 48비트 주소로, 16진수 12자리(`a0-b1-c2-d3-e4-f5`)로 씁니다. ARP 는 「이 IP 를 가진 장비는 MAC 을 알려 달라」를 같은 망 전체에 브로드캐스트로 묻고, 그 IP 를 가진 장비 하나만 자기 MAC 을 답합니다.

**왜** — 다른 망으로 가는 프레임의 목적지 MAC 은 게이트웨이의 MAC 입니다(5.2). 그래서 ARP 캐시에는 인터넷 건너편 서버가 아니라 게이트웨이 줄만 생깁니다.

**자주 틀리는 곳** — `ping` 이 `요청 시간이 만료되었습니다` 로 끝나면 실패라고 보고 멈추지만, 게이트웨이 MAC 은 이미 `arp -a` 에 들어 있습니다. `224.` · `255` 로 끝나는 줄을 게이트웨이로 적는 것도 흔합니다.

**관제에서는** — 게이트웨이 IP 의 MAC 이 평소와 다르게 바뀌어 있으면 ARP 위조(다른 장비가 게이트웨이인 척하는 공격)를 의심합니다.

### 정답 5-2

💻 **터미널에 입력합니다.** `python warmup_5_2.py` (맥북: `python3 warmup_5_2.py`)

**결과**

- (가) 바꾸기 전 `모든 포트로` · `"AA"` 로 바꾼 뒤 `포트 1 로만`
- (나) MAC 주소 표에는 출발지 `AA` 만 1번 포트로 적혀 있습니다. 목적지 `BB` 는 표에 없어 `else` 쪽(플러딩)이 나왔고, `AA` 는 표에 있어 `if` 쪽이 나왔습니다. `mac_table[dest]` 는 키 `AA` 로 꺼낸 **값** `1` 이라 숫자가 나왔습니다.
- (다) 플러딩은 목적지 MAC 이 MAC 주소 표에 없을 때(처음 보는 MAC · 브로드캐스트) 일어납니다. 플러딩이 많아지면 모든 포트로 복사본이 퍼져 망이 느려지고, 다른 장비에게 갈 프레임이 내 포트에도 와서 엿볼 수 있게 됩니다.

**왜** — 스위치는 **출발지**를 배우고 **목적지**로 표를 찾습니다(5.3 의 ① · ②). 표에 있으면 그 포트 하나로만, 없으면 들어온 포트를 뺀 모든 포트로 보냅니다.

**자주 틀리는 곳** — `dest = "BB"` 줄을 보고 `BB` 도 표에 적혔다고 읽어 첫 출력을 `포트 … 로만` 으로 적습니다. 표에 적는 줄은 `mac_table["AA"] = 1` 하나뿐입니다.

**관제에서는** — 스위치의 MAC 주소 표에서 의심 PC 의 MAC 이 몇 번 포트에 있는지 보면 그 PC 가 꽂힌 자리를 찾습니다. 한 포트에서 MAC 이 갑자기 많이 배워지면 표를 넘치게 해 플러딩을 일으키는 공격을 의심합니다.

### 정답 6-1

💻 **터미널에 입력합니다.**

```bash
ipconfig
tracert -d -h 5 8.8.8.8
```
맥북: `route -n get default` → `traceroute -n -m 5 8.8.8.8`

**결과**

- (가) `ipconfig` 의 `기본 게이트웨이 . . . . . . : 192.168.○.1` — 학원 PC 는 `192.168.1.1`. `tracert` 의 `1    <1 ms    <1 ms    <1 ms  192.168.1.1` — 1번 홉도 `192.168.1.1`.
- (나) 같습니다. `8.8.8.8` 은 다른 망이라 PC 는 라우팅 표에서 기본 경로 줄을 쓰고, 그 줄의 다음 홉인 게이트웨이로 먼저 보냅니다. 그래서 첫 홉은 늘 기본 게이트웨이입니다.
- (다) 기본 경로는 라우팅 표의 다른 어느 줄에도 맞지 않는 목적지 — 곧 인터넷 쪽 주소 전부 — 로 갈 때 쓰입니다. 기본 경로가 없으면 맞는 줄이 없는 패킷은 갈 곳이 없어 **버려지고**, 인터넷으로 나가지 못합니다.

**왜** — 기본 게이트웨이는 내 PC 라우팅 표의 기본 경로 `0.0.0.0/0` 줄의 다음 홉입니다. `tracert` 의 줄 하나는 홉(라우터) 하나이고, 1번 줄은 내 PC 가 처음 넘겨준 장비(다음 홉)입니다.

**자주 틀리는 곳** — `ipconfig` 의 IPv4 주소(내 PC 의 IP)를 기본 게이트웨이로 적습니다. `tracert` 의 `*  *  *` 줄을 보고 연결이 끊겼다고 판단합니다 — 그 장비가 답을 막아 둔 것일 뿐입니다.

**관제에서는** — 기본 게이트웨이가 회사가 정한 주소와 다르면 경로를 바꾸는 악성 설정이나 가짜 게이트웨이를 의심합니다. 장애가 나면 `tracert` 의 몇 번째 줄부터 끊기는지 봐 구간을 좁힙니다.

### 정답 6-2

💻 **터미널에 입력합니다.** `python warmup_6_2.py` (맥북: `python3 warmup_6_2.py`)

**결과** — 바꾸기 전

```
맞는 줄: 192.168.30.0/24 → 직접 연결 VLAN 30
```

`8.8.8.8` 로 바꾼 뒤

```
회사 망 줄에 없음 → 기본 경로 0.0.0.0/0 (인터넷 쪽 라우터)
```

- (가-1) · (가-2) 위 두 출력
- (나) `192.168.30.5` 는 회사 망 줄 `192.168.30.0/24` 에 들어가므로 라우터는 그 줄로, 곧 **직접 연결 VLAN 30** 으로 보냅니다. `8.8.8.8` 은 첫째 마디부터 회사 망과 달라 회사 망 세 줄 어디에도 들어가지 않습니다. `found` 가 `False` 로 남아 마지막 `if` 가 실행되고, 라우터는 기본 경로 `0.0.0.0/0` 줄로 인터넷 쪽 라우터에 보냅니다.
- (다) 부서마다 VLAN 을 나누면 브로드캐스트가 그 부서에만 퍼져 망이 덜 붐비고, 한 부서 PC 가 감염돼도 다른 부서로 바로 퍼지지 않습니다. 부서 사이 통신은 라우터를 거치므로 그곳에서 허용 · 차단 규칙으로 막을 수 있습니다.

**왜** — 라우터는 목적지가 들어가는 회사 망 줄이 있으면 그 줄로, 하나도 없으면 기본 경로 줄로 보냅니다(6.3).

**자주 틀리는 곳** — `found = True` 줄을 `if` 아래에 들여 쓰지 않으면, 맞는 줄이 없어도 `found` 가 `True` 가 되어 `8.8.8.8` 일 때 아무것도 출력되지 않습니다. 따옴표까지 지워 `ip_address(8.8.8.8)` 로 바꾸면 `SyntaxError` 가 납니다.

**관제에서는** — 회사 망으로 가야 할 통신이 기본 경로 쪽(인터넷 쪽 라우터)으로 나가고 있으면 라우팅 표가 바뀌었는지 의심하고, 라우팅 표에 낯선 줄이 생겼는지 봅니다.

### 정답 7-1

**결과**

- (가)
  - 운영팀 게이트웨이 `192.168.20.1` · PC `192.168.20.2` ~ `192.168.20.254`
  - 보안팀 게이트웨이 `192.168.30.1` · PC `192.168.30.2` ~ `192.168.30.254`
  - 서버망 게이트웨이 `192.168.40.1` · PC `192.168.40.2` ~ `192.168.40.254`
- (나) 셋째 마디 `10` · `20` · `30` 은 이미 세 부서가 쓰고 있어, 다음으로 비어 있는 `40` 을 골랐습니다. 셋째 마디가 다르니 어느 부서와도 겹치지 않고, VLAN 번호 40 과 셋째 마디를 맞춰 주소만 보고도 서버망인지 압니다. `/24` 는 쓸 수 있는 수가 254 라 서버 10대가 넉넉히 들어갑니다.
- (다) 개발팀 PC → 스위치(VLAN 10) → 게이트웨이 `192.168.10.1`(라우터) → 스위치(VLAN 30) → 보안팀 PC. 두 PC 는 셋째 마디 `10` · `30` 이 달라 다른 망이고 VLAN 도 다릅니다. 스위치는 VLAN 이 다르면 직접 넘기지 않고, PC 도 다른 망이라 게이트웨이로 보내므로 라우터를 거쳐야 오갑니다.

**왜** — 게이트웨이는 첫 호스트 `.1`, PC 범위는 게이트웨이 다음 `.2` 부터 브로드캐스트 `.255` 바로 앞 `.254` 까지입니다(7.1). 경로의 ③ 에서 라우터는 `192.168.30.0/24` 줄을 골라 VLAN 30 으로 내보냅니다(6-2).

**자주 틀리는 곳** — PC 범위 끝을 브로드캐스트 주소 `.255` 로 적습니다. (다) 의 첫 게이트웨이를 도착지 보안팀의 `192.168.30.1` 로 적습니다 — 먼저 가는 곳은 **출발지** 개발팀의 게이트웨이입니다.

**관제에서는** — 설계표가 있으면 로그의 IP 하나만 보고 셋째 마디로 어느 부서 · 어느 VLAN 장비인지 바로 압니다. 같은 VLAN 의 통신은 라우터를 안 지나므로 라우터 로그에 남지 않는다는 점도 기억합니다.

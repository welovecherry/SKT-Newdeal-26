### 5.1 두 장비가 하는 일

**여기 나오는 말**

- **MAC 주소 표 (MAC address table)** (맥 주소 테이블)
  - 스위치가 기억하는 「**이 MAC 주소는 몇 번 포트에 있다**」 표
  - 프레임이 들어오면 보낸 쪽 MAC 과 들어온 포트를 적어 둡니다
  - 다음부터는 그 MAC 으로 가는 프레임을 그 포트로만 보냅니다
- **스위치 포트**
  - 스위치에 **랜선을 꽂는 구멍**. 1번 · 2번 … 번호가 붙어 있습니다
  - 10/12 의 포트 번호(프로그램을 가리키는 번호)와 이름만 같고 다른 것입니다

| | 스위치(switch) | 라우터(router) |
|---|---|---|
| 층 | 2층(데이터링크) | 3층(네트워크) |
| 보는 주소 | **MAC 주소** | **IP 주소** |
| 잇는 범위 | **같은 망** 안의 장비들 | **다른 망** 사이 |
| 기억하는 표 | MAC 주소 표 — 「이 MAC 은 몇 번 포트」 | 라우팅 표(routing table) — 「이 망으로 가려면 다음은 누구」 |

### 5.2 스위치가 MAC 을 배우는 법

**여기 나오는 말**

- **프레임 (frame)**
  - 2계층에서 주고받는 데이터 묶음
  - 맨 앞에 보낸 쪽 · 받는 쪽 **MAC 주소**가 적혀 있고, 스위치는 이 MAC 을 보고 포트를 고릅니다
- **플러딩 (flooding)**
  - 목적지 MAC 이 MAC 주소 표에 없을 때 **들어온 포트를 뺀 모든 포트로** 복사해 보내는 것
  - 답이 돌아오면 스위치가 그 MAC 의 포트를 배우고, 그다음부터는 그 포트로만 보냅니다

1. 프레임이 들어오면 **출발지 MAC 과 들어온 포트**를 표에 적습니다.
2. 목적지 MAC 이 **표에 있으면** 그 포트 하나로만 보냅니다.
3. **없으면** 들어온 포트를 뺀 모든 포트로 복사해 보냅니다 — 이것이 **플러딩**입니다.

#### 🐍 문법 상자 · 사전에 키가 있나 · 리스트에 하나씩 더하기

```python
mac_table = {"AA": 1}                        # 딕셔너리 = 키(MAC) → 값(포트 번호)
print("AA" in mac_table, "BB" in mac_table)  # 키 in 딕셔너리 = 그 키가 있으면 True
out = []                                     # 빈 리스트를 만든다
for port in [1, 2, 3, 4]:                    # 포트 번호를 하나씩 꺼내 반복
    if port != 1:                            # != = 같지 않으면 True
        out.append(port)                     # .append() = 리스트 끝에 하나 더한다
print(out)                                   # 모은 리스트를 출력
# True False
# [2, 3, 4]
```

| 쓰는 것 | 뜻 |
|---|---|
| `키 in 사전` | 사전에 그 **키**가 있나 (1과목) |
| `리스트.append(값)` | 리스트 끝에 하나 더한다 |
| `!=` | 같지 않다 |

⚠ `mac_table["BB"]` 처럼 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">없는 키를 바로 꺼내면 `KeyError`</mark> 입니다. 먼저 `in` 으로 확인합니다.

### 5.3 다른 망으로 보낼 때 무엇이 바뀌나

**여기 나오는 말**

- **다음 홉 (next hop)** (넥스트 홉)
  - 지금 장비가 패킷을 **바로 넘겨줄 다음 장비**
  - 패킷은 목적지까지 장비를 하나씩 건너가는데, 장비마다 「다음은 누구」만 알면 됩니다
  - PC 의 다음 홉은 보통 기본 게이트웨이(공유기)입니다

PC `192.168.10.10/26` 이 다른 망의 서버 `192.168.10.70` 으로 보낼 때:

| 필드 | 값 | 바뀌나 |
|---|---|---|
| 목적지 **IP** | `192.168.10.70` (최종 목적지) | 끝까지 **그대로** |
| 목적지 **MAC** | **게이트웨이의 MAC** | 장비를 하나 지날 때마다 **바뀐다** |

- PC 는 먼저 목적지가 **내 망 안인지** 계산합니다. 안이면 목적지의 MAC 으로 스위치를 거쳐 바로, 밖이면 **게이트웨이의 MAC** 으로 보냅니다.
- ARP(에이알피 · IP 로 MAC 을 묻는 방법)는 **같은 망 안에서만** 묻습니다. 그래서 `arp -a` 에는 **게이트웨이의 MAC** 은 있어도, 인터넷 건너편 서버의 MAC 은 없습니다(5-4).

#### 🐍 문법 상자 · 주소가 망 안에 있나 — `in`

```python
import ipaddress                                    # import = 파이썬에 들어 있는 IP 계산 도구를 불러온다
net = ipaddress.ip_network("192.168.10.0/24")       # 글자를 망 객체로
# ip_address() = 글자를 주소 객체로 — 주소 in 망 = 그 망 안이면 True
print(ipaddress.ip_address("192.168.10.1") in net)
print(ipaddress.ip_address("192.168.11.1") in net)  # 다른 주소로 같은 검사
# True
# False
```

| 쓰는 것 | 뜻 |
|---|---|
| `ipaddress.ip_address("주소")` | 주소 **하나** |
| `주소 in 망` | 그 망 안에 있나 — 1과목 리스트의 `in` 과 같은 모양 |

⚠ 글자 `"192.168.10.1"` 을 그대로 `in net` 하면 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">`AttributeError`</mark> 가 납니다(실측). 꼭 `ip_address()` 로 바꿉니다.

### ✍️ 문제 5-4 · ARP 캐시에서 게이트웨이 찾기

**할 일** — 두 명령을 차례로 입력해, `arp -a` 에 **기본 게이트웨이의 MAC 은 있지만 `8.8.8.8` 은 없는 것**을 확인하고 보고서에 적습니다.

**왜 중요한가** — 5.3 표의 「목적지 MAC 은 게이트웨이의 MAC」을 내 PC 의 ARP 캐시로 직접 확인합니다. 다른 망 장비의 MAC 을 PC 가 몰라도 통신이 되는 이유가 여기 있습니다.

**순서**

1. **[터미널]** `8.8.8.8` 로 한 번 보냅니다.

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">6교시 (15:00–15:50) · VLAN · 라우팅 표 · 기본 경로</mark>

### 왜 필요한가

1. 부서마다 스위치를 따로 사면 비쌉니다. **스위치 하나를 여러 망으로 나누는 것**이 VLAN 입니다.
2. VLAN 이 다르면 **같은 스위치에 꽂혀 있어도** 직접 못 주고받습니다. 개발팀 PC 가 감염돼도 보안팀 망으로 바로 퍼지지 않습니다.
3. VLAN 사이를 오가려면 라우터가 필요하고, 라우터는 **라우팅 표**를 보고 경로를 고릅니다. 내 PC 에도 라우팅 표가 있습니다.

### 6.1 VLAN 과 서브넷

**여기 나오는 말**

- **LAN (Local Area Network)** (랜)
  - 건물 · 층처럼 **가까운 곳의 장비를 묶은 망**
  - 같은 LAN 안에서는 스위치가 MAC 주소로 프레임을 전달합니다
- **VLAN (Virtual LAN)** (브이랜)
  - 스위치 포트마다 번호를 정해 **스위치 하나를 여러 망으로** 나눈 것
  - VLAN 이 다르면 같은 스위치에 꽂혀 있어도 서로 다른 망이라 직접 통신하지 못합니다
  - 부서마다 VLAN 을 나누면 브로드캐스트가 그 부서 안에서만 돕니다
- **액세스 포트 (access port)**
  - PC · 프린터 같은 장비를 꽂는 포트
  - VLAN **하나**에만 속하고, 장비는 자기가 어느 VLAN 인지 모릅니다
- **트렁크 포트 (trunk port)**
  - VLAN **여러 개를 한 선으로** 나르는 포트
  - 프레임마다 VLAN 번호를 붙여 보내서, 받는 쪽이 어느 VLAN 것인지 압니다
  - 보통 스위치 ↔ 라우터, 스위치 ↔ 스위치 사이에 씁니다

| | 서브넷 | VLAN |
|---|---|---|
| 나누는 층 | 3층 — IP 주소와 마스크로 | 2층 — 스위치 **포트 설정**으로 |
| 정하는 곳 | PC 의 IP 설정 | 스위치 |
| 운영 규칙 | **VLAN 하나 = 서브넷 하나**로 짝을 맞춘다 | 〃 |

| 포트 종류 | 연결하는 것 | VLAN |
|---|---|---|
| 액세스 포트 | PC · 프린터 | **하나**만 |
| 트렁크 포트 | 스위치 ↔ 스위치 · 스위치 ↔ 라우터 | 여러 개를 한 선으로 — 번호표(태그)를 붙여서 |

- 브로드캐스트는 **같은 VLAN 의 포트에만** 퍼집니다. VLAN 하나가 브로드캐스트가 닿는 범위 하나입니다.
- VLAN 이 다른 장비끼리는 같은 스위치에 꽂혀 있어도 **라우터를 거쳐야** 오갑니다.

⚠ 서로 다른 VLAN 에 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">같은 서브넷</mark>을 주면, PC 는 같은 망이라 생각해 게이트웨이로 안 보내고, 스위치는 VLAN 이 달라 막습니다 — 라우터가 있어도 안 됩니다.

### 6.3 맞는 줄이 여럿일 때 — 가장 좁은 줄

- 목적지에 맞는 줄이 여러 개면 **CIDR 숫자가 가장 큰(가장 좁은) 줄**을 고릅니다.
- `0.0.0.0/0` 은 모든 주소에 맞지만 숫자가 0 이라 **맨 마지막 선택지**입니다. 더 좁은 줄이 하나라도 맞으면 그 줄이 이깁니다.

#### 🐍 문법 상자 · `.prefixlen` — CIDR 숫자 꺼내기

```python
import ipaddress                              # import = 파이썬에 들어 있는 IP 계산 도구를 불러온다
a = ipaddress.ip_network("0.0.0.0/0")         # /0 = 모든 주소를 품는 망
b = ipaddress.ip_network("192.168.10.64/26")  # .64 ~ .127 인 /26 망
dest = ipaddress.ip_address("192.168.10.70")  # ip_address() = 글자를 주소 객체로
print(dest in a, dest in b)                   # 주소 in 망 = 그 망 안이면 True — 두 망을 한 번에 검사
print(a.prefixlen, b.prefixlen)               # .prefixlen = 망의 CIDR 숫자 — 클수록 좁은 망
# True True
# 0 26
```

| 쓰는 것 | 뜻 |
|---|---|
| `망.prefixlen` | CIDR 숫자 — 클수록 좁은(구체적인) 망 |
| `주소 in 망` | 그 줄이 맞는가 |

⚠ 맞는 줄이 둘 이상이면 `prefixlen` 이 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">큰</mark> 쪽입니다. 먼저 맞은 줄을 고르면 기본 경로로 엉뚱하게 갈 수 있습니다.

### ✍️ 문제 6-4 · 라우팅 표에서 경로 고르기 (`route_lookup.py`)

**할 일** — 목적지마다 **맞는 줄 가운데 CIDR 숫자가 가장 큰 줄**의 다음 홉을 고르는 함수를 완성해 실행하고, 출력을 보고서에 적습니다.

**왜 중요한가** — 라우터가 맞는 줄 여러 개 가운데 하나를 고르는 규칙을 직접 구현합니다. 이 규칙을 틀리면 내부 망으로 갈 패킷이 기본 경로를 타고 인터넷 쪽으로 나갑니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `route_lookup.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 복사해 파일에 붙여 넣습니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 를 누릅니다.
   ```python
   import ipaddress                                  # import = 파이썬에 들어 있는 IP 계산 도구를 불러온다

   # ── 미리 채워 둔 줄입니다. 고치지 않습니다 ──
   routes = [                                        # (목적지 망, 다음 홉)
       ("0.0.0.0/0", "인터넷 게이트웨이"),           # 튜플 하나 = (목적지 망, 다음 홉)
       ("192.168.10.0/26", "직접 연결 G0/0"),        # G0/0 · G0/1 은 라우터의 포트 이름
       ("192.168.10.64/26", "직접 연결 G0/1"),       # 같은 꼴의 튜플
   ]                                                 # 리스트를 닫는다
   # ── 여기까지 ──

   def lookup(dest):                                 # 목적지 주소의 다음 홉을 리턴한다
       dest = ipaddress.ip_address(dest)             # 글자를 주소 객체로 바꿔 같은 이름에 다시 담는다
       best = None                                   # 지금까지 고른 줄
       for cidr, hop in routes:                      # 표를 한 줄씩
           net = ipaddress.ip_network(cidr)          # 글자를 망 객체로
           # 1. dest 가 net 안에 있고, best 가 None 이거나 net.prefixlen 이 best 의 prefixlen 보다 크면 best 에 (net, hop) 을 담으세요

       return best[1]                                # 고른 줄의 다음 홉

   for d in ["192.168.10.20", "192.168.10.70", "8.8.8.8"]:  # 목적지 주소를 하나씩 꺼내 반복
       print(d, "→", lookup(d))                      # 주소와 함수가 리턴한 다음 홉을 출력
   ```
3. **[VS Code]** 번호 주석 아래를 채웁니다.
4. **[터미널]** 실행합니다. 터미널의 줄 위에 `…/network_zt` 가 보여야 합니다. 아니면 먼저 `cd network_zt` 를 입력합니다.
   ```bash
   python route_lookup.py
   ```

**자주 틀리는 곳** — `mac_table[dest]` 가 키 `BB` 가 아니라 값 `3` 을 꺼낸다는 점을 놓쳐 `포트 BB 로만` 으로 적습니다.

**관제에서는** — 스위치의 MAC 표에서 의심 PC 의 MAC 이 몇 번 포트에 있는지 보면 그 PC 가 꽂힌 자리를 찾습니다.

### 정답 5-2

```python
PORTS = [1, 2, 3, 4]                              # 스위치의 포트 네 개
mac_table = {}                                    # 처음엔 아무것도 모른다

def receive(in_port, src, dest):                  # 프레임 하나가 in_port 로 들어왔다
    # 1. mac_table 의 src 키에 in_port 를 담으세요 (출발지를 배운다)
    mac_table[src] = in_port                      # 이 MAC 은 이 포트에 있다
    # 2. dest 가 mac_table 에 있으면 [mac_table[dest]] 를 return 하세요
    if dest in mac_table:                         # 목적지를 안다면
        return [mac_table[dest]]                  # 그 포트 하나로만
    out = []                                      # 모르면 플러딩할 포트들
    for port in PORTS:                            # 포트 번호를 하나씩 꺼내 반복
        # 3. port 가 in_port 가 아니면 out 에 더하세요
        if port != in_port:                       # 들어온 포트는 빼고
            out.append(port)                      # .append() = 리스트 끝에 하나 더한다
    return out                                    # 모은 포트 리스트를 리턴한다

print("AA → BB :", receive(1, "AA", "BB"))       # BB 를 아직 모른다
print("BB → AA :", receive(3, "BB", "AA"))       # AA 는 1번에서 배웠다
print("AA → BB :", receive(1, "AA", "BB"))       # 이제 BB 도 안다
print("표:", mac_table)                           # 지금까지 배운 표(딕셔너리)를 출력
```

💻 **터미널에 입력합니다.** `python switch_sim.py`

**결과** — `AA → BB : [2, 3, 4]` · `BB → AA : [1]` · `AA → BB : [3]` · `표: {'AA': 1, 'BB': 3}`

**왜** — 스위치는 들어온 프레임의 **출발지** MAC 과 포트를 배웁니다. 첫 줄에선 BB 를 몰라 플러딩하고, 둘째 줄에서 BB 가 3번에 있다고 배웁니다.

**자주 틀리는 곳** — `mac_table[dest] = in_port` 로 목적지를 적어, BB 가 1번 포트에 있다고 잘못 배우게 합니다.

**관제에서는** — 한 포트에서 MAC 이 갑자기 많이 배워지거나 같은 MAC 이 여러 포트를 오가면 MAC 위조나 허락 없이 꽂은 장비를 의심합니다.

### 정답 6-4

```python
import ipaddress                                  # import = 파이썬에 들어 있는 IP 계산 도구를 불러온다

routes = [                                        # (목적지 망, 다음 홉)
    ("0.0.0.0/0", "인터넷 게이트웨이"),           # 튜플 하나 = (목적지 망, 다음 홉)
    ("192.168.10.0/26", "직접 연결 G0/0"),        # G0/0 · G0/1 은 라우터의 포트 이름
    ("192.168.10.64/26", "직접 연결 G0/1"),       # 같은 꼴의 튜플
]                                                 # 리스트를 닫는다

def lookup(dest):                                 # 목적지 주소의 다음 홉을 리턴한다
    dest = ipaddress.ip_address(dest)             # 글자를 주소 객체로 바꿔 같은 이름에 다시 담는다
    best = None                                   # 지금까지 고른 줄
    for cidr, hop in routes:                      # 표를 한 줄씩
        net = ipaddress.ip_network(cidr)          # 글자를 망 객체로
        # 1. dest 가 net 안에 있고, best 가 None 이거나 net.prefixlen 이 best 의 prefixlen 보다 크면 best 에 (net, hop) 을 담으세요
        if dest in net and (best is None or net.prefixlen > best[0].prefixlen):   # 맞고 더 좁으면
            best = (net, hop)                     # (망, 다음 홉) 튜플로 지금까지 고른 줄을 바꾼다
    return best[1]                                # 고른 줄의 다음 홉

for d in ["192.168.10.20", "192.168.10.70", "8.8.8.8"]:  # 목적지 주소를 하나씩 꺼내 반복
    print(d, "→", lookup(d))                      # 주소와 함수가 리턴한 다음 홉을 출력
```

💻 **터미널에 입력합니다.** `python route_lookup.py`

**왜** — 맞는 줄이 여럿이면 CIDR 숫자가 가장 큰(가장 좁은) 줄을 고릅니다. `0.0.0.0/0` 은 늘 맞지만 숫자가 0 이라 다른 줄이 안 맞을 때만 쓰입니다.

**자주 틀리는 곳** — 처음 맞은 줄에서 멈춰 세 목적지가 모두 `인터넷 게이트웨이` 로 나옵니다.

**관제에서는** — 누가 더 좁은 경로 한 줄을 끼워 넣으면 기본 경로보다 먼저 골라지므로, 라우팅 표에 낯선 줄이 생겼는지 봅니다.

### 정답 7-2

```python
import ipaddress                                  # import = 파이썬에 들어 있는 IP 계산 도구를 불러온다

used = [                                          # 이미 쓰는 세 부서의 망
    ipaddress.ip_network("10.20.0.0/26"),         # 리스트 안에 망 객체를 바로 넣는다
    ipaddress.ip_network("10.20.0.64/27"),        # 같은 꼴의 망 객체
    ipaddress.ip_network("10.20.0.96/28"),        # 같은 꼴의 망 객체
]                                                 # 리스트를 닫는다
parent = ipaddress.ip_network("10.20.0.0/24")     # 후보를 고를 전체 망 /24

server = None                                     # None = 아직 아무것도 안 담았다는 표시
for candidate in parent.subnets(new_prefix=28):   # /28 후보를 앞에서부터
    # 1. candidate 가 used 의 어느 것과도 겹치지 않으면 server 에 담고 반복을 끝내세요(break)
    hits = 0                                      # 겹치는 부서 수
    for net in used:                              # 기존 부서 망을 하나씩 꺼내 반복
        if candidate.overlaps(net):               # .overlaps() = 후보가 그 망과 겹치면 True
            hits = hits + 1                       # 겹친 수를 1 늘린다
    if hits == 0:                                 # 아무와도 안 겹치면
        server = candidate                        # 안 겹치는 후보를 서버망으로 담는다
        break                                     # 처음 빈 자리를 찾았으니 끝

print("서버망:", server)                          # 고른 서버망을 출력
overlap = False                                   # 처음엔 False 로 두고 반복에서 바꾼다
for net in used:                                  # 기존 부서와 하나씩 비교
    # 2. server 가 net 과 겹치면 overlap 을 True 로 바꾸세요
    if server.overlaps(net):                      # 서버망이 그 망과 겹치면 True
        overlap = True                            # 겹침을 찾았다고 표시
print("겹침 있음:", overlap)                      # 겹침 판정을 출력
```

**관제에서는** — 서버망 대역이 하나로 정해져 있으면 그 대역으로 들어오는 접속만 모아 볼 수 있습니다.

**왜** — `git add .` 는 `.gitignore` 에 적힌 것을 빼고 지금 폴더 아래 바뀐 것을 전부 고릅니다. 그래서 고르기 전에 `git status` 로 `.env` 가 목록에 없는지 먼저 봅니다.

**자주 틀리는 곳** — `git status` 를 건너뛰고 `git add .` 부터 하면 `.env` 가 섞여도 모릅니다. `git commit` 만 하고 `git push` 를 빠뜨리면 깃허브에 안 보입니다.

**관제에서는** — 설계서가 깃허브에 남아 있으면 사고가 났을 때 원래 설계와 실제 설정을 맞대어 봅니다.

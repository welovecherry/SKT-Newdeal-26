### 왜 필요한가

1. 보안 관제에서 보는 로그(방화벽 · 웹 서버 · 침입 탐지 시스템 로그)에는 거의 언제나 **출발지 IP 주소**와 **목적지 IP 주소** 필드가 기록됩니다. 분석은 그 주소가 **내부망**(우리 회사 네트워크)인지 **외부망**(인터넷)인지 가리는 것부터 시작합니다.
2. 그 기준이 **사설 IP**(회사 · 가정의 내부망에서만 쓰는 주소)와 **공인 IP**(인터넷 전체에서 하나뿐인 주소)입니다.
3. 내부망 PC 의 사설 IP 는 인터넷과 통신할 때 공유기 · 라우터의 **NAT**(냇 · Network Address Translation, 주소 변환)를 거쳐 **공인 IP 로 바뀌어** 나갑니다. 그래서 외부 서버나 방화벽 로그에 기록된 출발지 주소는 실제 PC 의 사설 IP 가 아니라 공유기의 공인 IP 일 수 있습니다. 어느 PC 가 보낸 것인지 찾으려면 공유기 · 방화벽에 남은 **NAT 변환 기록**을 함께 봐야 합니다.

### 2.1 IP 주소는 32비트

**여기 나오는 말**

- **비트 (bit)**
  - 0 또는 1 하나를 담는 **2진수 한 자리**. 컴퓨터가 다루는 가장 작은 정보 단위입니다
  - IPv4 주소 하나는 **32비트**로 되어 있습니다
  - 점으로 나뉜 마디(옥텟 · octet) 하나는 **8비트**라, 마디마다 0~255 를 담습니다
- **2진수** (이진수)
  - 0 과 1 두 글자로만 쓰는 수. 자리 하나가 왼쪽으로 갈수록 2배씩 커집니다(1 · 2 · 4 · 8 · …)
  - 예: `192` 는 128 + 64 라서 `11000000`
  - 컴퓨터는 IP 주소를 이 모양으로 읽고, 서브넷 마스크도 이 모양으로 비교합니다

`192.168.10.25` 는 사람이 읽는 모양입니다. 컴퓨터는 점으로 나뉜 **마디 네 개**를 각각 **8비트 2진수**로 읽습니다. 그래서 IPv4(아이피 브이포) 주소는 모두 **32비트**입니다.

| 마디 | 10진수(평소 쓰는 수) | 2진수(0과 1 로만 쓰는 수 · 8비트) |
|---|---|---|
| 1 | 192 | `11000000` |
| 2 | 168 | `10101000` |
| 3 | 10 | `00001010` |
| 4 | 25 | `00011001` |

8비트가 전부 1 이면 `11111111` = 255 입니다. 그래서 한 마디에는 **0~255** 만 들어갑니다(256가지).

#### 🐍 문법 상자 · `format(숫자, "08b")` — 8비트 2진수로

```python
print(format(5, "08b"))        # 5 를 2진수 여덟 칸 글자로 바꿔 출력 — "08b" = 0 으로 채운 8칸 2진수
print(format(255, "08b"))      # 255 → 여덟 칸이 전부 1
print(len(format(25, "08b")))  # len() = 글자 수 — 여덟 칸이니 8
# 00000101
# 11111111
# 8
```

| 쓰는 것 | 뜻 |
|---|---|
| `b` | 2진수(binary)로 바꾼다 |
| `08` | 빈 앞자리를 0 으로 채워 **8자리**를 만든다 |
| `int("25")` | 글자 `"25"` 를 숫자 25 로 (1과목) |

⚠ `"08b"` 를 따옴표 없이 `08b` 로 쓰면 `SyntaxError` 입니다. 글자로 넘겨야 합니다.

### ✍️ 문제 2-2 · 내 IP 를 32비트 2진수로 펼치기 (`ip_bits.py`)

**할 일** — IP 주소를 32비트 2진수로 펼치는 함수 `to_bits` 를 완성해 실행하고, 내 주소의 출력을 보고서에 적습니다.

**왜 중요한가** — IP 주소를 32비트로 펼쳐 두어야 3교시에서 서브넷 마스크가 어느 비트까지를 같은 망으로 묶는지 비트끼리 맞대어 볼 수 있습니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `ip_bits.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 복사해 파일에 붙여 넣습니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 를 누릅니다.
   ```python
   # ── 강사용: 정답을 채운 코드입니다 ──
   def to_bits(ip):                                  # IP 주소를 2진수 32칸 글자로 바꾸는 함수
       bits = ""                                     # 이어 붙일 빈 글자
       for part in ip.split("."):                    # 점으로 나눈 마디를 하나씩
           # 1. bits 뒤에 format(int(part), "08b") 를 이어 붙이세요
           bits = bits + format(int(part), "08b")    # 마디 하나를 여덟 칸으로 바꿔 붙인다
       return bits                                   # 32칸 글자를 리턴한다

   ip = "192.168.10.25"                              # 내 IPv4 주소로 바꿔 봅니다
   print(ip)                                         # 원래 IP 주소 글자를 출력
   print(to_bits(ip))                                # 함수를 불러 리턴한 32칸 글자를 출력
   print("길이:", len(to_bits(ip)))                  # len() = 글자 수 — 32칸이 맞는지 확인
   ```

### 2.2 사설 IP 와 공인 IP

**여기 나오는 말**

- **사설 IP (private IP)** (프라이빗 아이피)
  - 회사 · 가정의 **내부망에서만** 쓰는 주소. 이 주소 그대로는 인터넷에서 통신하지 못합니다
  - 내부망에서만 쓰므로 다른 회사와 같은 주소를 써도 충돌하지 않습니다
  - 정해진 세 범위: `10.x.x.x` · `172.16~31.x.x` · `192.168.x.x`
  - 관제에서는 로그의 주소가 이 범위면 「내부망 장비」로 먼저 분류합니다
- **공인 IP (public IP)** (퍼블릭 아이피)
  - **인터넷 전체에서 하나뿐인** 주소. 통신사가 나눠 줍니다
  - 인터넷의 서버들은 이 주소로 서로를 찾습니다
  - 예: `8.8.8.8`(구글 DNS 서버)

| 사설 IP 범위 | 예 | 주의 |
|---|---|---|
| `10.0.0.0` ~ `10.255.255.255` | `10.0.0.8` | 첫 마디가 10 이면 전부 |
| `172.16.0.0` ~ `172.31.255.255` | `172.20.5.6` | ⚠ **둘째 마디가 16~31 일 때만.** `172.32.5.6` 은 공인 |
| `192.168.0.0` ~ `192.168.255.255` | `192.168.10.25` | 첫 두 마디가 192.168 |

- 세 범위는 인터넷 공통 약속입니다. 이 범위 밖은 **공인 IP** 입니다.
- 사설 IP 는 회사마다 겹쳐도 됩니다. 인터넷으로는 나가지 않기 때문입니다.
- **사설이면 안전, 공인이면 공격이라는 뜻은 아닙니다.** 안 · 밖을 가르는 첫 기준일 뿐입니다.

#### 🐍 문법 상자 · `and` · `or` · 범위 비교

```python
second = 20                        # 변수 second 에 숫자 20 을 담는다
print(16 <= second <= 31)          # True — 16 이상 31 이하
print(second == 10 or second == 20)  # or = 둘 중 하나만 True 여도 True
# True
# True
```

| 쓰는 것 | 뜻 |
|---|---|
| `16 <= second <= 31` | 둘 사이에 있나 (양 끝 포함) |
| `A and B` | 둘 다 참이어야 참 |
| `A or B` | 하나만 참이어도 참 |

⚠ `first == 172` 만 보면 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">`172.32.5.6` 까지 사설로</mark> 잘못 판정합니다. 둘째 마디도 봐야 합니다.

### 2.3 NAT — 사설 IP 를 공인 IP 로 변환

**여기 나오는 말**

- **NAT (Network Address Translation)** (나트 · 냇)
  - 내부망의 사설 IP 를 인터넷으로 보낼 때 **공인 IP 로 바꾸는 주소 변환**
  - 집 · 학원의 **공유기**가 이 일을 합니다 — 내부망 PC 가 보낸 패킷의 출발지 주소를 자기 공인 IP 로 바꿔 보내고, 응답이 오면 변환 기록을 보고 원래 PC 의 사설 IP 로 되돌려 전달합니다
  - 그래서 외부 서버의 로그에는 내 PC 의 사설 IP 가 아니라 **공유기의 공인 IP** 가 남습니다
  - 정적 · 동적 NAT 의 차이는 아래 표에서 **직접 찾아 씁니다**
- **PAT (Port Address Translation)** (팻)
  - 공인 IP **하나**를 내부망의 여러 PC 가 함께 쓰는 NAT
  - 연결마다 공인 IP 쪽 **포트 번호**를 다르게 붙이고, 응답이 오면 그 포트 번호로 어느 PC 의 연결인지 찾아 전달합니다
  - 집 · 학원 공유기는 대부분 이 방식입니다

공유기는 내부망 PC 가 인터넷과 통신할 때 **출발지 주소를 자기 공인 IP 로 바꿔** 보냅니다. 이것이 NAT 입니다.

> 학생 문서에서는 아래 표의 일부 칸이 **[찾아 쓰기]** 로 비어 있습니다. 강사용에는 채운 표를 둡니다.

| 방식 | 바꾸는 법 |
|---|---|
| 정적 NAT | 사설 IP 하나 ↔ 공인 IP 하나를 **고정**해 짝지어 둔다 — 인터넷에서 내부망 서버로 접속하게 할 때 쓴다 |
| 동적 NAT | 공인 IP 여러 개 가운데 사용하지 않는 것을 통신할 때마다 **그때그때** 하나 배정한다 — 짝이 고정되지 않는다 |
| PAT | 공인 IP **하나**를 여러 PC 가 같이 쓰고, **포트 번호로** 누구 것인지 구별한다 — 집 · 학원 공유기가 대부분 이것 |

PAT 공유기는 「공인 IP 쪽 포트 40002번 = 내부망 `192.168.10.25:51234`」 같은 **변환표**를 가지고 있다가, 답이 오면 표를 보고 원래 PC 로 넘겨 줍니다.

### 왜 필요한가

1. 같은 `192.168.10` 으로 시작해도 관리자가 경계를 어디에 뒀는지에 따라 **다른 망**일 수 있습니다.
2. 같은 망이면 스위치(같은 망 안의 장비들을 잇는 장비)가 바로 전달하고, 다른 망이면 **게이트웨이(라우터 · 망과 망을 잇는 장비)** 를 거칩니다. 방화벽(허용 · 차단 규칙으로 통신을 거르는 장비) 규칙도 이 경계로 씁니다.
3. 그 경계를 정하는 값이 `255.255.255.0` — **서브넷 마스크**(서브넷 · 큰 망을 나눈 작은 망)입니다.

### 3.1 서브넷 마스크와 CIDR

**여기 나오는 말**

- **서브넷 (subnet)**
  - 큰 망을 나눈 **작은 망** 하나
  - 같은 서브넷 안의 장비끼리는 공유기 · 라우터를 거치지 않고 바로 통신합니다
  - 회사는 부서마다 서브넷을 나눠, 부서끼리 오가는 통신을 따로 관리합니다
- **서브넷 마스크 (subnet mask)**
  - IP 주소에서 **어디까지가 같은 망**인지 정하는 32비트 값
  - 1 인 비트까지가 **네트워크 부분**, 0 인 비트가 **호스트 부분**입니다
  - 예: `255.255.255.0` 이면 앞 세 마디가 같은 주소끼리 같은 망
- **CIDR (Classless Inter-Domain Routing)** (사이더)
  - 서브넷 마스크를 **1 의 개수**로 짧게 쓰는 표기
  - 예: `255.255.255.0` 은 1 이 24개라 `/24`
  - 숫자가 클수록 망이 작아집니다 — `/24` 는 주소 256개, `/26` 은 64개
- **호스트 (host)**
  - 망 안에서 주소를 받는 **장비 하나**
  - 예: PC · 서버 · 프린터 · 스마트폰
- **네트워크 주소**
  - 그 망의 **첫 주소**. 장비 부분이 모두 0 입니다
  - 망 자체를 가리키는 주소라 장비에 주지 않습니다
  - 예: `192.168.10.0/24` 의 네트워크 주소는 `192.168.10.0`
- **브로드캐스트 주소 (broadcast)** (브로드캐스트)
  - 망 안의 **모든 장비에 한 번에** 보내는 주소
  - 그 망의 **마지막 주소**로, 장비 부분이 모두 1 입니다
  - 예: `192.168.10.0/24` 의 브로드캐스트 주소는 `192.168.10.255` — 장비에 주지 않습니다

| | 1 인 비트 | 0 인 비트 |
|---|---|---|
| 서브넷 마스크 32비트 | **네트워크 부분** — 같은 망이면 모두 같다 | **호스트 부분** — 장비마다 다르다 |

| 서브넷 마스크 | 2진수의 마지막 마디 | CIDR | 주소 수 | 장비에 쓸 수 있는 수 |
|---|---|---|---|---|
| `255.255.255.0` | `00000000` | `/24` | 256 | 254 |
| `255.255.255.128` | `10000000` | `/25` | 128 | 126 |
| `255.255.255.192` | `11000000` | `/26` | 64 | 62 |
| `255.255.255.224` | `11100000` | `/27` | 32 | 30 |
| `255.255.255.240` | `11110000` | `/28` | 16 | 14 |

- CIDR 숫자가 1 커지면 호스트 비트가 하나 줄어 주소 수는 **절반**이 됩니다.
- 쓸 수 있는 수가 2 적은 이유: **첫 주소**는 망 자체를 가리키는 **네트워크 주소**, **마지막 주소**는 망 전체에 한 번에 보내는 **브로드캐스트 주소**라 장비에 주지 않습니다.
- 기본 게이트웨이도 그 사이의 주소 하나를 씁니다(보통 첫 번째).

#### <mark style="display:block; background:#fff59d; color:#1a1a1a; padding:4px 12px; border-radius:4px; text-decoration:underline">정답 3-1</mark>

<mark style="background:#fff59d; color:#1a1a1a; text-decoration:underline; padding:0 4px; border-radius:3px">**결과** — `26` · `6`</mark>

**왜** — 1 이 26개라 `/26` 이고, 호스트 비트가 6개라 주소는 2⁶ = 64개, 장비에 쓸 수 있는 수는 64 − 2 = 62 입니다.

**자주 틀리는 곳** — 0 의 개수 6 을 주소 수로 읽는 것입니다. 6 은 비트 수이고 주소 수는 2 를 여섯 번 곱한 64 입니다.

**관제에서는** — 로그 · 방화벽 규칙의 `/26` 을 보고 그 규칙이 주소 몇 개를 덮는지 바로 셀 수 있어야 합니다.

**강사 메모** — 「0 의 개수 = 호스트 비트 수, 주소 수 = 2 를 그만큼 곱한 수」를 분명히 나눠 말합니다. 「`/24` 는요?」에는 「0 이 8비트라 256개, 쓸 수 있는 수는 254」라고 답합니다. 이어서 학원망 `/16` 은 0 이 16비트라 주소가 2¹⁶ = 65536개라고 미리 알려 두면 3-2 에서 덜 헷갈립니다.

### ✍️ 문제 3-2 · 내 서브넷 마스크를 CIDR 로

**왜 중요한가** — 내 PC 의 CIDR 을 알아야 3-3 에서 내 PC 가 속한 망의 범위를 계산할 수 있습니다.

3. **[이 문서]** 3.1 표에서 그 마스크의 CIDR 을 찾습니다. 표에 없으면 `255` 하나를 1 여덟 개로 세어 1 의 개수를 셉니다.

| | |
|---|---|

2. 255 하나는 1 이 여덟 개입니다.
3. 표에 없는 값이면 1 의 개수를 셉니다 — 예: `255.255.254.0` 은 8 + 8 + 7 = `/23` 입니다.

#### <mark style="display:block; background:#fff59d; color:#1a1a1a; padding:4px 12px; border-radius:4px; text-decoration:underline">정답 3-2</mark>

💻 **터미널에 입력합니다.** `ipconfig` → `서브넷 마스크` 줄.

<mark style="background:#fff59d; color:#1a1a1a; text-decoration:underline; padding:0 4px; border-radius:3px">**결과** — 예: `255.255.255.0` → `/24`. 학원망은 다를 수 있습니다</mark>

**왜** — 255 는 1 이 여덟 개라 255 세 개면 1 이 24개, 곧 `/24` 입니다. 주소는 2⁸ = 256개, 쓸 수 있는 수는 254 입니다.

**자주 틀리는 곳** — 마스크 대신 바로 위 IPv4 주소 줄이나 아래 게이트웨이 줄을 읽는 것입니다. `255.255.254.0` 이면 `/23` 입니다.

**관제에서는** — 내 PC 가 속한 망의 크기를 알아야 어떤 주소까지가 같은 망 장비인지 가릴 수 있습니다.

**강사 메모** — 학원 PC 는 `255.255.0.0` 이 나오므로 답이 `/16` 이고, 3.1 표(`/24` ~ `/28`)에 없는 값이라는 점을 먼저 말합니다. 「예시는 `/24` 인데 저는 왜 다른가요?」에는 「마스크는 망 관리자가 정하는 값이라 집 공유기(`/24`)와 학원망(`/16`)이 다릅니다」라고 답합니다. 표에 없는 값이라 255 두 개 = 1 이 16개 = `/16` 으로 셈하는지 학생 화면에서 봅니다.

### 3.2 `ipaddress` 로 망 계산하기

손으로 세던 마스크 · 주소 수를 파이썬의 `ipaddress` 가 계산해 줍니다. 3.1 의 네트워크 주소 · 브로드캐스트 주소도 바로 꺼낼 수 있습니다.

#### 🐍 문법 상자 · `ipaddress` 로 망 계산하기

```python
import ipaddress  # import = 파이썬에 들어 있는 IP 계산 도구를 불러온다
# ip_network() = 글자를 망 객체로 — strict=False 면 호스트 주소도 받는다
net = ipaddress.ip_network("192.168.10.70/26", strict=False)
print(net)        # 망을 「네트워크 주소/CIDR」 꼴로 출력
# .network_address · .broadcast_address · .num_addresses = 망의 첫 주소 · 끝 주소 · 주소 수
print(net.network_address, net.broadcast_address, net.num_addresses)
# 192.168.10.64/26
# 192.168.10.64 192.168.10.127 64
```

| 쓰는 것 | 뜻 |
|---|---|
| `ipaddress.ip_network("주소/CIDR", strict=False)` | 그 주소가 속한 **망**을 만든다. `strict=False` 는 「망의 첫 주소가 아니어도 받아 준다」 |
| `.network_address` | 네트워크 주소(첫 주소) |
| `.broadcast_address` | 브로드캐스트 주소(마지막 주소) |
| `.num_addresses` | 주소 수 — 쓸 수 있는 수는 여기서 2 를 뺀다 |
| `.netmask` | 서브넷 마스크 |

⚠ `strict=False` 를 빼면 `192.168.10.70/26` 처럼 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">망의 첫 주소가 아닌 값에서 `ValueError`</mark>(값이 맞지 않다는 에러)가 납니다.

### 왜 필요한가

1. 회사가 `192.168.50.0/24`(주소 256개)를 받았습니다. 개발팀 · 운영팀 · 보안팀을 **다른 망**으로 나눠야 서로의 PC 에 함부로 닿지 않습니다.
2. 큰 망을 작은 망 여러 개로 나누는 일이 **서브네팅**입니다.
3. 아무렇게나 나누면 주소가 모자라거나 **두 부서가 같은 주소를 받는** 사고가 납니다. 그래서 계산하고 검증합니다.

### 4.1 장비 수 → CIDR

**여기 나오는 말**

- **서브네팅 (subnetting)**
  - 큰 망을 **작은 망 여러 개로 나누는** 일
  - 부서마다 망을 따로 주면 주소를 아끼고, 부서 사이 통신을 나눠 관리할 수 있습니다

| 필요한 장비 수 | 호스트 비트 | 쓸 수 있는 수 | CIDR |
|---|---|---|---|
| 10대 | 4비트 | 2⁴ − 2 = 14 | `/28` |
| 25대 | 5비트 | 2⁵ − 2 = 30 | `/27` |
| 50대 | 6비트 | 2⁶ − 2 = 62 | `/26` |

**처음으로 「충분」해지는 가장 작은 크기**를 고릅니다. 더 크게 주면 다른 부서 몫이 줄어듭니다.

### 4.2 두 가지 나누는 법

**여기 나오는 말**

- **FLSM (Fixed Length Subnet Mask)** (에프엘에스엠)
  - 모든 부서에 **같은 크기**의 망을 주는 방식
  - 계산이 쉽지만, 사람이 적은 부서에서는 남는 주소가 많습니다
- **VLSM (Variable Length Subnet Mask)** (브이엘에스엠)
  - 부서마다 **필요한 크기**의 망을 주는 방식
  - 큰 부서부터 차례로 나눠야 겹치지 않습니다. 주소를 아낄 수 있어 실무에서 많이 씁니다

| | FLSM | VLSM |
|---|---|---|
| 뜻 | **모든** 부서에 같은 크기 | 부서마다 **필요한 크기** |
| 예 (50 · 25 · 10대) | `/26` 네 개 — 전부 62개씩 | `/26` · `/27` · `/28` |
| 장점 | 단순하다 | 주소를 아낀다 |
| 단점 | 작은 부서에 빈 주소가 많이 남는다 | 계산 · 검증이 필요하다 |

**VLSM 은 큰 블록부터 놓습니다.** `/26` 은 0 · 64 · 128 · 192 에서만 시작할 수 있어서, 작은 것을 먼저 흩어 놓으면 큰 블록이 들어갈 자리가 없어집니다.

```
192.168.50.0/24
  0 ─────────── 63 │ 64 ──── 95 │ 96 ─ 111 │ 112 ───────────────── 255
  개발팀 /26 (62대) │ 운영팀 /27  │ 보안팀 /28 │ 남는 공간 (다음 부서용)
```

#### 🐍 문법 상자 · `**` 거듭제곱 · `.subnets()`

```python
import ipaddress                                  # import = 파이썬에 들어 있는 IP 계산 도구를 불러온다
print(2 ** 6 - 2)                                 # ** = 거듭제곱 — 2 의 6제곱에서 2 를 뺀 값 출력
parent = ipaddress.ip_network("192.168.50.0/24")  # 나눌 큰 망 /24 를 망 객체로
# .subnets(new_prefix=26) = /26 으로 나눈 망들 — list() 로 모아 len() 으로 개수
print(len(list(parent.subnets(new_prefix=26))))
# 62
# 4
```

| 쓰는 것 | 뜻 |
|---|---|
| `2 ** 6` | 2 를 여섯 번 곱한다(64) |
| `망.subnets(new_prefix=26)` | 그 망을 `/26` 크기로 나눈 작은 망들 |

⚠ `subnets()` 의 결과는 리스트가 아니라 차례로 꺼내는 것이라 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">개수를 세려면 `list()` 로 감쌉니다</mark>.

### ✍️ 문제 4-2 · 장비 수에 맞는 가장 작은 CIDR (`smallest_prefix.py`)

**할 일** — 장비 수를 받아 **그만큼 담는 가장 작은 망의 CIDR 숫자**를 리턴하는 함수를 완성해 실행하고, 부서마다 나온 CIDR 을 보고서에 적습니다.

**왜 중요한가** — 장비 수에 맞는 가장 작은 망을 골라야 남는 주소를 다음 부서에 줄 수 있습니다. 오후 7-2 의 서버망 크기도 이 방법으로 정합니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `smallest_prefix.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 복사해 파일에 붙여 넣습니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 를 누릅니다.
   ```python
   # ── 강사용: 정답을 채운 코드입니다 ──
   def smallest_prefix(required):                    # 장비 수를 받아 CIDR 숫자를 리턴한다
       for host_bits in range(2, 33):                # 호스트 칸을 2칸부터 하나씩 늘려 본다
           # 1. 2 ** host_bits - 2 가 required 이상이면 32 - host_bits 를 return 하세요
           if 2 ** host_bits - 2 >= required:        # 이 칸 수로 충분하면
               return 32 - host_bits                 # 나머지가 네트워크 칸 = CIDR 숫자

   for name, count in [("보안팀", 10), ("운영팀", 25), ("개발팀", 50)]:  # (이름, 수) 묶음을 하나씩 꺼내 두 변수에 나눠 담는다
       print(name, count, f"/{smallest_prefix(count)}")  # 함수가 리턴한 CIDR 숫자 앞에 / 를 붙여 출력
   ```

**왜** — 호스트 비트 수를 늘려 가다 `2 ** host_bits - 2` 가 처음으로 장비 수 이상이 되는 비트 수(10 → 4비트 14 · 25 → 5비트 30 · 50 → 6비트 62)에서 `32 - host_bits` 를 리턴합니다.

**자주 틀리는 곳** — `- 2` 를 빼먹어 주소 수로 비교하는 것입니다. 그러면 장비 63 · 64 대도 `/26` 이 나오는데, 실제로는 62 대까지만 들어갑니다.

**강사 메모** — 「처음으로 충분해지는 비트 수에서 바로 `return`」이 가장 작은 망을 고르는 이유라는 점을 짚습니다. 「왜 `range(2, 33)` 으로 2 부터 시작하나요?」에는 「호스트 비트가 1개면 2¹ − 2 = 0 이라 장비를 하나도 못 넣기 때문입니다」라고 답합니다. 끝나면 「63대면?」을 물어 6비트(62)로는 모자라 7비트(126), 곧 `/25` 가 나오는지 확인합니다.

### 4.3 설계 검증 — 용량과 겹침

**여기 나오는 말**

- **겹침 (overlap)** (오버랩)
  - 두 망이 **같은 주소를 함께 가진** 상태
  - 겹치면 그 주소로 가는 패킷이 어느 망으로 가야 할지 정할 수 없어 통신이 꼬입니다
  - 설계에서 생기면 안 됩니다

설계표를 만들면 두 가지를 검증합니다.

| 검증 | 묻는 것 | 틀리면 생기는 일 |
|---|---|---|
| 용량 | 쓸 수 있는 수 ≥ 필요한 장비 수인가 | 장비에 줄 주소가 모자란다 |
| 겹침 | 두 부서의 망이 같은 주소를 갖지 않는가 | 같은 주소를 두 부서 장비가 받아 **주소 충돌**로 통신이 끊긴다. 방화벽 규칙이 다른 부서까지 덮고, 로그의 주소로 어느 장비인지 가릴 수 없다 |

#### 🐍 문법 상자 · `.overlaps()` — 두 망이 겹치나

```python
import ipaddress                              # import = 파이썬에 들어 있는 IP 계산 도구를 불러온다
a = ipaddress.ip_network("192.168.50.0/26")   # .0 부터 시작하는 /26 망 객체
b = ipaddress.ip_network("192.168.50.32/27")  # .32 부터 시작하는 /27 망 객체
print(a.overlaps(b))                          # .overlaps() = 두 망이 주소를 하나라도 같이 쓰면 True
# True
```

| 쓰는 것 | 뜻 |
|---|---|
| `망.overlaps(다른 망)` | 주소가 **하나라도 겹치면** `True` |

### ✍️ 문제 4-4 · 설계 검증 — 용량과 겹침 (`plan_check.py`)

**할 일** — VLSM 설계표가 **부서마다 충분한지**, **서로 겹치지 않는지** 검증하는 코드를 완성해 실행하고, 출력을 보고서에 적습니다.

**왜 중요한가** — 부서 망이 모자라거나 겹치면 주소 충돌로 통신이 끊기고, 방화벽 규칙이 엉뚱한 부서까지 덮습니다. 오후 7-2 에서 서버망을 더할 때도 같은 검증을 합니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `plan_check.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 복사해 파일에 붙여 넣습니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 를 누릅니다.
   ```python
   # ── 강사용: 정답을 채운 코드입니다 ──
   import ipaddress                                  # import = 파이썬에 들어 있는 IP 계산 도구를 불러온다

   plan = [                                          # (부서, CIDR, 필요한 장비 수)
       ("개발팀", "192.168.50.0/26", 50),            # 튜플 하나 = (부서, CIDR, 장비 수)
       ("운영팀", "192.168.50.64/27", 25),           # 같은 꼴의 튜플
       ("보안팀", "192.168.50.96/28", 10),           # 같은 꼴의 튜플
   ]                                                 # 리스트를 닫는다
   networks = []                                     # 겹침 검사용으로 망을 모을 리스트

   for name, cidr, required in plan:                 # 부서를 하나씩
       net = ipaddress.ip_network(cidr)              # CIDR 을 망으로
       # 1. ok 라는 변수에 「쓸 수 있는 수가 required 이상인지」 를 담으세요
       ok = net.num_addresses - 2 >= required        # 장비를 다 담을 수 있나
       print(name, cidr, "충분:", ok)                # 부서 · CIDR · 판정을 한 줄에 출력
       networks.append(net)                          # 겹침 검사용으로 모은다

   # 2. overlap 에 「앞 둘(networks[0], networks[1])이 겹치거나 networks[1] 과 networks[2] 가 겹치거나 networks[0] 과 networks[2] 가 겹치는지」 를 담으세요
   # 세 쌍 중 하나라도 .overlaps() 가 True 면 overlap 은 True
   overlap = networks[0].overlaps(networks[1]) or networks[1].overlaps(networks[2]) or networks[0].overlaps(networks[2])
   print("겹침 있음:", overlap)                      # 겹침 판정을 출력
   ```
3. **[VS Code]** 번호 주석 아래를 채웁니다.
4. **[터미널]** 실행합니다. 터미널의 줄 위에 `…/network_zt` 가 보여야 합니다. 아니면 먼저 `cd network_zt` 를 입력합니다.
   ```bash
   python plan_check.py
   ```
   맥북: `python3 plan_check.py`
5. **[터미널]** 고친 뒤에는 **↑(위 화살표)** 를 눌러 방금 입력한 명령을 다시 실행합니다.
6. **[보고서]** `day02_subnet_design.md`의 `## 4교시` › `### 문제 4-4` 아래를 채웁니다.
   - 출력 네 줄:
   - 🔍 두 부서의 망이 겹치면 어떤 문제가 생기나요?

| | |
|---|---|
| 🎯 나와야 하는 결과 | `개발팀 192.168.50.0/26 충분: True` · `운영팀 192.168.50.64/27 충분: True` · `보안팀 192.168.50.96/28 충분: True` · `겹침 있음: False` |

**💡 힌트**

1. 1번은 `net.num_addresses - 2 >= required` 입니다.
2. 2번은 `.overlaps()` 세 개를 `or` 로 잇습니다.
3. 개발팀을 `/27` 로 바꿔 실행해 보면 `충분: False` 가 나옵니다 — 이런 실수를 잡는 검사입니다.

#### <mark style="display:block; background:#fff59d; color:#1a1a1a; padding:4px 12px; border-radius:4px; text-decoration:underline">정답 4-4</mark>

(코드는 위 문제 코드에 채워 두었습니다.)

💻 **터미널에 입력합니다.** `python plan_check.py`

<mark style="background:#fff59d; color:#1a1a1a; text-decoration:underline; padding:0 4px; border-radius:3px">**결과** — `개발팀 192.168.50.0/26 충분: True` · `운영팀 … 충분: True` · `보안팀 … 충분: True` · `겹침 있음: False`</mark>

**왜** — 쓸 수 있는 수가 62 ≥ 50 · 30 ≥ 25 · 14 ≥ 10 이라 모두 충분하고, 0~63 · 64~95 · 96~111 로 이어져 `.overlaps()` 셋이 모두 `False` 입니다.

**자주 틀리는 곳** — `num_addresses >= required` 로 비교해 2 를 빼먹는 것입니다. 이번 값은 그래도 `True` 라 틀린 줄 모르고 넘어갑니다.

**관제에서는** — 두 부서 망이 겹치면 같은 주소를 두 PC 가 받을 수 있어, 로그 주소로 장비를 특정할 수 없게 됩니다.

**강사 메모** — 검증은 용량(`>=`)과 겹침(`.overlaps()`) 두 가지라는 점을 짚습니다. 「짝을 왜 세 번 쓰나요?」에는 「부서가 셋이면 비교할 짝이 0-1 · 1-2 · 0-2 세 쌍이기 때문입니다」라고 답합니다. 끝나면 힌트 3처럼 개발팀을 `/27` 로 바꿔 `충분: False`(30 < 50)를, 운영팀을 `192.168.50.32/27` 로 바꿔 `겹침 있음: True` 를 직접 보게 합니다.

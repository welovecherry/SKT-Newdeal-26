## 2교시 · IP 주소 · 사설과 공인

### 문제 2-1 · 내 IP 를 2진수로

- **(가) 두 번째 파일(`warmup_2_1b.py`, 내 IPv4 주소)의 출력 네 줄:** 예) 예시 주소 그대로면 `192 11000000` · `168 10101000` · `10 00001010` · `25 00011001`
  - 확인할 것: 예시 주소가 아니라 **내 IPv4 주소**로 바꿔 실행했는가(학원 PC 는 `192.168.○.○`). 줄마다 2진수가 **8자리**인가.
- **(나-1) `format(number, "08b")` 가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.**
  - 모범 답: 마디 하나의 10진수를 0 과 1 로 된 8자리 2진수 글자로 바꾼다. 예를 들어 내 출력의 `10 00001010` 줄처럼 `10` 이 `00001010` 이 된다. 주소를 비트 단위로 펼쳐야 마스크가 어느 비트에서 망 부분과 장비 부분을 나누는지 볼 수 있다.
  - 핵심 낱말: **10진수 → 8자리 2진수 글자 · 내 출력 한 줄을 예로 듦**
- **(나-2) `"08b"` 에서 `08` 을 빼고 `"b"` 만 쓰면 `10` 은 어떻게 출력되나요? 마디마다 8자리로 맞춰 써야 하는 이유를 함께 설명하세요.**
  - 모범 답: `"b"` 만 쓰면 `10` 은 `1010` 네 자리로 출력된다. `08` 은 빈 앞자리를 0 으로 채워 8자리를 만들라는 뜻이고, `b` 는 2진수로 바꾸라는 뜻이다. 8자리로 맞추지 않으면 마디마다 길이가 달라 32비트 가운데 몇 번째 비트인지 줄을 맞춰 볼 수 없고, 비트 자리 단위로 나누는 마스크를 대어 볼 수 없다.
  - 핵심 낱말: **`1010` 네 자리 · `08` = 앞자리를 0 으로 채워 8자리 · 비트 자리를 맞춰야 마스크와 비교**
- **(다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.**
  - 모범 답: IPv4 주소는 마디 네 개 × 8비트 = 32비트다. 마디 하나가 8비트라 `00000000` ~ `11111111`, 곧 10진수 0 ~ 255 의 256 가지 값만 가질 수 있다. 그래서 `256` 같은 값은 IPv4 주소의 마디가 될 수 없다.
  - 핵심 낱말: **마디 4개 × 8비트 · 8비트 = 0 ~ 255(256 가지)**
- **(다-2) 32비트로 만들 수 있는 주소는 모두 몇 개이며, 이 수의 한계가 사설 IP 와 NAT 를 쓰게 된 것과 어떻게 이어지는지 설명하세요.**
  - 모범 답: 2³² = 4,294,967,296개(약 43억 개)다. 인터넷에 연결되는 장비가 이보다 많아져 모든 장비에 공인 IP 를 하나씩 줄 수 없다. 그래서 내부망에서는 회사마다 겹쳐도 되는 사설 IP 를 쓰고, 인터넷으로 나갈 때 NAT 로 공인 IP 하나를 여러 PC 가 함께 쓴다.
  - 핵심 낱말: **약 43억 개 · 장비보다 모자람 → 사설 IP · NAT**
  - 확인할 것: 개수만 적고 사설 IP · NAT 와 잇는 이유가 없으면 다시 쓰게 한다.
- **(다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.**
  - 모범 답: 비트 한 자리에는 0 또는 1, 두 가지 값이 들어간다. 자리가 하나 늘 때마다 경우의 수가 2배가 되므로 1자리 2가지, 2자리 4가지, … 8자리(마디 하나) 2⁸ = 256 가지가 된다. 같은 계산으로 32자리면 2 를 32번 곱한 2³² = 4,294,967,296 가지다.
  - 핵심 낱말: **한 자리에 2가지 · 자리마다 2배 · 2³²**

### 문제 2-2 · 내 주소는 사설일까 — 인터넷이 보는 내 주소

- **(가) `ipconfig` 의 내 IPv4 주소 · `curl` 로 본 공인 IP:** 예) `192.168.10.25 · 211.○○○.○○○.○○`
  - 확인할 것: 두 값이 **다르다**. 공인 IP 항목에 `192.168.…` 을 적지 않았는가.
- **(나-1) 🔍 내 IPv4 주소는 2.2 표의 어느 범위에 들어가며, 그래서 사설과 공인 가운데 무엇인가요? 범위의 시작 주소와 끝 주소를 근거로 판정하세요.**
  - 모범 답: 내 주소 `192.168.…` 은 2.2 표 셋째 줄의 시작 주소 `192.168.0.0` 과 끝 주소 `192.168.255.255` 사이에 들어가므로 사설 IP 다. 첫 두 마디가 `192.168` 이면 뒤 두 마디가 무엇이든 이 범위 안이다.
  - 핵심 낱말: **`192.168.0.0` ~ `192.168.255.255` 범위 = 사설**
  - 확인할 것: 값만 적고 이유가 없으면 다시 쓰게 한다.
- **(나-2) `curl` 로 본 주소는 사설과 공인 가운데 무엇인가요? 2.2 표의 세 범위와 맞춰 본 근거를 들어 설명하세요.**
  - 모범 답: 공인 IP 다. `curl` 로 본 주소는 `10.` · `172.16~31.` · `192.168.` 세 범위 어디에도 들지 않기 때문이다. 세 범위에 들지 않는 주소는 모두 공인 IP 다.
  - 핵심 낱말: **세 범위 어디에도 없음 = 공인**
- **(나-3) 관제 로그의 출발지 주소가 `172.20.5.6` 과 `172.32.5.6` 이라면, 각각 내부망 장비와 외부 주소 가운데 무엇으로 먼저 분류해야 하나요? 2.2 표를 근거로 설명하세요.**
  - 모범 답: `172.20.5.6` 은 둘째 마디 20 이 16 ~ 31 사이라 사설 IP 이므로 내부망 장비로 먼저 분류한다. `172.32.5.6` 은 둘째 마디 32 가 16 ~ 31 을 벗어나 공인 IP 이므로 외부 주소로 분류한다. 다만 사설이라고 안전하다는 뜻은 아니고, 내부와 외부를 가르는 첫 기준일 뿐이다.
  - 핵심 낱말: **`172` 은 둘째 마디 16 ~ 31 만 사설 · `172.20` 내부 / `172.32` 외부**
  - 확인할 것: 첫 마디 `172` 만 보고 둘 다 사설로 적지 않았는가.
- **(다-1) 외부 서버 로그에 남은 출발지 IP 만으로는 내부망의 어느 PC 인지 특정할 수 없는 이유를 NAT 의 동작으로 설명하고, 특정하려면 어떤 기록이 더 필요한지 쓰세요.**
  - 모범 답: NAT(학원 · 집 공유기는 PAT)는 내부망 PC 가 보낸 패킷의 출발지 사설 IP 를 공유기의 공인 IP 로 바꿔 보내므로, 외부 서버 로그에는 공유기의 공인 IP 만 남는다. 그 공인 IP 하나를 내부망 PC 여러 대가 함께 쓰므로 그 주소만으로는 어느 PC 인지 가릴 수 없다. 특정하려면 공유기의 변환 기록(공인 IP 쪽 포트 번호 ↔ 내부 사설 IP · 포트)과 통신한 시각이 더 필요하다.
  - 핵심 낱말: **출발지를 공인 IP 로 바꿈 · 여러 PC 가 한 공인 IP 를 씀 · 공유기 변환 기록(포트) · 시각**
  - 확인할 것: 값만 적고 이유가 없으면 다시 쓰게 한다.
- **(다-2) 정적 NAT 과 동적 NAT 은 사설 IP 와 공인 IP 를 연결하는 방식이 어떻게 다른가요? 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 어느 방식이 맞는지 이유와 함께 설명하세요.**
  - 모범 답: 정적 NAT 은 사설 IP 하나와 공인 IP 하나를 **고정**해 연결해 두고, 동적 NAT 은 공인 IP 여러 개 가운데 쓰지 않는 것을 통신할 때마다 **그때그때** 하나 배정한다. 내부망 웹 서버는 외부 사용자가 늘 같은 공인 IP 로 찾아와야 하므로 정적 NAT 이 맞다. 동적 NAT 은 공인 IP 가 바뀌므로 외부에서 그 서버를 찾아올 주소가 정해지지 않는다.
  - 핵심 낱말: **고정 연결 / 그때그때 배정 · 웹 서버 = 정적 NAT(주소가 늘 같아야 함)**

- **(다-3) 사원 PC 여러 대가 인터넷을 쓸 때는 동적 NAT 을 쓰는 이유는 무엇인가요? 동적 NAT 환경에서 외부 로그의 공인 IP 로 PC 를 특정하려면 무엇을 함께 봐야 하는지와 이어서 설명하세요.**
  - 모범 답: 사원 PC 는 밖에서 찾아올 일이 없고 안에서 밖으로 나가기만 하므로 공인 IP 를 고정해 줄 필요가 없다. 동적 NAT 은 쓰지 않는 공인 IP 를 통신할 때마다 하나씩 배정해, 적은 공인 IP 를 여러 PC 가 돌아가며 나눠 쓸 수 있다(주소 절약). 대신 같은 공인 IP 가 시간마다 다른 PC 일 수 있어, 로그의 공인 IP 로 PC 를 특정하려면 그 시각의 NAT 변환 기록(공인 IP ↔ 사설 IP)을 함께 봐야 한다.
  - 핵심 낱말: **나가기만 하는 PC · 공인 IP 돌려 쓰기(절약) · 그 시각의 변환 기록**

### 이 교시에 새로 안 것

- 자유. 「IP 주소는 32비트」, 「사설 IP 는 NAT 으로 공인 IP 로 바뀌어 나간다」 정도면 충분합니다.

## 3교시 · 서브넷 마스크 · CIDR

### 문제 3-1 · 내 서브넷 마스크 읽기

- **(가) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수:** 학원 PC `255.255.0.0 · /16 · 65,536 · 65,534` (집 공유기는 보통 `255.255.255.0 · /24 · 256 · 254`)
  - 확인할 것: `서브넷 마스크` 줄을 읽었는가(IPv4 주소 · 게이트웨이 줄 아님). 주소 수 · 쓸 수 있는 수를 3.3 표의 같은 줄에서 옮겼는가.
- **(나-1) 🔍 내 서브넷 마스크를 2진수로 펼쳤을 때 1 인 비트와 0 인 비트가 각각 주소의 어느 부분을 가리키는지, 1 이 8개인 마디의 수를 근거로 설명하세요.**
  - 모범 답(학원 `/16`): `255.255.0.0` 은 2진수로 `11111111.11111111.00000000.00000000` 이다. 1 인 비트는 망 부분, 0 인 비트는 장비 부분을 가리킨다. 1 이 8개인 마디가 두 개라 앞 두 마디가 망 부분, 뒤 두 마디가 장비 부분이다.
  - 핵심 낱말: **1 = 망 부분 · 0 = 장비 부분 · `255` 마디 두 개**
  - 확인할 것: 값만 적고 이유가 없으면 다시 쓰게 한다.
- **(나-2) 내 주소의 망 부분은 앞 몇 마디이며, 그 마디 수에서 CIDR 숫자가 어떤 계산으로 나오는지 설명하세요.**
  - 모범 답(학원 `/16`): 망 부분은 앞 두 마디 `192.168` 이다. CIDR 숫자는 마스크의 1 의 개수라, 1 이 8개인 마디 두 개를 세면 8 × 2 = 16, 그래서 `/16` 이다.
  - 핵심 낱말: **CIDR = 1 의 개수 · 8 × 마디 수**
- **(다-1) 내 마스크를 기준으로 `192.168.10.25` 와 `192.168.20.25` 가 같은 망인지 판정하고, 비교해야 하는 마디를 짚어 근거를 설명하세요.**
  - 모범 답(학원 `/16`): 같은 망이다. `/16` 은 망 부분인 앞 두 마디만 비교하는데 둘 다 `192.168` 이다. 셋째 마디 `10` · `20` 은 장비 부분이라 달라도 같은 망이다.
  - 핵심 낱말: **망 부분 마디만 비교 · `/16` 은 앞 두 마디**
  - 확인할 것: 내 마스크 기준으로 답했는가. 학원 PC 인데 「다른 망」이면 예시 `/24` 로 판단한 것이다.
- **(다-2) 같은 두 주소를 `/24` 마스크로 판정하면 결과가 어떻게 달라지나요? 마스크에 따라 판정이 달라진다는 사실이 통신 경로와 방화벽 규칙을 정할 때 왜 중요한지 설명하세요.**
  - 모범 답: `/24` 면 앞 세 마디를 비교하므로 셋째 마디 `10` ≠ `20` 이라 다른 망이 된다. 같은 망이면 스위치가 바로 전달하고 다른 망이면 게이트웨이를 거치므로, 마스크가 통신이 지나는 장비를 정한다. 방화벽 규칙도 이 경계로 쓰므로 마스크를 잘못 알면 규칙이 의도하지 않은 장비를 덮거나 빠뜨린다.
  - 핵심 낱말: **`/24` 면 다른 망 · 마스크가 경로(스위치 / 게이트웨이)를 정함 · 방화벽 규칙의 경계**

### 문제 3-2 · 내 망 범위

- **(가) 내 주소/CIDR · 출력 세 줄:**
  - 학원 PC 예) `192.168.10.25/16 · 255.255.0.0 · 192.168.0.0 · 192.168.255.255`
  - 예시 값 그대로면 `192.168.10.25/24 · 255.255.255.0 · 192.168.10.0 · 192.168.10.255`
  - 확인할 것: `prefix` 를 3-1 의 내 CIDR(학원 `16`)로 바꿨는가. 학원망이면 학생 주소가 달라도 둘째 · 셋째 줄은 모두 `192.168.0.0` · `192.168.255.255` 다.
- **(나-1) 출력 세 줄이 각각 3.2 의 ① ~ ④ 가운데 어느 단계의 값인지 쓰고, 둘째 줄 값이 3.2 의 AND 연산으로 어떻게 나오는지 설명하세요.**
  - 모범 답: 첫째 줄은 ① 서브넷 마스크, 둘째 줄은 ③ 네트워크 주소, 셋째 줄은 ③ 브로드캐스트 주소다. 둘째 줄은 내 주소와 마스크를 2진수로 바꿔 같은 자리끼리 AND 한 결과다. 마스크가 1 인 자리는 주소 비트가 그대로 남고, 0 인 자리는 모두 0 이 된다.
  - 핵심 낱말: **① 마스크 · ③ 네트워크 · 브로드캐스트 · AND(1 이면 그대로, 0 이면 0)**
- **(나-2) 내 주소에서 `0` · `255` 로 바뀐 마디는 어디이며, 왜 그 마디만 바뀌고 나머지 마디는 그대로인지 망 부분과 장비 부분으로 설명하세요.**
  - 모범 답(학원 `/16`): 셋째 · 넷째 마디가 바뀌었다. 마스크가 `0` 인 이 두 마디가 장비 부분이라, 모두 `0` 으로 바꾼 것이 네트워크 주소, 모두 `255` 로 바꾼 것이 브로드캐스트 주소다. 앞 두 마디는 마스크가 `255` 인 망 부분이라 그대로 남는다.
  - 핵심 낱말: **장비 부분만 `0` / `255` 로 · 망 부분은 그대로**
- **(다-1) `ipconfig` 의 내 기본 게이트웨이 주소가 둘째 줄과 셋째 줄 사이에 있는지 확인하고, 게이트웨이 주소가 이 범위 안에 있어야 하는 이유를 설명하세요.**
  - 모범 답: 있다. 학원 게이트웨이 `192.168.1.1` 은 `192.168.0.0` 과 `192.168.255.255` 사이다. PC 는 같은 망의 장비에게만 바로 패킷을 넘기므로, 게이트웨이도 같은 망 안의 장비 주소(④ 장비에 줄 수 있는 주소)여야 PC 가 다른 망으로 갈 패킷을 넘길 수 있다.
  - 핵심 낱말: **게이트웨이도 같은 망 안의 장비 주소 · 같은 망이어야 바로 넘긴다**
  - 확인할 것: 값만 적고 이유가 없으면 다시 쓰게 한다.
- **(다-2) 게이트웨이 주소를 둘째 줄의 네트워크 주소나 셋째 줄의 브로드캐스트 주소로 잘못 설정하면 왜 문제가 되는지, 두 주소의 역할을 들어 설명하세요.**
  - 모범 답: 네트워크 주소는 망 전체를 가리키는 주소이고, 브로드캐스트 주소는 망 안의 장비 모두가 받는 주소라 어느 쪽도 장비 한 대를 가리키지 못한다. 그래서 게이트웨이를 그 주소로 설정하면 PC 가 다른 망으로 갈 패킷을 넘길 장비를 정하지 못해 인터넷과 통신하지 못한다.
  - 핵심 낱말: **망 전체 / 장비 모두 → 장비 한 대가 아님 · 다른 망으로 못 나감**

### 이 교시에 새로 안 것

- 자유. 「마스크의 `255` 마디까지가 망 부분」, 「같은 망인지는 주소가 아니라 마스크로 정한다」, 「학원망은 `/16`, 집은 `/24`」 정도면 충분합니다.

## 4교시 · 서브네팅

### 문제 4-1 · 반으로 나누기 `/25`

- **(가) 출력 두 줄:** `192.168.50.0/25` · `192.168.50.128/25`
  - 확인할 것: 출력이 두 줄인가. 네 줄이면 `new_prefix=26` 으로 친 것이다.
- **(나-1) 4.1 표와 맞춰 블록마다 범위를 쓰고, 블록 이름 `192.168.50.128/25` 의 `/` 앞 주소가 그 블록에서 어떤 주소인지 설명하세요.**
  - 모범 답: 블록 1 은 `.0` ~ `.127`, 블록 2 는 `.128` ~ `.255` 다. 블록 이름 `192.168.50.128/25` 의 `/` 앞 주소 `.128` 은 그 블록에서 가장 작은 주소, 곧 네트워크 주소다.
  - 핵심 낱말: **`.0` ~ `.127` · `.128` ~ `.255` · `/` 앞 = 네트워크 주소**
- **(나-2) 두 블록이 `.128` 에서 나뉘는 이유를 블록 하나의 주소 수로 설명하고, 쓸 수 있는 수(126)만큼씩 자르면 안 되는 이유도 쓰세요.**
  - 모범 답: `/25` 블록 하나는 주소가 128개다(3.3 표). 256개를 앞에서부터 128개씩 자르면 첫 블록이 `.127` 에서 끝나, 둘째 블록은 그 바로 다음 `.128` 에서 시작한다. 블록은 네트워크 주소 · 브로드캐스트 주소까지 포함한 주소 수만큼 잘라야 하므로, 126개씩 자르면 블록의 시작과 끝이 마스크가 정하는 경계와 어긋난다.
  - 핵심 낱말: **`/25` = 128개 · 주소 수로 자른다(126 아님)**
- **(다) 4.1 첫 표의 `/26` 줄에서 읽은 주소 수 · 장비에 쓸 수 있는 수:** 64 · 62
- **(다) 두 수가 2 만큼 다른 이유를 빠지는 두 주소의 역할로 설명하고, 장비 64대인 부서에 `/26` 블록을 주면 어떤 설계 실수가 되는지 쓰세요.**
  - 모범 답: 블록의 가장 작은 주소는 네트워크 주소(망 전체를 가리킴), 가장 큰 주소는 브로드캐스트 주소(망 안의 장비 모두가 받음)라서 이 두 개는 장비에 주지 않는다. 그래서 64 − 2 = 62 대까지 줄 수 있다. 장비 64대인 부서에 `/26` 을 주면 2대가 주소를 받지 못하므로, 한 단계 큰 `/25`(126대)를 줘야 한다.
  - 핵심 낱말: **네트워크 주소 · 브로드캐스트 주소는 장비에 주지 않는다 · 62대뿐이라 용량 부족**

### 문제 4-2 · 겹침 검사

## 5교시 · 스위치와 라우터

### 문제 5-1 · ARP 캐시에서 게이트웨이 찾기

- **(가) 기본 게이트웨이 줄의 IP · MAC 주소 · `8.8.8.8` 줄이 있었나:** 학원 PC 예) `192.168.1.1 · ○○-○○-○○-○○-○○-○○ · 없음`
  - 확인할 것: `인터넷 주소` 가 **내 기본 게이트웨이**인 줄을 골랐는가(`224.` · `255` 로 끝나는 줄이 아니다). `8.8.8.8` 줄은 없어야 한다.
- **(나) 🔍 방금 `8.8.8.8` 로 보냈는데도 ARP 캐시에는 내 망(학원 PC 는 앞 두 마디 `192.168`)의 장비만 있고 `8.8.8.8` 줄이 없는 이유를, 다른 망으로 보내는 프레임의 목적지 MAC 과 이어서 설명하세요.**
  - 모범 답: 다른 망으로 보내는 프레임의 목적지 MAC 은 `8.8.8.8` 의 MAC 이 아니라 게이트웨이의 MAC 이다. ARP 는 같은 망의 장비에게만 MAC 을 묻기 때문에 PC 는 `8.8.8.8` 의 MAC 을 묻지 않고 게이트웨이의 MAC 만 알아냈다. 그래서 ARP 캐시에는 게이트웨이처럼 같은 망 장비의 줄만 생긴다.
  - 핵심 낱말: **다른 망 → 목적지 MAC = 게이트웨이 MAC · ARP 는 같은 망에서만**
  - 확인할 것: 값만 적고 이유가 없으면 다시 쓰게 한다.
- **(다-1) MAC 주소와 IP 주소는 각각 누가 정하며, 패킷이 다른 망으로 건너갈 때 두 주소가 바뀌는지 그대로인지 비교해 설명하세요.**
  - 모범 답: MAC 주소는 랜카드를 만든 회사가 정해 넣는 48비트(16진수 12자리) 주소이고, IP 주소는 망을 관리하는 쪽(공유기 · 학원 네트워크 장비)이 나눠 준다. 다른 망으로 건너갈 때 목적지 IP 는 끝까지 그대로이고, 목적지 MAC 은 장비를 하나 지날 때마다 바뀐다(5.2).
  - 핵심 낱말: **MAC = 제조사 · IP = 망 관리자 · IP 그대로 / MAC 은 바뀜**
- **(다-2) ARP 가 MAC 주소를 알아낼 때 질문은 브로드캐스트로 보내고 답은 한 장비만 하는 이유를 설명하세요.**
  - 모범 답: 묻는 쪽은 상대의 MAC 을 아직 모르므로 장비 하나를 가리켜 보낼 수 없어, 같은 망 전체에 브로드캐스트로 「이 IP 를 가진 장비는 MAC 을 알려 달라」고 묻는다. 모두가 받지만 그 IP 를 가진 장비 하나만 해당하므로 그 장비만 자기 MAC 을 답한다.
  - 핵심 낱말: **MAC 을 몰라 브로드캐스트 · IP 주인만 답한다**

### 문제 5-2 · 스위치의 MAC 주소 표 읽기

- **(가) 첫 파일 출력 · 두 번째 파일(`"AA"`) 출력:** `모든 포트로` · `포트 1 로만`
  - 확인할 것: 두 출력을 모두 적었는가. 두 번째 파일 출력이 `포트 AA 로만` 이면 키와 값을 헷갈린 것.
- **(나-1) 두 출력이 다른 이유를 MAC 주소 표에 적힌 내용과 5.3 의 ② · ③ 단계로 설명하세요.**
  - 모범 답: MAC 주소 표에는 출발지 `AA` 만 1번 포트로 적혀 있다. ② 에서 목적지 `BB` 는 표에 없어 ③ 의 `else` 쪽(플러딩)이 나왔고, `AA` 는 표에 있어 `if` 쪽(그 포트로만)이 나왔다.
  - 핵심 낱말: **표에 있으면 그 포트로만, 없으면 플러딩**
- **(나-2) 둘째 출력에 `AA` 가 아니라 숫자가 나온 이유를 딕셔너리의 키와 값으로 설명하고, 그 숫자가 실제 스위치에서 무엇을 뜻하는지 쓰세요.**
  - 모범 답: `mac_table[dest]` 는 키 `AA` 로 꺼낸 값 `1` 이라 숫자가 나왔다. 이 숫자는 실제 스위치에서 `AA` 장비가 꽂힌 스위치 포트 번호다.
  - 핵심 낱말: **키로 값을 꺼낸다 · 값 = 스위치 포트 번호**
- **(다-1) 플러딩이 일어나는 조건을 쓰고, 5.3 의 예처럼 처음에는 플러딩하던 스위치가 그다음부터 한 포트로만 보내게 되는 과정을 설명하세요.**
  - 모범 답: 목적지 MAC 이 MAC 주소 표에 없을 때(처음 보는 MAC · 브로드캐스트) 일어난다. 5.3 의 예에서 `CC → DD` 는 `DD` 를 몰라 플러딩했지만, `DD` 가 4번 포트로 답을 보내자 스위치가 출발지 `DD` 를 4번으로 배웠다. 그다음부터 `DD` 로 가는 프레임은 4번 포트로만 보낸다.
  - 핵심 낱말: **표에 없을 때 · 출발지를 배운다 · 그다음부터 한 포트로만**
- **(다-2) 플러딩이 많아지면 망의 성능과 보안에 각각 어떤 문제가 생기는지 예를 들어 설명하세요.**
  - 모범 답: 성능 — 모든 포트로 복사본이 퍼져 망이 느려진다. 보안 — 다른 장비에게 갈 프레임이 내 포트에도 와서 엿볼 수 있게 된다. 예를 들어 한 포트에서 MAC 이 갑자기 많이 배워져 표가 넘치면 스위치가 계속 플러딩하게 된다.
  - 핵심 낱말: **망이 느려짐 · 다른 포트에서 엿볼 수 있음**
  - 확인할 것: 성능과 보안 두 쪽을 모두 썼는가.

### 이 교시에 새로 안 것

- 자유. 「스위치는 MAC, 라우터는 IP 를 본다」, 「다른 망으로 보낼 때 목적지 MAC 은 게이트웨이 MAC」 정도면 충분합니다.

## 6교시 · VLAN · 라우팅 표

### 문제 6-1 · 내 PC 의 기본 경로와 첫 홉

- **(가) `ipconfig` 의 기본 게이트웨이 주소 · `tracert` 1번 홉의 주소:** 학원 PC `192.168.1.1 · 192.168.1.1`
  - 확인할 것: 내 IPv4 주소가 아니라 `기본 게이트웨이` 줄을 읽었는가. `tracert` 뒤 줄이 `*  *  *` 여도 정상.
- **(나-1) 🔍 두 주소가 일치한다는 것은 이 PC 의 트래픽 경로에 대해 무엇을 말해 주나요? 5.2 의 「보낼 곳」 표와 이어서 설명하세요.**
  - 모범 답: 이 PC 가 다른 망(인터넷)으로 보내는 패킷은 모두 기본 게이트웨이를 첫 홉으로 지난다는 뜻이다. 5.2 표처럼 목적지가 다른 망이면 PC 는 라우팅 표의 기본 경로 줄을 쓰고, 그 줄의 다음 홉인 기본 게이트웨이로 먼저 보낸다. 그래서 인터넷 통신 장애를 볼 때 첫 확인 지점이 기본 게이트웨이다.
  - 핵심 낱말: **다른 망은 기본 경로 · 첫 홉 = 기본 게이트웨이 · 모든 인터넷 통신이 지난다**
  - 확인할 것: 값만 적고 이유가 없으면 다시 쓰게 한다.
- **(나-2) 두 주소가 일치하지 않는다면 어떤 상황을 의심해야 하나요? 근거와 함께 설명하세요.**
  - 모범 답: 먼저 `ipconfig` 에서 다른 장치의 게이트웨이를 읽지 않았는지 확인한다. 그래도 다르면 패킷이 설정된 게이트웨이가 아닌 다른 장비로 가고 있다는 뜻이므로, 잘못된 설정이나 경로를 바꾸는 가짜 게이트웨이를 의심한다.
  - 핵심 낱말: **읽은 줄 확인 · 다른 장비로 감 → 잘못된 설정 · 가짜 게이트웨이**
- **(다-1) 기본 경로(`0.0.0.0/0`)가 어떤 목적지로 갈 때 쓰이는지, `/0` 이 무엇을 뜻하는지와 함께 설명하세요.**
  - 모범 답: `/0` 은 비교할 마디가 하나도 없다는 뜻이라 모든 주소에 맞는다. 그래서 라우팅 표의 다른 어느 줄에도 맞지 않는 목적지 — 곧 인터넷 쪽 주소 전부 — 로 갈 때 쓰인다.
  - 핵심 낱말: **`/0` = 모든 주소 · 다른 줄에 안 맞는 목적지 전부**
- **(다-2) 라우팅 표에서 기본 경로가 빠지면 맞는 줄이 없는 목적지로 가는 패킷은 어떻게 되나요? 이때 같은 망 통신과 인터넷 통신이 각각 어떻게 되는지 이유와 함께 설명하세요.**
  - 모범 답: 맞는 줄이 없는 패킷은 갈 곳이 없어 버려진다. 같은 망 통신은 내 망 줄(직접 연결)이 남아 있어 그대로 되지만, 인터넷 통신은 맞는 줄이 없어 되지 않는다.
  - 핵심 낱말: **버려진다 · 같은 망은 됨 / 인터넷은 안 됨**

### 문제 6-2 · 회사 망 줄인가, 기본 경로인가

- **(가-1) 첫 파일 출력:** `맞는 줄: 192.168.30.0/24 → 직접 연결 VLAN 30`
- **(가-2) 두 번째 파일(`8.8.8.8`) 출력:** `회사 망 줄에 없음 → 기본 경로 0.0.0.0/0 (인터넷 쪽 라우터)`
  - 확인할 것: 두 번째 파일에서 `맞는 줄:` 이 사라지고 기본 경로 줄이 나왔는가. `SyntaxError` 가 났으면 코드를 붙여 넣다 따옴표가 빠진 것. 아무것도 안 나오면 `found = True` 의 들여쓰기를 본다.
- **(나-1) 라우터가 `192.168.30.5` 를 보낼 줄을 고르는 과정을 6.3 의 라우팅 표와 첫 파일 출력으로 설명하세요.**
  - 모범 답: 코드는 6.3 의 회사 망 세 줄을 위에서부터 하나씩 꺼내 목적지가 그 망에 들어가는지 본다. `192.168.30.5` 는 셋째 줄 `192.168.30.0/24` 에 들어가므로 그 줄, 곧 직접 연결 VLAN 30 으로 보낸다. 바꾸기 전 출력 `맞는 줄: 192.168.30.0/24 → 직접 연결 VLAN 30` 이 그 결과다.
  - 핵심 낱말: **줄마다 비교 · 들어가는 회사 망 줄 · VLAN 30**
- **(나-2) `8.8.8.8` 일 때 `found` 가 반복이 끝날 때까지 `False` 로 남은 이유를 쓰고, 그것이 라우터가 기본 경로 줄을 고르는 조건과 어떻게 대응하는지 설명하세요.**
  - 모범 답: `8.8.8.8` 은 첫째 마디부터 회사 망과 달라 세 줄 어디에도 들어가지 않으므로 `if` 아래가 한 번도 실행되지 않고 `found` 가 `False` 로 남는다. 이것이 「회사 망 줄에 하나도 맞지 않으면 기본 경로 줄로 보낸다」는 라우터의 조건과 같아서, 마지막 `if` 가 기본 경로 `0.0.0.0/0` 으로 보낸다고 출력한다.
  - 핵심 낱말: **한 줄도 안 맞음 → `found` 그대로 `False` = 기본 경로**
- **(다) 부서마다 VLAN 을 나누면 한 부서 PC 가 악성코드에 감염됐을 때 피해 범위와 대응 방법이 어떻게 달라지나요? 브로드캐스트 범위와 라우터에서의 접근 통제를 들어 설명하세요.**
  - 모범 답: VLAN 이 다르면 같은 스위치여도 직접 통신하지 못하고 브로드캐스트도 그 VLAN 안에만 퍼지므로, 감염이 다른 부서로 바로 퍼지지 않고 피해가 그 부서 망 안으로 좁혀진다. 부서 사이 통신은 반드시 라우터를 거치므로, 그곳에서 허용 · 차단 규칙으로 감염된 부서에서 나가는 통신을 막아 대응할 수 있다.
  - 핵심 낱말: **브로드캐스트 범위를 나눈다 · 피해가 한 부서로 좁혀진다 · 부서 사이를 라우터에서 통제**
  - 확인할 것: 값만 적고 이유가 없으면 다시 쓰게 한다.

### 이 교시에 새로 안 것

- 자유. 「VLAN 이 다르면 같은 스위치여도 라우터를 거친다」, 「회사 망 줄에 없는 목적지는 기본 경로로 간다」 정도면 충분합니다.

### 문제 7-1 · 새 주소로 다시 풀기

- **(가) `172.16.8.40` 은 사설 · 공인 가운데 무엇이며, 2.2 표의 어느 범위인가요:** 사설 · `172.16.0.0` ~ `172.31.255.255`
  - 확인할 것: 둘째 마디 `16` 이 16 ~ 31 사이라는 근거를 알고 있는가. 「172 로 시작하니 사설」만으로는 부족하다.
- **(나) 출력 세 줄(마스크 · 네트워크 주소 · 브로드캐스트 주소):** `255.255.255.0` · `172.16.8.0` · `172.16.8.255`
  - 확인할 것: 넷째 마디만 `0` · `255` 로 바뀌었는가.
- **(다-1) 🔍 `172.16.8.200` 과 `172.16.9.40` 가운데 스위치로 바로 가는 주소와 게이트웨이를 거치는 주소는 각각 무엇인가요? 망 부분을 근거로 설명하세요.**
  - 모범 답: `/24` 는 앞 세 마디가 망 부분이다. `172.16.8.200` 은 앞 세 마디 `172.16.8` 이 같아 같은 망이므로 스위치로 바로 간다. `172.16.9.40` 은 셋째 마디 `9` 가 `8` 과 달라 다른 망이므로 기본 게이트웨이를 거친다.
  - 핵심 낱말: **`/24` = 앞 세 마디 · 셋째 마디가 같으면 스위치 · 다르면 게이트웨이**
  - 확인할 것: 넷째 마디 `200` · `40` 을 근거로 쓰지 않았는가.
- **(다-2) 오늘 2~6교시에서 배운 것 가운데 이 문제를 풀 때 가장 도움이 된 것과, 아직 헷갈리는 것을 하나씩 쓰세요.**
  - 자유. 하나씩 이유와 함께 썼으면 맞다. 헷갈리는 것으로 적힌 내용은 다음 날 아침에 다시 짚는다.

### 문제 7-2 · 서브넷 마스크 다시 보기

- **(가) 세 마스크의 CIDR · 주소 수:** `/24` · 256 · `/16` · 65,536 · `/25` · 128
  - 확인할 것: 「쓸 수 있는 수」(254 등)가 아니라 주소 수를 적었는가.
- **(나) 서브넷 마스크는 IP 주소에서 무엇을 정하는 값인가요? 마스크를 2진수로 썼을 때 1 과 0 이 각각 무엇을 뜻하는지 넣어 설명하세요.**
  - 모범 답: 서브넷 마스크는 IP 주소에서 어디까지가 망 부분인지 정하는 값이다. 2진수로 1 인 자리는 망 부분, 0 인 자리는 장비 부분이다. 그래서 1 의 개수가 CIDR 숫자가 되고, 예를 들어 `255.255.255.0` 은 1 이 24개라 `/24` 다.
  - 핵심 낱말: **1 = 망 부분 · 0 = 장비 부분 · 1 의 개수 = CIDR**
- **(다) `172.16.8.40` 과 `172.16.9.40` 은 마스크가 `255.255.255.0` 이면 다른 망, `255.255.0.0` 이면 같은 망입니다. 같은 두 주소인데 판정이 달라지는 이유를 망 부분으로 설명하세요.**
  - 모범 답: `/24` 는 앞 세 마디가 망 부분이라 셋째 마디 `8` 과 `9` 를 비교하게 되고, 달라서 다른 망이다. `/16` 은 앞 두 마디 `172.16` 만 망 부분이라 셋째 마디는 장비 부분이 되어 비교하지 않으므로 같은 망이다. 같은 망인지는 주소가 아니라 마스크가 정한다.
  - 핵심 낱말: **마스크가 비교할 마디 수를 정한다**
- **(라) 원래 `/24` 로 써야 하는 PC 에 실수로 `255.255.0.0` 을 설정하면, 그 PC 가 `172.16.9.40` 으로 보낼 때 어떤 문제가 생길지 게이트웨이와 이어서 설명하세요.**
  - 모범 답: PC 는 `/16` 으로 판단해 `172.16.9.40` 을 같은 망으로 여긴다. 그래서 게이트웨이로 넘기지 않고 같은 망에서 직접 찾으려 하지만, 실제로는 다른 망에 있어 찾지 못하고 통신이 실패한다. 장비 한 대만 특정 주소와 통신이 안 될 때 마스크 설정을 먼저 확인하는 이유다.
  - 핵심 낱말: **같은 망으로 착각 · 게이트웨이로 안 보냄 · 통신 실패**

### 문제 7-3 · 설계서 완성하고 올리기

- **(가) `git status` 빨간 목록에 보인 파일 이름 · 깃허브 `network_zt` 폴더에 설계서가 보이나요:** 예) `network_zt/day02_subnet_design.md · warmup_5_2.py · warmup_6_2.py … · 예`
  - 확인할 것: 목록에 `.env` · `.venv` 가 없었다. 깃허브에서 설계서를 열었을 때 빈 항목이 없다.
- **(나) `git status` 를 확인하지 않고 `git add .` 를 실행해 `.env` 가 깃허브에 올라가면 어떤 일이 생길 수 있는지, `git add .` 가 파일을 고르는 방식과 이어서 설명하세요.**
  - 모범 답: `git add .` 는 `.gitignore` 에 적힌 것을 빼고 지금 폴더 아래 바뀐 파일을 한꺼번에 고르므로, `.gitignore` 가 빠졌거나 잘못돼 있으면 `.env` 도 골라진다. `.env` 가 깃허브에 올라가면 그 안의 API 키를 다른 사람이 보고 내 키로 API 를 호출할 수 있어, 키를 폐기하고 새로 받아야 한다. 그래서 고르기 전에 목록을 먼저 본다.
  - 핵심 낱말: **한꺼번에 고른다 · `.env` 의 API 키가 드러난다 · 키를 폐기**

## 최종 설계서

### 1. 부서마다 망 · VLAN · 게이트웨이 — 5.2 · 6.3

- **세 부서의 망 · VLAN · 게이트웨이:**
  - 개발팀 `192.168.10.0/24` · VLAN 10 · `192.168.10.1`
  - 운영팀 `192.168.20.0/24` · VLAN 20 · `192.168.20.1`
  - 보안팀 `192.168.30.0/24` · VLAN 30 · `192.168.30.1`
  - 확인할 것: 게이트웨이를 네트워크 주소(`.0`)로 적지 않았는가.
- **부서마다 VLAN 하나에 서브넷 하나를 맞춘 이유를, 서로 다른 VLAN 에 같은 서브넷을 주었을 때 PC 와 스위치가 각각 어떻게 동작하는지와 견주어 설명하세요.**
  - 모범 답: 다른 VLAN 에 같은 서브넷을 주면 PC 는 같은 망이라 여겨 게이트웨이로 보내지 않고, 스위치는 VLAN 이 달라 직접 넘기지 않으므로 라우터가 있어도 통신이 안 된다. VLAN 하나에 서브넷 하나를 맞춰야 VLAN 사이 통신이 라우터를 거쳐 오가고, 부서마다 브로드캐스트가 닿는 범위도 나뉜다.
  - 핵심 낱말: **같은 서브넷을 나누면 통신이 막힌다 · 라우터를 거치게 된다**

### 2. 라우팅 경로 — 6-2

- **운영팀 PC `192.168.20.30` → 인터넷 `8.8.8.8` 이 지나는 장비와, 라우터가 그때 쓴 라우팅 표의 줄:** `운영팀 PC → 스위치(VLAN 20) → 게이트웨이 192.168.20.1(라우터) → 인터넷 쪽 라우터 · 기본 경로 0.0.0.0/0`
  - 확인할 것: 첫 게이트웨이가 출발지 운영팀의 `192.168.20.1` 인가.
- **라우터가 6-2 의 `192.168.30.5`(보안팀 PC)와 이 통신(`8.8.8.8`)에서 다음 홉을 다르게 고른 이유를, 라우팅 표에서 맞는 줄을 찾는 순서로 설명하세요.**
  - 모범 답: 라우터는 먼저 목적지가 들어가는 회사 망 줄을 찾는다. 보안팀 PC `192.168.30.5` 는 직접 연결된 `192.168.30.0/24` 줄에 맞아 VLAN 30 쪽으로 보냈다. `8.8.8.8` 은 어느 부서 망 줄에도 맞지 않아 마지막으로 기본 경로(`0.0.0.0/0`)를 써서 인터넷 쪽 라우터에 보냈다.
  - 핵심 낱말: **회사 망 줄을 먼저 · 없으면 기본 경로**

### 3. 오늘 하루 정리

- 자유. **이유까지 썼는지**만 봅니다. 예) 「같은 망 판정 — 셋째 마디가 다르면 게이트웨이를 거치므로, 다른 부서로만 안 되는 문의를 여기서 풀 수 있어서」.

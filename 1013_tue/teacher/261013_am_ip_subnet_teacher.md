### 왜 필요한가

1. 보안 관제에서 보는 로그(방화벽 · 웹 서버 · 침입 탐지 시스템 로그)에는 거의 언제나 **출발지 IP 주소**와 **목적지 IP 주소** 필드가 기록됩니다. 분석은 그 주소가 **내부망**(우리 회사 네트워크)인지 **외부망**(인터넷)인지 가리는 것부터 시작합니다.
2. 그 기준이 **사설 IP**(회사 · 가정의 내부망에서만 쓰는 주소)와 **공인 IP**(인터넷 전체에서 하나뿐인 주소)입니다.
3. 내부망 PC 의 사설 IP 는 인터넷과 통신할 때 공유기 · 라우터의 **NAT**(냇 · Network Address Translation, 주소 변환)를 거쳐 **공인 IP 로 바뀌어** 나갑니다. 그래서 외부 서버나 방화벽 로그에 기록된 출발지 주소는 실제 PC 의 사설 IP 가 아니라 공유기의 공인 IP 일 수 있습니다. 어느 PC 가 보낸 것인지 찾으려면 공유기 · 방화벽에 남은 **NAT 변환 기록**을 함께 봐야 합니다.

### 2.1 IP 주소는 32비트

**여기 나오는 말**

- **비트 (bit)**
  - 0 또는 1 하나를 담는 **2진수 한 자리**. 컴퓨터가 다루는 가장 작은 정보 단위입니다
  - IPv4 주소 하나는 **32비트**로 되어 있습니다
  - 점으로 나뉜 마디(옥텟 · octet) 하나는 **8비트**라, 마디마다 0~255 를 담습니다
- **2진수** (이진수)
  - 0 과 1 두 글자로만 쓰는 수. 자리 하나가 왼쪽으로 갈수록 2배씩 커집니다(1 · 2 · 4 · 8 · …)
  - 예: `192` 는 128 + 64 라서 `11000000`
  - 컴퓨터는 IP 주소를 이 모양으로 읽고, 서브넷 마스크도 이 모양으로 비교합니다

`192.168.10.25` 는 사람이 읽는 모양입니다. 컴퓨터는 점으로 나뉜 **마디 네 개**를 각각 **8비트 2진수**로 읽습니다. 그래서 IPv4(아이피 브이포) 주소는 모두 **32비트**입니다.

| 마디 | 10진수(평소 쓰는 수) | 2진수(0과 1 로만 쓰는 수 · 8비트) |
|---|---|---|
| 1 | 192 | `11000000` |
| 2 | 168 | `10101000` |
| 3 | 10 | `00001010` |
| 4 | 25 | `00011001` |

8비트가 전부 1 이면 `11111111` = 255 입니다. 그래서 한 마디에는 **0~255** 만 들어갑니다(256가지).

#### 🐍 문법 상자 · `format(숫자, "08b")` — 8비트 2진수로

```python
print(format(5, "08b"))        # format(숫자, "08b") 는 숫자를 앞자리를 0 으로 채운 8자리 2진수 글자로 바꾼다. 5 를 바꿔 출력한다
print(format(255, "08b"))      # 255 를 8자리 2진수 글자로 바꿔 출력한다. 255 는 8비트로 나타낼 수 있는 가장 큰 수다
bits = format(25, "08b")       # 25 를 8자리 2진수 글자로 바꿔 변수 bits 에 담는다
print(len(bits))               # len() 은 글자 수를 리턴한다. bits 의 글자 수를 출력한다

# 00000101
# 11111111
# 8
```

| 쓰는 것 | 뜻 |
|---|---|
| `b` | 2진수(binary)로 바꾼다 |
| `08` | 빈 앞자리를 0 으로 채워 **8자리**를 만든다 |
| `int("25")` | 글자 `"25"` 를 숫자 25 로 (1과목) |

⚠ `"08b"` 를 따옴표 없이 `08b` 로 쓰면 `SyntaxError` 입니다. 글자로 넘겨야 합니다.

### ✍️ 문제 2-2 · 내 IP 를 32비트 2진수로 펼치기 (`ip_bits.py`)

**할 일** — IP 주소를 32비트 2진수로 펼치는 함수 `to_bits` 를 완성해 실행하고, 내 주소의 출력을 보고서에 적습니다.

**왜 중요한가** — IP 주소를 32비트로 펼쳐 두어야 3교시 문법 상자와 4교시 4.1 에서 서브넷 마스크가 어느 비트까지를 같은 망으로 묶는지 비트끼리 맞대어 볼 수 있습니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `ip_bits.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 파일에 붙여 넣고, **줄마다 주석을 읽어** 각 줄이 무엇을 하는지 먼저 이해합니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 로 복사합니다.
   ```python
   # ── 강사용: 정답을 채운 코드입니다 ──
   def to_bits(ip):                  # def 로 함수 to_bits 를 만든다. IP 주소 글자 ip 를 받아 32비트 2진수 글자를 리턴한다
       bits = ""                     # 2진수 글자를 이어 붙일 변수 bits 를 빈 글자로 시작한다
       for part in ip.split("."):    # .split(".") 은 글자를 점에서 나눈 리스트를 리턴한다. 마디를 하나씩 part 에 담아 반복한다
           # 1. int() 로 part 를 숫자로 바꿔 number 에 담으세요
           number = int(part)                   # int() 는 글자를 숫자로 바꿔 리턴한다. 마디 글자 part 를 숫자로 바꿔 number 에 담는다
           # 2. bits 뒤에 format(number, "08b") 를 이어 붙이세요
           bits = bits + format(number, "08b")  # number 를 8자리 2진수 글자로 바꿔 bits 뒤에 이어 붙인다
       return bits                   # 32비트 2진수 글자가 된 bits 를 리턴한다

   ip = "192.168.10.25"              # 변수 ip 에 IPv4 주소 글자를 담는다. 내 IPv4 주소로 바꿔 실행한다
   print(ip)                         # 원래 IP 주소 글자를 출력한다
   result = to_bits(ip)              # to_bits() 를 불러 리턴한 32비트 2진수 글자를 result 에 담는다
   print(result)                     # 32비트 2진수 글자를 출력한다
   print("길이:", len(result))         # len() 은 글자 수를 리턴한다. result 의 글자 수를 출력해 32자리가 맞는지 확인한다
   ```
3. **[VS Code]** 번호 주석(`# 1.` · `# 2.` …)이 시키는 일을 그 바로 아래 줄에 코드로 씁니다.

### 2.2 사설 IP 와 공인 IP

**여기 나오는 말**

- **사설 IP (private IP)** (프라이빗 아이피)
  - 회사 · 가정의 **내부망에서만** 쓰는 주소. 이 주소 그대로는 인터넷에서 통신하지 못합니다
  - 내부망에서만 쓰므로 다른 회사와 같은 주소를 써도 충돌하지 않습니다
  - 정해진 세 범위: `10.x.x.x` · `172.16~31.x.x` · `192.168.x.x`
  - 관제에서는 로그의 주소가 이 범위면 「내부망 장비」로 먼저 분류합니다
- **공인 IP (public IP)** (퍼블릭 아이피)
  - **인터넷 전체에서 하나뿐인** 주소. 통신사가 나눠 줍니다
  - 인터넷의 서버들은 이 주소로 서로를 찾습니다
  - 예: `8.8.8.8`(구글 DNS 서버)

| 사설 IP 범위 | 예 | 주의 |
|---|---|---|
| `10.0.0.0` ~ `10.255.255.255` | `10.0.0.8` | 첫 마디가 10 이면 전부 |
| `172.16.0.0` ~ `172.31.255.255` | `172.20.5.6` | ⚠ **둘째 마디가 16~31 일 때만.** `172.32.5.6` 은 공인 |
| `192.168.0.0` ~ `192.168.255.255` | `192.168.10.25` | 첫 두 마디가 192.168 |

- 세 범위는 인터넷 공통 약속입니다. 이 범위 밖은 **공인 IP** 입니다.
- 사설 IP 는 회사마다 겹쳐도 됩니다. 인터넷으로는 나가지 않기 때문입니다.
- **사설이면 안전, 공인이면 공격이라는 뜻은 아닙니다.** 안 · 밖을 가르는 첫 기준일 뿐입니다.

#### 🐍 문법 상자 · `and` · `or` · 범위 비교

```python
second = 20                # 변수 second 에 숫자 20 을 담는다
print(16 <= second <= 31)  # a <= x <= b 는 x 가 a 이상 b 이하일 때 True 가 된다. second 를 검사한 결과를 출력한다

# or 는 양쪽 조건 중 하나라도 True 이면 True 가 된다. second 가 10 이거나 20 인지 검사한 결과를 출력한다
print(second == 10 or second == 20)

# True
# True
```

| 쓰는 것 | 뜻 |
|---|---|
| `16 <= second <= 31` | 둘 사이에 있나 (양 끝 포함) |
| `A and B` | 둘 다 참이어야 참 |
| `A or B` | 하나만 참이어도 참 |

⚠ `first == 172` 만 보면 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">`172.32.5.6` 까지 사설로</mark> 잘못 판정합니다. 둘째 마디도 봐야 합니다.

### ✍️ 문제 2-3 · 사설 IP 판별기 (`private_ip.py`)

**할 일** — 주소가 사설 IP 인지 판별하는 함수 `is_private` 를 완성해 실행하고, `[공인]` 으로 나온 주소를 보고서에 적습니다.

**왜 중요한가** — 로그에 찍힌 주소가 사설인지 공인인지로 내부 PC 의 통신인지 외부에서 온 접속인지를 가릅니다. 관제에서 주소를 보면 가장 먼저 하는 판정입니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `private_ip.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 파일에 붙여 넣고, **줄마다 주석을 읽어** 각 줄이 무엇을 하는지 먼저 이해합니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 로 복사합니다.
   ```python
   # ── 강사용: 정답을 채운 코드입니다 ──
   # def 로 함수 is_private 를 만든다. IP 주소 글자 ip 가 사설 IP 이면 True, 아니면 False 를 리턴한다
   def is_private(ip):
       parts = ip.split(".")    # .split(".") 은 글자를 점에서 나눈 리스트를 리턴한다. 마디 네 개가 담긴 리스트를 parts 에 담는다
       first = int(parts[0])    # parts[0] 은 리스트의 첫째 값이다. int() 로 숫자로 바꿔 first 에 담는다
       second = int(parts[1])   # parts[1] 은 리스트의 둘째 값이다. int() 로 숫자로 바꿔 second 에 담는다
       # 1. first 가 10 이면 True 를 return 하세요
       if first == 10:          # 첫 마디가 10 이면 10.0.0.0/8 사설 대역이다
           return True          # True 를 리턴하고 함수를 끝낸다
       # 2. first 가 172 이고 second 가 16 이상 31 이하이면 True 를 return 하세요
       # and 는 양쪽 조건이 모두 True 일 때만 True 가 된다. 172.16 ~ 172.31 로 시작하면 172.16.0.0/12 사설 대역이다
       if first == 172 and 16 <= second <= 31:
           return True          # True 를 리턴하고 함수를 끝낸다
       # 3. first 가 192 이고 second 가 168 이면 True 를 return 하세요
       # 192.168 로 시작하면 192.168.0.0/16 사설 대역이다
       if first == 192 and second == 168:
           return True          # True 를 리턴하고 함수를 끝낸다
       return False             # 앞의 if 세 개에서 리턴하지 않았으면 공인 IP 이므로 False 를 리턴한다

   # for 변수 in 리스트: 는 리스트의 값을 앞에서부터 하나씩 변수에 담아 아래 줄을 반복한다.
   # 주소 여섯 개를 하나씩 ip 에 담는다
   for ip in ["10.0.0.8", "172.20.5.6", "172.32.5.6", "192.168.10.25", "8.8.8.8", "203.0.113.7"]:
       if is_private(ip):       # if 는 조건이 True 일 때만 아래 줄을 실행한다. is_private() 가 True 를 리턴하면 실행한다
           print("[사설]", ip)  # 사설 IP 일 때 [사설] 표시와 주소를 출력한다
       else:                    # else 는 위 if 의 조건이 False 일 때 아래 줄을 실행한다
           print("[공인]", ip)  # 공인 IP 일 때 [공인] 표시와 주소를 출력한다
   ```

### 2.3 NAT — 사설 IP 를 공인 IP 로 변환

**여기 나오는 말**

- **NAT (Network Address Translation)** (나트 · 냇)
  - 내부망의 사설 IP 를 인터넷으로 보낼 때 **공인 IP 로 바꾸는 주소 변환**
  - 집 · 학원의 **공유기**가 이 일을 합니다 — 내부망 PC 가 보낸 패킷의 출발지 주소를 자기 공인 IP 로 바꿔 보내고, 응답이 오면 변환 기록을 보고 원래 PC 의 사설 IP 로 되돌려 전달합니다
  - 그래서 외부 서버의 로그에는 내 PC 의 사설 IP 가 아니라 **공유기의 공인 IP** 가 남습니다
  - 정적 · 동적 NAT 의 차이는 아래 표에서 **직접 찾아 씁니다**
- **PAT (Port Address Translation)** (팻)
  - 공인 IP **하나**를 내부망의 여러 PC 가 함께 쓰는 NAT
  - 연결마다 공인 IP 쪽 **포트 번호**를 다르게 붙이고, 응답이 오면 그 포트 번호로 어느 PC 의 연결인지 찾아 전달합니다
  - 집 · 학원 공유기는 대부분 이 방식입니다

공유기는 내부망 PC 가 인터넷과 통신할 때 **출발지 주소를 자기 공인 IP 로 바꿔** 보냅니다. 이것이 NAT 입니다.

> 학생 문서에서는 아래 표의 일부 칸이 **[찾아 쓰기]** 로 비어 있습니다. 강사용에는 채운 표를 둡니다.

| 방식 | 바꾸는 법 |
|---|---|
| 정적 NAT | 사설 IP 하나 ↔ 공인 IP 하나를 **고정**해 짝지어 둔다 — 인터넷에서 내부망 서버로 접속하게 할 때 쓴다 |
| 동적 NAT | 공인 IP 여러 개 가운데 사용하지 않는 것을 통신할 때마다 **그때그때** 하나 배정한다 — 짝이 고정되지 않는다 |
| PAT | 공인 IP **하나**를 여러 PC 가 같이 쓰고, **포트 번호로** 누구 것인지 구별한다 — 집 · 학원 공유기가 대부분 이것 |

PAT 공유기는 「공인 IP 쪽 포트 40002번 = 내부망 `192.168.10.25:51234`」 같은 **변환표**를 가지고 있다가, 답이 오면 표를 보고 원래 PC 로 넘겨 줍니다.

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">3교시 (11:00–11:50) · 서브넷 마스크 · CIDR · 같은 망 판정</mark>

### 왜 필요한가

1. 주소 두 개가 **같은 망**인지 알아야 통신이 어떤 장비를 거쳐 가는지 말할 수 있습니다.
2. 같은 망이면 스위치(같은 망 안의 장비들을 잇는 장비)가 바로 전달하고, 다른 망이면 **게이트웨이(라우터 · 망과 망을 잇는 장비)** 를 거칩니다. 방화벽(허용 · 차단 규칙으로 통신을 거르는 장비) 규칙도 이 경계로 씁니다.
3. 그 경계를 정하는 값이 `255.255.255.0` 같은 **서브넷 마스크**입니다.

### 3.1 서브넷 마스크 — 마디로 먼저 읽기

**여기 나오는 말**

- **서브넷 (subnet)**
  - 큰 망을 나눈 **작은 망** 하나
  - 같은 서브넷 안의 장비끼리는 공유기 · 라우터를 거치지 않고 바로 통신합니다
  - 회사는 부서마다 서브넷을 나눠, 부서끼리 오가는 통신을 따로 관리합니다
- **서브넷 마스크 (subnet mask)**
  - IP 주소에서 **어디까지가 같은 망**인지 정하는 값
  - `255` 인 마디는 **망 부분**, `0` 인 마디는 **장비 부분**입니다
  - 망 부분은 이 장비가 **어느 망에 속하는지**를 나타내는 앞쪽 자리입니다. 같은 망에 있는 장비들은 이 부분이 **모두 똑같습니다**
  - 장비 부분은 그 망 안에서 **어느 장비인지**를 나타내는 뒤쪽 자리입니다. 장비마다 다릅니다
  - 예: `255.255.255.0` 이면 앞 세 마디가 망 부분
  - 예: `192.168.10.1` · `192.168.10.25` · `192.168.10.30` 은 망 부분 `192.168.10` 이 같아서 같은 망입니다. 장비 부분 `1` · `25` · `30` 으로 장비를 구별합니다
  - 컴퓨터는 IP 주소와 서브넷 마스크를 **2진수로 바꿔 AND 연산**을 합니다. 그 결과가 그 주소의 **네트워크 주소**입니다(3.2 에서 풀어 봅니다)
  - 두 주소의 네트워크 주소가 같으면 같은 망입니다
- **CIDR (Classless Inter-Domain Routing)** (사이더)
  - 서브넷 마스크를 `/숫자` 로 짧게 쓰는 표기
  - `/` 뒤의 숫자는 서브넷 마스크를 2진수로 바꿨을 때 **1 의 개수**입니다
  - `255` 를 2진수로 바꾸면 `11111111` 로 1 이 8개입니다. 그래서 `255` 인 마디 하나는 8 로 셉니다
  - `0` 을 2진수로 바꾸면 `00000000` 으로 1 이 0개입니다. 그래서 `0` 인 마디는 0 으로 셉니다
  - 예: `255.255.255.0` 을 2진수로 쓰면 `11111111.11111111.11111111.00000000` 입니다. 1 이 8개인 마디가 세 개라 8 × 3 = 24, 그래서 `/24` 입니다
  - 예: `255.255.0.0` 을 2진수로 쓰면 `11111111.11111111.00000000.00000000` 입니다. 1 이 8개인 마디가 두 개라 8 × 2 = 16, 그래서 `/16` 입니다
- **호스트 (host)**
  - 망 안에서 주소를 받는 **장비 하나**
  - 예: PC · 서버 · 프린터 · 스마트폰

**마디**는 IP 주소에서 점으로 나뉜 숫자 하나입니다. `192.168.10.25` 는 마디가 네 개입니다.

| 첫째 마디 | 둘째 마디 | 셋째 마디 | 넷째 마디 |
|---|---|---|---|
| `192` | `168` | `10` | `25` |

**서브넷 마스크는 「1 인 자리는 망 부분, 0 인 자리는 장비 부분」이라고 표시하는 값입니다.** `255` 는 2진수로 `11111111` 이라 8자리가 모두 1 입니다. 그래서 `255` 인 마디는 마디 전체가 망 부분입니다.

| | 첫째 마디 | 둘째 마디 | 셋째 마디 | 넷째 마디 |
|---|---|---|---|---|
| 마스크 `255.255.255.0` | `11111111` | `11111111` | `11111111` | `00000000` |
| 뜻 | 망 부분 | 망 부분 | 망 부분 | 장비 부분 |
| IP `192.168.10.25` | `192` | `168` | `10` | `25` |

- 앞 세 마디는 마스크가 모두 1 이라 망 부분입니다. 그래서 IP 의 앞 세 마디 `192.168.10` 이 망 부분입니다.
- 넷째 마디는 마스크가 모두 0 이라 장비 부분입니다. 그래서 `25` 가 장비 부분입니다.
- 마스크는 망을 관리하는 쪽이 정합니다. 집 공유기나 학원 네트워크 장비가 PC 에 IP 주소와 함께 마스크를 나눠 줍니다. 앞 세 마디로 망을 구분하는 곳은 `255.255.255.0`, 앞 두 마디로 구분하는 학원망은 `255.255.0.0` 을 줍니다.

**같은 망인지 가리는 법** — 두 주소에서 망 부분만 꺼내 비교합니다. 망 부분이 같으면 같은 망, 하나라도 다르면 다른 망입니다. 장비 부분은 달라도 상관없습니다.

**`/24` 이면 앞 세 마디를 비교합니다.**

| 주소 A | 주소 B | A 의 앞 세 마디 | B 의 앞 세 마디 | 비교 | 결과 |
|---|---|---|---|---|---|
| `192.168.10.25` | `192.168.10.200` | `192.168.10` | `192.168.10` | 같다 | **같은 망** |
| `192.168.10.25` | `192.168.20.25` | `192.168.10` | `192.168.20` | 셋째 마디 `10` ≠ `20` | **다른 망** |

- 첫째 줄의 넷째 마디 `25` 와 `200` 은 장비 부분이라 달라도 같은 망입니다.

**`/16` 이면 앞 두 마디만 비교합니다.**

| 주소 A | 주소 B | A 의 앞 두 마디 | B 의 앞 두 마디 | 비교 | 결과 |
|---|---|---|---|---|---|
| `192.168.10.25` | `192.168.20.25` | `192.168` | `192.168` | 같다 | **같은 망** |
| `192.168.10.25` | `172.16.10.25` | `192.168` | `172.16` | 첫째 마디 `192` ≠ `172` | **다른 망** |

- 첫째 줄의 셋째 마디 `10` 과 `20` 은 `/16` 에서는 장비 부분이라 달라도 같은 망입니다.

- 같은 두 주소 `192.168.10.25` 와 `192.168.20.25` 도 `/24` 에서는 다른 망, `/16` 에서는 같은 망입니다. 마스크가 「앞에서 몇 마디까지 비교할지」를 정하므로, 같은 망인지는 **주소가 아니라 마스크**가 정합니다.
- **학원망은 `/16`** 입니다 — 서브넷 마스크 `255.255.0.0`, 기본 게이트웨이 `192.168.1.1`. 앞 두 마디 `192.168` 이 같으면 같은 망입니다.
- **집 공유기는 보통 `/24`** 입니다 — 서브넷 마스크 `255.255.255.0`. 앞 세 마디가 같아야 같은 망입니다.

### 3.2 풀이 순서 — `192.168.10.25/24` 하나 풀어 보기

**여기 나오는 말**

- **네트워크 주소**
  - `192.168.10.25/24` 가 속한 망에는 `192.168.10.0` 부터 `192.168.10.255` 까지 주소 256개가 있습니다. 이 가운데 **가장 작은 주소** `192.168.10.0` 이 네트워크 주소입니다
  - `/24` 에서는 넷째 마디가 장비 부분입니다. 네트워크 주소는 이 넷째 마디가 `0` 입니다
  - 장비 하나가 아니라 **망 전체를 가리키는** 주소입니다. 그래서 PC · 서버 같은 장비의 IP 주소로 설정하지 않습니다
  - 예: `192.168.10.25/24` 의 네트워크 주소는 장비 부분(마지막 마디) `25` 를 `0` 으로 바꾼 `192.168.10.0` 입니다
- **브로드캐스트 주소 (broadcast)** (브로드캐스트)
  - 이 주소로 패킷을 하나 보내면 **같은 망의 장비 전부가** 받습니다
  - 보통 주소 `192.168.10.30` 으로 보내면 그 장비 **한 대만** 받습니다. 브로드캐스트 주소 `192.168.10.255` 로 보내면 `.1` · `.25` · `.30` · `.200` … 망 안의 장비가 **모두** 받습니다
  - 같은 망의 주소 256개 가운데 **가장 큰 주소** `192.168.10.255` 가 브로드캐스트 주소입니다
  - `/24` 에서는 장비 부분인 넷째 마디가 `255` 입니다
  - 모두가 받는 주소라서 장비 한 대의 IP 주소로는 설정하지 않습니다
  - 예: `192.168.10.25/24` 의 브로드캐스트 주소는 장비 부분(마지막 마디) `25` 를 `255` 로 바꾼 `192.168.10.255` 입니다

주소 하나를 받으면 아래 네 단계로 풉니다.

1. **① 마스크** — `/24` 는 `255.255.255.0` 입니다(아래 3.3 표).
2. **② 망 부분** — `255` 가 앞 세 마디라 `192.168.10` 이 망 부분, 마지막 마디 `25` 가 장비 부분입니다.
3. **③ 네트워크 주소 · 브로드캐스트 주소** — 장비 부분을 `0` 으로 두면 네트워크 주소 `192.168.10.0`, `255` 로 두면 브로드캐스트 주소 `192.168.10.255` 입니다.
4. **④ 장비에 줄 수 있는 주소** — 그 둘을 뺀 `192.168.10.1` ~ `192.168.10.254`, 254개입니다. 기본 게이트웨이도 이 가운데 하나를 씁니다(보통 `.1`).

3-2 에서 내 주소를 같은 ① ~ ④ 순서로 풉니다. 학원망 `/16` 이면 ② 의 망 부분이 앞 두 마디가 되고, ③ 에서는 뒤 두 마디가 함께 `0` · `255` 가 됩니다.

#### 컴퓨터는 이렇게 계산합니다 — AND 연산

**여기 나오는 말**

- **AND 연산** (앤드 연산)
  - 같은 자리의 비트끼리 비교해서 **둘 다 1 일 때만 1**, 하나라도 0 이면 0 을 남기는 계산
  - 예: `1` AND `1` = `1`, `1` AND `0` = `0`, `0` AND `0` = `0`

위 ③ 의 네트워크 주소 `192.168.10.0` 을 컴퓨터는 아래 순서로 구합니다.

1. **IP 주소와 마스크를 2진수로 바꿉니다.**

| | 첫째 마디 | 둘째 마디 | 셋째 마디 | 넷째 마디 |
|---|---|---|---|---|
| IP `192.168.10.25` | `11000000` | `10101000` | `00001010` | `00011001` |
| 마스크 `255.255.255.0` | `11111111` | `11111111` | `11111111` | `00000000` |

2. **같은 자리끼리 AND 합니다.**
   - 마스크가 `1` 인 자리는 IP 의 비트가 **그대로** 남습니다. 그래서 앞 세 마디가 그대로 나옵니다.
   - 마스크가 `0` 인 자리는 IP 의 비트와 상관없이 **모두 0** 이 됩니다. 그래서 넷째 마디가 `0` 이 됩니다.

| | 첫째 마디 | 둘째 마디 | 셋째 마디 | 넷째 마디 |
|---|---|---|---|---|
| AND 결과 | `11000000` | `10101000` | `00001010` | `00000000` |

3. **결과를 10진수로 다시 바꿉니다.** `192.168.10.0` 이 나오고, 이것이 네트워크 주소입니다.
4. **같은 망인지 판정합니다.** 다른 주소도 같은 마스크로 AND 해서, 네트워크 주소가 같으면 같은 망입니다.
   - `192.168.10.200` 을 AND 하면 `192.168.10.0` 이라 `192.168.10.25` 와 같은 망입니다.
   - `192.168.20.25` 를 AND 하면 `192.168.20.0` 이라 다른 망입니다.

③ 에서 「장비 부분을 `0` 으로 둔다」고 한 것이 바로 이 AND 의 결과입니다.

### 3.3 마스크 · CIDR · 주소 수 표

주소 수는 계산하지 않고 이 표에서 찾습니다.

| 서브넷 마스크 | 2진수 (1 의 개수 = CIDR 숫자) | CIDR | 주소 수 | 장비에 쓸 수 있는 수 |
|---|---|---|---|---|
| `255.255.0.0` | `11111111.11111111.00000000.00000000` | `/16` | 65,536 | 65,534 |
| `255.255.255.0` | `11111111.11111111.11111111.00000000` | `/24` | 256 | 254 |
| `255.255.255.128` | `11111111.11111111.11111111.10000000` | `/25` | 128 | 126 |
| `255.255.255.192` | `11111111.11111111.11111111.11000000` | `/26` | 64 | 62 |
| `255.255.255.224` | `11111111.11111111.11111111.11100000` | `/27` | 32 | 30 |
| `255.255.255.240` | `11111111.11111111.11111111.11110000` | `/28` | 16 | 14 |

- 쓸 수 있는 수는 주소 수에서 네트워크 주소 · 브로드캐스트 주소 2개를 뺀 수입니다.
- 2진수 칸의 `1` 을 세면 CIDR 숫자가 됩니다. 예: `/26` 은 `1` 이 8 + 8 + 8 + 2 = 26개입니다.
- CIDR 숫자가 클수록 망이 작아집니다.
- `/25` ~ `/28` 은 넷째 마디 **중간**에서 망 부분과 장비 부분이 나뉘는 마스크입니다. 4교시 4.1 에서 다룹니다.

💻 **터미널에 입력합니다.** `ipconfig` → `서브넷 마스크` 줄.

<mark style="background:#fff59d; color:#1a1a1a; text-decoration:underline; padding:0 4px; border-radius:3px">**결과** — 학원 PC 는 `255.255.0.0` · `/16` · 65,536 · 65,534. 집 공유기는 보통 `255.255.255.0` · `/24` · 256 · 254</mark>

**왜** — `255` 는 2진수로 `11111111` 이라 1 이 8개입니다. 그래서 `255` 가 두 마디면 1 이 16개라 `/16`, 세 마디면 24개라 `/24` 입니다. 주소 수와 쓸 수 있는 수는 3.3 표의 같은 줄에서 읽습니다.

**자주 틀리는 곳** — 마스크 대신 바로 위 IPv4 주소 줄이나 아래 게이트웨이 줄을 읽는 것입니다.

**관제에서는** — 내 PC 가 속한 망의 크기를 알아야 어떤 주소까지가 같은 망 장비인지 가릴 수 있습니다.

**강사 메모** — 학원 PC 는 `255.255.0.0` 이 나오고, 3.1 에서 미리 말한 값이라 3.3 표의 `/16` 줄에서 바로 찾는지 봅니다. 「예시는 `/24` 인데 저는 왜 다른가요?」에는 「마스크는 망 관리자가 정하는 값이라 집 공유기(`/24`)와 학원망(`/16`)이 다릅니다」라고 답합니다. 주소 수를 직접 계산하려는 학생에게는 표의 같은 줄을 읽으면 된다고 안내합니다.

### ✍️ 문제 3-2 · 내 PC 가 속한 망 풀기 (`my_network.py`)

**할 일** — 다 짜인 코드에 내 IPv4 주소와 CIDR 을 넣어 실행하고, 출력을 3.2 의 ① ~ ④ 순서로 읽어 보고서에 적습니다.

**왜 중요한가** — 네트워크 주소와 브로드캐스트 주소를 알면 내 망이 어디부터 어디까지인지 정확히 말할 수 있습니다. 오후 7-1 에서 부서마다 게이트웨이와 PC 범위를 정할 때도 이 두 주소를 씁니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `my_network.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 파일에 붙여 넣고, 실행하기 전에 **줄마다 주석을 읽어** 각 줄이 무엇을 하는지 이해합니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 로 복사합니다.
   ```python
   import ipaddress         # import 로 파이썬에 들어 있는 IP 계산 모듈 ipaddress 를 불러온다

   # ── 내 값으로 바꿔 적습니다 ──
   my_ip = "192.168.10.25"  # 변수 my_ip 에 내 IPv4 주소 글자를 담는다. ipconfig 로 확인한 주소로 바꾼다
   prefix = 24              # 변수 prefix 에 CIDR 숫자를 담는다. 3-1 에서 찾은 숫자로 바꾼다
   # ── 여기까지 ──

   # f-string 으로 「주소/CIDR」 글자를 만들고, strict=False 로 그 주소가 속한 망 객체를 만들어 net 에 담는다
   net = ipaddress.ip_network(f"{my_ip}/{prefix}", strict=False)

   # .netmask 는 그 망의 서브넷 마스크다. ① 마스크를 출력한다
   print("① 서브넷 마스크:", net.netmask)

   # .network_address 는 망의 첫 주소다. ③ 네트워크 주소를 출력한다
   print("③ 네트워크 주소:", net.network_address)

   # .broadcast_address 는 망의 마지막 주소다. ③ 브로드캐스트 주소를 출력한다
   print("③ 브로드캐스트 주소:", net.broadcast_address)

   first = net.network_address + 1              # 주소에 1 을 더하면 바로 다음 주소가 된다. 장비에 줄 수 있는 첫 주소를 first 에 담는다
   last = net.broadcast_address - 1             # 주소에서 1 을 빼면 바로 앞 주소가 된다. 장비에 줄 수 있는 마지막 주소를 last 에 담는다
   print("④ 장비에 줄 수 있는 주소:", first, "~", last)  # ④ 첫 주소와 마지막 주소를 출력한다

   # .num_addresses 는 전체 주소 수다. 네트워크 · 브로드캐스트 주소 2개를 빼서 ④ 쓸 수 있는 수를 출력한다
   print("④ 쓸 수 있는 수:", net.num_addresses - 2)
   ```

3. 아무렇게나 나누면 주소가 모자라거나 **두 부서가 같은 주소를 받는** 사고가 납니다. 그래서 3.3 표로 크기를 고르고, 코드로 검증합니다.

### 4.1 마디 중간에서 나뉘는 마스크 — `/26` 하나 풀어 보기

**여기 나오는 말**

- **서브네팅 (subnetting)** (서브네팅)
  - 큰 망을 **작은 망 여러 개로 나누는** 일
  - 부서마다 망을 따로 주면 부서 사이 통신을 나눠 관리할 수 있습니다
  - 예: `192.168.50.0/24` 를 `/26` 네 개로 나누기
- **블록**
  - 큰 망을 나눈 **작은 망 하나**
  - 블록의 첫 주소가 네트워크 주소, 마지막 주소가 브로드캐스트 주소입니다
  - 예: `192.168.50.64/26` 은 `.64` 부터 `.127` 까지인 블록

`192.168.50.0/24` 는 마지막 마디만 `0` ~ `255` 로 바뀌는 망입니다. 주소가 256개입니다.

이 망을 `/26` 으로 나눕니다. 3.3 표의 `/26` 줄을 보면 `/26` 망 하나는 **주소가 64개**입니다. 그래서 마지막 마디 `0` ~ `255` 를 **앞에서부터 64개씩** 자릅니다.

```
.0 ──── .63 │ .64 ──── .127 │ .128 ──── .191 │ .192 ──── .255
 블록 1 (64개)    블록 2 (64개)     블록 3 (64개)      블록 4 (64개)
```

1. 블록 1 은 `.0` 부터 64개라 `.63` 에서 끝납니다.
2. 블록 2 는 그 바로 다음 `.64` 부터 64개라 `.127` 에서 끝납니다.
3. 블록 3 은 `.128` ~ `.191`, 블록 4 는 `.192` ~ `.255` 입니다. `.255` 에서 끝나므로 블록은 4개입니다.

블록 하나는 3.2 에서 푼 망 하나와 같습니다. 블록 2(`.64` ~ `.127`)로 봅니다.

- 블록 2 에 든 주소 64개 가운데 **가장 작은 주소** `.64` 가 **네트워크 주소**입니다. 블록 2 라는 망 전체를 가리키는 주소입니다.
- **가장 큰 주소** `.127` 이 **브로드캐스트 주소**입니다. 블록 2 안의 장비 모두에게 한 번에 보낼 때 쓰는 주소입니다.
- 이 두 주소는 장비에 주지 않습니다. 그 사이 `.65` ~ `.126`(62개)이 장비에 줄 수 있는 주소입니다.
- 다른 블록도 같습니다. 예: 블록 1 은 `.0` 이 네트워크 주소, `.63` 이 브로드캐스트 주소, `.1` ~ `.62` 가 장비 주소입니다.

| 블록 | 네트워크 주소 | 브로드캐스트 주소 | 장비에 줄 수 있는 주소 | 쓸 수 있는 수 |
|---|---|---|---|---|
| `192.168.50.0/26` | `.0` | `.63` | `.1` ~ `.62` | 62 |
| `192.168.50.64/26` | `.64` | `.127` | `.65` ~ `.126` | 62 |
| `192.168.50.128/26` | `.128` | `.191` | `.129` ~ `.190` | 62 |
| `192.168.50.192/26` | `.192` | `.255` | `.193` ~ `.254` | 62 |

- 블록은 쓸 수 있는 수 62 가 아니라 **주소 수 64** 로 끊습니다.

#### <mark style="display:block; background:#fff59d; color:#1a1a1a; padding:4px 12px; border-radius:4px; text-decoration:underline">정답 4-2</mark>

<mark style="background:#fff59d; color:#1a1a1a; text-decoration:underline; padding:0 4px; border-radius:3px">**결과** — 50대 `/26` · 25대 `/27` · 10대 `/28` · 63대 `/25`</mark>

**왜** — 3.3 표를 맨 아래부터 올라가며 「쓸 수 있는 수」가 장비 수 이상이 처음 되는 줄을 고릅니다. 50 은 `/27`(30)로 모자라고 `/26`(62)에서 처음 들어갑니다. 25 는 `/28`(14)로 모자라고 `/27`(30), 10 은 `/28`(14)에서 들어갑니다. 63 은 `/26` 의 62 로 모자라 `/25`(126)입니다. 63대일 때 `/26` 이 안 되는 이유는 64개 가운데 네트워크 주소 · 브로드캐스트 주소 2개는 장비에 줄 수 없어 실제로는 62대까지만 들어가기 때문입니다.

**자주 틀리는 곳** — 「주소 수」 열로 골라 63대에 `/26` 을 적는 것입니다. 2개를 뺀 「쓸 수 있는 수」로 비교합니다.

**관제에서는** — 부서 망이 필요보다 크면 쓰지 않는 주소가 남아, 허가 없이 꽂은 장비가 그 주소를 받기 쉬워집니다.

**강사 메모** — 계산 없이 표에서 찾는 문제입니다. 50 · 25 · 10 은 4.2 설계표와 같으니 학생이 그대로 옮겨도 괜찮고, 확인은 63대 줄과 🔍 로 합니다. 63대에 `/26` 을 적은 학생에게는 3.3 표 아래 첫 줄(네트워크 · 브로드캐스트 2개를 뺀다)을 다시 읽게 합니다. 「위에서부터 읽으면요?」에는 「`/8` 부터 다 맞으니 가장 작은 망을 고르려면 아래부터 올라갑니다」라고 답합니다.

### 4.3 설계 검증 — 용량과 겹침

**여기 나오는 말**

- **겹침 (overlap)** (오버랩)
  - 두 부서의 망이 **같은 주소를 함께 가진** 상태
  - 같은 주소를 두 부서 장비가 받으면 **주소 충돌**로 통신이 끊기고, 로그의 주소로 어느 장비인지 가릴 수 없습니다

설계표를 만들면 두 가지를 확인합니다.

- **용량** — 부서 망의 「쓸 수 있는 수」가 장비 수 이상인가
- **겹침** — 두 부서의 망이 같은 주소를 갖지 않는가

4-3 에서 이 두 가지를 코드로 확인합니다.

### ✍️ 문제 4-3 · 설계 검증 — 용량과 겹침 (`plan_check.py`)

**할 일** — 다 짜인 검증 코드를 실행해 4.2 의 회사 설계가 충분한지 · 겹치지 않는지 읽고, 보안팀 줄 하나만 겹치는 주소로 바꿔 다시 실행해 결과를 보고서에 적습니다.

**왜 중요한가** — 부서 망이 모자라거나 겹치면 주소 충돌로 통신이 끊기고, 방화벽 규칙이 엉뚱한 부서까지 덮습니다. 오후 7-2 에서 서버망을 더할 때도 같은 `.overlaps()` 검증을 씁니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `plan_check.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 파일에 붙여 넣고, 실행하기 전에 **줄마다 주석을 읽어** 각 줄이 무엇을 하는지 이해합니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 로 복사합니다.
   ```python
   import ipaddress                                 # import 로 파이썬에 들어 있는 IP 계산 모듈 ipaddress 를 불러온다

   dev = ipaddress.ip_network("192.168.50.0/26")    # 개발팀 망 192.168.50.0/26 을 망 객체로 바꿔 dev 에 담는다
   ops = ipaddress.ip_network("192.168.50.64/27")   # 운영팀 망 192.168.50.64/27 을 망 객체로 바꿔 ops 에 담는다
   sec = ipaddress.ip_network("192.168.50.96/28")   # 보안팀 망 192.168.50.96/28 을 망 객체로 바꿔 sec 에 담는다

   # 쓸 수 있는 수(전체 주소 수 − 2)가 필요한 장비 수 이상이면 True 가 된다. 부서마다 용량 판정을 출력한다
   print("개발팀 충분:", dev.num_addresses - 2 >= 50)
   print("운영팀 충분:", ops.num_addresses - 2 >= 25)  # 운영팀 망이 25대를 담을 수 있는지 출력한다
   print("보안팀 충분:", sec.num_addresses - 2 >= 10)  # 보안팀 망이 10대를 담을 수 있는지 출력한다

   # .overlaps() 는 두 망이 주소를 하나라도 같이 쓰면 True 를 리턴한다. 개발팀과 운영팀 망이 겹치는지 출력한다
   print("개발-운영 겹침:", dev.overlaps(ops))
   print("운영-보안 겹침:", ops.overlaps(sec))         # 운영팀과 보안팀 망이 겹치는지 출력한다
   print("개발-보안 겹침:", dev.overlaps(sec))         # 개발팀과 보안팀 망이 겹치는지 출력한다
   ```
3. **[터미널]** 실행합니다. 터미널의 줄 위에 `…/network_zt` 가 보여야 합니다. 아니면 먼저 `cd network_zt` 를 입력합니다.
   ```bash
   python plan_check.py
   ```
   맥북: `python3 plan_check.py`
4. **[터미널]** 출력 여섯 줄에서 위 세 줄의 `충분:` 과 아래 세 줄의 `겹침:` 을 읽습니다.
5. **[VS Code]** `sec =` 줄(보안팀)의 `"192.168.50.96/28"` 을 `"192.168.50.32/28"` 로 **한 곳만** 바꿉니다. `.32` ~ `.47` 은 개발팀 블록(`.0` ~ `.63`) 안의 주소입니다.
6. **[터미널]** **↑(위 화살표)** 를 눌러 방금 입력한 명령을 다시 실행하고, 달라진 줄을 찾습니다.
7. **[보고서]** `day02_subnet_design.md`의 `## 4교시` › `### 문제 4-3` 아래를 채웁니다.

   - 🔍 두 부서의 망이 겹치면 어떤 문제가 생기나요?

| | |
|---|---|
| 🎯 나와야 하는 결과 | 바꾸기 전 `충분: True` 세 줄 · `겹침: False` 세 줄. 바꾼 뒤 `개발-보안 겹침: True` 한 줄만 바뀐다 |

**💡 힌트**

1. 처음 설계는 4.2 그림처럼 `.0` ~ `.63` · `.64` ~ `.95` · `.96` ~ `.111` 로 이어집니다.
2. 바꾼 뒤에도 보안팀의 크기(`/28`)는 그대로라 `충분:` 은 바뀌지 않습니다.
3. 겹침의 문제는 4.3 의 「겹침」 설명에 있습니다.

#### <mark style="display:block; background:#fff59d; color:#1a1a1a; padding:4px 12px; border-radius:4px; text-decoration:underline">정답 4-3</mark>

(코드는 위 문제 코드 그대로입니다. 5단계에서 `sec =` 줄(보안팀) 한 곳만 바꿉니다.)

💻 **터미널에 입력합니다.** `python plan_check.py`

<mark style="background:#fff59d; color:#1a1a1a; text-decoration:underline; padding:0 4px; border-radius:3px">**결과** — 바꾸기 전 `충분: True` 세 줄 · `개발-운영 겹침: False` · `운영-보안 겹침: False` · `개발-보안 겹침: False`. 보안팀을 `192.168.50.32/28` 로 바꾼 뒤 달라진 줄은 `개발-보안 겹침: True` 한 줄</mark>

**왜** — 처음 설계는 쓸 수 있는 수가 62 ≥ 50 · 30 ≥ 25 · 14 ≥ 10 이라 모두 충분하고, `.0` ~ `.63` · `.64` ~ `.95` · `.96` ~ `.111` 로 이어져 겹치지 않습니다. 바꾼 보안팀 `.32` ~ `.47` 은 개발팀 `.0` ~ `.63` 안에 들어가므로 `dev.overlaps(sec)` 가 `True` 가 되어 「개발-보안 겹침」 줄만 바뀝니다. 크기는 그대로라 `충분:` 은 바뀌지 않습니다. 두 부서 망이 겹치면 같은 주소를 두 부서 장비가 받아 주소 충돌로 통신이 끊기고, 방화벽 규칙이 다른 부서까지 덮으며, 로그의 주소로 어느 장비인지 가릴 수 없습니다.

**자주 틀리는 곳** — `충분: True` 만 보고 설계가 맞다고 보는 것입니다. 용량이 충분해도 겹칠 수 있어서 두 검증을 모두 봅니다.

**관제에서는** — 두 부서 망이 겹치면 같은 주소를 두 PC 가 받을 수 있어, 로그 주소로 장비를 특정할 수 없게 됩니다.

**강사 메모** — 검증은 용량(`>=`)과 겹침(`.overlaps()`) 두 가지라는 점을 짚습니다. 「`.overlaps()` 를 왜 세 번 쓰나요?」에는 「부서가 셋이면 비교할 두 부서 묶음이 개발-운영 · 운영-보안 · 개발-보안 세 가지이기 때문입니다」라고 답합니다. 바꾼 뒤 `개발-보안 겹침: True` 가 안 나오면 다른 줄을 고쳤거나 따옴표를 지운 것입니다. 시간이 남으면 `dev =` 줄을 `/27` 로 바꿔 `개발팀 충분: False`(30 < 50)도 보게 합니다. 끝나면 `sec =` 줄을 `192.168.50.96/28` 로 되돌리게 합니다.

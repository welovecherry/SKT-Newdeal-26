### 왜 필요한가

1. 보안 관제에서 보는 로그(방화벽 · 웹 서버 · 침입 탐지 시스템 로그)에는 거의 언제나 **출발지 IP 주소**와 **목적지 IP 주소** 필드가 기록됩니다. 분석은 그 주소가 **내부망**(우리 회사 네트워크)인지 **외부망**(인터넷)인지 가리는 것부터 시작합니다.
2. 그 기준이 **사설 IP**(회사 · 가정의 내부망에서만 쓰는 주소)와 **공인 IP**(인터넷 전체에서 하나뿐인 주소)입니다.
3. 내부망 PC 의 사설 IP 는 인터넷과 통신할 때 공유기 · 라우터의 **NAT**(냇 · Network Address Translation, 주소 변환)를 거쳐 **공인 IP 로 바뀌어** 나갑니다. 그래서 외부 서버나 방화벽 로그에 기록된 출발지 주소는 실제 PC 의 사설 IP 가 아니라 공유기의 공인 IP 일 수 있습니다. 어느 PC 가 보낸 것인지 찾으려면 공유기 · 방화벽에 남은 **NAT 변환 기록**을 함께 봐야 합니다.

### 2.1 IP 주소는 32비트

**여기 나오는 말**

- **비트 (bit)**
  - 0 또는 1 하나를 담는 **2진수 한 자리**. 컴퓨터가 다루는 가장 작은 정보 단위입니다
  - IPv4 주소 하나는 **32비트**로 되어 있습니다
  - 점으로 나뉜 마디(옥텟 · octet) 하나는 **8비트**라, 마디마다 0~255 를 담습니다
- **2진수** (이진수)
  - 0 과 1 두 글자로만 쓰는 수. 자리 하나가 왼쪽으로 갈수록 2배씩 커집니다(1 · 2 · 4 · 8 · …)
  - 예: `192` 는 128 + 64 라서 `11000000`
  - 컴퓨터는 IP 주소를 이 모양으로 읽고, 서브넷 마스크도 이 모양으로 비교합니다

`192.168.10.25` 는 사람이 읽는 모양입니다. 컴퓨터는 점으로 나뉜 **마디 네 개**를 각각 **8비트 2진수**로 읽습니다. 그래서 IPv4(아이피 브이포) 주소는 모두 **32비트**입니다.

| 마디 | 10진수(평소 쓰는 수) | 2진수(0과 1 로만 쓰는 수 · 8비트) |
|---|---|---|
| 1 | 192 | `11000000` |
| 2 | 168 | `10101000` |
| 3 | 10 | `00001010` |
| 4 | 25 | `00011001` |

8비트가 전부 1 이면 `11111111` = 255 입니다. 그래서 한 마디에는 **0~255** 만 들어갑니다(256가지).

#### 🐍 문법 상자 · `.split(".")` · `리스트[번호]` — 주소를 마디로 나누기

`.split(".")` 은 글자를 점에서 나눠 **리스트**로 리턴합니다. 리스트의 값 하나는 `리스트[번호]` 로 꺼내고, 번호는 0 부터 셉니다.

```python
parts = "192.168.10.25".split(".")  # .split(".") 은 글자를 점에서 나눈 리스트를 리턴한다. 그 리스트를 parts 에 담는다
print(parts)                        # 리스트 parts 전체를 출력한다. 마디 네 개가 따옴표 붙은 글자로 들어 있다

print(parts[0])                     # parts[0] 은 리스트의 첫 번째 값이다. 첫째 마디 글자를 출력한다
print(int(parts[3]) + 1)            # 넷째 마디 글자를 int() 로 숫자로 바꾸고 1 을 더해 출력한다

# ['192', '168', '10', '25']
# 192
# 26
```

| 쓰는 것 | 뜻 |
|---|---|
| `글자.split(".")` | 글자를 점에서 나눈 리스트를 리턴한다 |
| `리스트[0]` | 리스트의 첫 번째 값. 번호는 0 부터 센다 |
| `int("25")` | 글자 `"25"` 를 숫자 25 로 바꿔 리턴한다. 글자인 채로는 더하기 계산을 할 수 없다 |

#### 🐍 문법 상자 · `format(숫자, "08b")` — 8비트 2진수로

```python
print(format(5, "08b"))        # format(숫자, "08b") 는 숫자를 앞자리를 0 으로 채운 8자리 2진수 글자로 바꾼다. 5 를 바꿔 출력한다
print(format(255, "08b"))      # 255 를 8자리 2진수 글자로 바꿔 출력한다. 255 는 8비트로 나타낼 수 있는 가장 큰 수다
bits = format(25, "08b")       # 25 를 8자리 2진수 글자로 바꿔 변수 bits 에 담는다
print(len(bits))               # len() 은 글자 수를 리턴한다. bits 의 글자 수를 출력한다

# 00000101
# 11111111
# 8
```

| 쓰는 것 | 뜻 |
|---|---|
| `b` | 2진수(binary)로 바꾼다 |
| `08` | 빈 앞자리를 0 으로 채워 **8자리**를 만든다 |
| `int("25")` | 글자 `"25"` 를 숫자 25 로 (1과목) |

⚠ `"08b"` 를 따옴표 없이 `08b` 로 쓰면 `SyntaxError` 입니다. 글자로 넘겨야 합니다.

### 2.2 사설 IP 와 공인 IP

**여기 나오는 말**

- **사설 IP (private IP)** (프라이빗 아이피)
  - 회사 · 가정의 **내부망에서만** 쓰는 주소. 이 주소 그대로는 인터넷에서 통신하지 못합니다
  - 내부망에서만 쓰므로 다른 회사와 같은 주소를 써도 충돌하지 않습니다
  - 정해진 세 범위: `10.x.x.x` · `172.16~31.x.x` · `192.168.x.x`
  - 관제에서는 로그의 주소가 이 범위면 「내부망 장비」로 먼저 분류합니다
- **공인 IP (public IP)** (퍼블릭 아이피)
  - **인터넷 전체에서 하나뿐인** 주소. 통신사가 나눠 줍니다
  - 인터넷의 서버들은 이 주소로 서로를 찾습니다
  - 예: `8.8.8.8`(구글 DNS 서버)

| 사설 IP 범위 | 예 | 주의 |
|---|---|---|
| `10.0.0.0` ~ `10.255.255.255` | `10.0.0.8` | 첫 마디가 10 이면 전부 |
| `172.16.0.0` ~ `172.31.255.255` | `172.20.5.6` | ⚠ **둘째 마디가 16~31 일 때만.** `172.32.5.6` 은 공인 |
| `192.168.0.0` ~ `192.168.255.255` | `192.168.10.25` | 첫 두 마디가 192.168 |

- 세 범위는 인터넷 공통 약속입니다. 세 범위에 들지 않는 주소는 **공인 IP** 입니다.
- 사설 IP 는 회사마다 겹쳐도 됩니다. 인터넷으로는 나가지 않기 때문입니다.
- **사설이면 안전, 공인이면 공격이라는 뜻은 아닙니다.** 내부망과 외부망을 가르는 첫 기준일 뿐입니다.

### 2.3 NAT — 사설 IP 를 공인 IP 로 변환

**여기 나오는 말**

- **NAT (Network Address Translation)** (나트 · 냇)
  - 내부망의 사설 IP 를 인터넷으로 보낼 때 **공인 IP 로 바꾸는 주소 변환**
  - 쓰는 이유 ① 사설 IP 는 인터넷에서 쓸 수 없는 주소라, 그대로 보내면 응답이 돌아올 수 없습니다
  - 쓰는 이유 ② IPv4 주소는 약 43억 개뿐이라 모든 PC 에 공인 IP 를 줄 수 없습니다. 공인 IP 하나를 내부망 PC 여러 대가 함께 씁니다
  - 집 · 학원의 **공유기**가 이 일을 합니다 — 내부망 PC 가 보낸 패킷의 출발지 주소를 자기 공인 IP 로 바꿔 보내고, 응답이 오면 변환 기록을 보고 원래 PC 의 사설 IP 로 되돌려 전달합니다
  - 그래서 외부 서버의 로그에는 내 PC 의 사설 IP 가 아니라 **공유기의 공인 IP** 가 남습니다
  - 정적 · 동적 NAT 의 차이는 2-2 에서 **검색해 찾아 씁니다**
- **PAT (Port Address Translation)** (팻)
  - 공인 IP **하나**를 내부망의 여러 PC 가 함께 쓰는 NAT
  - 연결마다 공인 IP 쪽 **포트 번호**를 다르게 붙이고, 응답이 오면 그 포트 번호로 어느 PC 의 연결인지 찾아 전달합니다
  - 집 · 학원 공유기는 대부분 이 방식입니다

공유기는 내부망 PC 가 인터넷과 통신할 때 **출발지 주소를 자기 공인 IP 로 바꿔** 보냅니다. 이것이 NAT 입니다.

| 방식 | 바꾸는 법 |
|---|---|
| 정적 NAT | **[찾아 쓰기]** 2-2 (다-2) · (다-4) 에서 검색해 보고서에 씁니다 |
| 동적 NAT | **[찾아 쓰기]** 2-2 (다-2) · (다-3) 에서 검색해 보고서에 씁니다 |
| PAT | 공인 IP **하나**를 여러 PC 가 같이 쓰고, **포트 번호로** 누구 것인지 구별한다 — 집 · 학원 공유기가 대부분 이것 |

PAT 공유기는 「공인 IP 쪽 포트 40002번 = 내부망 `192.168.10.25:51234`」 같은 **변환표**를 가지고 있다가, 답이 오면 표를 보고 원래 PC 로 넘겨 줍니다.

### 왜 필요한가

1. 주소 두 개가 **같은 망**인지 알아야 통신이 어떤 장비를 거쳐 가는지 말할 수 있습니다.
2. 같은 망이면 스위치(같은 망 안의 장비들을 잇는 장비)가 바로 전달하고, 다른 망이면 **게이트웨이(라우터 · 망과 망을 잇는 장비)** 를 거칩니다. 방화벽(허용 · 차단 규칙으로 통신을 거르는 장비) 규칙도 이 경계로 씁니다.
3. 그 경계를 정하는 값이 `255.255.255.0` 같은 **서브넷 마스크**입니다.

### 3.1 서브넷 마스크 — 마디로 먼저 읽기

**여기 나오는 말**

- **서브넷 (subnet)**
  - 큰 망을 나눈 **작은 망** 하나
  - 같은 서브넷 안의 장비끼리는 공유기 · 라우터를 거치지 않고 바로 통신합니다
  - 회사는 부서마다 서브넷을 나눠, 부서끼리 오가는 통신을 따로 관리합니다
- **서브넷 마스크 (subnet mask)**
  - IP 주소에서 **어디까지가 같은 망**인지 정하는 값
  - `255` 인 마디는 **망 부분**, `0` 인 마디는 **장비 부분**입니다
  - 망 부분은 이 장비가 **어느 망에 속하는지**를 나타내는 앞쪽 자리입니다. 같은 망에 있는 장비들은 이 부분이 **모두 똑같습니다**
  - 장비 부분은 그 망 안에서 **어느 장비인지**를 나타내는 뒤쪽 자리입니다. 장비마다 다릅니다
  - 예: `255.255.255.0` 이면 앞 세 마디가 망 부분
  - 예: `192.168.10.1` · `192.168.10.25` · `192.168.10.30` 은 망 부분 `192.168.10` 이 같아서 같은 망입니다. 장비 부분 `1` · `25` · `30` 으로 장비를 구별합니다
  - 컴퓨터는 IP 주소와 서브넷 마스크를 **2진수로 바꿔 AND 연산**을 합니다. 그 결과가 그 주소의 **네트워크 주소**입니다(3.2 에서 풀어 봅니다)
  - 두 주소의 네트워크 주소가 같으면 같은 망입니다
- **CIDR (Classless Inter-Domain Routing)** (사이더)
  - 서브넷 마스크를 `/숫자` 로 짧게 쓰는 표기
  - `/` 뒤의 숫자는 서브넷 마스크를 2진수로 바꿨을 때 **1 의 개수**입니다
  - `255` 를 2진수로 바꾸면 `11111111` 로 1 이 8개입니다. 그래서 `255` 인 마디 하나는 8 로 셉니다
  - `0` 을 2진수로 바꾸면 `00000000` 으로 1 이 0개입니다. 그래서 `0` 인 마디는 0 으로 셉니다
  - 예: `255.255.255.0` 을 2진수로 쓰면 `11111111.11111111.11111111.00000000` 입니다. 1 이 8개인 마디가 세 개라 8 × 3 = 24, 그래서 `/24` 입니다
  - 예: `255.255.0.0` 을 2진수로 쓰면 `11111111.11111111.00000000.00000000` 입니다. 1 이 8개인 마디가 두 개라 8 × 2 = 16, 그래서 `/16` 입니다
- **호스트 (host)**
  - 망 안에서 주소를 받는 **장비 하나**
  - 예: PC · 서버 · 프린터 · 스마트폰

**마디**는 IP 주소에서 점으로 나뉜 숫자 하나입니다. `192.168.10.25` 는 마디가 네 개입니다.

| 첫째 마디 | 둘째 마디 | 셋째 마디 | 넷째 마디 |
|---|---|---|---|
| `192` | `168` | `10` | `25` |

**서브넷 마스크는 「1 인 자리는 망 부분, 0 인 자리는 장비 부분」이라고 표시하는 값입니다.** `255` 는 2진수로 `11111111` 이라 8자리가 모두 1 입니다. 그래서 `255` 인 마디는 마디 전체가 망 부분입니다.

| | 첫째 마디 | 둘째 마디 | 셋째 마디 | 넷째 마디 |
|---|---|---|---|---|
| 마스크 `255.255.255.0` | `11111111` | `11111111` | `11111111` | `00000000` |
| 뜻 | 망 부분 | 망 부분 | 망 부분 | 장비 부분 |
| IP `192.168.10.25` | `192` | `168` | `10` | `25` |

- 앞 세 마디는 마스크가 모두 1 이라 망 부분입니다. 그래서 IP 의 앞 세 마디 `192.168.10` 이 망 부분입니다.
- 넷째 마디는 마스크가 모두 0 이라 장비 부분입니다. 그래서 `25` 가 장비 부분입니다.
- 마스크는 망을 관리하는 쪽이 정합니다. 집 공유기나 학원 네트워크 장비가 PC 에 IP 주소와 함께 마스크를 나눠 줍니다. 앞 세 마디로 망을 구분하는 곳은 `255.255.255.0`, 앞 두 마디로 구분하는 학원망은 `255.255.0.0` 을 줍니다.

**같은 망인지 가리는 법** — 두 주소에서 망 부분만 꺼내 비교합니다. 망 부분이 같으면 같은 망, 하나라도 다르면 다른 망입니다. 장비 부분은 달라도 상관없습니다.

**`/24` 이면 앞 세 마디를 비교합니다.**

| 주소 A | 주소 B | A 의 앞 세 마디 | B 의 앞 세 마디 | 비교 | 결과 |
|---|---|---|---|---|---|
| `192.168.10.25` | `192.168.10.200` | `192.168.10` | `192.168.10` | 같다 | **같은 망** |
| `192.168.10.25` | `192.168.20.25` | `192.168.10` | `192.168.20` | 셋째 마디 `10` ≠ `20` | **다른 망** |

- 첫째 줄의 넷째 마디 `25` 와 `200` 은 장비 부분이라 달라도 같은 망입니다.

**`/16` 이면 앞 두 마디만 비교합니다.**

| 주소 A | 주소 B | A 의 앞 두 마디 | B 의 앞 두 마디 | 비교 | 결과 |
|---|---|---|---|---|---|
| `192.168.10.25` | `192.168.20.25` | `192.168` | `192.168` | 같다 | **같은 망** |
| `192.168.10.25` | `172.16.10.25` | `192.168` | `172.16` | 첫째 마디 `192` ≠ `172` | **다른 망** |

- 첫째 줄의 셋째 마디 `10` 과 `20` 은 `/16` 에서는 장비 부분이라 달라도 같은 망입니다.

- 같은 두 주소 `192.168.10.25` 와 `192.168.20.25` 도 `/24` 에서는 다른 망, `/16` 에서는 같은 망입니다. 마스크가 「앞에서 몇 마디까지 비교할지」를 정하므로, 같은 망인지는 **주소가 아니라 마스크**가 정합니다.
- **학원망은 `/16`** 입니다 — 서브넷 마스크 `255.255.0.0`, 기본 게이트웨이 `192.168.1.1`. 앞 두 마디 `192.168` 이 같으면 같은 망입니다.
- **집 공유기는 보통 `/24`** 입니다 — 서브넷 마스크 `255.255.255.0`. 앞 세 마디가 같아야 같은 망입니다.

---

### 3.2 풀이 순서 — `192.168.10.25/24` 하나 풀어 보기

**여기 나오는 말**

- **네트워크 주소**
  - `192.168.10.25/24` 가 속한 망에는 `192.168.10.0` 부터 `192.168.10.255` 까지 주소 256개가 있습니다. 이 가운데 **가장 작은 주소** `192.168.10.0` 이 네트워크 주소입니다
  - `/24` 에서는 넷째 마디가 장비 부분입니다. 네트워크 주소는 이 넷째 마디가 `0` 입니다
  - 장비 하나가 아니라 **망 전체를 가리키는** 주소입니다. 그래서 PC · 서버 같은 장비의 IP 주소로 설정하지 않습니다
  - 예: `192.168.10.25/24` 의 네트워크 주소는 장비 부분(마지막 마디) `25` 를 `0` 으로 바꾼 `192.168.10.0` 입니다
- **브로드캐스트 주소 (broadcast)** (브로드캐스트)
  - **브로드캐스트**는 받는 장비를 한 대로 정하지 않고, **같은 망의 모든 장비에게 한 번에** 보내는 방식입니다
  - 누구에게 보내야 할지 모를 때 씁니다. 예: 「이 IP 주소를 쓰는 장비는 대답해 주세요」를 망 전체에 한 번에 묻고, 해당 장비만 대답합니다
  - 이 주소로 패킷을 하나 보내면 **같은 망의 장비 전부가** 받습니다
  - 보통 주소 `192.168.10.30` 으로 보내면 그 장비 **한 대만** 받습니다. 브로드캐스트 주소 `192.168.10.255` 로 보내면 `.1` · `.25` · `.30` · `.200` … 망 안의 장비가 **모두** 받습니다
  - 같은 망의 주소 256개 가운데 **가장 큰 주소** `192.168.10.255` 가 브로드캐스트 주소입니다
  - `/24` 에서는 장비 부분인 넷째 마디가 `255` 입니다
  - 모두가 받는 주소라서 장비 한 대의 IP 주소로는 설정하지 않습니다
  - 예: `192.168.10.25/24` 의 브로드캐스트 주소는 장비 부분(마지막 마디) `25` 를 `255` 로 바꾼 `192.168.10.255` 입니다

주소 하나를 받으면 아래 네 단계로 풉니다.

1. **① 마스크** — `/24` 는 `255.255.255.0` 입니다(아래 3.3 표).
2. **② 망 부분** — `255` 가 앞 세 마디라 `192.168.10` 이 망 부분, 마지막 마디 `25` 가 장비 부분입니다.
3. **③ 네트워크 주소 · 브로드캐스트 주소** — 장비 부분을 `0` 으로 두면 네트워크 주소 `192.168.10.0`, `255` 로 두면 브로드캐스트 주소 `192.168.10.255` 입니다.
4. **④ 장비에 줄 수 있는 주소** — 그 둘을 뺀 `192.168.10.1` ~ `192.168.10.254`, 254개입니다. 기본 게이트웨이도 이 가운데 하나를 씁니다(보통 `.1`).

3-2 에서 내 주소를 같은 순서로 읽습니다. 학원망 `/16` 이면 ② 의 망 부분이 앞 두 마디가 되고, ③ 에서는 뒤 두 마디가 함께 `0` · `255` 가 됩니다.

#### 컴퓨터는 이렇게 계산합니다 — AND 연산

**여기 나오는 말**

- **AND 연산** (앤드 연산)
  - 같은 자리의 비트끼리 비교해서 **둘 다 1 일 때만 1**, 하나라도 0 이면 0 을 남기는 계산
  - 예: `1` AND `1` = `1`, `1` AND `0` = `0`, `0` AND `0` = `0`

위 ③ 의 네트워크 주소 `192.168.10.0` 을 컴퓨터는 아래 순서로 구합니다.

1. **IP 주소와 마스크를 2진수로 바꿉니다.**

| | 첫째 마디 | 둘째 마디 | 셋째 마디 | 넷째 마디 |
|---|---|---|---|---|
| IP `192.168.10.25` | `11000000` | `10101000` | `00001010` | `00011001` |
| 마스크 `255.255.255.0` | `11111111` | `11111111` | `11111111` | `00000000` |

2. **같은 자리끼리 AND 합니다.**
   - 마스크가 `1` 인 자리는 IP 의 비트가 **그대로** 남습니다. 그래서 앞 세 마디가 그대로 나옵니다.
   - 마스크가 `0` 인 자리는 IP 의 비트와 상관없이 **모두 0** 이 됩니다. 그래서 넷째 마디가 `0` 이 됩니다.

| | 첫째 마디 | 둘째 마디 | 셋째 마디 | 넷째 마디 |
|---|---|---|---|---|
| AND 결과 | `11000000` | `10101000` | `00001010` | `00000000` |

3. **결과를 10진수로 다시 바꿉니다.** `192.168.10.0` 이 나오고, 이것이 네트워크 주소입니다.
4. **같은 망인지 판정합니다.** 다른 주소도 같은 마스크로 AND 해서, 네트워크 주소가 같으면 같은 망입니다.
   - `192.168.10.200` 을 AND 하면 `192.168.10.0` 이라 `192.168.10.25` 와 같은 망입니다.
   - `192.168.20.25` 를 AND 하면 `192.168.20.0` 이라 다른 망입니다.

③ 에서 「장비 부분을 `0` 으로 둔다」고 한 것이 바로 이 AND 의 결과입니다.

### 3.3 마스크 · CIDR · 주소 수 표

주소 수는 계산하지 않고 이 표에서 찾습니다.

| 서브넷 마스크 | 2진수 (1 의 개수 = CIDR 숫자) | CIDR | 주소 수 | 장비에 쓸 수 있는 수 |
|---|---|---|---|---|
| `255.255.0.0` | `11111111.11111111.00000000.00000000` | `/16` | 65,536 | 65,534 |
| `255.255.255.0` | `11111111.11111111.11111111.00000000` | `/24` | 256 | 254 |
| `255.255.255.128` | `11111111.11111111.11111111.10000000` | `/25` | 128 | 126 |
| `255.255.255.192` | `11111111.11111111.11111111.11000000` | `/26` | 64 | 62 |
| `255.255.255.224` | `11111111.11111111.11111111.11100000` | `/27` | 32 | 30 |
| `255.255.255.240` | `11111111.11111111.11111111.11110000` | `/28` | 16 | 14 |

- 쓸 수 있는 수는 주소 수에서 네트워크 주소 · 브로드캐스트 주소 2개를 뺀 수입니다.
- 2진수 열의 `1` 을 세면 CIDR 숫자가 됩니다. 예: `/26` 은 `1` 이 8 + 8 + 8 + 2 = 26개입니다.
- CIDR 숫자가 클수록 망이 작아집니다.
- `/25` ~ `/28` 은 넷째 마디 **중간**에서 망 부분과 장비 부분이 나뉘는 마스크입니다. 4교시 4.1 에서 다룹니다.

### 3.4 `ipaddress` 로 같은 순서 풀기

**여기 나오는 말**

- **ipaddress** (아이피어드레스)
  - IP 주소와 망을 계산하는 파이썬 모듈. 파이썬에 기본으로 들어 있어 설치가 필요 없습니다
  - `ipaddress.ip_network("주소/CIDR")` 는 그 망을 나타내는 **망 객체**를 리턴합니다. 망 객체에서 마스크 · 네트워크 주소 · 브로드캐스트 주소를 꺼내 씁니다

3.2 의 ① · ③ 을 `ipaddress` 가 계산해 줍니다. 3-2 코드에서 줄마다 주석으로 어떤 값을 꺼내는지 읽어 봅니다.

⚠ `strict=False` 를 빼면 `192.168.10.25/24` 처럼 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">망의 첫 주소가 아닌 값에서 `ValueError`</mark>(값이 맞지 않다는 에러)가 납니다.

#### 🐍 문법 상자 · `import` · 망 객체 · `.netmask` — `ipaddress` 쓰기

`ipaddress.ip_network("주소/CIDR")` 는 **망 객체**를 리턴합니다. 객체는 값과 그 값으로 할 수 있는 기능을 함께 가진 것이고, 객체 뒤에 `.이름` 을 붙여 그 값이나 기능을 씁니다.

```python
import ipaddress                                # import 로 IP 계산 모듈 ipaddress 를 불러온다. 그 뒤로 ipaddress. 으로 모듈의 기능을 쓴다

net = ipaddress.ip_network("192.168.10.0/24")   # ip_network() 는 「주소/CIDR」 글자로 망 객체를 만들어 리턴한다. 그 객체를 net 에 담는다
print(net.netmask)                              # .netmask 로 망 객체 net 의 서브넷 마스크를 꺼내 출력한다

net2 = ipaddress.ip_network("192.168.10.25/24", strict=False)  # 망의 첫 주소가 아니므로 strict=False 를 붙여 이 주소가 속한 망 객체를 만든다
print(net2)                                     # 망 객체 net2 를 「네트워크 주소/CIDR」 꼴로 출력한다

# 255.255.255.0
# 192.168.10.0/24
```

| 쓰는 것 | 뜻 |
|---|---|
| `import ipaddress` | 파이썬에 들어 있는 모듈 `ipaddress` 를 불러온다. 파일 맨 위에 한 번 쓴다 |
| `ipaddress.ip_network("주소/CIDR")` | 그 망을 나타내는 망 객체를 리턴한다 |
| `strict=False` | 망의 첫 주소가 아닌 값을 넣어도 에러 없이, 그 주소가 속한 망을 만든다 |
| `망.netmask` | 서브넷 마스크 |
| `망.network_address` | 네트워크 주소(망에서 가장 작은 주소) |
| `망.broadcast_address` | 브로드캐스트 주소(망에서 가장 큰 주소) |

### 4.1 큰 망을 반으로 나누기 — `/25`

**여기 나오는 말**

- **서브네팅 (subnetting)** (서브네팅)
  - 큰 망을 **작은 망 여러 개로 나누는** 일
  - 부서마다 망을 따로 주면 부서 사이 통신을 나눠 관리할 수 있습니다
- **블록**
  - 큰 망을 나눠 생긴 **작은 망 하나**
  - 블록 하나도 3.2 에서 푼 망 하나와 같습니다. 가장 작은 주소가 네트워크 주소, 가장 큰 주소가 브로드캐스트 주소입니다

회사 망 `192.168.50.0/24` 는 넷째 마디만 `0` ~ `255` 로 바뀌는 망입니다. 주소가 256개입니다. 이 망을 가장 쉬운 크기인 `/25` 로 나눠 봅니다.

1. **`/25` 블록 하나의 크기를 찾습니다.** 아래 표의 `/25` 줄을 보면 주소 수가 **128개**입니다. 3.3 표에서 4교시에 쓰는 줄만 다시 옮겼습니다.

| CIDR | 서브넷 마스크 | 주소 수 | 장비에 쓸 수 있는 수 |
|---|---|---|---|
| `/24` | `255.255.255.0` | 256 | 254 |
| `/25` | `255.255.255.128` | **128** | 126 |
| `/26` | `255.255.255.192` | 64 | 62 |
| `/27` | `255.255.255.224` | 32 | 30 |
| `/28` | `255.255.255.240` | 16 | 14 |

- **장비에 쓸 수 있는 수 = 주소 수 − 2** 입니다. 블록마다 주소 두 개는 장비에 주지 않기 때문입니다.
  - 가장 작은 주소는 **네트워크 주소**입니다. 장비 하나가 아니라 그 망 전체를 가리키는 주소입니다.
  - 가장 큰 주소는 **브로드캐스트 주소**입니다. 이 주소로 보내면 망 안의 장비가 모두 받습니다.
  - 예: `/25` 블록 `.0` ~ `.127` 은 주소가 128개입니다. 네트워크 주소 `.0` 과 브로드캐스트 주소 `.127` 을 빼면 장비에 줄 수 있는 주소는 `.1` ~ `.126`, 126개입니다.

2. **앞에서부터 128개씩 자릅니다.** 256개를 128개씩 자르면 블록이 **2개** 생깁니다. 정확히 반으로 나뉩니다.

```
.0 ──────────────── .127 │ .128 ──────────────── .255
      블록 1 (128개)      │       블록 2 (128개)
```

3. **블록마다 범위를 읽습니다.**
   - 블록 1 은 `.0` 부터 128개라 `.127` 에서 끝납니다.
   - 블록 2 는 그 바로 다음 주소 `.128` 에서 시작해 `.255` 에서 끝납니다.
4. **블록마다 네트워크 주소와 브로드캐스트 주소를 정합니다.** 3.2 와 같은 방법입니다. 가장 작은 주소가 네트워크 주소, 가장 큰 주소가 브로드캐스트 주소, 그 사이가 장비에 줄 수 있는 주소입니다.

| 블록 | 범위 | 네트워크 주소 | 브로드캐스트 주소 | 장비에 줄 수 있는 주소 | 쓸 수 있는 수 |
|---|---|---|---|---|---|
| `192.168.50.0/25` | `.0` ~ `.127` | `.0` | `.127` | `.1` ~ `.126` | 126 |
| `192.168.50.128/25` | `.128` ~ `.255` | `.128` | `.255` | `.129` ~ `.254` | 126 |

- 블록 이름 `192.168.50.128/25` 는 「`.128` 에서 시작하는 `/25` 크기 블록」이라는 뜻입니다. `/` 앞의 주소가 그 블록의 네트워크 주소입니다.
- 블록은 쓸 수 있는 수(126)가 아니라 **주소 수(128)** 만큼씩 자릅니다.

**더 작게 나누면** — 방법은 같고, 자르는 크기만 바뀝니다. 자르는 크기는 4.1 첫 표의 주소 수입니다.

| CIDR | 한 블록의 주소 수 | 블록 수 | 블록이 시작하는 주소 |
|---|---|---|---|
| `/25` | 128개 | 256 ÷ 128 = 2개 | `.0` · `.128` |
| `/26` | 64개 | 256 ÷ 64 = 4개 | `.0` · `.64` · `.128` · `.192` |

#### 🐍 문법 상자 · `.subnets(new_prefix=…)` — 망을 블록으로 나누기

`import` 와 `ip_network()` 는 3.4 아래 문법 상자에서 봤습니다. `망.subnets(new_prefix=26)` 은 그 망을 `/26` 블록으로 나눠 앞에서부터 하나씩 리턴하고, `for` 가 블록을 하나씩 받아 반복합니다.

```python
import ipaddress                                    # import 로 IP 계산 모듈 ipaddress 를 불러온다

parent = ipaddress.ip_network("192.168.50.0/24")    # 나눌 망 192.168.50.0/24 를 망 객체로 만들어 parent 에 담는다

for block in parent.subnets(new_prefix=26):         # .subnets(new_prefix=26) 이 /26 블록을 하나씩 리턴하고, 그 블록을 block 에 담아 반복한다
    print(block)                                    # 블록을 「네트워크 주소/CIDR」 꼴로 출력한다

# 192.168.50.0/26
# 192.168.50.64/26
# 192.168.50.128/26
# 192.168.50.192/26
```

| 쓰는 것 | 뜻 |
|---|---|
| `망.subnets(new_prefix=26)` | 망을 `/26` 크기 블록으로 나눠 앞에서부터 하나씩 리턴한다 |
| `for block in …:` | 리턴된 블록을 하나씩 `block` 에 담아 아래 줄을 반복한다 |

### 4.2 설계 검증 — 용량과 겹침

**여기 나오는 말**

- **겹침 (overlap)** (오버랩)
  - 두 부서의 망이 **같은 주소를 함께 가진** 상태
  - 같은 주소를 두 부서 장비가 받으면 **주소 충돌**로 통신이 끊기고, 로그의 주소로 어느 장비인지 가릴 수 없습니다

설계표를 만들면 두 가지를 확인합니다.

- **용량** — 부서 망의 「쓸 수 있는 수」가 장비 수 이상인가. 4.1 첫 표의 「장비에 쓸 수 있는 수」로 확인합니다.
- **겹침** — 두 부서의 망이 같은 주소를 갖지 않는가. 4-2 에서 코드로 확인합니다.

#### 🐍 문법 상자 · `.overlaps()` — 두 망이 겹치는지

`망1.overlaps(망2)` 는 두 망이 같은 주소를 하나라도 가지면 `True`, 하나도 없으면 `False` 를 리턴합니다.

```python
import ipaddress                                    # import 로 IP 계산 모듈 ipaddress 를 불러온다

a = ipaddress.ip_network("192.168.50.0/26")         # .0 ~ .63 망을 망 객체로 만들어 a 에 담는다
b = ipaddress.ip_network("192.168.50.64/26")        # .64 ~ .127 망을 망 객체로 만들어 b 에 담는다
c = ipaddress.ip_network("192.168.50.0/25")         # .0 ~ .127 망을 망 객체로 만들어 c 에 담는다

print(a.overlaps(b))                                # a 와 b 가 같이 가진 주소가 있는지 출력한다. 하나도 없으므로 False 다
print(a.overlaps(c))                                # a 와 c 가 같이 가진 주소가 있는지 출력한다. a 의 주소가 모두 c 에도 있으므로 True 다

# False
# True
```

| 쓰는 것 | 뜻 |
|---|---|
| `망1.overlaps(망2)` | 같이 가진 주소가 하나라도 있으면 `True`, 없으면 `False` 를 리턴한다 |
| `True` · `False` | 참 · 거짓을 나타내는 값. 따옴표 없이 첫 글자를 대문자로 쓴다 |

**왜** — (나) `format(number, "08b")` 는 마디 하나의 10진수를 0 과 1 로 된 8자리 2진수 글자로 바꿉니다. 예를 들어 `10` 은 `00001010` 으로 출력됩니다. `b` 는 2진수(binary)로 바꾸라는 뜻이고, `08` 은 빈 앞자리를 0 으로 채워 8자리를 만들라는 뜻입니다. `08` 을 빼고 `"b"` 만 쓰면 `10` 은 `1010` 네 자리가 되어 마디마다 길이가 달라지고, 32비트 가운데 몇 번째 비트인지 줄을 맞춰 볼 수 없습니다. 서브넷 마스크는 비트 자리 단위로 망 부분과 장비 부분을 나누므로 마디마다 8자리로 맞춰 씁니다. (다) IPv4 주소는 마디 네 개 × 8비트 = 32비트입니다. 마디 하나가 8비트라 `00000000`(0) ~ `11111111`(255), 곧 2⁸ = 256 가지 값만 가집니다. 32비트로 만들 수 있는 주소는 4,294,967,296개(약 43억 개)입니다. 인터넷 장비가 이보다 많아져 주소가 모자라므로, 내부망에서는 사설 IP 를 쓰고 NAT 로 공인 IP 하나를 여러 PC 가 함께 씁니다. (다-3) 비트 한 자리에는 0 또는 1, 두 가지 값이 들어갑니다. 자리가 하나 늘 때마다 경우의 수가 2배가 되므로 32자리면 2 를 32번 곱한 2³² = 4,294,967,296 가지입니다.

**자주 틀리는 곳** — (나) 에 「2진수로 바꾼다」만 적고 `08` 을 빼는 것입니다. `08` 이 없으면 10 이 `1010` 네 자리가 되어 마디마다 길이가 달라집니다.

**관제에서는** — 마스크 · 망 경계 계산이 모두 이 8비트 단위로 이루어지므로, 2진수로 펼칠 줄 알아야 경계를 검산할 수 있습니다.

### 정답 2-2

💻 **터미널에 입력합니다.**

```bash
ipconfig
curl https://api.ipify.org
```

**결과** — `ipconfig` 는 `192.168.○.○`(학원 PC), `curl` 은 `211.○○○.○○○.○○` 같은 주소 한 줄 — 두 주소가 **다르다.** (값은 장소마다 다릅니다)

**왜** — (나) 학원 주소 `192.168.…` 은 2.2 표 셋째 줄 `192.168.0.0` ~ `192.168.255.255` 사이에 들어가므로 사설 IP 입니다. `curl` 로 본 주소는 세 범위 어디에도 들지 않아 공인 IP 입니다. `172.20.5.6` 은 둘째 마디 20 이 16~31 사이라 사설 IP, 곧 내부망 장비로 먼저 분류합니다. `172.32.5.6` 은 둘째 마디 32 가 범위를 벗어나 공인 IP, 곧 외부 주소입니다. 다만 사설이라고 안전하다는 뜻은 아닙니다. (다) NAT(학원 · 집 공유기는 PAT)는 내부망 PC 가 보낸 패킷의 출발지 주소를 공유기의 공인 IP 로 바꿔 보내므로, 외부 서버 로그에는 공유기의 공인 IP 만 남습니다. 그 공인 IP 하나를 내부망 PC 여러 대가 함께 쓰므로 그 주소만으로는 어느 PC 인지 알 수 없습니다. 특정하려면 공유기의 변환 기록(공인 IP 쪽 포트 번호 ↔ 내부 사설 IP · 포트)과 통신한 시각이 더 필요합니다. 정적 NAT 은 사설 IP 하나와 공인 IP 하나를 **고정**해 연결해 둡니다. 동적 NAT 은 공인 IP 여러 개 가운데 쓰지 않는 것을 통신할 때마다 **그때그때** 하나 배정합니다. 인터넷에서 내부망 웹 서버로 접속하게 하려면 외부 사용자가 늘 같은 공인 IP 로 찾아올 수 있어야 하므로 정적 NAT 이 맞습니다. (다-3) 사원 PC 는 밖에서 찾아올 일이 없어 공인 IP 를 고정할 필요가 없으므로, 동적 NAT 으로 적은 공인 IP 를 돌아가며 나눠 씁니다. 같은 공인 IP 가 시간마다 다른 PC 일 수 있어, 로그로 PC 를 특정하려면 그 시각의 NAT 변환 기록을 함께 봐야 합니다.

**자주 틀리는 곳** — `ipconfig` 의 `192.168.…` 을 공인 IP 항목에 적는 것입니다. 그 주소는 사설이라 인터넷에서는 보이지 않습니다. `172.32.…` 처럼 둘째 마디가 16~31 이 아닌 172 주소를 사설로 판정하는 것도 자주 틀립니다.

**관제에서는** — 외부 서버 로그에 찍힌 주소는 PC 주소가 아니라 공유기의 공인 주소라, 실제 PC 를 찾으려면 NAT 변환 기록을 함께 봐야 합니다.

### 정답 3-1

💻 **터미널에 입력합니다.** `ipconfig` → `서브넷 마스크` 줄.

**결과** — 학원 PC 는 `255.255.0.0` · `/16` · 65,536 · 65,534. 집 공유기는 보통 `255.255.255.0` · `/24` · 256 · 254

**왜** — (나) `255` 는 2진수로 `11111111` 이라 1 이 8개입니다. 마스크에서 1 인 비트는 망 부분, 0 인 비트는 장비 부분을 가리킵니다. 학원 마스크 `255.255.0.0` 은 1 이 8개인 마디가 두 개라 망 부분이 앞 두 마디(`192.168`)이고, 1 의 개수 8 × 2 = 16 이라 `/16` 입니다. 집 `255.255.255.0` 이면 세 개라 앞 세 마디, `/24` 입니다. (다) 학원 `/16` 이면 앞 두 마디만 비교하는데 둘 다 `192.168` 이라 **같은 망**입니다. 셋째 마디 `10` · `20` 은 장비 부분이라 달라도 됩니다. 같은 두 주소를 `/24` 로 보면 셋째 마디까지 비교하므로 `10` ≠ `20` 이라 **다른 망**입니다. 같은 망이면 스위치가 바로 전달하고 다른 망이면 게이트웨이를 거치며, 방화벽 규칙도 이 경계로 씁니다. 그래서 마스크를 잘못 알면 통신 경로와 규칙이 덮는 범위를 모두 잘못 판단합니다. (가-2) 학원 `/16` 이면 망 부분은 앞 두 마디 `192.168`, 장비 부분은 뒤 두 마디입니다. 집 `/24` 이면 망 부분은 앞 세 마디, 장비 부분은 넷째 마디입니다. (나-3) 같은 교실 PC 는 같은 망이라 망 부분이 모두 같고, 장비 부분은 PC 마다 다릅니다. 망 부분은 「어느 망인지」, 장비 부분은 「그 망 안의 어느 장비인지」를 나타내기 때문입니다.

**자주 틀리는 곳** — 마스크 대신 바로 위 IPv4 주소 줄이나 아래 게이트웨이 줄을 읽는 것입니다. (다) 에서 예시 `/24` 기준으로만 답하고 내 마스크(학원 `/16`)로 보지 않는 것도 자주 틀립니다.

**관제에서는** — 내 PC 가 속한 망의 크기를 알아야 어떤 주소까지가 같은 망 장비인지 가릴 수 있습니다.

### 정답 3-2

코드는 문제의 코드 그대로입니다. 두 번째 파일 `warmup_3_2b.py` 는 `my_ip` · `prefix` 두 줄에 내 값을 적은 것만 다릅니다.

학원망 `/16` 에서 주소가 `192.168.10.25` 라면

**왜** — (나) 첫째 줄은 ① 서브넷 마스크, 둘째 줄은 ③ 네트워크 주소, 셋째 줄은 ③ 브로드캐스트 주소입니다. 둘째 줄은 내 주소와 마스크를 2진수로 바꿔 같은 자리끼리 AND 한 결과입니다. 마스크가 1 인 자리는 주소의 비트가 그대로 남고, 0 인 자리는 모두 0 이 됩니다. 학원 `/16` 은 앞 두 마디 `192.168` 이 망 부분이라 그대로 남고, 장비 부분인 뒤 두 마디만 모두 `0` 으로 바꾼 것이 네트워크 주소, 모두 `255` 로 바꾼 것이 브로드캐스트 주소입니다. `/24` 라면 마지막 마디 하나만 바뀝니다. PC 는 같은 망의 장비에게만 바로 패킷을 넘기므로, 게이트웨이도 같은 망의 장비로서 ④ 장비에 줄 수 있는 주소 가운데 하나를 써야 합니다. 네트워크 주소는 망 전체를 가리키고 브로드캐스트 주소는 망 안의 장비 모두가 받는 주소라, 어느 쪽도 장비 한 대를 가리키지 못합니다. 그래서 게이트웨이를 그 주소로 설정하면 PC 가 다른 망으로 갈 패킷을 넘길 장비를 정하지 못해 인터넷과 통신하지 못합니다.

**관제에서는** — 이 범위가 내 PC 와 같은 망이라, 범위 안 주소에서 온 접속은 게이트웨이를 거치지 않은 같은 망 내부 통신입니다.

### 정답 4-1

코드는 문제의 코드 그대로입니다.

💻 **터미널에 입력합니다.** `python warmup_4_1.py`

**결과** — 아래 두 줄 — 블록 1 은 `.0` ~ `.127`, 블록 2 는 `.128` ~ `.255`. `/26` 은 주소 수 64 · 장비에 쓸 수 있는 수 62

```
192.168.50.0/25
192.168.50.128/25
```

**왜** — (나) 4.1 첫 표에서 `/25` 블록 하나는 주소가 128개입니다. 256개를 앞에서부터 128개씩 자르면 블록 1 은 `.0` ~ `.127` 이고, 블록 2 는 그 바로 다음 `.128` 에서 시작해 `.255` 까지입니다. 블록 이름의 `/` 앞 주소는 그 블록에서 가장 작은 주소, 곧 네트워크 주소입니다. 블록은 네트워크 주소 · 브로드캐스트 주소까지 포함한 주소 수(128)만큼 잘라야 합니다. 쓸 수 있는 수(126)만큼씩 자르면 블록의 시작과 끝이 마스크가 정하는 경계와 어긋납니다. (다) `/26` 블록은 주소가 64개이지만, 가장 작은 주소(네트워크 주소)는 망 전체를 가리키고 가장 큰 주소(브로드캐스트 주소)는 망 안의 장비 모두가 받는 주소라 장비에 주지 않습니다. 그래서 장비에 줄 수 있는 주소는 64 − 2 = 62개입니다. 장비 64대인 부서에 `/26` 을 주면 2대가 주소를 받지 못하므로, 한 단계 큰 `/25`(126대)를 골라야 합니다.

**자주 틀리는 곳** — 쓸 수 있는 수 126 으로 잘라 둘째 블록이 `.126` 에서 시작한다고 적는 것입니다. 블록은 주소 수 128 로 자릅니다. (다) 에서 주소 수 64 를 그대로 장비 수로 적는 것도 자주 틀립니다.

**관제에서는** — 로그에 `192.168.50.200` 이 찍히면 `.128` ~ `.255` 블록, 즉 둘째 망에서 온 것입니다. 부서 망이 필요보다 크면 쓰지 않는 주소가 남아, 허가 없이 꽂은 장비가 그 주소를 받기 쉬워집니다.

**관제에서는** — 두 부서 망이 겹치면 같은 주소를 두 PC 가 받을 수 있어, 로그 주소로 장비를 특정할 수 없게 됩니다. 새 부서 망을 더할 때마다 겹침을 다시 검사합니다.

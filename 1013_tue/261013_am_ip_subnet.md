### 왜 필요한가

1. 보안 관제에서 보는 로그(방화벽 · 웹 서버 · 침입 탐지 시스템 로그)에는 거의 언제나 **출발지 IP 주소**와 **목적지 IP 주소** 필드가 기록됩니다. 분석은 그 주소가 **내부망**(우리 회사 네트워크)인지 **외부망**(인터넷)인지 가리는 것부터 시작합니다.
2. 그 기준이 **사설 IP**(회사 · 가정의 내부망에서만 쓰는 주소)와 **공인 IP**(인터넷 전체에서 하나뿐인 주소)입니다.
3. 내부망 PC 의 사설 IP 는 인터넷과 통신할 때 공유기 · 라우터의 **NAT**(냇 · Network Address Translation, 주소 변환)를 거쳐 **공인 IP 로 바뀌어** 나갑니다. 그래서 외부 서버나 방화벽 로그에 기록된 출발지 주소는 실제 PC 의 사설 IP 가 아니라 공유기의 공인 IP 일 수 있습니다. 어느 PC 가 보낸 것인지 찾으려면 공유기 · 방화벽에 남은 **NAT 변환 기록**을 함께 봐야 합니다.

### 2.1 IP 주소는 32비트

**여기 나오는 말**

- **비트 (bit)**
  - 0 또는 1 하나를 담는 **2진수 한 자리**. 컴퓨터가 다루는 가장 작은 정보 단위입니다
  - IPv4 주소 하나는 **32비트**로 되어 있습니다
  - 점으로 나뉜 마디(옥텟 · octet) 하나는 **8비트**라, 마디마다 0~255 를 담습니다
- **2진수** (이진수)
  - 0 과 1 두 글자로만 쓰는 수. 자리 하나가 왼쪽으로 갈수록 2배씩 커집니다(1 · 2 · 4 · 8 · …)
  - 예: `192` 는 128 + 64 라서 `11000000`
  - 컴퓨터는 IP 주소를 이 모양으로 읽고, 서브넷 마스크도 이 모양으로 비교합니다

`192.168.10.25` 는 사람이 읽는 모양입니다. 컴퓨터는 점으로 나뉜 **마디 네 개**를 각각 **8비트 2진수**로 읽습니다. 그래서 IPv4(아이피 브이포) 주소는 모두 **32비트**입니다.

| 마디 | 10진수(평소 쓰는 수) | 2진수(0과 1 로만 쓰는 수 · 8비트) |
|---|---|---|
| 1 | 192 | `11000000` |
| 2 | 168 | `10101000` |
| 3 | 10 | `00001010` |
| 4 | 25 | `00011001` |

8비트가 전부 1 이면 `11111111` = 255 입니다. 그래서 한 마디에는 **0~255** 만 들어갑니다(256가지).

#### 🐍 문법 상자 · `format(숫자, "08b")` — 8비트 2진수로

```python
print(format(5, "08b"))        # format(숫자, "08b") 는 숫자를 앞자리를 0 으로 채운 8자리 2진수 글자로 바꾼다. 5 를 바꿔 출력한다
print(format(255, "08b"))      # 255 를 8자리 2진수 글자로 바꿔 출력한다. 255 는 8비트로 나타낼 수 있는 가장 큰 수다
print(len(format(25, "08b")))  # len() 은 글자 수를 리턴한다. 25 를 바꾼 8자리 2진수 글자의 글자 수를 출력한다
# 00000101
# 11111111
# 8
```

| 쓰는 것 | 뜻 |
|---|---|
| `b` | 2진수(binary)로 바꾼다 |
| `08` | 빈 앞자리를 0 으로 채워 **8자리**를 만든다 |
| `int("25")` | 글자 `"25"` 를 숫자 25 로 (1과목) |

⚠ `"08b"` 를 따옴표 없이 `08b` 로 쓰면 `SyntaxError` 입니다. 글자로 넘겨야 합니다.

### 2.2 사설 IP 와 공인 IP

**여기 나오는 말**

- **사설 IP (private IP)** (프라이빗 아이피)
  - 회사 · 가정의 **내부망에서만** 쓰는 주소. 이 주소 그대로는 인터넷에서 통신하지 못합니다
  - 내부망에서만 쓰므로 다른 회사와 같은 주소를 써도 충돌하지 않습니다
  - 정해진 세 범위: `10.x.x.x` · `172.16~31.x.x` · `192.168.x.x`
  - 관제에서는 로그의 주소가 이 범위면 「내부망 장비」로 먼저 분류합니다
- **공인 IP (public IP)** (퍼블릭 아이피)
  - **인터넷 전체에서 하나뿐인** 주소. 통신사가 나눠 줍니다
  - 인터넷의 서버들은 이 주소로 서로를 찾습니다
  - 예: `8.8.8.8`(구글 DNS 서버)

| 사설 IP 범위 | 예 | 주의 |
|---|---|---|
| `10.0.0.0` ~ `10.255.255.255` | `10.0.0.8` | 첫 마디가 10 이면 전부 |
| `172.16.0.0` ~ `172.31.255.255` | `172.20.5.6` | ⚠ **둘째 마디가 16~31 일 때만.** `172.32.5.6` 은 공인 |
| `192.168.0.0` ~ `192.168.255.255` | `192.168.10.25` | 첫 두 마디가 192.168 |

- 세 범위는 인터넷 공통 약속입니다. 이 범위 밖은 **공인 IP** 입니다.
- 사설 IP 는 회사마다 겹쳐도 됩니다. 인터넷으로는 나가지 않기 때문입니다.
- **사설이면 안전, 공인이면 공격이라는 뜻은 아닙니다.** 안 · 밖을 가르는 첫 기준일 뿐입니다.

#### 🐍 문법 상자 · `and` · `or` · 범위 비교

```python
second = 20                # 변수 second 에 숫자 20 을 담는다
print(16 <= second <= 31)  # a <= x <= b 는 x 가 a 이상 b 이하일 때 True 가 된다. second 를 검사한 결과를 출력한다
# or 는 양쪽 조건 중 하나라도 True 이면 True 가 된다. second 가 10 이거나 20 인지 검사한 결과를 출력한다
print(second == 10 or second == 20)
# True
# True
```

| 쓰는 것 | 뜻 |
|---|---|
| `16 <= second <= 31` | 둘 사이에 있나 (양 끝 포함) |
| `A and B` | 둘 다 참이어야 참 |
| `A or B` | 하나만 참이어도 참 |

⚠ `first == 172` 만 보면 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">`172.32.5.6` 까지 사설로</mark> 잘못 판정합니다. 둘째 마디도 봐야 합니다.

### ✍️ 문제 2-3 · 사설 IP 판별기 (`private_ip.py`)

**할 일** — 주소가 사설 IP 인지 판별하는 함수 `is_private` 를 완성해 실행하고, `[공인]` 으로 나온 주소를 보고서에 적습니다.

**왜 중요한가** — 로그에 찍힌 주소가 사설인지 공인인지로 내부 PC 의 통신인지 외부에서 온 접속인지를 가릅니다. 관제에서 주소를 보면 가장 먼저 하는 판정입니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `private_ip.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 복사해 파일에 붙여 넣습니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 를 누릅니다.
   ```python
   # def 로 함수 is_private 를 만든다. IP 주소 글자 ip 가 사설 IP 이면 True, 아니면 False 를 리턴한다
   def is_private(ip):
       parts = ip.split(".")    # .split(".") 은 글자를 점에서 나눈 리스트를 리턴한다. 마디 네 개가 담긴 리스트를 parts 에 담는다
       first = int(parts[0])    # parts[0] 은 리스트의 첫째 값이다. int() 로 숫자로 바꿔 first 에 담는다
       second = int(parts[1])   # parts[1] 은 리스트의 둘째 값이다. int() 로 숫자로 바꿔 second 에 담는다
       # 1. first 가 10 이면 True 를 return 하세요

       # 2. first 가 172 이고 second 가 16 이상 31 이하이면 True 를 return 하세요

       # 3. first 가 192 이고 second 가 168 이면 True 를 return 하세요

       return False             # 앞의 if 세 개에서 리턴하지 않았으면 공인 IP 이므로 False 를 리턴한다

   # ── 미리 채워 둔 줄입니다. 고치지 않습니다 ──
   # for 변수 in 리스트: 는 리스트의 값을 앞에서부터 하나씩 변수에 담아 아래 줄을 반복한다.
   # 주소 여섯 개를 하나씩 ip 에 담는다
   for ip in ["10.0.0.8", "172.20.5.6", "172.32.5.6", "192.168.10.25", "8.8.8.8", "203.0.113.7"]:
       if is_private(ip):       # if 는 조건이 True 일 때만 아래 줄을 실행한다. is_private() 가 True 를 리턴하면 실행한다
           print("[사설]", ip)  # 사설 IP 일 때 [사설] 표시와 주소를 출력한다
       else:                    # else 는 위 if 의 조건이 False 일 때 아래 줄을 실행한다
           print("[공인]", ip)  # 공인 IP 일 때 [공인] 표시와 주소를 출력한다
   # ── 여기까지 ──
   ```
3. **[VS Code]** 번호 주석 아래를 채웁니다.

### 2.3 NAT — 사설 IP 를 공인 IP 로 변환

**여기 나오는 말**

- **NAT (Network Address Translation)** (나트 · 냇)
  - 내부망의 사설 IP 를 인터넷으로 보낼 때 **공인 IP 로 바꾸는 주소 변환**
  - 집 · 학원의 **공유기**가 이 일을 합니다 — 내부망 PC 가 보낸 패킷의 출발지 주소를 자기 공인 IP 로 바꿔 보내고, 응답이 오면 변환 기록을 보고 원래 PC 의 사설 IP 로 되돌려 전달합니다
  - 그래서 외부 서버의 로그에는 내 PC 의 사설 IP 가 아니라 **공유기의 공인 IP** 가 남습니다
  - 정적 · 동적 NAT 의 차이는 아래 표에서 **직접 찾아 씁니다**
- **PAT (Port Address Translation)** (팻)
  - 공인 IP **하나**를 내부망의 여러 PC 가 함께 쓰는 NAT
  - 연결마다 공인 IP 쪽 **포트 번호**를 다르게 붙이고, 응답이 오면 그 포트 번호로 어느 PC 의 연결인지 찾아 전달합니다
  - 집 · 학원 공유기는 대부분 이 방식입니다

공유기는 내부망 PC 가 인터넷과 통신할 때 **출발지 주소를 자기 공인 IP 로 바꿔** 보냅니다. 이것이 NAT 입니다.

> **검색해서 채웁니다.** 아래 질문을 한 번에 하나씩 검색합니다. 답은 오늘 보고서의 그 교시 `### 찾아본 것` 아래에 복사하지 말고 내 말로 적습니다. 다 적은 뒤 맨 아래 「정답」 표와 비교합니다.
> - 정적 NAT 은 사설 IP 와 공인 IP 를 어떻게 연결해 두나요?
> - 동적 NAT 은 정적 NAT 과 무엇이 다른가요?
> ⚠ 검색 결과는 영어 · 리눅스 화면이 많습니다. 내 화면(한국어 Windows)의 용어와 짝을 맞춰 읽습니다.

| 방식 | 바꾸는 법 |
|---|---|
| 정적 NAT | **[찾아 쓰기]** 사설 IP 와 공인 IP 를 어떻게 연결해 두나요? |
| 동적 NAT | **[찾아 쓰기]** 정적 NAT 과 무엇이 다른가요? |
| PAT | 공인 IP **하나**를 여러 PC 가 같이 쓰고, **포트 번호로** 누구 것인지 구별한다 — 집 · 학원 공유기가 대부분 이것 |

PAT 공유기는 「공인 IP 쪽 포트 40002번 = 내부망 `192.168.10.25:51234`」 같은 **변환표**를 가지고 있다가, 답이 오면 표를 보고 원래 PC 로 넘겨 줍니다.

### 왜 필요한가

1. 주소 두 개가 **같은 망**인지 알아야 통신이 어떤 장비를 거쳐 가는지 말할 수 있습니다.
2. 같은 망이면 스위치(같은 망 안의 장비들을 잇는 장비)가 바로 전달하고, 다른 망이면 **게이트웨이(라우터 · 망과 망을 잇는 장비)** 를 거칩니다. 방화벽(허용 · 차단 규칙으로 통신을 거르는 장비) 규칙도 이 경계로 씁니다.
3. 그 경계를 정하는 값이 `255.255.255.0` 같은 **서브넷 마스크**입니다.

### 3.1 서브넷 마스크 — 마디로 먼저 읽기

**여기 나오는 말**

- **서브넷 (subnet)**
  - 큰 망을 나눈 **작은 망** 하나
  - 같은 서브넷 안의 장비끼리는 공유기 · 라우터를 거치지 않고 바로 통신합니다
  - 회사는 부서마다 서브넷을 나눠, 부서끼리 오가는 통신을 따로 관리합니다
- **서브넷 마스크 (subnet mask)**
  - IP 주소에서 **어디까지가 같은 망**인지 정하는 값
  - `255` 인 마디는 **망 부분**, `0` 인 마디는 **장비 부분**입니다
  - 예: `255.255.255.0` 이면 앞 세 마디가 망 부분
- **CIDR (Classless Inter-Domain Routing)** (사이더)
  - 서브넷 마스크를 `/숫자` 로 짧게 쓰는 표기
  - `255` 마디 하나가 8 입니다
  - 예: `255.255.255.0` 은 8 × 3 = `/24`, `255.255.0.0` 은 8 × 2 = `/16`
- **호스트 (host)**
  - 망 안에서 주소를 받는 **장비 하나**
  - 예: PC · 서버 · 프린터 · 스마트폰

**마스크에서 `255` 인 마디까지가 망 부분입니다.** 그 마디가 모두 같은 주소끼리 같은 망입니다.

| 서브넷 마스크 | CIDR | 망 부분 | 같은 망인 예 | 다른 망인 예 |
|---|---|---|---|---|
| `255.255.255.0` | `/24` | 앞 세 마디 | `192.168.10.25` 와 `192.168.10.200` | `192.168.10.25` 와 `192.168.20.25` |
| `255.255.0.0` | `/16` | 앞 두 마디 | `192.168.10.25` 와 `192.168.20.25` | `192.168.10.25` 와 `172.16.10.25` |

- `192.168.10.25` 와 `192.168.20.25` 는 `/24` 에서는 다른 망, `/16` 에서는 같은 망입니다. 같은 망인지는 **주소가 아니라 마스크**가 정합니다.
- **학원망은 `/16`** 입니다 — 서브넷 마스크 `255.255.0.0`, 기본 게이트웨이 `192.168.1.1`. 앞 두 마디 `192.168` 이 같으면 같은 망입니다.
- **집 공유기는 보통 `/24`** 입니다 — 서브넷 마스크 `255.255.255.0`. 앞 세 마디가 같아야 같은 망입니다.

#### 🐍 문법 상자 · 마스크를 2진수로 — `format()` · `.count()`

2교시 2-2 처럼 마스크도 2진수로 펼칠 수 있습니다. **1 인 비트가 망 부분, 0 인 비트가 장비 부분**이고, CIDR 숫자는 1 의 개수입니다.

```python
print(format(255, "08b"))                     # format(숫자, "08b") 는 숫자를 8자리 2진수 글자로 바꿔 리턴한다. 255 를 2진수로 출력한다
print(format(0, "08b"))                       # 같은 방법으로 0 을 8자리 2진수 글자로 바꿔 출력한다
mask = "11111111.11111111.11111111.00000000"  # 255.255.255.0 을 32비트 2진수로 펼친 글자를 변수 mask 에 담는다
print(mask.count("1"))                        # .count("1") 은 글자 안에 "1" 이 몇 번 나오는지 리턴한다. 1 의 개수를 출력한다
# 11111111
# 00000000
# 24
```

| 쓰는 것 | 뜻 |
|---|---|
| `format(255, "08b")` | 255 를 8자리 2진수 글자로 — `11111111`. `255` 마디는 1 이 여덟 개 |
| `글자.count("1")` | 글자 안의 `"1"` 개수 — 마스크라면 CIDR 숫자 |

### 3.2 풀이 순서 — `192.168.10.25/24` 하나 풀어 보기

**여기 나오는 말**

- **네트워크 주소**
  - 그 망의 **첫 주소**
  - 장비 부분이 모두 `0` 입니다
  - 망 자체를 가리키는 주소라 장비에 주지 않습니다
  - 예: `192.168.10.0/24` 의 네트워크 주소는 `192.168.10.0`
- **브로드캐스트 주소 (broadcast)** (브로드캐스트)
  - 망 안의 **모든 장비에 한 번에** 보내는 주소
  - 그 망의 **마지막 주소**로, 장비 부분이 모두 `255` 입니다
  - 장비에 주지 않습니다
  - 예: `192.168.10.0/24` 의 브로드캐스트 주소는 `192.168.10.255`

주소 하나를 받으면 아래 네 단계로 풉니다.

1. **① 마스크** — `/24` 는 `255.255.255.0` 입니다(아래 3.3 표).
2. **② 망 부분** — `255` 가 앞 세 마디라 `192.168.10` 이 망 부분, 마지막 마디 `25` 가 장비 부분입니다.
3. **③ 네트워크 주소 · 브로드캐스트 주소** — 장비 부분을 `0` 으로 두면 네트워크 주소 `192.168.10.0`, `255` 로 두면 브로드캐스트 주소 `192.168.10.255` 입니다.
4. **④ 장비에 줄 수 있는 주소** — 그 둘을 뺀 `192.168.10.1` ~ `192.168.10.254`, 254개입니다. 기본 게이트웨이도 이 가운데 하나를 씁니다(보통 `.1`).

3-3 에서 내 주소를 같은 ① ~ ④ 순서로 풉니다. 학원망 `/16` 이면 ② 의 망 부분이 앞 두 마디가 되고, ③ 에서는 뒤 두 마디가 함께 `0` · `255` 가 됩니다.

주소 수는 계산하지 않고 이 표에서 찾습니다.

|---|---|---|---|
| `255.0.0.0` | `/8` | 16,777,216 | 16,777,214 |
| `255.255.0.0` | `/16` | 65,536 | 65,534 |
| `255.255.255.0` | `/24` | 256 | 254 |
| `255.255.255.128` | `/25` | 128 | 126 |
| `255.255.255.192` | `/26` | 64 | 62 |
| `255.255.255.224` | `/27` | 32 | 30 |
| `255.255.255.240` | `/28` | 16 | 14 |

- 쓸 수 있는 수는 주소 수에서 네트워크 주소 · 브로드캐스트 주소 2개를 뺀 수입니다.
- CIDR 숫자가 클수록 망이 작아집니다.
- `/25` ~ `/28` 은 넷째 마디 **중간**에서 망 부분과 장비 부분이 나뉘는 마스크입니다. 4교시 4.1 에서 다룹니다.

```python
# strict=False 를 주면 망의 첫 주소가 아닌 주소를 넣어도 그 주소가 속한 망을 리턴한다. 그 망을 net 에 담는다
net = ipaddress.ip_network("192.168.10.25/24", strict=False)
print(net)           # 망 객체를 출력하면 「네트워크 주소/CIDR」 꼴의 글자로 나온다
print(net.netmask)   # .netmask 는 그 망의 서브넷 마스크다. 마스크를 출력한다
# .network_address 는 망의 첫 주소, .broadcast_address 는 마지막 주소, .num_addresses 는 전체 주소 수다.
# 세 값을 한 줄에 출력한다
print(net.network_address, net.broadcast_address, net.num_addresses)
# 192.168.10.0/24
# 255.255.255.0
# 192.168.10.0 192.168.10.255 256
```

| 쓰는 것 | 뜻 |
|---|---|
| `ipaddress.ip_network("주소/CIDR", strict=False)` | 그 주소가 속한 **망**을 만든다. `strict=False` 는 「망의 첫 주소가 아니어도 받아 준다」 |
| `.netmask` | ① 서브넷 마스크 |
| `.network_address` · `.broadcast_address` | ③ 네트워크 주소(첫 주소) · 브로드캐스트 주소(마지막 주소) |

| `주소 + 1` · `주소 - 1` | 바로 다음 주소 · 바로 앞 주소 — ④ 의 첫 장비 주소 · 마지막 장비 주소 |

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">4교시 (12:00–12:50) · 서브네팅 — 부서마다 필요한 만큼 나누기</mark>

### 왜 필요한가

1. 회사가 `192.168.50.0/24`(주소 256개)를 받았습니다. 개발팀 · 운영팀 · 보안팀을 **다른 망**으로 나눠야 서로의 PC 에 함부로 닿지 않습니다.
2. 큰 망을 작은 망 여러 개로 나누는 일이 **서브네팅**입니다.
3. 아무렇게나 나누면 주소가 모자라거나 **두 부서가 같은 주소를 받는** 사고가 납니다. 그래서 3.3 표로 크기를 고르고, 코드로 검증합니다.

### 4.1 마디 중간에서 나뉘는 마스크 — `/26` 하나 풀어 보기

**여기 나오는 말**

- **서브네팅 (subnetting)** (서브네팅)
  - 큰 망을 **작은 망 여러 개로 나누는** 일
  - 부서마다 망을 따로 주면 부서 사이 통신을 나눠 관리할 수 있습니다
  - 예: `192.168.50.0/24` 를 `/26` 네 개로 나누기
- **블록**
  - 큰 망을 나눈 **작은 망 하나**
  - 블록의 첫 주소가 네트워크 주소, 마지막 주소가 브로드캐스트 주소입니다
  - 예: `192.168.50.64/26` 은 `.64` 부터 `.127` 까지인 블록

3교시의 `/24` · `/16` 은 `255` 인 마디까지가 망 부분이었습니다. 3.3 표의 `/25` ~ `/28` 은 넷째 마디 **안에서** 망 부분과 장비 부분이 나뉩니다. 이때는 넷째 마디를 **3.3 표의 주소 수만큼씩** 끊어 읽습니다.

`192.168.50.0/24` 를 `/26` 네 개로 나누는 것을 아래 네 단계로 풉니다.

1. **① 주소 수** — 3.3 표의 `/26` 줄에서 주소 수 64, 쓸 수 있는 수 62 를 읽습니다.
2. **② 블록 수** — `/24` 의 주소 256개를 64개씩 끊으면 256 ÷ 64 = 4개입니다.
3. **③ 시작 주소** — 0 에서 시작해 64 씩 더하면 `.0` · `.64` · `.128` · `.192` 입니다.
4. **④ 블록마다 범위** — 시작 주소가 네트워크 주소이고, 다음 블록 시작 주소의 바로 앞이 브로드캐스트 주소입니다. 그 둘 사이가 장비에 줄 수 있는 주소입니다.

| 블록 | 네트워크 주소 | 브로드캐스트 주소 | 장비에 줄 수 있는 주소 | 쓸 수 있는 수 |
|---|---|---|---|---|
| `192.168.50.0/26` | `.0` | `.63` | `.1` ~ `.62` | 62 |
| `192.168.50.64/26` | `.64` | `.127` | `.65` ~ `.126` | 62 |
| `192.168.50.128/26` | `.128` | `.191` | `.129` ~ `.190` | 62 |
| `192.168.50.192/26` | `.192` | `.255` | `.193` ~ `.254` | 62 |

- 블록은 쓸 수 있는 수 62 가 아니라 **주소 수 64** 로 끊습니다.
- 그래서 `/26` 에서는 `192.168.50.70` 과 `192.168.50.130` 이 앞 세 마디가 같아도 **다른 망**입니다. `.70` 은 `.64` 블록에, `.130` 은 `.128` 블록에 있습니다.
- `/27` 은 32 씩, `/28` 은 16 씩 같은 순서로 끊습니다. 끊는 단위는 3.3 표의 주소 수입니다.
- 2진수로 보면 `/26` 마스크의 넷째 마디 `192` 는 `11000000` 입니다. 앞 2비트가 망 부분, 뒤 6비트가 장비 부분입니다.

#### 🐍 문법 상자 · `.subnets()` — 망을 같은 크기로 나누기

```python
import ipaddress                                  # import 로 파이썬에 들어 있는 IP 계산 모듈 ipaddress 를 불러온다
parent = ipaddress.ip_network("192.168.50.0/24")  # 나눌 전체 망 192.168.50.0/24 를 망 객체로 바꿔 parent 에 담는다
# .subnets(new_prefix=25) 는 망을 /25 크기로 나눈 작은 망을 앞에서부터 하나씩 리턴한다. 그 망을 sub 에 담아 반복한다
for sub in parent.subnets(new_prefix=25):
    print(sub)                                    # 나눈 작은 망을 「네트워크 주소/CIDR」 꼴로 출력한다
# 192.168.50.0/25
# 192.168.50.128/25
```

| 쓰는 것 | 뜻 |
|---|---|
| `망.subnets(new_prefix=25)` | 그 망을 `/25` 크기 블록으로 나눠 앞에서부터 하나씩 꺼낸다 |

- `/25` 는 주소 수가 128 이라 256 ÷ 128 = 2개, `.0` 과 `.128` 에서 시작합니다.

### 4.2 FLSM · VLSM — 같은 크기로 나눌까, 필요한 크기로 나눌까

**여기 나오는 말**

- **FLSM (Fixed Length Subnet Mask)** (에프엘에스엠)
  - 모든 부서에 **같은 크기**의 망을 주는 방식
  - 예: `/24` 를 `/26` 네 개로 나눠 부서마다 하나씩
- **VLSM (Variable Length Subnet Mask)** (브이엘에스엠)
  - 부서마다 **필요한 크기**의 망을 주는 방식
  - 주소를 아낄 수 있어 실무에서 많이 씁니다
  - 예: 개발팀은 `/26`, 보안팀은 `/28`

| | FLSM | VLSM |
|---|---|---|
| 크기 | **모든** 부서에 같은 크기 | 부서마다 **필요한 크기** |
| 장점 | 나누는 법이 단순하다 | 주소를 아낀다 |
| 단점 | 사람이 적은 부서에 빈 주소가 많이 남는다 | 크기를 고르고 겹침을 검증해야 한다 |

**VLSM 은 이 순서로 나눕니다.** 예: 개발팀 50대 · 운영팀 25대 · 보안팀 10대

1. **① 큰 부서부터 줄 세우기** — 개발팀 50 → 운영팀 25 → 보안팀 10.
2. **② 3.3 표에서 CIDR 고르기** — 「쓸 수 있는 수」가 장비 수 이상인 줄 가운데 **가장 작은 망**을 고릅니다. 개발팀 `/26`(62) · 운영팀 `/27`(30) · 보안팀 `/28`(14).
3. **③ 앞에서부터 이어 붙이기** — 개발팀 `.0` ~ `.63`, 그 바로 다음 운영팀 `.64` ~ `.95`, 그다음 보안팀 `.96` ~ `.111`.
4. **④ 검증** — 부서마다 주소가 충분한지, 서로 겹치지 않는지 확인합니다(4.3).

```
192.168.50.0/24
  0 ─────────── 63 │ 64 ──── 95 │ 96 ─ 111 │ 112 ───────────────── 255
  개발팀 /26 (62대) │ 운영팀 /27  │ 보안팀 /28 │ 남는 공간 (다음 부서용)
```

- 큰 블록부터 놓는 이유: `/26` 은 `.0` · `.64` · `.128` · `.192` 에서만 시작할 수 있습니다. 작은 블록을 먼저 여기저기 놓으면 큰 블록이 들어갈 자리가 없어집니다.

### ✍️ 문제 4-3 · 같은 크기로 나누기 — FLSM (`flsm.py`)

**할 일** — 다 짜인 코드를 실행해 `/26` 네 블록의 범위와 쓸 수 있는 수를 읽고, 부서 장비 수와 비교해 남는 주소를 보고서에 적습니다.

**왜 중요한가** — 모든 부서에 같은 크기를 주면 빈 주소가 얼마나 남는지 숫자로 확인합니다. 이 남는 주소가 4.2 에서 VLSM 을 쓰는 이유입니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `flsm.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 복사해 파일에 붙여 넣습니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 를 누릅니다. 고칠 곳은 없습니다.
   ```python
   import ipaddress                                  # import 로 파이썬에 들어 있는 IP 계산 모듈 ipaddress 를 불러온다

   parent = ipaddress.ip_network("192.168.50.0/24")  # 나눌 전체 망 192.168.50.0/24 를 망 객체로 바꿔 parent 에 담는다
   # .subnets(new_prefix=26) 은 /26 크기로 나눈 망을 앞에서부터 하나씩 리턴한다. 그 망을 sub 에 담아 반복한다
   for sub in parent.subnets(new_prefix=26):
       first = sub.network_address + 1               # 네트워크 주소에 1 을 더해 장비에 줄 수 있는 첫 주소를 first 에 담는다

       usable = sub.num_addresses - 2                # 전체 주소 수에서 2 를 빼 쓸 수 있는 수를 usable 에 담는다
       # f-string 은 {} 안의 변수 값을 글자에 넣는다. 블록 · 장비 주소 범위 · 쓸 수 있는 수를 한 줄에 출력한다
       print(f"{sub} 범위 {first} ~ {last} 쓸 수 있는 수 {usable}")
   ```

### 4.3 설계 검증 — 용량과 겹침

**여기 나오는 말**

- **겹침 (overlap)** (오버랩)
  - 두 망이 **같은 주소를 함께 가진** 상태
  - 겹치면 그 주소로 가는 패킷이 어느 망으로 가야 할지 정할 수 없어 통신이 꼬입니다
  - 설계에서 생기면 안 됩니다

설계표를 만들면 두 가지를 검증합니다.

| 검증 | 묻는 것 | 틀리면 생기는 일 |
|---|---|---|
| 용량 | 쓸 수 있는 수 ≥ 필요한 장비 수인가 | 장비에 줄 주소가 모자란다 |
| 겹침 | 두 부서의 망이 같은 주소를 갖지 않는가 | 같은 주소를 두 부서 장비가 받아 **주소 충돌**로 통신이 끊긴다. 방화벽 규칙이 다른 부서까지 덮고, 로그의 주소로 어느 장비인지 가릴 수 없다 |

#### 🐍 문법 상자 · `.overlaps()` — 두 망이 겹치나

```python
import ipaddress                              # import 로 파이썬에 들어 있는 IP 계산 모듈 ipaddress 를 불러온다
a = ipaddress.ip_network("192.168.50.0/26")   # 192.168.50.0/26 망 객체를 a 에 담는다. 이 망은 .0 부터 .63 까지다
b = ipaddress.ip_network("192.168.50.32/27")  # 192.168.50.32/27 망 객체를 b 에 담는다. 이 망은 .32 부터 .63 까지다
c = ipaddress.ip_network("192.168.50.64/27")  # 192.168.50.64/27 망 객체를 c 에 담는다. 이 망은 .64 부터 .95 까지다
print(a.overlaps(b))                          # .overlaps() 는 두 망이 주소를 하나라도 같이 쓰면 True 를 리턴한다. a 와 b 의 결과를 출력한다
print(a.overlaps(c))                          # 같은 방법으로 a 와 c 가 주소를 하나라도 같이 쓰는지 출력한다
# True
# False
```

| 쓰는 것 | 뜻 |
|---|---|
| `망.overlaps(다른 망)` | 주소가 **하나라도 겹치면** `True`, 하나도 안 겹치면 `False` |

- `a` 와 `b` 는 `.32` ~ `.63` 을 함께 가져 `True` 입니다. `a` 는 `.63` 에서 끝나고 `c` 는 `.64` 에서 시작해 `False` 입니다.

### ✍️ 문제 4-4 · 설계 검증 — 용량과 겹침 (`plan_check.py`)

**할 일** — 다 짜인 검증 코드를 실행해 4.2 의 VLSM 설계가 충분한지 · 겹치지 않는지 읽고, 보안팀 줄 하나만 겹치는 주소로 바꿔 다시 실행해 결과를 보고서에 적습니다.

**왜 중요한가** — 부서 망이 모자라거나 겹치면 주소 충돌로 통신이 끊기고, 방화벽 규칙이 엉뚱한 부서까지 덮습니다. 오후 7-2 에서 서버망을 더할 때도 같은 `.overlaps()` 검증을 씁니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `plan_check.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 복사해 파일에 붙여 넣습니다. 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 를 누릅니다.
   ```python
   import ipaddress                         # import 로 파이썬에 들어 있는 IP 계산 모듈 ipaddress 를 불러온다

   plan = [                                 # 리스트 plan 에 (부서, CIDR, 필요한 장비 수) 튜플을 담는다
       ("개발팀", "192.168.50.0/26", 50),   # 튜플 하나는 (부서, CIDR, 필요한 장비 수) 순서로 값을 묶는다
       ("운영팀", "192.168.50.64/27", 25),  # 같은 순서로 묶은 운영팀 튜플이다
       ("보안팀", "192.168.50.96/28", 10),  # 같은 순서로 묶은 보안팀 튜플이다
   ]                                        # 리스트를 닫는다
   networks = []                            # 겹침 검사에 쓸 망 객체를 모을 빈 리스트를 만든다

   for name, cidr, required in plan:        # plan 의 튜플을 하나씩 꺼내 name · cidr · required 세 변수에 나눠 담아 반복한다
       net = ipaddress.ip_network(cidr)     # 글자 cidr 를 망 객체로 바꿔 net 에 담는다
       # 쓸 수 있는 수(전체 주소 수 − 2)가 필요한 장비 수 이상이면 True, 아니면 False 를 ok 에 담는다
       ok = net.num_addresses - 2 >= required
       print(name, cidr, "충분:", ok)       # 부서 · CIDR · 용량 판정 결과를 한 줄에 출력한다
       networks.append(net)                 # .append() 는 리스트 끝에 값을 하나 더한다. 겹침 검사에 쓰도록 net 을 networks 에 더한다

   # 부서 세 개를 두 개씩 짝지은 세 쌍(0-1 · 1-2 · 0-2)을 .overlaps() 로 검사하고 or 로 묶는다.
   # 하나라도 True 이면 overlap 에 True 가 담긴다
   overlap = networks[0].overlaps(networks[1]) or networks[1].overlaps(networks[2]) or networks[0].overlaps(networks[2])
   print("겹침 있음:", overlap)             # 겹침 판정 결과를 출력한다
   ```
3. **[터미널]** 실행합니다. 터미널의 줄 위에 `…/network_zt` 가 보여야 합니다. 아니면 먼저 `cd network_zt` 를 입력합니다.
   ```bash
   python plan_check.py
   ```
   맥북: `python3 plan_check.py`
4. **[터미널]** 출력 네 줄에서 세 부서의 `충분:` 과 마지막 줄의 `겹침 있음:` 을 읽습니다.
5. **[VS Code]** 보안팀 줄의 `"192.168.50.96/28"` 을 `"192.168.50.32/28"` 로 **한 곳만** 바꿉니다. `.32` ~ `.47` 은 개발팀 블록(`.0` ~ `.63`) 안의 주소입니다.

7. **[보고서]** `day02_subnet_design.md`의 `## 4교시` › `### 문제 4-4` 아래를 채웁니다.
   - 바꾸기 전 출력 네 줄 · 바꾼 뒤 달라진 줄:
   - 🔍 두 부서의 망이 겹치면 어떤 문제가 생기나요?

### 정답 · 2.3 NAT 표

| 방식 | 바꾸는 법 |
|---|---|
| 정적 NAT | 사설 IP 하나 ↔ 공인 IP 하나를 **고정**해 짝지어 둔다 — 인터넷에서 내부망 서버로 접속하게 할 때 쓴다 |
| 동적 NAT | 공인 IP 여러 개 가운데 사용하지 않는 것을 통신할 때마다 **그때그때** 하나 배정한다 — 짝이 고정되지 않는다 |
| PAT | 공인 IP **하나**를 여러 PC 가 같이 쓰고, **포트 번호로** 누구 것인지 구별한다 — 집 · 학원 공유기가 대부분 이것 |

### 정답 2-1

**결과** — `11000000` · `00001010` · `16`

**왜** — 192 = 128 + 64 라 앞 두 자리만 1 이고, 10 = 8 + 2 라 `00001010` 입니다. 8비트 두 개를 이어 붙여 16자리입니다.

**자주 틀리는 곳** — 10 을 `1010` 네 자리로 적는 것입니다. `08` 이 빈 앞자리를 0 으로 채워 8자리를 만듭니다.

**관제에서는** — 마스크 · 망 경계 계산이 모두 이 8비트 단위로 이루어지므로, 2진수로 펼칠 줄 알아야 경계를 검산할 수 있습니다.

### 정답 2-2

```python
def to_bits(ip):                  # def 로 함수 to_bits 를 만든다. IP 주소 글자 ip 를 받아 32비트 2진수 글자를 리턴한다
    bits = ""                     # 2진수 글자를 이어 붙일 변수 bits 를 빈 글자로 시작한다
    for part in ip.split("."):    # .split(".") 은 글자를 점에서 나눈 리스트를 리턴한다. 마디를 하나씩 part 에 담아 반복한다
        # 1. bits 뒤에 format(int(part), "08b") 를 이어 붙이세요
        # int() 로 마디 글자를 숫자로 바꾸고, format() 으로 8자리 2진수 글자로 바꿔 bits 뒤에 이어 붙인다
        bits = bits + format(int(part), "08b")
    return bits                   # 32비트 2진수 글자가 된 bits 를 리턴한다

ip = "192.168.10.25"              # 변수 ip 에 IPv4 주소 글자를 담는다. 내 IPv4 주소로 바꿔 실행한다
print(ip)                         # 원래 IP 주소 글자를 출력한다
print(to_bits(ip))                # to_bits() 를 불러 리턴한 32비트 2진수 글자를 출력한다
print("길이:", len(to_bits(ip)))  # len() 은 글자 수를 리턴한다. 2진수 글자의 글자 수를 출력해 32자리가 맞는지 확인한다
```

💻 **터미널에 입력합니다.** `python ip_bits.py`

**결과** — `11000000101010000000101000011001` 과 `길이: 32`

**왜** — 마디 네 개를 `format(int(part), "08b")` 로 8비트씩 바꿔 이어 붙이므로 8 × 4 = 32자리가 됩니다.

**자주 틀리는 곳** — `"b"` 만 써서 `10` 이 `1010` 네 자리가 되면 길이가 32 보다 짧게 나옵니다.

**관제에서는** — 주소를 32비트로 펼쳐 봐야 마스크가 어디서 망과 장비를 가르는지 확인할 수 있습니다.

### 정답 2-3

```python
# def 로 함수 is_private 를 만든다. IP 주소 글자 ip 가 사설 IP 이면 True, 아니면 False 를 리턴한다
def is_private(ip):
    parts = ip.split(".")    # .split(".") 은 글자를 점에서 나눈 리스트를 리턴한다. 마디 네 개가 담긴 리스트를 parts 에 담는다
    first = int(parts[0])    # parts[0] 은 리스트의 첫째 값이다. int() 로 숫자로 바꿔 first 에 담는다
    second = int(parts[1])   # parts[1] 은 리스트의 둘째 값이다. int() 로 숫자로 바꿔 second 에 담는다
    # 1. first 가 10 이면 True 를 return 하세요
    if first == 10:          # 첫 마디가 10 이면 10.0.0.0/8 사설 대역이다
        return True          # True 를 리턴하고 함수를 끝낸다
    # 2. first 가 172 이고 second 가 16 이상 31 이하이면 True 를 return 하세요
    # and 는 양쪽 조건이 모두 True 일 때만 True 가 된다. 172.16 ~ 172.31 로 시작하면 172.16.0.0/12 사설 대역이다
    if first == 172 and 16 <= second <= 31:
        return True          # True 를 리턴하고 함수를 끝낸다
    # 3. first 가 192 이고 second 가 168 이면 True 를 return 하세요
    # 192.168 로 시작하면 192.168.0.0/16 사설 대역이다
    if first == 192 and second == 168:
        return True          # True 를 리턴하고 함수를 끝낸다
    return False             # 앞의 if 세 개에서 리턴하지 않았으면 공인 IP 이므로 False 를 리턴한다

# for 변수 in 리스트: 는 리스트의 값을 앞에서부터 하나씩 변수에 담아 아래 줄을 반복한다.
# 주소 여섯 개를 하나씩 ip 에 담는다
for ip in ["10.0.0.8", "172.20.5.6", "172.32.5.6", "192.168.10.25", "8.8.8.8", "203.0.113.7"]:
    if is_private(ip):       # if 는 조건이 True 일 때만 아래 줄을 실행한다. is_private() 가 True 를 리턴하면 실행한다
        print("[사설]", ip)  # 사설 IP 일 때 [사설] 표시와 주소를 출력한다
    else:                    # else 는 위 if 의 조건이 False 일 때 아래 줄을 실행한다
        print("[공인]", ip)  # 공인 IP 일 때 [공인] 표시와 주소를 출력한다
```

💻 **터미널에 입력합니다.** `python private_ip.py`

**결과** — `[사설] 10.0.0.8` · `[사설] 172.20.5.6` · `[공인] 172.32.5.6` · `[사설] 192.168.10.25` · `[공인] 8.8.8.8` · `[공인] 203.0.113.7`

**왜** — 사설 범위는 `10.x` · `172.16~31.x` · `192.168.x` 세 개뿐이라, 172 는 둘째 마디까지 `16 <= second <= 31` 로 봅니다.

**자주 틀리는 곳** — `first == 172` 만 보고 `172.32.5.6` 을 사설로 판정하는 것입니다. 172.32 부터는 공인입니다.

**관제에서는** — 로그의 출발지 주소를 이 함수로 먼저 나눠 외부망에서 온 접속부터 살펴봅니다.

```
① 서브넷 마스크: 255.255.0.0
③ 네트워크 주소: 192.168.0.0
③ 브로드캐스트 주소: 192.168.255.255
```

**관제에서는** — 이 범위가 내 PC 와 같은 망이라, 범위 안 주소에서 온 접속은 게이트웨이를 거치지 않은 같은 망 내부 통신입니다.

### 정답 3-4

```python
# def 로 함수 same_net_24 를 만든다. 주소 글자 두 개를 받아 /24 에서 같은 망인지를 True · False 로 리턴한다
def same_net_24(ip1, ip2):
    parts1 = ip1.split(".")            # 첫째 주소를 점에서 나눈 네 마디 리스트를 parts1 에 담는다
    parts2 = ip2.split(".")            # 둘째 주소를 점에서 나눈 네 마디 리스트를 parts2 에 담는다
    # 1. parts1 과 parts2 의 앞 세 마디가 같은지를 return 하세요
    # [:3] 으로 두 리스트의 앞 세 마디를 꺼내고, == 로 비교한 True · False 를 리턴한다
    return parts1[:3] == parts2[:3]

my_ip = "192.168.10.25"                       # 기준이 되는 PC 주소 글자를 변수 my_ip 에 담는다
# for 로 비교할 주소 세 개를 하나씩 other 에 담아 아래 줄을 반복한다
for other in ["192.168.10.1", "192.168.10.200", "192.168.20.25"]:
    print(other, same_net_24(my_ip, other))  # 비교한 주소와 함수가 리턴한 판정을 한 줄에 출력한다
```

💻 **터미널에 입력합니다.** `python same_network.py`

**결과** — `192.168.10.1 True` · `192.168.10.200 True` · `192.168.20.25 False`

**왜** — `/24` 는 앞 세 마디가 망 부분입니다. `.1` · `.200` 은 앞 세 마디가 `192.168.10` 으로 같고, `192.168.20.25` 는 셋째 마디가 `20` 으로 달라 다른 망입니다. 다른 망으로 보낼 때는 기본 게이트웨이(라우터)를 거칩니다.

**자주 틀리는 곳** — 마지막 마디 `25` 가 같으니 `192.168.20.25` 도 같은 망이라고 답하는 것입니다. 비교하는 것은 앞 세 마디이고, 마지막 마디는 장비 부분입니다.

**관제에서는** — `192.168.20.25` 와의 통신은 게이트웨이를 거치므로 그 사이 방화벽 로그에 남는지 확인할 수 있습니다.

### 정답 4-1

**결과** — `192.168.50.0/26` · `192.168.50.64/26` · `192.168.50.128/26` · `192.168.50.192/26` 네 줄

**왜** — `/24`(256개)를 `/26`(64개)로 나누면 256 ÷ 64 = 4개이고, 0 에서 시작해 64 씩 더하므로 각 망은 `.0` · `.64` · `.128` · `.192` 에서 시작합니다(4.1 의 ② · ③).

**자주 틀리는 곳** — 장비에 쓸 수 있는 62 로 끊어 `.62` · `.124` … 에서 시작한다고 적는 것입니다. 블록은 주소 수 64 로 끊습니다.

**관제에서는** — 주소 하나를 보고 `.0` · `.64` · `.128` · `.192` 중 어느 블록인지 알면 어느 부서 망에서 왔는지 바로 가립니다.

### 정답 4-2

**결과** — 50대 `/26` · 25대 `/27` · 10대 `/28` · 63대 `/25`

**왜** — 3.3 표를 맨 아래부터 올라가며 「쓸 수 있는 수」가 장비 수 이상이 처음 되는 줄을 고릅니다. 50 은 `/27`(30)로 모자라고 `/26`(62)에서 처음 들어갑니다. 25 는 `/28`(14)로 모자라고 `/27`(30), 10 은 `/28`(14)에서 들어갑니다. 63 은 `/26` 의 62 로 모자라 `/25`(126)입니다. 63대일 때 `/26` 이 안 되는 이유는 64개 가운데 네트워크 주소 · 브로드캐스트 주소 2개는 장비에 줄 수 없어 실제로는 62대까지만 들어가기 때문입니다.

**자주 틀리는 곳** — 「주소 수」 열로 골라 63대에 `/26` 을 적는 것입니다. 2개를 뺀 「쓸 수 있는 수」로 비교합니다.

**관제에서는** — 부서 망이 필요보다 크면 쓰지 않는 주소가 남아, 허가 없이 꽂은 장비가 그 주소를 받기 쉬워집니다.

### 정답 4-3

코드는 문제의 코드 그대로입니다. 고칠 곳이 없습니다.

💻 **터미널에 입력합니다.** `python flsm.py`

**결과**

```
192.168.50.0/26 범위 192.168.50.1 ~ 192.168.50.62 쓸 수 있는 수 62
192.168.50.64/26 범위 192.168.50.65 ~ 192.168.50.126 쓸 수 있는 수 62
192.168.50.128/26 범위 192.168.50.129 ~ 192.168.50.190 쓸 수 있는 수 62
192.168.50.192/26 범위 192.168.50.193 ~ 192.168.50.254 쓸 수 있는 수 62
```

남는 주소 — 개발팀 62 − 50 = 12개 · 운영팀 62 − 25 = 37개 · 보안팀 62 − 10 = 52개. 넷째 블록은 줄 부서가 없어 62개가 통째로 비어 있습니다.

**왜** — FLSM 은 모든 블록이 같은 `/26` 이라 쓸 수 있는 수가 모두 62 입니다. 장비가 적은 부서일수록 남는 주소가 많아집니다. 이것이 4.2 표의 FLSM 단점이고, VLSM 으로 부서마다 크기를 고르는 이유입니다.

**자주 틀리는 곳** — 주소 수 64 에서 빼서 14 · 39 · 54 로 적는 것입니다. 장비에 줄 수 있는 것은 62개입니다.

**관제에서는** — 같은 크기로 나눈 망은 경계가 `.0` · `.64` · `.128` · `.192` 로 일정해, 로그 주소만 보고 어느 부서인지 쉽게 가립니다.

### 정답 4-4

코드는 문제의 코드 그대로입니다. 5단계에서 보안팀 줄 한 곳만 바꿉니다.

💻 **터미널에 입력합니다.** `python plan_check.py`

**결과** — 바꾸기 전

```
개발팀 192.168.50.0/26 충분: True
운영팀 192.168.50.64/27 충분: True
보안팀 192.168.50.96/28 충분: True
겹침 있음: False
```

보안팀을 `192.168.50.32/28` 로 바꾼 뒤

```
개발팀 192.168.50.0/26 충분: True
운영팀 192.168.50.64/27 충분: True
보안팀 192.168.50.32/28 충분: True
겹침 있음: True
```

**왜** — 처음 설계는 쓸 수 있는 수가 62 ≥ 50 · 30 ≥ 25 · 14 ≥ 10 이라 모두 충분하고, `.0` ~ `.63` · `.64` ~ `.95` · `.96` ~ `.111` 로 이어져 겹치지 않습니다. 바꾼 보안팀 `.32` ~ `.47` 은 개발팀 `.0` ~ `.63` 안에 들어가므로 `networks[0].overlaps(networks[2])` 가 `True` 가 됩니다. 크기는 그대로라 `충분:` 은 바뀌지 않습니다. 두 부서 망이 겹치면 같은 주소를 두 부서 장비가 받아 주소 충돌로 통신이 끊기고, 방화벽 규칙이 다른 부서까지 덮으며, 로그의 주소로 어느 장비인지 가릴 수 없습니다.

**자주 틀리는 곳** — `충분: True` 만 보고 설계가 맞다고 보는 것입니다. 용량이 충분해도 겹칠 수 있어서 두 검증을 모두 봅니다.

**관제에서는** — 두 부서 망이 겹치면 같은 주소를 두 PC 가 받을 수 있어, 로그 주소로 장비를 특정할 수 없게 됩니다.

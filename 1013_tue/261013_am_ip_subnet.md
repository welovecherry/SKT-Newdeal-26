# 10/13(화) 오전 · IP 주소 · 사설 주소 · 서브넷 · 서브네팅 — 실습

어제 `ipconfig`(아이피컨피그 · 내 PC 의 네트워크 설정을 보는 명령)에서 `192.168.0.15` 와 `255.255.255.0` 을 봤습니다. 내 주소도 옆 사람 주소도 `192.168` 로 시작했습니다. 오늘 오전에는 그 숫자들의 정체 — **IP 주소의 구조**, **내부 주소와 외부 주소**, **어디까지가 같은 망인지 정하는 서브넷**을 배우고, 회사 부서마다 주소를 나눠 주는 **설계**까지 해 봅니다.

| 교시 | 무엇 | 쓰는 것 |
|---|---|---|
| 2교시 | IP 주소를 32칸으로 펼치기 · 사설 IP 와 공인 IP · NAT(냇) | 파이썬 · `curl`(컬 · 터미널에서 웹 요청을 보내는 도구) |
| 3교시 | 서브넷 마스크 · CIDR(사이더) · 같은 망인지 판정 | `ipconfig` · 파이썬 `ipaddress` |
| 4교시 | 서브네팅 — 부서마다 필요한 만큼 주소 나누기 | 파이썬 `ipaddress` |

**오전에 남기는 것:** `network_zt/day02_subnet_design.md` 의 **2 · 3 · 4교시 칸**. 오후에 라우팅(routing · 다른 망으로 가는 경로를 고르는 일) · VLAN(브이랜 · 스위치 하나를 여러 망으로 나누기)을 더해 완성합니다 — 강의계획서의 2일 차 산출물입니다.

2. 그 기준이 **사설 IP**(회사 · 집 안에서만 쓰는 주소)와 **공인 IP**(인터넷 전체에서 하나뿐인 주소)입니다.
3. 안의 주소는 밖으로 나갈 때 **NAT**(냇 · 주소 바꾸기)로 공인 주소로 바뀝니다. 그래서 로그에 찍힌 주소가 실제 PC 의 주소와 다를 수 있습니다.

### 2.1 IP 주소는 0과 1 서른두 칸

**여기 나오는 말**

- **비트 (bit)** — 0 또는 1 이 들어가는 **한 칸**. IPv4 주소는 32비트, 마디 하나는 8비트
- **2진수** (이진수) — 0 과 1 두 글자로만 쓰는 수 — `192` 는 `11000000`

`192.168.10.25` 는 사람이 읽는 모양입니다. 컴퓨터는 점으로 나뉜 **마디 네 개**를 각각 **0과 1 여덟 칸**(8비트)으로 읽습니다. 그래서 IPv4(아이피 브이포) 주소는 모두 **32비트**입니다.

| 마디 | 10진수(평소 쓰는 수) | 2진수(0과 1 로만 쓰는 수 · 8칸) |
|---|---|---|
| 1 | 192 | `11000000` |
| 2 | 168 | `10101000` |
| 3 | 10 | `00001010` |
| 4 | 25 | `00011001` |

여덟 칸이 전부 1 이면 `11111111` = 255 입니다. 그래서 한 마디에는 **0~255** 만 들어갑니다(256가지).

#### 🐍 문법 상자 · `format(숫자, "08b")` — 2진수 여덟 칸으로

```python
print(format(5, "08b"))
print(format(255, "08b"))
print(len(format(25, "08b")))
# 00000101
# 11111111
# 8
```

| 쓰는 것 | 뜻 |
|---|---|
| `b` | 2진수(binary)로 바꾼다 |
| `08` | 빈 앞자리를 0 으로 채워 **여덟 칸**을 만든다 |
| `int("25")` | 글자 `"25"` 를 숫자 25 로 (1과목) |

⚠ `"08b"` 를 따옴표 없이 `08b` 로 쓰면 `SyntaxError` 입니다. 글자로 넘겨야 합니다.

### 2.2 사설 IP 와 공인 IP

**여기 나오는 말**

- **사설 IP (private IP)** (프라이빗 아이피) — 회사 · 집 **안에서만** 쓰는 주소. 다른 회사와 겹쳐도 된다 — `192.168.x.x` · `10.x.x.x` · `172.16~31.x.x`
- **공인 IP (public IP)** (퍼블릭 아이피) — **인터넷 전체에서 하나뿐인** 주소 — `8.8.8.8`

| 사설 IP 범위 | 예 | 주의 |
|---|---|---|
| `10.0.0.0` ~ `10.255.255.255` | `10.0.0.8` | 첫 마디가 10 이면 전부 |
| `172.16.0.0` ~ `172.31.255.255` | `172.20.5.6` | ⚠ **둘째 마디가 16~31 일 때만.** `172.32.5.6` 은 공인 |
| `192.168.0.0` ~ `192.168.255.255` | `192.168.10.25` | 첫 두 마디가 192.168 |

- 세 범위는 인터넷 공통 약속입니다. 이 범위 밖은 **공인 IP** 입니다.
- 사설 IP 는 회사마다 겹쳐도 됩니다. 인터넷으로는 나가지 않기 때문입니다.
- **사설이면 안전, 공인이면 공격이라는 뜻은 아닙니다.** 안 · 밖을 가르는 첫 기준일 뿐입니다.

#### 🐍 문법 상자 · `and` · `or` · 범위 비교

```python
second = 20
print(16 <= second <= 31)          # True — 16 이상 31 이하
print(second == 10 or second == 20)
# True
# True
```

| 쓰는 것 | 뜻 |
|---|---|
| `16 <= second <= 31` | 둘 사이에 있나 (양 끝 포함) |
| `A and B` | 둘 다 참이어야 참 |
| `A or B` | 하나만 참이어도 참 |

⚠ `first == 172` 만 보면 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">`172.32.5.6` 까지 사설로</mark> 잘못 판정합니다. 둘째 마디도 봐야 합니다.

### 2.3 NAT — 안의 주소를 밖의 주소로

**여기 나오는 말**

- **NAT (Network Address Translation)** (나트 · 냇) — 안의 사설 IP 를 밖으로 나갈 때 **공인 IP 로 바꾸는 일**. 공유기가 한다. 정적 · 동적 NAT 의 차이는 아래 표에서 **직접 찾아 씁니다**
- **PAT (Port Address Translation)** (팻) — 공인 IP **하나**를 여러 PC 가 같이 쓰고 **포트 번호로** 누구 것인지 구별하는 NAT

공유기는 안의 PC 가 인터넷으로 나갈 때 **출발지 주소를 자기 공인 IP 로 바꿔** 보냅니다. 이것이 NAT 입니다.

> **검색해서 채웁니다.** 아래 질문을 한 번에 하나씩 검색합니다. 답은 오늘 보고서의 그 교시 `### 찾아본 것` 아래에 복사하지 말고 내 말로 적습니다. 다 적은 뒤 맨 아래 「정답」 표와 비교합니다.
> - 정적 NAT 은 안의 주소와 공인 주소를 어떻게 짝짓나요?
> - 동적 NAT 은 정적 NAT 과 무엇이 다른가요?
> ⚠ 검색 결과는 영어 · 리눅스 화면이 많습니다. 내 화면(한국어 Windows)의 용어와 짝을 맞춰 읽습니다.

| 방식 | 바꾸는 법 |
|---|---|
| 정적 NAT | **[찾아 쓰기]** 안의 주소와 공인 주소를 어떻게 짝짓나요? |
| 동적 NAT | **[찾아 쓰기]** 정적 NAT 과 무엇이 다른가요? |
| PAT | 공인 IP **하나**를 여러 PC 가 같이 쓰고, **포트 번호로** 누구 것인지 구별한다 — 집 · 학원 공유기가 대부분 이것 |

PAT 공유기는 「바깥 포트 40002번 = 안의 `192.168.10.25:51234`」 같은 **변환표**를 가지고 있다가, 답이 오면 표를 보고 원래 PC 로 넘겨 줍니다.

### 왜 필요한가

1. 같은 `192.168.10` 으로 시작해도 관리자가 경계를 어디에 뒀는지에 따라 **다른 망**일 수 있습니다.
2. 같은 망이면 스위치(같은 망 안의 장비들을 잇는 장비)가 바로 전달하고, 다른 망이면 **게이트웨이(라우터 · 망과 망을 잇는 장비)** 를 거칩니다. 방화벽(허용 · 차단 규칙으로 통신을 거르는 장비) 규칙도 이 경계로 씁니다.
3. 그 경계를 정하는 값이 `255.255.255.0` — **서브넷 마스크**(서브넷 · 큰 망을 나눈 작은 망)입니다.

### 3.1 서브넷 마스크와 CIDR

**여기 나오는 말**

- **서브넷 (subnet)** — 큰 망을 나눈 **작은 망** 하나
- **서브넷 마스크 (subnet mask)** — IP 주소에서 **어디까지가 같은 망**인지 정하는 32칸 값 — `255.255.255.0`
- **CIDR (Classless Inter-Domain Routing)** (사이더) — 서브넷 마스크를 **1 의 개수**로 짧게 쓰는 표기 — `/24`
- **호스트 (host)** — 망 안의 **장비 하나** — PC · 서버 · 프린터
- **네트워크 주소** — 그 망의 **첫 주소** — 망 자체를 가리키는 주소라 장비에 주지 않는다
- **브로드캐스트 주소 (broadcast)** (브로드캐스트) — 망 안의 **모든 장비에 한 번에** 보내는 주소 — 그 망의 마지막 주소

| | 1 인 칸 | 0 인 칸 |
|---|---|---|
| 서브넷 마스크 32칸 | **네트워크 부분** — 같은 망이면 모두 같다 | **호스트 부분** — 장비마다 다르다 |

| 서브넷 마스크 | 2진수의 마지막 마디 | CIDR | 주소 수 | 장비에 쓸 수 있는 수 |
|---|---|---|---|---|
| `255.255.255.0` | `00000000` | `/24` | 256 | 254 |
| `255.255.255.128` | `10000000` | `/25` | 128 | 126 |
| `255.255.255.192` | `11000000` | `/26` | 64 | 62 |
| `255.255.255.224` | `11100000` | `/27` | 32 | 30 |
| `255.255.255.240` | `11110000` | `/28` | 16 | 14 |

- CIDR 숫자가 1 커지면 호스트 칸이 하나 줄어 주소 수는 **절반**이 됩니다.
- 쓸 수 있는 수가 2 적은 이유: **첫 주소**는 망 자체를 가리키는 **네트워크 주소**, **마지막 주소**는 망 전체에 한 번에 보내는 **브로드캐스트 주소**라 장비에 주지 않습니다.
- 기본 게이트웨이도 그 사이의 주소 하나를 씁니다(보통 첫 번째).

### 3.2 `ipaddress` 로 망 계산하기

손으로 세던 마스크 · 주소 수를 파이썬의 `ipaddress` 가 계산해 줍니다. 3.1 의 네트워크 주소 · 브로드캐스트 주소도 바로 꺼낼 수 있습니다.

#### 🐍 문법 상자 · `ipaddress` 로 망 계산하기

```python
import ipaddress
net = ipaddress.ip_network("192.168.10.70/26", strict=False)
print(net)
print(net.network_address, net.broadcast_address, net.num_addresses)
# 192.168.10.64/26
# 192.168.10.64 192.168.10.127 64
```

| 쓰는 것 | 뜻 |
|---|---|
| `ipaddress.ip_network("주소/CIDR", strict=False)` | 그 주소가 속한 **망**을 만든다. `strict=False` 는 「망의 첫 주소가 아니어도 받아 준다」 |
| `.network_address` | 네트워크 주소(첫 주소) |
| `.broadcast_address` | 브로드캐스트 주소(마지막 주소) |
| `.num_addresses` | 주소 수 — 쓸 수 있는 수는 여기서 2 를 뺀다 |
| `.netmask` | 서브넷 마스크 |

⚠ `strict=False` 를 빼면 `192.168.10.70/26` 처럼 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">망의 첫 주소가 아닌 값에서 `ValueError`</mark>(값이 맞지 않다는 에러)가 납니다.

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">4교시 (12:00–12:50) · 서브네팅 — 부서마다 필요한 만큼 나누기</mark>

### 왜 필요한가

1. 회사가 `192.168.50.0/24`(주소 256개)를 받았습니다. 개발팀 · 운영팀 · 보안팀을 **다른 망**으로 나눠야 서로의 PC 에 함부로 닿지 않습니다.
2. 큰 망을 작은 망 여러 개로 나누는 일이 **서브네팅**입니다.
3. 아무렇게나 나누면 주소가 모자라거나 **두 부서가 같은 주소를 받는** 사고가 납니다. 그래서 계산하고 검증합니다.

### 4.1 장비 수 → CIDR

**여기 나오는 말**

- **서브네팅 (subnetting)** — 큰 망을 **작은 망 여러 개로 나누는** 일

| 필요한 장비 수 | 호스트 칸 | 쓸 수 있는 수 | CIDR |
|---|---|---|---|
| 10대 | 4칸 | 2⁴ − 2 = 14 | `/28` |
| 25대 | 5칸 | 2⁵ − 2 = 30 | `/27` |
| 50대 | 6칸 | 2⁶ − 2 = 62 | `/26` |

**처음으로 「충분」해지는 가장 작은 크기**를 고릅니다. 더 크게 주면 다른 부서 몫이 줄어듭니다.

### 4.2 두 가지 나누는 법

**여기 나오는 말**

- **FLSM (Fixed Length Subnet Mask)** (에프엘에스엠) — 모든 부서에 **같은 크기**의 망을 주는 방식
- **VLSM (Variable Length Subnet Mask)** (브이엘에스엠) — 부서마다 **필요한 크기**의 망을 주는 방식

| | FLSM | VLSM |
|---|---|---|
| 뜻 | **모든** 부서에 같은 크기 | 부서마다 **필요한 크기** |
| 예 (50 · 25 · 10대) | `/26` 네 개 — 전부 62칸씩 | `/26` · `/27` · `/28` |
| 장점 | 단순하다 | 주소를 아낀다 |
| 단점 | 작은 부서에 빈 주소가 많이 남는다 | 계산 · 검증이 필요하다 |

**VLSM 은 큰 블록부터 놓습니다.** `/26` 은 0 · 64 · 128 · 192 에서만 시작할 수 있어서, 작은 것을 먼저 흩어 놓으면 큰 블록이 들어갈 자리가 없어집니다.

```
192.168.50.0/24
  0 ─────────── 63 │ 64 ──── 95 │ 96 ─ 111 │ 112 ───────────────── 255
  개발팀 /26 (62대) │ 운영팀 /27  │ 보안팀 /28 │ 남는 공간 (다음 부서용)
```

#### 🐍 문법 상자 · `**` 거듭제곱 · `.subnets()`

```python
import ipaddress
print(2 ** 6 - 2)
parent = ipaddress.ip_network("192.168.50.0/24")
print(len(list(parent.subnets(new_prefix=26))))
# 62
# 4
```

| 쓰는 것 | 뜻 |
|---|---|
| `2 ** 6` | 2 를 여섯 번 곱한다(64) |
| `망.subnets(new_prefix=26)` | 그 망을 `/26` 크기로 나눈 작은 망들 |

⚠ `subnets()` 의 결과는 리스트가 아니라 차례로 꺼내는 것이라 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">개수를 세려면 `list()` 로 감쌉니다</mark>.

### 4.3 설계 검증 — 용량과 겹침

**여기 나오는 말**

- **겹침 (overlap)** (오버랩) — 두 망이 **같은 주소를 함께 가진** 상태 — 설계에서 생기면 안 된다

설계표를 만들면 두 가지를 검증합니다.

| 검증 | 묻는 것 | 틀리면 생기는 일 |
|---|---|---|
| 용량 | 쓸 수 있는 수 ≥ 필요한 장비 수인가 | 장비에 줄 주소가 모자란다 |
| 겹침 | 두 부서의 망이 같은 주소를 갖지 않는가 | 같은 주소를 두 부서 장비가 받아 **주소 충돌**로 통신이 끊긴다. 방화벽 규칙이 다른 부서까지 덮고, 로그의 주소로 어느 장비인지 가릴 수 없다 |

#### 🐍 문법 상자 · `.overlaps()` — 두 망이 겹치나

```python
import ipaddress
a = ipaddress.ip_network("192.168.50.0/26")
b = ipaddress.ip_network("192.168.50.32/27")
print(a.overlaps(b))
# True
```

| 쓰는 것 | 뜻 |
|---|---|
| `망.overlaps(다른 망)` | 주소가 **하나라도 겹치면** `True` |

### 정답 · 2.3 NAT 표

| 방식 | 바꾸는 법 |
|---|---|
| 정적 NAT | 안의 주소 하나 ↔ 공인 주소 하나를 **고정**해 짝지어 둔다 — 바깥에서 안의 서버로 들어오게 할 때 쓴다 |
| 동적 NAT | 공인 주소 여러 개 가운데 빈 것을 나갈 때마다 **그때그때** 하나 준다 — 짝이 고정되지 않는다 |
| PAT | 공인 IP **하나**를 여러 PC 가 같이 쓰고, **포트 번호로** 누구 것인지 구별한다 — 집 · 학원 공유기가 대부분 이것 |

### 정답 2-1

**결과** — `11000000` · `00001010` · `16`

**왜** — 192 = 128 + 64 라 앞 두 칸만 1 이고, 10 = 8 + 2 라 `00001010` 입니다. 여덟 칸짜리 두 개를 이어 붙여 16칸입니다.

**자주 틀리는 곳** — 10 을 `1010` 네 칸으로 적는 것입니다. `08` 이 빈 앞자리를 0 으로 채워 여덟 칸을 만듭니다.

**관제에서는** — 마스크 · 망 경계 계산이 모두 이 여덟 칸 단위로 이루어지므로, 2진수로 펼칠 줄 알아야 경계를 검산할 수 있습니다.

### 정답 2-2

```python
def to_bits(ip):                                  # IP 주소를 2진수 32칸 글자로 바꾸는 함수
    bits = ""                                     # 이어 붙일 빈 글자
    for part in ip.split("."):                    # 점으로 나눈 마디를 하나씩
        # 1. bits 뒤에 format(int(part), "08b") 를 이어 붙이세요
        bits = bits + format(int(part), "08b")    # 마디 하나를 여덟 칸으로 바꿔 붙인다
    return bits                                   # 32칸 글자를 리턴한다


ip = "192.168.10.25"                              # 내 IPv4 주소로 바꿔 봅니다
print(ip)
print(to_bits(ip))
print("길이:", len(to_bits(ip)))
```

💻 **터미널에 입력합니다.** `python ip_bits.py`

**결과** — `11000000101010000000101000011001` 과 `길이: 32`

**왜** — 마디 네 개를 `format(int(part), "08b")` 로 여덟 칸씩 바꿔 이어 붙이므로 8 × 4 = 32칸이 됩니다.

**자주 틀리는 곳** — `"b"` 만 써서 `10` 이 `1010` 네 칸이 되면 길이가 32 보다 짧게 나옵니다.

**관제에서는** — 주소를 32칸으로 펼쳐 봐야 마스크가 어디서 망과 장비를 가르는지 확인할 수 있습니다.

```python
def is_private(ip):                               # 사설 IP 면 True 를 리턴하는 함수
    parts = ip.split(".")                         # 점으로 나눈 마디 네 개
    first = int(parts[0])                         # 첫 마디(숫자)
    second = int(parts[1])                        # 둘째 마디(숫자)
    # 1. first 가 10 이면 True 를 return 하세요
    if first == 10:                               # 10.x.x.x
        return True
    # 2. first 가 172 이고 second 가 16 이상 31 이하이면 True 를 return 하세요
    if first == 172 and 16 <= second <= 31:       # 172.16 ~ 172.31 만
        return True
    # 3. first 가 192 이고 second 가 168 이면 True 를 return 하세요
    if first == 192 and second == 168:            # 192.168.x.x
        return True
    return False                                  # 셋 다 아니면 공인


for ip in ["10.0.0.8", "172.20.5.6", "172.32.5.6", "192.168.10.25", "8.8.8.8", "203.0.113.7"]:
    if is_private(ip):
        print("[사설]", ip)
    else:
        print("[공인]", ip)
```

```python
b = ipaddress.ip_network("192.168.10.120/26", strict=False)
c = ipaddress.ip_network("192.168.10.130/26", strict=False)
print(a, b, c)

# 1. a 와 b 가 같은 망인지(a == b) 를 「70과 120: True」 꼴로 출력하세요
print("70과 120:", a == b)                        # 둘 다 64~127
# 2. a 와 c 가 같은 망인지를 같은 꼴로 출력하세요
print("70과 130:", a == c)                        # 130 은 128~191
```

💻 **터미널에 입력합니다.** `python same_network.py`

**결과** — `192.168.10.64/26 192.168.10.64/26 192.168.10.128/26` · `70과 120: True` · `70과 130: False`

**왜** — `/26` 은 마지막 마디를 64 씩 끊어 70 · 120 은 64~127, 130 은 128~191 블록이므로 `a == b` 만 `True` 입니다.

**자주 틀리는 곳** — 앞 세 마디 `192.168.10` 이 같으니 셋 다 같은 망이라고 답하는 것입니다. `/26` 에서는 넷째 마디도 경계를 가릅니다.

**관제에서는** — `.70` 과 `.130` 사이 통신은 게이트웨이를 거치므로 그 사이 방화벽 로그에 남는지 확인할 수 있습니다.

### 정답 4-1

**결과** — `192.168.50.0/26` · `192.168.50.64/26` · `192.168.50.128/26` · `192.168.50.192/26` 네 줄

**왜** — `/24`(256개)를 `/26`(64개)로 나누면 256 ÷ 64 = 4개이고, 각 망은 0 · 64 · 128 · 192 에서 시작합니다.

**자주 틀리는 곳** — 장비에 쓸 수 있는 62 로 끊어 `.62` · `.124` … 에서 시작한다고 적는 것입니다. 블록은 주소 수 64 로 끊습니다.

**관제에서는** — 주소 하나를 보고 0 · 64 · 128 · 192 중 어느 블록인지 알면 어느 부서 망에서 왔는지 바로 가립니다.

### 정답 4-2

```python
def smallest_prefix(required):                    # 장비 수를 받아 CIDR 숫자를 리턴한다
    for host_bits in range(2, 33):                # 호스트 칸을 2칸부터 하나씩 늘려 본다
        # 1. 2 ** host_bits - 2 가 required 이상이면 32 - host_bits 를 return 하세요
        if 2 ** host_bits - 2 >= required:        # 이 칸 수로 충분하면
            return 32 - host_bits                 # 나머지가 네트워크 칸 = CIDR 숫자


for name, count in [("보안팀", 10), ("운영팀", 25), ("개발팀", 50)]:
    print(name, count, f"/{smallest_prefix(count)}")
```

💻 **터미널에 입력합니다.** `python smallest_prefix.py`

**결과** — `보안팀 10 /28` · `운영팀 25 /27` · `개발팀 50 /26`

**왜** — 호스트 칸을 늘려 가다 `2 ** host_bits - 2` 가 처음으로 장비 수 이상이 되는 칸(10 → 4칸 14 · 25 → 5칸 30 · 50 → 6칸 62)에서 `32 - host_bits` 를 리턴합니다.

**자주 틀리는 곳** — `- 2` 를 빼먹어 주소 수로 비교하는 것입니다. 그러면 장비 63 · 64 대도 `/26` 이 나오는데, 실제로는 62 대까지만 들어갑니다.

**관제에서는** — 부서 망이 필요보다 크면 쓰지 않는 주소가 남아, 허가 없이 꽂은 장비가 그 주소를 받기 쉬워집니다.

### 정답 4-3

```python
import ipaddress

parent = ipaddress.ip_network("192.168.50.0/24")  # 회사가 받은 전체 주소
for sub in parent.subnets(new_prefix=26):         # /26 네 개를 하나씩
    # 1. sub 와 「사용 가능 62」 처럼 쓸 수 있는 수를 한 줄에 출력하세요
    print(sub, "사용 가능", sub.num_addresses - 2)
```

💻 **터미널에 입력합니다.** `python flsm.py`

**결과** — `192.168.50.0/26 사용 가능 62` 부터 `192.168.50.192/26 사용 가능 62` 까지 네 줄

**왜** — FLSM 은 모두 같은 크기라 `/26` 네 개가 모두 64 − 2 = 62 입니다. 50 · 25 · 10대에 주면 62 × 3 − 85 = 101칸이 남고 넷째 `/26` 은 통째로 남습니다.

**자주 틀리는 곳** — `sub.num_addresses` 를 그대로 출력해 `64` 가 나오는 것입니다. 네트워크 · 브로드캐스트 주소 2 개를 빼야 합니다.

**관제에서는** — 같은 크기로 나눈 망은 경계가 0 · 64 · 128 · 192 로 일정해, 로그 주소만 보고 어느 부서인지 쉽게 가릅니다.

### 정답 4-4

```python
import ipaddress

plan = [                                          # (부서, CIDR, 필요한 장비 수)
    ("개발팀", "192.168.50.0/26", 50),
    ("운영팀", "192.168.50.64/27", 25),
    ("보안팀", "192.168.50.96/28", 10),
]
networks = []                                     # 겹침 검사용으로 망을 모을 리스트

for name, cidr, required in plan:                 # 부서를 하나씩
    net = ipaddress.ip_network(cidr)              # CIDR 을 망으로
    # 1. ok 라는 변수에 「쓸 수 있는 수가 required 이상인지」 를 담으세요
    ok = net.num_addresses - 2 >= required        # 장비를 다 담을 수 있나
    print(name, cidr, "충분:", ok)
    networks.append(net)                          # 겹침 검사용으로 모은다

# 2. overlap 에 「앞 둘(networks[0], networks[1])이 겹치거나 networks[1] 과 networks[2] 가 겹치거나 networks[0] 과 networks[2] 가 겹치는지」 를 담으세요
overlap = networks[0].overlaps(networks[1]) or networks[1].overlaps(networks[2]) or networks[0].overlaps(networks[2])
print("겹침 있음:", overlap)
```

💻 **터미널에 입력합니다.** `python plan_check.py`

**결과** — `개발팀 192.168.50.0/26 충분: True` · `운영팀 … 충분: True` · `보안팀 … 충분: True` · `겹침 있음: False`

**왜** — 쓸 수 있는 수가 62 ≥ 50 · 30 ≥ 25 · 14 ≥ 10 이라 모두 충분하고, 0~63 · 64~95 · 96~111 로 이어져 `.overlaps()` 셋이 모두 `False` 입니다.

**자주 틀리는 곳** — `num_addresses >= required` 로 비교해 2 를 빼먹는 것입니다. 이번 값은 그래도 `True` 라 틀린 줄 모르고 넘어갑니다.

**관제에서는** — 두 부서 망이 겹치면 같은 주소를 두 PC 가 받을 수 있어, 로그 주소로 장비를 특정할 수 없게 됩니다.

### 정답 ⭐4-5

```python
import ipaddress

assignments = [                                   # (부서, CIDR, 필요한 장비 수)
    ("개발팀", "10.20.0.0/26", 50),
    ("운영팀", "10.20.0.64/27", 25),
    ("보안팀", "10.20.0.96/28", 10),
]

# 1. 부서를 하나씩 꺼내 망을 만들고, 첫 호스트(네트워크 주소 + 1)와 마지막 호스트(브로드캐스트 주소 - 1)를 구해
#    「개발팀 10.20.0.0/26 첫 10.20.0.1 마지막 10.20.0.62 사용 가능 62 필요 50」 꼴로 한 줄씩 출력하세요
for name, cidr, required in assignments:          # 부서를 하나씩
    net = ipaddress.ip_network(cidr)              # CIDR 을 망으로
    first = net.network_address + 1               # 첫 호스트
    last = net.broadcast_address - 1              # 마지막 호스트
    print(f"{name} {cidr} 첫 {first} 마지막 {last} 사용 가능 {net.num_addresses - 2} 필요 {required}")
```

💻 **터미널에 입력합니다.** `python design_table.py`

**결과** — `개발팀 10.20.0.0/26 첫 10.20.0.1 마지막 10.20.0.62 사용 가능 62 필요 50` · `운영팀 10.20.0.64/27 첫 10.20.0.65 마지막 10.20.0.94 사용 가능 30 필요 25` · `보안팀 10.20.0.96/28 첫 10.20.0.97 마지막 10.20.0.110 사용 가능 14 필요 10`

**왜** — 첫 호스트는 네트워크 주소 + 1, 마지막 호스트는 브로드캐스트 주소 − 1 입니다. 운영팀 `/27` 은 64~95 라 65~94 를 씁니다.

**자주 틀리는 곳** — 마지막 호스트에 브로드캐스트 주소(`10.20.0.63` · `.95` · `.111`)를 그대로 적는 것입니다.

**관제에서는** — 이 범위가 있으면 경보에 찍힌 `10.20.0.○○` 가 어느 부서 장비인지 바로 찾습니다.

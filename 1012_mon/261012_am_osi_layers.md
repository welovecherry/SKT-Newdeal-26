# 10/12(월) 오전 · 네트워크 첫 관찰 · OSI 7계층 — 실습

오늘부터 2과목 **네트워크 · ZT(제로 트러스트, Zero Trust) 운영 기초**입니다. 제로 트러스트는 「회사 안이라도 아무도 그냥 믿지 않고 매번 확인한다」는 보안 원칙으로, 6일 차 10/19(월)에 배웁니다. 1과목에서 `requests.post(url, …)` 한 줄로 경보를 보내고 LLM 에 질문했습니다. 그 한 줄이 실행될 때 데이터는 **잘게 나뉘어 선과 공유기를 지나 서버까지 갔다가** 답을 들고 돌아왔습니다. 오늘은 그 경로를 처음으로 들여다봅니다.

관제 데스크에 오는 문의는 대부분 「인터넷이 안 돼요」 한 문장입니다. 선이 빠졌는지, 주소를 못 찾는지, 서버가 죽었는지 — 원인은 여러 가지인데 증상은 하나입니다. 통신을 일곱 층으로 나눠 놓은 표준 모델이 **OSI(오에스아이) 7계층**입니다. 층마다 맡은 일이 달라서, 어느 층에서 막혔는지 차례로 좁혀 갈 수 있습니다.

1. 「인터넷이 안 돼요」가 오면 관제는 먼저 **닿는지**부터 봅니다. 그 첫 명령이 `ping` 입니다.
2. `ping` 은 상대에게 「거기 있어요?」 하고 작은 신호를 보내고, 답이 오는 데 걸린 시간을 잽니다.
3. 답이 오면 **상대까지 패킷이 오가고 있다**는 뜻입니다. 안 오면 어느 단계에서 끊겼는지 좁혀 갑니다(4교시).

### 2.1 `ping` 의 결과 읽기

**여기 나오는 말**

- **패킷 (packet)** — 보낼 데이터를 작게 나눈 **한 조각**. 받는 쪽 주소가 적혀 있다
- **`ping`** (핑) — 상대에게 「거기 있어요?」 신호를 보내 **답이 오는지와 걸린 시간**을 재는 명령
- **라우터 (router)** — **망과 망을 잇고**, 패킷에 적힌 주소를 보고 다음 장비로 넘겨 주는 장비. 회사 · 통신사에 있는 큰 장비
- **공유기** — 집 · 작은 사무실용 장비. 라우터 기능에 더해 **여러 기기가 인터넷 주소 하나를 나눠 쓰게** 해 주고, 와이파이까지 한 상자에 담았다. 학원 PC 의 기본 게이트웨이가 이것
- **DNS** (디엔에스) — `google.com` 같은 **이름을 IP 주소로 바꿔 주는** 시스템 (10/14 에 자세히 배움)
- **TTL (Time To Live)** (티티엘) — `ping` 결과 줄 끝의 숫자. 무슨 뜻인지는 바로 아래 2.1 표에서 **직접 찾아 씁니다**

```
Ping 8.8.8.8 32바이트 데이터 사용:
8.8.8.8의 응답: 바이트=32 시간=34ms TTL=115
8.8.8.8의 응답: 바이트=32 시간=33ms TTL=115
8.8.8.8의 응답: 바이트=32 시간=35ms TTL=115
8.8.8.8의 응답: 바이트=32 시간=34ms TTL=115

8.8.8.8에 대한 Ping 통계:
    패킷: 보냄 = 4, 받음 = 4, 손실 = 0 (0% 손실),
왕복 시간(밀리초):
    최소 = 33ms, 최대 = 35ms, 평균 = 34ms
```

> **검색해서 채웁니다.** 아래 질문을 한 번에 하나씩 검색합니다. 답은 오늘 보고서의 그 교시 `### 찾아본 것` 아래에 복사하지 말고 내 말로 적습니다. 다 적은 뒤 맨 아래 「정답」 표와 비교합니다.
> - TTL은 어떤 값을 나타내나요?
> - 라우터를 지날 때 TTL 값은 어떻게 바뀌나요?
> ⚠ 검색 결과는 영어 · 리눅스 화면이 많습니다. 내 화면(한국어 Windows)의 용어와 짝을 맞춰 읽습니다.

| 보이는 것 | 뜻 |
|---|---|
| `8.8.8.8의 응답` | 답이 왔다 — 상대까지 패킷이 오간다. `8.8.8.8` 은 구글의 공개 DNS(디엔에스 · 이름을 IP 주소로 바꿔 주는 시스템) 서버 주소다 |
| `시간=34ms` | 갔다가 돌아오는 데 걸린 시간(**왕복 시간**). ms(밀리초)는 1000분의 1초 |
| `TTL=115` | **[찾아 쓰기]** TTL은 어떤 값을 나타내나요? <br> 라우터를 지날 때 TTL 값은 어떻게 바뀌나요? |
| `손실 = 0 (0% 손실)` | 보낸 것 가운데 돌아오지 않은 비율 — 0% 면 보낸 4개가 모두 돌아왔다 |
| `평균 = 34ms` | 네 번의 왕복 시간의 평균 |

`ping` 이 쓰는 방식을 **ICMP**(아이시엠피 · Internet Control Message Protocol)라고 부릅니다. 웹 페이지(HTTP · 에이치티티피)와 달리 「살아 있나」만 묻는 통신입니다.

#### 명령 상자 · `ping` 의 옵션

`ping` 은 **터미널**에 입력하는 명령입니다.

```bash
ping 8.8.8.8          # 4번 보내고 끝난다
ping -n 10 8.8.8.8    # 10번 보낸다
ping -t 8.8.8.8       # 멈출 때까지 계속 보낸다 — Ctrl + C 로 멈춘다
```
맥북: `ping -c 4 8.8.8.8` → `ping -c 10 8.8.8.8` → `ping 8.8.8.8`(멈출 때까지 — `Ctrl + C`)

| 쓰는 것 | 뜻 |
|---|---|
| `-n 숫자` | 보낼 횟수 (number) |
| `-t` | 멈출 때까지 계속 |
| `Ctrl + C` | 터미널에서 실행 중인 명령을 멈춘다 |

⚠ 리눅스 · 맥의 `ping` 은 옵션이 다릅니다(`-c 10`). 검색한 글이 리눅스 기준이면 Windows 에서 안 될 수 있습니다.

### ✍️ 문제 2-2 · 구글 DNS 서버에 `ping` 열 번 보내기

**할 일** — 내 PC 에서 `8.8.8.8` 에 `ping` 을 열 번 보내, 평균 왕복 시간 · TTL · 받은 횟수 · 손실을 보고서에 기록합니다.

**왜 중요한가** — 정상일 때의 왕복 시간과 TTL 을 내 PC 에서 직접 재 둡니다. 열 번을 보내야 가끔 생기는 손실도 숫자로 잡힙니다. 이 숫자가 3-3 에서 게이트웨이 결과와 비교하는 기준이 됩니다.

**순서**
1. **[터미널]** `ping -n 10 8.8.8.8` 을 입력합니다. 열 번이라 10초쯤 걸립니다.
   맥북: `ping -c 10 8.8.8.8`
2. **[터미널]** 맨 아래 `패킷:` 줄에서 받음 · 손실을, `왕복 시간` 줄에서 평균을, `응답:` 줄 끝에서 TTL 을 찾습니다.
3. **[보고서]** `day01_packet_analysis.md`의 `## 2교시` › `### 문제 2-2` 아래를 채웁니다.
   - `8.8.8.8` 까지 평균 왕복 시간 · TTL · 받음 · 손실:

| | |
|---|---|
| 🎯 나와야 하는 결과 | `8.8.8.8의 응답:` 열 줄과 `패킷: 보냄 = 10, 받음 = 10, 손실 = 0 (0% 손실)` · `평균 = ○○ms` 꼴. 학원망이 붐비면 손실이 생길 수 있습니다 (숫자는 PC · 실행할 때마다 다릅니다) |

**💡 힌트**

1. 보낼 횟수를 정하는 옵션 `-n` 은 바로 위 명령 상자에 있습니다. 옵션은 주소 **앞**에 씁니다.

4. 열 줄이 모두 `요청 시간이 만료되었습니다` 이면 학원망이 `ping` 을 막은 것일 수 있습니다. 명령은 맞았으니 강사에게 알립니다.

### ⭐ 도전 2-5 · `ping` 결과를 파이썬으로 판정하기 (선택)

**할 일** — 준비된 ping 결과를 기준으로 정상 · 느림 · 실패를 구분하는 파이썬 코드를 완성해 실행합니다.

**왜 중요한가** — 서버가 수십 대면 `ping` 결과를 사람이 다 읽을 수 없습니다. 기준값으로 정상 · 느림 · 실패를 나누는 것이 자동 감시 스크립트가 하는 일입니다.

**이 문제에 나오는 말**

- **임계값 (`LIMIT`)** — 이 값을 넘으면 결과를 느리다고 판단하는 기준
- **`None`** — 응답이 없어 왕복 시간이 기록되지 않은 상태

**순서**
1. **[VS Code]** `network_zt` 폴더에 `ping_check.py`를 만듭니다.
2. **[VS Code]** 아래 코드를 파일에 붙여 넣습니다.
3. **[VS Code]** 번호 주석 아래를 채웁니다.
4. **[터미널]** `network_zt` 폴더에서 `python ping_check.py`를 실행합니다.
5. **[보고서]** `day01_packet_analysis.md`의 `## 2교시` › `### ⭐ 도전 2-5` 아래를 채웁니다.
   - 출력 첫 줄:

```python

    {"target": "192.0.2.1", "ms": None},          # None = 답이 오지 않았다

# ── 여기까지 ──

    # 2. 아니고 r["ms"] 가 LIMIT 보다 크면 f"[느림] {r['target']} {r['ms']}ms" 를 출력하세요

    # 3. 그 밖에는 f"[정상] {r['target']} {r['ms']}ms" 를 출력하세요

```

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">3교시 (11:00–11:50) · OSI 7계층 ① 아래 세 층 — MAC 과 IP</mark>

### 왜 필요한가

1. 네트워크는 하는 일을 **일곱 층**으로 나눠 놓았습니다. 층마다 맡은 일이 달라서, 문제가 생기면 층을 나눠 원인을 찾을 수 있습니다.
2. 3교시에는 **아래 세 층**을 봅니다 — 신호(1층), 같은 망 안의 전달(2층), 다른 망까지 경로 선택(3층).
3. 2층과 3층에는 각각 **주소**가 있습니다 — MAC 주소와 IP 주소. 둘을 구별하는 것이 오늘의 핵심입니다.

### 3.1 OSI 7계층 한눈에

**여기 나오는 말**

- **OSI 7계층** (오에스아이 칠계층) — 통신 과정을 역할별로 **일곱 층**으로 나눈 국제 표준
- **IP 주소 (Internet Protocol)** (아이피 주소) — 지금 연결된 망에서 받은 **위치 주소** — 장소가 바뀌면 바뀐다. 예 `192.168.0.15`
- **MAC 주소 (Media Access Control)** (맥 주소) — 랜카드에 정해져 나오는 **고유 번호** — 장소가 바뀌어도 그대로. 예 `A4-B1-C2-D3-E4-F5`
- **기본 게이트웨이 (default gateway)** (디폴트 게이트웨이) — 우리 망에서 **다른 망(인터넷)으로 가는 패킷을 받아 넘기는 장비**(보통 공유기)의 주소
- **ARP (Address Resolution Protocol)** (에이알피) — 같은 망에서 「이 IP 의 MAC 주소가 뭐예요?」 하고 **묻는 방법**
- **스위치 (switch)** — 같은 망 안에서 MAC 주소를 보고 패킷을 넘기는 장비

| 층 | 이름 | 하는 일 | 쓰는 주소 · 단위 | 오늘 보는 명령 |
|---|---|---|---|---|
| 7 | 응용 (Application) | 사용자가 쓰는 서비스 — 웹 · 메일 · DNS | URL(유알엘 · 웹 주소) · 도메인 이름(`google.com` 같은 이름) | `ping 이름` |
| 6 | 표현 (Presentation) | 암호화 · 압축 · 글자 형식 | — | — |
| 5 | 세션 (Session) | 대화의 시작과 끝을 관리 | — | — |
| 4 | 전송 (Transport) | 어느 프로그램에 줄지 — TCP(티시피) · UDP(유디피) | **포트 번호** | `netstat` (4교시) |
| 3 | 네트워크 (Network) | 다른 망에 있는 상대까지 경로 선택(라우팅) | **IP 주소** | `ipconfig` · `ping` |
| 2 | 데이터링크 (Data Link) | 같은 망 안에서 옆 장비로 전달 | **MAC 주소** | `ipconfig //all` · `arp -a` |
| 1 | 물리 (Physical) | 전기 · 빛 · 전파 신호 | — | 랜선 · Wi-Fi |

실무에서는 5 · 6 · 7층을 묶어 「응용 계층」으로 부르는 **TCP/IP 4계층**도 많이 씁니다.

#### 개념 상자 · IP 주소와 MAC 주소

| | IP 주소 | MAC 주소 (물리적 주소) |
|---|---|---|
| 층 | 3층 | 2층 |
| 모양 | 숫자 4덩어리, 점으로 구분 — `192.168.0.15` | 16진수(0~9 와 A~F 로 세는 수) 6덩어리, `-` 로 구분 — `A4-B1-C2-D3-E4-F5` |
| 누가 정하나 | 망에 들어갈 때 받는다 — 장소가 바뀌면 바뀐다 | 랜카드(랜선을 꽂는 부품) · Wi-Fi(와이파이) 장치에 새겨져 나온다 |
| 쓰는 범위 | 인터넷 전체 — 멀리 있는 상대 | **같은 망 안** — 바로 옆 장비까지 |

⚠ 한 PC 에 MAC 주소가 여러 개일 수 있습니다. 랜 · Wi-Fi · 가상 장치마다 하나씩입니다. <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">기본 게이트웨이가 적힌 장치</mark>가 지금 쓰는 장치입니다. 게이트웨이(gateway)는 우리 망에서 다른 망(인터넷)으로 가는 패킷을 받아 넘겨 주는 장비로, 보통 공유기입니다.

### ✍️ 문제 3-4 · ARP 캐시 보기 — `arp -a`

**할 일** — ARP 표에서 기본 게이트웨이 IP에 대응하는 MAC 주소와 그 항목의 유형을 확인해 보고서에 기록합니다.

**왜 중요한가** — ARP 캐시는 IP 와 MAC 을 잇는 표입니다. 게이트웨이 줄의 MAC 주소가 평소와 다르면 같은 망의 다른 장비가 게이트웨이로 위장하는 공격을 의심합니다.

**이 문제에 나오는 말**

- **ARP 캐시** — IP 주소와 MAC 주소의 대응을 PC가 잠시 저장해 둔 표
- **동적** — 같은 망에 물어본 뒤 알아낸 항목

**순서**
1. **[터미널]** `arp -a`를 입력합니다.
2. **[터미널]** 기본 게이트웨이 IP와 같은 줄에서 물리적 주소와 유형을 찾습니다.
3. **[보고서]** `day01_packet_analysis.md`의 `## 3교시` › `### 문제 3-4` 아래를 채웁니다.
   - 게이트웨이 줄의 MAC 주소 · 유형:
   - 🔍 ARP 는 무엇을 알아내려고 쓰나요? 내 결과의 게이트웨이 줄을 예로 들어 설명합니다.

```
인터페이스: 192.168.0.15 --- 0x9
  인터넷 주소           물리적 주소           유형
  192.168.0.1           a8-5e-45-01-2b-3c     동적
  192.168.0.255         ff-ff-ff-ff-ff-ff     정적
```

| | |
|---|---|
| 🎯 나와야 하는 결과 | 게이트웨이 IP 줄의 `물리적 주소` 와 `동적` (주소 값은 PC 마다 다릅니다) |

**💡 힌트**

1. **ARP**(에이알피 · Address Resolution Protocol) 는 「이 IP 의 MAC 이 뭐예요?」 하고 같은 망에 묻는 방법입니다. 그 답을 PC 가 잠시 저장해 둔 표가 **ARP 캐시**입니다.
2. `동적` 은 물어봐서 알아낸 것, `정적` 은 미리 정해진 것입니다.
3. `ff-ff-ff-ff-ff-ff` 는 특정 장비가 아니라 **같은 망 전체에 보내는 주소**(브로드캐스트)입니다.
4. 그래도 막히면 문서 맨 아래 「정답 3-4」에서 확인합니다.

### ⭐ 도전 3-5 · 주소 모양으로 IP 와 MAC 구별하기 (선택)

**할 일** — 주소 문자열의 모양을 검사해 IP인지 MAC인지 분류하는 파이썬 코드를 완성해 실행합니다.

**왜 중요한가** — 로그에는 IP 와 MAC 이 한 칸에 섞여 들어오기도 합니다. 모양으로 종류를 가르는 함수는 로그를 자동으로 분류할 때 씁니다.

**이 문제에 나오는 말**

새 용어 없음.

**순서**
1. **[VS Code]** `network_zt` 폴더에 `addr_kind.py`를 만듭니다.
2. **[VS Code]** 아래 코드를 파일에 붙여 넣습니다.
3. **[VS Code]** 번호 주석 아래를 채웁니다.
4. **[터미널]** `network_zt` 폴더에서 `python addr_kind.py`를 실행합니다.
5. **[보고서]** `day01_packet_analysis.md`의 `## 3교시` › `### ⭐ 도전 3-5` 아래를 채웁니다.
   - 출력 첫 줄:

```python
def kind(address):                                # 주소의 모양을 보고 종류를 리턴하는 함수
    # 1. address 를 "." 로 나눈 조각이 4개이면 "IP" 를 return 하세요

    # 2. address 를 "-" 로 나눈 조각이 6개이면 "MAC" 을 return 하세요

    # 3. 둘 다 아니면 "모름" 을 return 하세요

# ── 미리 채워 둔 줄입니다. 고치지 않습니다 ──
for a in ["192.168.0.15", "a8-5e-45-01-2b-3c", "ff-ff-ff-ff-ff-ff", "192.168.0"]:
    print(kind(a), a)                             # 종류와 주소를 한 줄에
# ── 여기까지 ──
```

| | |
|---|---|
| 🎯 나와야 하는 결과 | `IP 192.168.0.15` · `MAC a8-5e-45-01-2b-3c` · `MAC ff-ff-ff-ff-ff-ff` · `모름 192.168.0` |

**💡 힌트**

1. `"192.168.0.15".split(".")` 은 `['192', '168', '0', '15']` 입니다.
2. 조각의 개수는 `len()` 으로 셉니다.
3. `return` 을 만나면 함수는 거기서 끝납니다. 그래서 `else` 없이 순서대로 써도 됩니다.
4. 그래도 막히면 문서 맨 아래 「정답 ⭐3-5」에서 확인합니다.

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">4교시 (12:00–12:50) · OSI 7계층 ② 위 네 층 — 포트와 지금의 연결</mark>

### 왜 필요한가

1. IP 주소는 **어느 컴퓨터**인지까지만 알려 줍니다. 한 컴퓨터에는 브라우저 · 메신저 · 업데이트 같은 프로그램이 동시에 통신합니다.
2. 그중 **어느 프로그램**에 줄지는 4층의 **포트 번호**가 정합니다.
3. 관제는 「지금 이 PC 가 **누구와 · 어느 포트로** 연결돼 있나」를 봅니다. 모르는 연결이 있으면 의심합니다.

### 4.1 관제가 외워 두는 포트

**여기 나오는 말**

- **포트 번호 (port)** (포트) — 한 컴퓨터 안에서 **어느 프로그램에게 줄지** 정하는 번호(0~65535). 주소 뒤 `:443` 처럼 붙는다
- **서비스** — 그 포트에서 일하는 프로그램의 종류 — 443 이면 HTTPS(암호화된 웹)
- **`netstat` (network statistics)** (넷스탯) — 지금 내 PC 의 **연결 목록**을 보여 주는 명령
- **LISTENING** (리스닝) — 내 PC 가 연결 요청을 **기다리며 열어 둔** 상태
- **PID (Process ID)** (피아이디) — 실행 중인 **프로그램마다 붙는 번호**

> **검색해서 채웁니다.** 아래 질문을 한 번에 하나씩 검색합니다. 답은 오늘 보고서의 그 교시 `### 찾아본 것` 아래에 복사하지 말고 내 말로 적습니다. 다 적은 뒤 맨 아래 「정답」 표와 비교합니다.
> - 포트 3389가 인터넷에 열려 있으면 어떤 위험이 있나요?
> - 어떤 랜섬웨어가 포트 445를 이용해 퍼졌나요?
> ⚠ 검색 결과는 영어 · 리눅스 화면이 많습니다. 내 화면(한국어 Windows)의 용어와 짝을 맞춰 읽습니다.

| 포트 | 서비스 | 쓰임 |
|---|---|---|
| 22 | SSH(에스에스에이치) | 서버 원격 접속 (리눅스) |
| 53 | DNS | 이름 → IP 주소 |
| 80 | HTTP | 웹 (암호화 없음) |
| 443 | HTTPS(에이치티티피에스) | 웹 (암호화) — 요즘 웹은 거의 다 이것 |
| 3389 | RDP(알디피) | 원격 데스크톱 (Windows) — **[찾아 쓰기]** 인터넷에 열려 있으면 어떤 위험이 있나요? |
| 135 | RPC(알피시) | Windows 가 다른 PC 의 기능을 원격으로 불러 쓸 때 |
| 445 | SMB(에스엠비) | Windows 파일 · 프린터 공유 — **[찾아 쓰기]** 어떤 랜섬웨어가 이 포트를 이용해 퍼졌나요? |

#### 명령 상자 · 포트 번호와 PID, `netstat` 의 옵션

| | 포트 번호 | PID(피아이디 · Process ID) |
|---|---|---|
| 뜻 | 통신에서 **프로그램을 가리키는 번호** | 실행 중인 **프로그램의 번호** |
| 어디서 보나 | 주소 뒤 `:443` | `netstat -ano` 의 맨 끝 칸 |

| 쓰는 것 | 뜻 |
|---|---|
| `netstat -n` | 지금의 연결을 숫자 주소로 보여 준다 |
| `-a` | 연결뿐 아니라 **연결을 기다리는(LISTENING · 리스닝) 포트**까지 전부 |
| `-o` | 그 연결을 가진 프로그램의 **PID** 를 붙인다 |
| `\| grep 글자` | 앞 명령의 결과에서 그 글자가 든 줄만 남긴다. `\|` 는 파이프(pipe) — 앞 결과를 뒤 명령에 넘긴다. `grep`(그렙) |
| `tasklist` | 실행 중인 프로그램 목록과 PID(태스크리스트). `tasklist \| grep 1234` 는 PID 가 1234 인 줄만 |

⚠ `192.168.0.15:51234` 처럼 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">내 쪽 포트가 큰 숫자</mark>인 것은 PC 가 그때그때 고른 임시 번호입니다. 서비스를 알려 주는 것은 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">상대 쪽 포트</mark>(`:443`)입니다.

### ✍️ 문제 4-3 · 그 연결은 어느 프로그램의 것인가

| | |
|---|---|
| 🎯 나와야 하는 결과 | PID 숫자 하나와 프로그램 이름(예: `chrome.exe` · `msedge.exe`) |

**💡 힌트**

1. PID 는 줄의 **맨 끝 칸**입니다.

2. **[터미널]** 결과에서 LISTENING 상태인 줄의 포트 번호를 확인합니다.

   - 🔍 LISTENING 과 ESTABLISHED 는 무엇이 다른가요? 4-2 와 4-4 에서 본 줄을 예로 들어 설명합니다.

| | |
|---|---|
| 🎯 나와야 하는 결과 | `TCP    0.0.0.0:135 … LISTENING` · `TCP    0.0.0.0:445 … LISTENING` 꼴의 줄. 135 는 RPC(원격 기능 호출), 445 는 SMB(파일 공유)입니다. PC 설정에 따라 135 · 445 가 안 보이거나 다른 번호(예: 22 · 80)가 더 있을 수 있습니다 — PC 마다 켜 둔 프로그램이 다릅니다. 4.1 표에 있는 번호가 하나도 없으면 「없음」이라고 적습니다 |

3. `0.0.0.0` 은 「이 PC 의 모든 주소에서 듣는다」는 뜻입니다.

def kind(address):                                # 주소의 모양을 보고 종류를 리턴하는 함수
    # 1. address 를 "." 로 나눈 조각이 4개이면 "IP" 를 return 하세요
    if len(address.split(".")) == 4:              # 점으로 나눠 네 조각이면

        return "MAC"
    # 3. 둘 다 아니면 "모름" 을 return 하세요
    return "모름"                                  # 둘 다 아니면

for a in ["192.168.0.15", "a8-5e-45-01-2b-3c", "ff-ff-ff-ff-ff-ff", "192.168.0"]:
    print(kind(a), a)                             # 종류와 주소를 한 줄에

| ③ `ping` 은 되는데 웹 하나만 안 됨 | 4층 이상 — 그 서버의 포트 · 서비스 | 3층(`ping`)은 되니, 그 위의 포트나 서비스가 문제다 |

**결과** — 가장 먼저 의심할 곳은 ① 7층 DNS(이름 → IP 변환) ② 1~3층 우리 망 안(선 · Wi-Fi · 공유기) ③ 4층 이상 그 서버의 포트나 서비스. 확정이 아니라 「어디부터 확인할지」를 좁히는 것입니다.

**왜** — 아래 층부터 되는지 확인하고, 처음으로 안 되는 층을 원인으로 봅니다. 숫자 주소 `ping` 이 되면 3층까지는 정상입니다.

**자주 틀리는 곳** — ①을 「인터넷이 끊겼다」(1~3층)로 적는 실수가 많습니다. `ping 8.8.8.8` 이 되었으니 아래 층은 정상입니다.

**관제에서는** — 「인터넷이 안 돼요」 문의를 받으면 이 순서로 원인 층을 좁힌 뒤 맞는 담당자에게 넘깁니다.

# 아침 과제 8 · Wireshark 설치하고 새 과목 폴더 만들기 · `git add .`

10월 12일 (월) · 아침 과제

**오늘 하는 일:** 오후 실습에 쓸 **Wireshark**(와이어샤크 · 오가는 패킷을 붙잡아 보여 주는 프로그램)를 설치하고, 오늘부터 쓸 과목 폴더 **`network_zt`** 를 만듭니다. 마지막에 오늘의 기록을 **`git add .`** 로 깃허브에 올립니다.

설치는 **기다리는 시간이 대부분**입니다. 설치를 먼저 걸어 두고, 도는 동안 폴더를 만듭니다.

**⚠ 이 과제는 점심시간 전까지 꼭 끝냅니다.** 오후 6교시 실습이 Wireshark 로 시작합니다.

---

## 1. 왜 이걸 설치하는지 찾아봅니다

먼저 **왜 필요한지**를 직접 찾아보고 한두 줄로 적습니다.

| 질문 | 검색어 예시 |
|---|---|
| 보안 담당자는 왜 패킷을 직접 열어 볼까요? | `와이어샤크 란`, `패킷 분석 보안 관제` |

정답을 맞히는 과제가 아닙니다. **찾은 내용을 자기 말로 적는 것**이 과제입니다.

---

## 2. 이 말들이 무슨 뜻인지 찾아봅니다

검색해서 읽고 자기 말로 한 줄씩 적습니다.

| 찾아볼 말 | 무엇을 알아 오면 되나 (힌트) |
|---|---|
| 패킷 (packet) | 네트워크로 보내는 데이터의 무엇인가 |
| 패킷 캡처 (packet capture) | 무엇을 붙잡는 것인가 |
| Npcap (엔피캡) | Wireshark 와 어떤 관계인가 |

오른쪽은 **힌트일 뿐입니다.** 뜻은 직접 찾아서 자기 말로 적습니다.

---

## 3. Wireshark 설치를 먼저 걸어 둡니다

**① 설치 파일을 받습니다**

1. 브라우저에서 `https://www.wireshark.org/download.html` 을 엽니다.
2. 맨 위 **Stable Release**(안정판) 아래에서 **Windows x64 Installer** 를 누릅니다.

| 목록에 보이는 것 | 고르나 | 이유 |
|---|---|---|
| **Windows x64 Installer** | ✅ 이것 | 학원 PC 같은 일반 Windows PC 용 설치 파일 |
| Windows Arm64 Installer | ❌ | ARM 칩을 쓰는 일부 노트북용 |
| Windows x64 PortableApps | ❌ | 설치 없이 쓰는 판 — 패킷을 붙잡는 부품(Npcap)이 같이 깔리지 않는다 |

**② 받은 파일을 실행합니다**

1. 내려받은 `Wireshark-…-x64.exe` 를 엽니다.
2. 「이 앱이 디바이스를 변경하도록 허용하시겠어요?」 창이 뜨면 **예** 를 누릅니다.
3. 그다음부터는 **Next**(다음)를 누르며 넘어갑니다. 아래 두 화면에서만 멈춰서 확인합니다.

| 화면 | 할 일 |
|---|---|
| **Packet Capture**(패킷 캡처) — `Install Npcap` 체크 칸 | **체크를 켠 채로 둡니다.** 이것이 빠지면 오후에 패킷을 하나도 못 잡습니다 |
| **USB Capture** — `Install USBPcap` 체크 칸 | 꺼도 됩니다. USB 장치용이라 이 수업에서는 쓰지 않습니다 |

4. 설치 중에 **Npcap 설치 창이 따로 뜨면** 기본값 그대로 **I Agree**(동의) → **Install**(설치) → **Next** → **Finish**(마침)를 누릅니다.
5. Wireshark 설치 창으로 돌아와 **Finish** 를 누릅니다.

**설치가 도는 동안 바로 4번으로 넘어갑니다.**

## 4. 새 과목 폴더를 만듭니다

오늘부터 2과목 「네트워크·ZT 운영」입니다. 과목마다 폴더를 하나씩 씁니다. 지금까지는 `agent_core`, 오늘부터는 **`network_zt`** 입니다.

**① `network_zt` 폴더를 만듭니다**

1. VS Code 에서 `security-agent-toolkit` 폴더를 엽니다.
2. 왼쪽 파일 목록의 **빈 곳을 오른쪽 클릭**하고 **New Folder**(새 폴더)를 누릅니다.
3. 이름을 `network_zt` 로 적습니다. `agent_core` · `docs` 와 **같은 높이**에 있어야 합니다.

**② 터미널을 그 폴더에서 엽니다**

`network_zt` 폴더를 오른쪽 클릭하고 **Open in Integrated Terminal**(통합 터미널에서 열기)을 누릅니다.

```
pwd
```

- 결과가 `…/security-agent-toolkit/network_zt` 로 끝나면 됩니다. 앞부분은 사람마다 다릅니다.

## 7. 오늘 만든 것을 깃허브에 올립니다 — `git add .`

10/8 에는 `git add agent_core docs` 처럼 **올릴 폴더 이름을 직접** 적었습니다. 오늘부터는 폴더가 하나 더 늘었으니, **`git add .`** 로 바뀐 것을 한 번에 고릅니다. 대신 **고르기 전에 `git status` 로 먼저 봅니다.**

**① 터미널을 `security-agent-toolkit` 에서 엽니다**

VS Code 왼쪽 파일 목록의 **빈 곳**을 오른쪽 클릭하고 **Open in Integrated Terminal** 을 누릅니다. 4번에서 연 `network_zt` 터미널이라면 `cd ..` 를 한 번 입력합니다.

```
pwd
```

결과가 `…/security-agent-toolkit` 으로 끝나야 합니다.

**② `.gitignore` 에 두 줄을 더합니다**

VS Code 에서 `.gitignore` 를 열고 맨 아래에 두 줄을 더해 네 줄로 만듭니다.

```
.env
.venv
.ipynb_checkpoints
__pycache__
```

| 더한 줄 | 무엇인가 | 왜 올리지 않나 |
|---|---|---|
| `.ipynb_checkpoints` | 노트북을 주피터 프로그램으로 열면 저절로 생기는 백업 폴더 | 내가 만든 파일이 아니고, 사람마다 다르다 |
| `__pycache__` | 파이썬이 `.py` 파일을 `import` 할 때 만드는 임시 폴더 (10/6 의 `llm_client.py` 를 불러올 때 생김) | 실행하면 저절로 다시 생긴다 |

`git add .` 는 「`.gitignore` 에 적힌 것을 빼고 전부」 고르기 때문에, 이 목록을 먼저 챙깁니다.

**③ 무엇이 바뀌었는지 먼저 봅니다**

```
git status
```

| 보이는 것 | 뜻 |
|---|---|
| 빨간 글씨 `modified: .gitignore` | 방금 두 줄을 더한 파일 |
| 빨간 글씨 `docs/2026-10-12.md` | 6번에서 만든 기록 파일 |
| `network_zt` 가 **안 보임** | 정상입니다. git 은 **파일**을 기록합니다. 아직 빈 폴더라 올릴 것이 없습니다. 오전 실습에서 파일이 생기면 그때 보입니다 |

⚠ 빨간 목록에 **`.env` 나 `.venv` 가 보이면 멈춥니다.** `.gitignore` 를 다시 확인하고 강사를 부릅니다. 이 확인이 `git add .` 앞에 `git status` 를 먼저 하는 이유입니다.

**④ 바뀐 것을 한 번에 고릅니다**

```
git add .
```

| 쓴 것 | 뜻 |
|---|---|
| `add` | 다음 기록(commit)에 넣을 파일을 고른다 (10/8) |
| `.` | **지금 폴더와 그 아래 전부**. 터미널에서 `.` 은 「지금 있는 폴더」라는 뜻이다. `.gitignore` 에 적힌 것은 저절로 빠진다 |

그래서 ①에서 터미널 위치를 `security-agent-toolkit` 으로 맞췄습니다. `network_zt` 안에서 `git add .` 를 하면 `network_zt` 안의 것만 골라집니다.

⚠ 인터넷에서 `git add *` 를 볼 수도 있습니다. 쓰지 않습니다. `*` 는 `.gitignore` 처럼 **점으로 시작하는 파일을 빠뜨리고**, 무시 목록에 걸리면 오류처럼 보이는 문구를 냅니다.

**⑤ 골라진 것을 다시 봅니다**

```
git status
```

③에서 빨간 글씨였던 두 파일이 **초록 글씨**(`Changes to be committed`)로 바뀌었으면 됩니다.

**⑥ 기록하고 올립니다 (10/8 과 같음)**

```
git commit -m "Add 10/12 morning notes"
```

```
git push
```

브라우저에서 내 저장소를 새로 고쳐 `docs/2026-10-12.md` 가 보이면 끝입니다.

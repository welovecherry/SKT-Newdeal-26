## 2교시 · nslookup

### 문제 2-1 · 이름을 IP 로 — 두 DNS 서버에 묻기

- **(가-1) 처음 물은 DNS 서버(위쪽 `Address`) · example.com 의 IPv4:** 학원 PC 예) `168.126.63.1` · `104.20.23.154`
  - 확인할 것: `서버:` 아래 `Address` 를 example.com 의 주소로 적지 않았는가.
- **(가-2) `8.8.8.8` 에 물었을 때 위쪽 `서버` · example.com 의 IPv4:** `dns.google` · (가-1) 과 같은 IPv4
  - 확인할 것: 시간 초과가 났으면 「시간 초과 — 학원망이 외부 DNS 를 막음」도 정답.
- **(가-3) `ipconfig //all` 의 `DNS 서버` 주소 · (가-1) 의 위쪽 `Address` 와 같은지:** `168.126.63.1` · 같다
  - 확인할 것: 기본 게이트웨이가 찬 장치의 줄을 읽었는가.
- **(나-1) 🔍 위 두 줄의 `Address` 와 아래 `Addresses` 가 각각 무엇의 주소인지 두 화면을 예로 들어 설명하세요.**
  - 모범 답: 위 두 줄의 `Address` 는 내가 물어본 DNS 서버의 주소라 첫 화면은 `168.126.63.1`, 둘째 화면은 `8.8.8.8` 로 바뀌었다. 아래 `Addresses` 는 물어본 이름 example.com 의 답이라 두 화면에서 같았다.
  - 핵심 낱말: **위 = 물어본 DNS 서버 · 아래 = 이름의 답**
- **(나-2) 서버를 적지 않은 첫 `nslookup` 이 어느 DNS 서버에 물었는지 (가-3) 을 근거로 설명하세요.**
  - 모범 답: 서버를 적지 않으면 `nslookup` 은 PC 에 설정된 DNS 서버에 묻는다. (가-3) 의 `ipconfig //all` DNS 서버 주소가 첫 화면의 위쪽 `Address` 와 같으므로, 첫 질문은 PC 에 설정된 학원 DNS 서버로 갔다.
  - 핵심 낱말: **PC 에 설정된 DNS 서버 · 두 값이 같다**
- **(다-1) 사내 PC 가 회사 DNS 서버 대신 `8.8.8.8` 같은 외부 DNS 서버에 직접 묻는 기록을 관제가 확인해야 하는 이유를 설명하세요.**
  - 모범 답: 회사는 사내 DNS 서버에서 위험한 이름을 막고 질의 기록을 남긴다. PC 가 외부 DNS 에 직접 물으면 그 차단과 기록을 피해 가므로, 악성 코드나 규정 위반이 숨어 있을 수 있어 확인한다.
  - 핵심 낱말: **사내 DNS = 차단 · 기록 → 외부 직접 질의는 우회**
- **(다-2) PC 의 `DNS 서버` 설정이 회사가 정한 주소가 아닌 낯선 주소로 바뀌어 있으면 어떤 위험이 있는지 설명하세요.**
  - 모범 답: 악성 코드가 DNS 서버 설정을 공격자의 서버로 바꾸면, 은행 · 메일 같은 이름을 물어도 공격자가 정한 가짜 IP 를 받는다. 사용자는 주소창의 이름이 맞아도 가짜 사이트로 접속하게 된다.
  - 핵심 낱말: **가짜 DNS 서버 → 가짜 IP → 가짜 사이트**

### 문제 2-2 · URL 에서 이름을 꺼내 묻기 — 없는 이름이면

- **(가-1) 첫 파일 출력 두 줄:** `['https:', '', 'example.com', 'news', 'today']` · `example.com → 104.20.23.154`
  - 확인할 것: IPv4 는 실행마다 다를 수 있다. 첫 줄의 빈 조각 `''` 이 있어야 한다.
- **(가-2) 두 번째 파일 마지막 줄의 에러 이름 · `nslookup` 이 낸 문구:** `socket.gaierror` · `Non-existent domain`
  - 확인할 것: 맥북은 `NXDOMAIN`. 에러 이름은 `socket.gaierror` 까지만 적어도 된다.
- **(나-1) `parts[2]` 에서 도메인 이름이 나온 이유를, 첫 줄의 칸을 0 번부터 세어 `//` 사이에서 무엇이 생겼는지와 함께 설명하세요.**
  - 모범 답: `/` 로 자르면 `https:` 와 `example.com` 사이의 `//` 에 글자가 없어 빈 조각 `''` 이 생긴다. 그래서 0 번 `https:`, 1 번 `''`, 2 번 `example.com` 이 되어 `parts[2]` 가 도메인 이름이다.
  - 핵심 낱말: **// 사이 빈 조각 · 0 번부터 세기**
- **(나-2) 두 번째 파일이 마지막 줄에서 에러로 멈춘 이유를 `nslookup` 의 답과 이어서 설명하세요.**
  - 모범 답: `gethostbyname()` 이 DNS 서버에 이름을 물었는데, `nslookup` 처럼 DNS 서버가 「그런 이름은 없다」(NXDOMAIN)고 답했다. 리턴할 IPv4 가 없어 `socket.gaierror` 에러가 나고 프로그램이 멈췄다.
  - 핵심 낱말: **NXDOMAIN → IPv4 없음 → gaierror**
- **(다-1) 🔍 `Non-existent domain`(NXDOMAIN) 이 인터넷이 끊겼다는 뜻이 아닌 이유를, DNS 서버가 답을 했는지로 설명하세요.**
  - 모범 답: NXDOMAIN 은 DNS 서버가 정상으로 답을 했고 그 답이 「이름이 없다」인 것이다. 연결이 끊겼다면 DNS 서버에서 답이 아예 오지 않아 시간 초과가 난다.
  - 핵심 낱말: **DNS 서버가 답했다 · 끊기면 시간 초과**
- **(다-2) 한 PC 에서 짧은 시간에 NXDOMAIN 이 수십 번 나오면 관제가 무엇을 의심하는지 설명하세요.**
  - 모범 답: 악성 코드가 무작위로 만든 이름을 차례로 물으며 공격자 서버를 찾는 중일 수 있다. 사람은 같은 없는 이름을 수십 번 묻지 않으므로, 그 PC 의 질의 기록과 프로세스를 확인한다.
  - 핵심 낱말: **무작위 이름 대량 질의 → 악성 코드 의심**

## 3교시 · DNS 계층

### 문제 3-1 · 이름을 층으로 나누고 담당 네임서버 찾기

- **(가-1) 첫 파일 출력 세 줄:** `com` · `example.com` · `['com', 'example', 'www']`
  - 확인할 것: 파이썬 출력이라 모두 같아야 한다.
- **(가-2) 두 번째 파일(`mail.google.co.kr`) 출력 세 줄:** `kr` · `co.kr` · `['kr', 'co', 'google', 'mail']`
  - 확인할 것: 둘째 줄이 `co.kr` 인가.
- **(가-3) example.com 의 담당 네임서버(`nameserver =` 뒤):** `hera.ns.cloudflare.com` · `elliott.ns.cloudflare.com`
  - 확인할 것: `internet address` 의 IP 를 적지 않았는가. 담당자는 바뀔 수 있다.
- **(나-1) `[-1]` 과 `[-2:]` 가 각각 무엇을 꺼냈는지, 그 조각이 3.1 표의 어느 층인지 첫 파일 출력으로 설명하세요.**
  - 모범 답: `[-1]` 은 맨 끝 조각 하나 `com` 을 꺼냈고 이는 TLD 층이다. `[-2:]` 는 끝의 두 조각 `['example', 'com']` 리스트를 꺼냈고, 점으로 이은 `example.com` 은 담당 네임서버가 원본을 가진 2단계 도메인 층이다.
  - 핵심 낱말: **[-1] = TLD · [-2:] = 2단계 도메인**
- **(나-2) 두 번째 파일의 둘째 줄이 `google.co.kr` 이 아니라 `co.kr` 로 나온 이유를 `.kr` 의 층 구조와 이어서 설명하세요.**
  - 모범 답: `.kr` 은 TLD 아래에 `co.kr`(회사용) 같은 층이 하나 더 있다. 그래서 끝의 두 조각은 `co.kr` 까지만 되고, 회사 이름 `google.co.kr` 을 얻으려면 끝의 세 조각이 필요하다.
  - 핵심 낱말: **.kr 은 한 층 더 · 세 조각이 회사 이름**
- **(다-1) 한 도메인에 담당 네임서버를 둘 이상 두는 이유를 설명하세요.**
  - 모범 답: 담당 네임서버가 하나뿐이면 그 서버가 멈추거나 공격받을 때 그 도메인의 모든 이름이 풀리지 않는다. 둘 이상 두면 하나가 멈춰도 다른 서버가 답한다.
  - 핵심 낱말: **하나가 멈춰도 답한다(이중화)**
- **(다-2) 도메인의 담당 네임서버가 갑자기 낯선 서버로 바뀌었다면 어떤 위험이 있는지 설명하세요.**
  - 모범 답: 담당 네임서버는 그 도메인 모든 이름의 원본 답을 정한다. 낯선 서버로 바뀌었다면 공격자가 도메인 관리 계정을 빼앗아 웹 · 메일 주소를 자기 서버로 돌렸을 수 있다.
  - 핵심 낱말: **원본 답을 공격자가 정함 · 도메인 탈취**

### 문제 3-2 · 담당 네임서버에게 직접 묻기

- **(가-1) 리졸버에 물었을 때 `권한 없는 응답:` 줄이 있었나 · IPv4:** 있었다 · `104.20.23.154`
  - 확인할 것: 맥북은 `Non-authoritative answer:`.
- **(가-2) 담당 네임서버에 물었을 때 `권한 없는 응답:` 줄이 있었나 · IPv4:** 없었다 · (가-1) 과 같은 IPv4
  - 확인할 것: 시간 초과면 「시간 초과 — 강사 화면: 없음」으로 적게 한다.
- **(가-3) `kr.` 의 네임서버 두 개:** 예) `b.dns.kr` · `d.dns.kr`
  - 확인할 것: 점을 빼고 쳐서 `can't find kr` 을 적지 않았는가.
- **(나-1) 🔍 두 화면에서 `권한 없는 응답:` 줄이 다르게 나온 이유를 누가 답했는지로 설명하세요.**
  - 모범 답: 첫 화면은 리졸버가 담당 네임서버에게서 찾아다 준 답이라 「권한 없는 응답」이 붙었다. 둘째 화면은 원본을 가진 담당 네임서버가 직접 답해 그 줄이 없었다.
  - 핵심 낱말: **리졸버가 찾아다 줌 vs 담당자가 직접**
- **(나-2) 「권한 없는 응답」이 틀린 답이 아닌 이유와, 그래도 옛 값일 수 있는 경우를 설명하세요.**
  - 모범 답: 권한 없는 응답은 리졸버가 담당 서버의 원본을 옮겨 온 답이라 틀린 것이 아니다. 다만 리졸버가 TTL 동안 저장해 둔 답이라, 담당자가 막 IP 를 바꿨다면 TTL 이 지날 때까지 옛 값을 줄 수 있다.
  - 핵심 낱말: **원본을 옮겨 옴 · TTL 동안 옛 값 가능**
- **(나-3) `kr.` 의 네임서버가 3.1 의 리졸버 질문 순서 ① ② ③ 가운데 어느 질문을 받는 서버인지 설명하세요.**
  - 모범 답: ②번이다. `kr.` 의 네임서버는 TLD 층 서버라 `○○.kr` 의 IP 는 모르지만 그 이름의 담당 네임서버가 누구인지 알려 준다.
  - 핵심 낱말: **② · TLD 층 · 담당자를 알려 줌**
- **(다) 리졸버의 답이 의심스러울 때 담당 네임서버에 직접 물어 보는 것이 관제에서 왜 도움이 되는지 설명하세요.**
  - 모범 답: 리졸버의 답은 저장해 둔 옛 값이거나 중간에서 바뀐 값일 수 있다. 원본을 가진 담당 네임서버에 직접 물어 두 답을 비교하면, 리졸버 쪽 문제인지 도메인 자체가 바뀐 것인지 가릴 수 있다.
  - 핵심 낱말: **원본과 비교 · 어디서 달라졌는지 가림**

## 4교시 · 레코드와 캐시

### 문제 4-1 · 메일 서버와 별명 — MX · CNAME

- **(가-1) google.com 의 메일 서버(`mail exchanger`) · `MX preference`:** `smtp.google.com` · `10`
  - 확인할 것: 아래 IP 를 메일 서버로 적지 않았는가.
- **(가-2) www.naver.com 의 별명(`Aliases`) · 최종 이름(`이름:` 줄):** `www.naver.com` · `www.naver.com.nheos.com`
  - 확인할 것: 단계는 바뀔 수 있다. 맥북은 `canonical name =` 뒤가 최종 이름.
- **(나-1) MX 의 답이 IP 가 아니라 서버 이름인 이유와, 그 서버의 IP 는 어떻게 알아내는지 설명하세요.**
  - 모범 답: MX 레코드는 「이 도메인의 메일을 받을 서버가 누구인가」를 담는 기록이라 서버 이름을 답한다. 그 서버의 IP 는 그 이름의 A 레코드를 다시 물어 알아낸다.
  - 핵심 낱말: **MX = 서버 이름 · IP 는 A 레코드로**
- **(나-2) `www.naver.com` 이 별명을 거쳐 다른 이름으로 이어지는 이유를 CDN 과 이어서 설명하세요.**
  - 모범 답: 큰 사이트는 사용자와 가까운 서버에서 내용을 내주는 CDN 을 쓴다. 원래 이름에 CNAME 으로 CDN 쪽 이름을 걸어 두면, 리졸버가 별명을 끝까지 따라가 CDN 서버의 IP 를 받는다.
  - 핵심 낱말: **CNAME 으로 CDN 이름에 연결**
- **(다-1) 🔍 피싱 메일을 분석할 때 보낸 쪽 도메인의 MX 레코드를 확인하는 이유를 설명하세요.**
  - 모범 답: 정상적으로 메일을 주고받는 회사 도메인은 대개 MX 가 있다. 보낸 쪽 도메인에 MX 가 없거나 막 만든 낯선 서버를 가리키면, 피싱용으로 급히 만든 도메인일 가능성이 높다.
  - 핵심 낱말: **정상 도메인은 MX 가 있다 · 없거나 낯설면 의심**
- **(다-2) 잘 아는 회사 이름이 처음 보는 도메인으로 CNAME 이 걸려 있으면 관제는 무엇을 확인해야 하는지 설명하세요.**
  - 모범 답: 별명을 끝까지 따라가 마지막 이름과 IP 가 누구의 서버인지 확인한다. 그 회사가 쓰는 정상 CDN 이면 문제없지만, 남의 서버나 이미 지운 서비스를 가리키면 이름을 가로챌 수 있는 상태다.
  - 핵심 낱말: **별명을 끝까지 · 정상 CDN 인지 확인**

### 문제 4-2 · 내 PC 의 DNS 캐시와 TTL

- **(가-1) `example.com` 항목의 TTL · `//flushdns` 뒤에 그 항목이 남았나:** 예) `245` · 없어짐
  - 확인할 것: TTL 은 PC 마다 · 시각마다 다르다. 맥북은 「건너뜀」.
- **(가-2) 첫 파일 출력 네 줄:** `30 초: 캐시의 답을 쓴다` · `100 초: 캐시의 답을 쓴다` · `299 초: 캐시의 답을 쓴다` · `300 초: DNS 서버에 새로 묻는다`
  - 확인할 것: 300초 줄이 「새로 묻는다」인가.
- **(가-3) 두 번째 파일(`ttl = 60`) 출력 네 줄:** `30 초: 캐시의 답을 쓴다` · `100 초: DNS 서버에 새로 묻는다` · `299 초: DNS 서버에 새로 묻는다` · `300 초: DNS 서버에 새로 묻는다`
  - 확인할 것: 파이썬 출력이라 모두 같아야 한다.
- **(나-1) 두 파일의 100초 줄이 다르게 나온 이유를 만료 시각으로 설명하세요.**
  - 모범 답: 만료 시각은 첫 파일이 0 + 300 = 300초, 두 번째 파일이 0 + 60 = 60초다. 100초는 300 보다 작아 첫 파일에서는 캐시를 쓰고, 60 보다 커서 두 번째 파일에서는 이미 만료되어 새로 묻는다.
  - 핵심 낱말: **만료 시각 300 vs 60**
- **(나-2) 첫 파일에서 299초는 캐시를 쓰고 300초는 새로 묻는 이유를 `<` 비교로 설명하세요.**
  - 모범 답: `299 < 300` 은 `True` 라 아직 만료 전이어서 캐시를 쓴다. `300 < 300` 은 `False` 라 만료 시각이 되어 새로 묻는다.
  - 핵심 낱말: **같으면 False · 만료 시각에 새로 묻는다**
- **(나-3) 1번에서 `nslookup` 이 아니라 `ping` 으로 캐시를 채운 이유를 설명하세요.**
  - 모범 답: `nslookup` 은 PC 캐시를 거치지 않고 DNS 서버에 바로 물어 캐시에 남기지 않는다. `ping` 은 보통 프로그램처럼 PC 의 DNS 기능을 거쳐 묻기 때문에 답이 캐시에 저장된다.
  - 핵심 낱말: **nslookup 은 캐시를 안 거침 · ping 은 거침**
- **(다-1) 🔍 담당 네임서버에서 IP 를 바꿔도 한동안 옛 IP 로 접속되는 이유를 TTL 과 캐시로 설명하세요.**
  - 모범 답: 리졸버와 PC 는 받은 답을 TTL 동안 캐시에 저장하고 그동안 다시 묻지 않는다. 그래서 담당자가 IP 를 바꿔도 만료 시각 전까지는 저장해 둔 옛 IP 로 접속된다.
  - 핵심 낱말: **TTL 동안 다시 묻지 않음 → 옛 IP**
- **(다-2) 이상한 주소로 계속 접속되는 PC 에서 관제가 `//flushdns` 를 먼저 하는 이유를 설명하세요.**
  - 모범 답: PC 캐시에 옛 답이나 위조된 답이 남아 있으면 TTL 동안 계속 그 주소로 간다. `//flushdns` 로 지우면 다음 접속에서 DNS 서버에 새로 물으므로, 문제가 캐시에 있었는지 바로 확인할 수 있다.
  - 핵심 낱말: **남은 옛 · 위조 답을 지우고 새로 묻게**

### 이 교시에 새로 안 것

- 자유. 그 교시 개념 하나와 이유가 있으면 충분합니다.

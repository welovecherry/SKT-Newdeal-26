# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">2교시 (10:00–10:50) · VPN 이 필요한 이유 · 터널 · 암호화</mark>

### 왜 필요한가

1. 재택근무 · 출장 중인 직원도 회사 업무 포털 · 메일 서버를 써야 합니다. 그런데 회사 서버를 인터넷 전체에 그대로 열면 누구나 접속을 시도할 수 있습니다.
2. 집 · 카페에서 회사까지는 공용 인터넷이라, 중간 장비나 같은 와이파이에 붙은 사람이 내용을 볼 수 있습니다.
3. VPN 은 이 두 문제를 함께 풉니다. 회사 서버는 VPN 을 거친 사람에게만 열고, 회사 VPN 은 보통 터널에 암호화를 함께 써서 오가는 내용을 숨깁니다.

### 2.1 터널링 — 패킷을 다른 패킷 안에 넣어 보낸다

**여기 나오는 말**

- **VPN (Virtual Private Network)** (브이피엔)
  - 공용 인터넷 위에서 회사 망(사설망)에 붙은 것처럼 통신하게 해 주는 기술
- **터널링 (tunneling)** (터널링)
  - 원래 패킷을 **통째로 다른 패킷 안에 넣어** 보내는 것
  - 10/12 에 배운 캡슐화(헤더를 붙여 감싸기)를 한 번 더 하는 것이다
  - 감싸기만 할 뿐이라 **터널만으로는 내용이 숨겨지지 않는다.** 숨기는 것은 암호화다
- **암호화 (encryption)** (인크립션)
  - 중간에서 봐도 **읽을 수 없는 글자로 바꾸는** 것. 키를 가진 쪽만 원래대로 되돌린다(복호화)
- **VPN 게이트웨이 (VPN gateway)** (브이피엔 게이트웨이)
  - 회사 쪽에서 터널을 맺는 장비. 바깥 헤더를 떼고 복호화해 원래 패킷을 사내망에 보낸다
- **VPN 주소**
  - VPN 에 접속한 PC 가 **VPN 게이트웨이에게서 받는 사내망 주소**. 캡슐화된 원래 패킷의 출발지가 된다
- **네트워크 어댑터 (network adapter)** (네트워크 어댑터)
  - PC 가 망에 연결되는 **통로 하나**. 랜 카드 · 와이파이처럼 실제 장치도 있고, VPN 프로그램이 만드는 **가상 어댑터**도 있다

```
집 PC ─[원래 패킷: 출발 10.8.0.21 → 도착 10.10.20.5]
      │  ① 원래 패킷을 암호화한다
      │  ② 바깥 헤더를 씌운다: 출발 211.36.10.7(집 공인 IP) → 도착 203.0.113.1(회사 VPN 게이트웨이)
      ▼
공용 인터넷 ── 중간 라우터는 바깥 헤더만 보고 보낸다
      ▼
회사 VPN 게이트웨이 ── ③ 바깥 헤더를 떼고 복호화한다 ── ④ 원래 패킷이 사내망으로 간다 → 업무 포털 10.10.20.5
```

| | VPN 없이 | VPN 사용 (터널링 + 암호화) |
|---|---|---|
| 중간 라우터가 보는 도착지 | 업무 포털 서버 주소 | 회사 VPN 게이트웨이 주소 |
| 안쪽 내용 · 사내 주소 | 암호화하지 않았으면 보인다 | 암호화되어 보이지 않는다 |
| 회사 서버가 보는 출발지 | 집 공인 IP | **VPN 주소**(사내망 주소) |
| 내 PC 의 어댑터 | 랜 · 와이파이 | 랜 · 와이파이 **+ VPN 가상 어댑터** |

VPN 에 붙으면 내 PC 가 사내망 안에 있는 것처럼 동작합니다. 회사 서버에는 집 공인 IP 가 아니라 VPN 주소가 출발지로 보입니다.

### ✍️ 문제 2-1 · 내 PC 의 네트워크 어댑터 읽기

**할 일** — `ipconfig` 로 내 PC 의 네트워크 어댑터 목록을 보고, 기본 게이트웨이가 있는 어댑터와 그 IPv4 주소를 보고서에 적습니다.

**왜 중요한가** — VPN 에 붙으면 어댑터가 하나 더 생기고 그 어댑터가 VPN 주소를 받습니다. 지금 내 PC 의 어댑터 목록을 읽을 줄 알아야, 직원 PC 를 점검할 때 「VPN 이 붙어 있는지 · 어느 주소로 나가는지」를 확인할 수 있습니다.

**이 문제에 나오는 말**

- **어댑터 이름 줄**
  - `ipconfig` 결과에서 `… 어댑터 …:` 로 끝나는 줄. 그 아래가 그 어댑터의 주소다
  - 예: `이더넷 어댑터 이더넷:` · `무선 LAN 어댑터 Wi-Fi:`

**순서**

1. **[터미널]** 어댑터 목록을 봅니다.
   ```bash
   ipconfig
   ```
   맥북: `ifconfig`
2. **[터미널]** `… 어댑터 …:` 로 끝나는 줄을 위에서부터 셉니다(영어 Windows 는 `… adapter …:`). 맥북은 줄 맨 앞에 붙은 이름(`lo0` · `en0` · `utun0` …)을 셉니다.
3. **[터미널]** 그 가운데 `기본 게이트웨이` 에 주소가 적힌 어댑터를 찾고, 같은 어댑터의 `IPv4 주소` 를 읽습니다. 맥북은 `en0` 아래 `inet` 뒤의 주소를 읽습니다.

   - (가-1) `ipconfig` 에 나온 어댑터 이름 줄을 모두 적고, 몇 개였는지 적어 주세요.

   - (다) 회사 서버의 접속 로그에는 VPN 으로 들어온 직원의 출발지가 집 공인 IP 가 아니라 VPN 주소로 남습니다. 관제 담당자가 VPN 주소만 보고는 알 수 없는 것은 무엇일까요?

#### 🐍 문법 상자 · 딕셔너리 안의 딕셔너리 `d["키"]["키"]` — 두 번 꺼내기

```python
outer = {"dst": "203.0.113.1", "data": {"dst": "10.10.20.5"}}  # data 칸의 값이 또 딕셔너리인 딕셔너리를 outer 에 담는다
print(outer["dst"])                                             # 바깥 딕셔너리의 dst 를 꺼내 출력한다
print(outer["data"])                                            # data 칸을 꺼내면 안쪽 딕셔너리 통째로 나온다
print(outer["data"]["dst"])                                     # 꺼낸 안쪽 딕셔너리에서 dst 를 한 번 더 꺼내 출력한다

# 203.0.113.1              ← print(outer["dst"])
# {'dst': '10.10.20.5'}    ← print(outer["data"]) — 중괄호가 있는 딕셔너리
# 10.10.20.5               ← print(outer["data"]["dst"])
```

| 쓰는 것 | 뜻 |
|---|---|
| `d["data"]` | 바깥 딕셔너리에서 `data` 칸을 꺼낸다 |
| `d["data"]["dst"]` | 꺼낸 값이 딕셔너리일 때만 그 안의 `dst` 를 또 꺼낼 수 있다 |
| 꺼낸 값이 글자일 때 `["dst"]` | `TypeError` — 글자는 `["이름"]` 으로 꺼낼 수 없다 |

### ✍️ 문제 2-2 · 캡슐화된 패킷 — 암호화하면 무엇이 안 보이나

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">3교시 (11:00–11:50) · Site-to-Site VPN · Remote Access VPN</mark>

### 왜 필요한가

1. VPN 은 **무엇을 잇느냐**에 따라 두 가지로 나뉩니다. 본사와 지점처럼 **망과 망**을 잇거나, 직원 노트북처럼 **기기 한 대**를 회사 망에 붙입니다.
2. 종류에 따라 누가 터널을 세우는지, 직원이 무엇을 해야 하는지, 로그에 어떤 주소가 남는지가 다릅니다.
3. 오후 방화벽 규칙에서 「VPN 으로 들어온 직원」과 「지점 PC」를 주소 범위로 구분해 다르게 허용합니다.

### 3.1 망을 잇는가, 기기 한 대를 붙이는가

**여기 나오는 말**

- **Site-to-Site VPN** (사이트 투 사이트)
  - **망과 망**을 통째로 잇는 VPN. 양쪽 VPN 게이트웨이끼리 터널을 세워 계속 유지한다
- **Remote Access VPN** (리모트 액세스)
  - **기기 한 대**를 회사 망에 붙이는 VPN. PC 에 VPN 프로그램(클라이언트)을 깔고 사용자가 직접 접속한다
- **VPN 클라이언트 (client)** (클라이언트)
  - Remote Access VPN 에 접속하려고 직원 PC 에 까는 프로그램
- **주소 풀 (address pool)** (어드레스 풀)
  - Remote Access VPN 게이트웨이가 접속한 PC 에 **하나씩 나눠 주는 주소 범위**
  - 예: `10.8.0.0/24`

| | Site-to-Site VPN | Remote Access VPN |
|---|---|---|
| 잇는 것 | 망 ↔ 망 (본사 ↔ 지점) | 기기 한 대 ↔ 회사 망 |
| 터널을 세우는 쪽 | 양쪽 VPN 게이트웨이 장비 | 직원 PC 의 VPN 클라이언트 |
| 직원이 하는 일 | 없음 — VPN 이 있는 줄도 모른다 | 프로그램을 켜고 로그인한다 |
| 유지 | 한 번 세우면 계속 | 접속할 때마다 인증하고, 끊으면 사라진다 |
| 터널 수 | 지점마다 1개 | 접속한 직원 PC 마다 1개 |
| 회사 서버가 보는 출발지 | 지점 PC 의 원래 주소 (예 `192.168.20.15`) | 주소 풀에서 받은 VPN 주소 (예 `10.8.0.21`) |
| 맞는 곳 | 본사와 지점 · 본사와 클라우드 데이터센터 | 재택근무자 · 출장자 |

⚠ 휴대폰 앱스토어의 **상용 VPN 앱**(개인용 VPN 서비스)도 터널과 암호화를 씁니다. 하지만 터널의 끝이 회사가 아니라 **VPN 업체의 서버**라서 회사 망에 붙지 않습니다. 켜면 그 PC 의 인터넷 트래픽이 암호화된 채 업체 서버로 갑니다.

### 3.2 로그의 출발지 주소로 어디서 왔는지 가리기

회사 방화벽 · 서버 로그에는 출발지 주소만 남습니다. 그 주소가 **어느 범위에 들어 있는지**로 어디서 들어왔는지 가립니다. 10/13 오후에 쓴 `ipaddress.ip_address()` 와 `주소 in 망` 을 그대로 씁니다.

| 범위 (오늘 쓰는 예시 회사) | 뜻 |
|---|---|
| `10.8.0.0/24` | Remote Access VPN 주소 풀 — VPN 으로 들어온 직원 |
| `192.168.20.0/24` | Site-to-Site VPN 으로 이어진 부산 지점 망 |
| `10.10.0.0/16` | 본사 PC · 서버 |

VPN 주소는 **VPN 게이트웨이**가 나눠 줍니다. 그래서 VPN 게이트웨이는 누가 · 언제 · 어느 공인 IP 에서 접속해 · 어떤 VPN 주소를 받았는지 기록을 남깁니다(4교시에 이 기록을 읽습니다).

### 4.1 VPN 접속 로그에서 먼저 확인하는 것

**여기 나오는 말**

- **접속 로그 (access log)** (액세스 로그)
  - VPN 게이트웨이가 접속 시도마다 남기는 기록 한 줄 — 사용자 · 시각 · 출발 공인 IP · 결과
- **무차별 대입 (brute force)** (브루트 포스)
  - 비밀번호를 여러 번 바꿔 넣어 보며 로그인을 시도하는 공격
- **경계 기반 보안 (perimeter security)** (퍼리미터 시큐리티)
  - 회사 망 **안은 믿고 밖은 믿지 않는** 방식. 경계를 한 번 통과하면 안에서는 다시 묻지 않는다

| 확인하는 것 | 이 로그에서 보는 칸 | 의심하는 까닭 |
|---|---|---|
| 업무 시간 밖 접속 | 시각 | 직원이 잘 쓰지 않는 시간대 |
| 해외 접속 | 나라 (출발 공인 IP 로 추정한 값) | 국내 근무 직원이 해외에서 접속할 일이 드물다 |
| 실패가 이어진 뒤 성공 | 결과 | 무차별 대입으로 비밀번호를 맞혔을 수 있다 |

#### 🐍 문법 상자 · 시각은 `int()` 로 바꿔 비교 — 글자끼리 `<` 는 글자 순서

```python
print("10" < "8")                       # 글자끼리 < 로 비교하면 숫자 크기가 아니라 첫 글자부터 글자 순서로 비교한다. "1" 이 "8" 보다 앞이라 True 를 출력한다
print(int("10") < int("8"))             # int() 로 숫자로 바꾼 뒤 비교하면 10 < 8 이라 False 를 출력한다
print(int("22:15".split(":")[0]))       # "22:15" 를 : 로 잘라 앞 칸 "22" 를 꺼내고, int() 로 숫자 22 로 바꿔 출력한다

# True     ← print("10" < "8") — 10시가 8시보다 이르다는 틀린 결과
# False    ← print(int("10") < int("8"))
# 22       ← print(int("22:15".split(":")[0]))
```

| 쓰는 것 | 뜻 |
|---|---|
| 글자 `"10" < "8"` | 글자 순서로 비교한다 — 시각 비교에 쓰면 틀린다 |
| `int(시각.split(":")[0])` | 시각 글자에서 「시」만 꺼내 숫자로 바꾼다. 그다음에 `<` · `>=` 로 비교한다 |

### 4.2 VPN 은 들어올 때 한 번만 확인한다

VPN 게이트웨이는 접속할 때 아이디 · 비밀번호를 확인합니다. 통과한 뒤의 패킷은 VPN 주소를 출발지로 사내망에 들어가고, VPN 은 그 안에서 어디에 접속하는지 다시 묻지 않습니다.

```
[VPN 게이트웨이]  아이디 · 비밀번호 확인 ── 한 번 ──▶ 통과
                                                      │
          사내망 안 ──▶ 업무 포털 · 관리 서버 · 고객 DB … 다시 묻지 않는다
```

**이 절에 나오는 포트 번호** (10/12 에 배운 포트 — 서버 안에서 프로그램을 구별하는 번호)

| 포트 | 쓰는 서비스 |
|---|---|
| `443` | HTTPS — 웹 페이지(업무 포털) |
| `22` | SSH (에스에스에이치) — 서버에 원격으로 접속해 명령을 내리는 관리용 접속 |
| `3306` | MySQL (마이에스큐엘) — 데이터베이스(DB) 서버 |

# 아침 과제 12 · 서버에서 파일 속 글 고치기 — `vim`

10월 16일 (금) · 아침 과제

**오늘 하는 일:** 서버에는 마우스도 VS Code 도 없습니다. 터미널 안에서 파일을 열어 글을 고치고 저장하는 편집기 `vim` 을 배웁니다. 파일을 만들고, 고치고, 저장하거나 저장 없이 나가는 것까지 직접 해 봅니다.

오늘 새로 쓰는 것은 `vim` 하나입니다. 파일을 만드는 `touch`, 복사하는 `cp`, 내용을 보는 `cat` 은 10/14 에 배웠습니다. 연습은 저장소 **바깥**에 만든 연습용 폴더 `vim_practice` 안에서 합니다. 실수해도 과제 파일에는 영향이 없습니다.

**오늘 못 끝냈으면 오후 5시 이후에 마무리합니다.**

## 3. `vim` 의 모드와 키를 익힙니다

**왜 중요한가** — `vim` 은 처음 열면 글자를 쳐도 입력되지 않아서 많은 사람이 여기서 막힙니다. 모드 세 개와 저장 · 종료 키만 알면 서버에서 파일을 고치고 나올 수 있습니다.

`vim`(빔 · 터미널 안에서 쓰는 글 편집기)은 마우스 없이 키보드로만 씁니다. 키가 하는 일을 정하는 상태, 즉 **모드**(mode)가 세 가지 있습니다.

| 모드 | 들어가는 법 | 이때 키가 하는 일 | 화면에서 보이는 것 |
|---|---|---|---|
| 일반 모드 (Normal mode · 명령을 내리는 상태) | `vim` 을 열면 처음 여기 · 다른 모드에서 `Esc` | 키가 **명령**이 된다 — 이동 · 지우기 · 복사 | 왼쪽 아래가 비어 있다 |
| 입력 모드 (Insert mode · 글자를 입력하는 상태) | 일반 모드에서 `i` | 키가 **글자**로 입력된다 | 왼쪽 아래 `-- INSERT --` |
| 명령줄 모드 (Command-line mode · 저장 · 종료 명령을 치는 상태) | 일반 모드에서 `:` | 저장 · 종료 · 바꾸기 명령을 친다 | 왼쪽 아래 `:` 와 친 글자 |

아래 키는 모두 **일반 모드**에서 칩니다. `:` 로 시작하는 명령은 끝에 Enter 를 누릅니다.

| 키 | 하는 일 |
|---|---|
| `i` | 입력 모드로 들어간다 (커서 앞에 글자가 들어간다) |
| `Esc` | 일반 모드로 돌아온다 |
| `:w` | **저장**한다 (write) |
| `:q` | 나간다 (quit). 고친 뒤 저장하지 않았으면 나가지지 않는다 |
| `:wq` | 저장하고 나간다 |
| `:q!` | **저장하지 않고** 강제로 나간다. 고친 내용은 사라진다 |
| `dd` | 커서가 있는 줄 하나를 지운다 |
| `yy` · `p` | 줄을 복사한다 · 커서 아래 줄에 붙여 넣는다 |
| `u` | 방금 한 것을 되돌린다 |
| `/단어` | 단어를 찾는다. `n` 을 누르면 다음 것으로 간다 |
| `gg` · `G` | 맨 위 줄로 · 맨 아래 줄로 간다 |
| `:%s/옛/새/g` | 파일 **전체**에서 `옛` 을 `새` 로 바꾼다 |

방향키로 커서를 움직여도 됩니다.

**키가 먹지 않을 때** — 아래 둘 중 하나입니다.
- 키보드가 **한글 상태**이면 `i` 가 `ㅑ` 로 입력되어 아무 일도 일어나지 않습니다. 한/영 키로 영문으로 바꿉니다.
- 입력 모드(`-- INSERT --`)에서 `:wq` 를 치면 글자로 입력됩니다. 먼저 `Esc` 를 누릅니다.

**어떻게 해도 못 나가겠으면** `Esc` 를 두 번 누르고 `:q!` Enter 를 입력합니다.

## 4. 네 가지 실습을 합니다

**왜 중요한가** — 키 표는 읽기만 해서는 손에 붙지 않습니다. 서버에서 설정 파일을 열 때 하는 일을 순서대로 해 보면 저장 · 나가기 · 되돌리기가 몸에 익습니다.

모두 2번에서 만든 `vim_practice` 폴더 안에서 합니다. 시작하기 전에 `pwd` 로 확인합니다. 명령은 **터미널**에서 칩니다.

### 실습 ① 파일은 저장해야 만들어집니다

**할 일** — `touch` 와 `vim` 이 파일을 만드는 때가 어떻게 다른지 확인하고, 로그 세 줄을 저장합니다.

**왜 중요한가** — `touch` 는 파일을 바로 만들지만 `vim` 은 저장해야 파일이 생깁니다. 이 차이를 알아야 서버에서 「분명히 열고 썼는데 파일이 없다」는 일을 만나지 않습니다.

1. `[터미널]` `touch` 로 빈 파일을 만들고 `ls` 로 확인합니다.
   ```
   touch a.txt
   ls
   ```
2. `[터미널]` 없는 파일 이름으로 `vim` 을 열고, 아무것도 하지 않고 `:q` Enter 로 나갑니다. 나간 뒤 `ls` 로 확인합니다.
   ```
   vim b.txt
   ls
   ```
3. `[터미널]` 이번에는 `notes.txt` 를 엽니다. `i` 를 눌러 입력 모드로 들어가고, 왼쪽 아래에 `-- INSERT --` 가 보이는지 확인한 뒤 아래 세 줄을 입력합니다 (줄마다 Enter).
   ```
   vim notes.txt
   ```
   ```
   2026-10-16 09:30:00 INFO login ok user=kim
   2026-10-16 09:31:10 WARN failed login user=admin
   2026-10-16 09:31:12 WARN failed login user=admin
   ```
4. `[터미널]` `Esc` 를 눌러 일반 모드로 돌아오고, `:wq` Enter 로 저장하고 나갑니다. 터미널로 돌아오면 내용을 확인합니다.
   ```
   cat notes.txt
   ```

| 나오면 성공 |
|---|
| 1번의 `ls` 에 `a.txt` 가 있다 (내용은 비어 있다) |
| 2번의 `ls` 에 `b.txt` 가 **없다** |
| 4번의 `cat` 으로 로그 세 줄이 보인다 |

### 실습 ② 저장하지 않고 나가면 어떻게 되는지 봅니다

**할 일** — 파일을 고친 뒤 저장하지 않고 나가 보고, 막히는 화면과 빠져나오는 법을 익힙니다.

**왜 중요한가** — 서버의 설정 파일은 저장하는 순간 실제로 바뀝니다. 실수로 고쳤을 때는 `:q!` 로 저장 없이 나가야 원래대로 남습니다.

1. `[터미널]` `notes.txt` 를 열고 `i` 를 눌러 아무 글자나 입력합니다 (예: `TEST`).
   ```
   vim notes.txt
   ```
2. `[터미널]` `Esc` 를 누르고 `:q` Enter 로 나가 봅니다. 나가지지 않고 화면 아래에 빨간 글씨 `E37: No write since last change (add ! to override)` 가 나옵니다. 「저장하지 않은 변경이 있다」는 뜻입니다.
3. `[터미널]` 이번에는 `:q!` Enter 로 나갑니다. 나간 뒤 내용을 확인합니다.
   ```
   cat notes.txt
   ```

| 나오면 성공 |
|---|
| 2번에서 `E37` 이 나오고 `vim` 이 닫히지 않는다 |
| 3번의 `cat` 에 `TEST` 가 **없다** |

### 실습 ③ 줄을 지우고 복사하고 되돌립니다

**할 일** — 일반 모드의 키로 줄을 지우고, 되돌리고, 복사해 붙여 넣습니다.

**왜 중요한가** — 로그나 설정 파일에서 비슷한 줄을 복사해 값만 바꾸는 일이 잦습니다. `dd` 로 잘못 지워도 `u` 로 되돌릴 수 있다는 것을 알아 두면 안심하고 고칠 수 있습니다.

1. `[터미널]` `notes.txt` 를 열고 `gg` 로 맨 위 줄로 갑니다.
   ```
   vim notes.txt
   ```
2. `[터미널]` `dd` 를 눌러 첫 줄을 지웁니다. 줄이 두 개만 남은 것을 확인한 뒤 `u` 를 눌러 되돌립니다. 세 줄로 돌아옵니다.
3. `[터미널]` 방향키 아래(↓)로 둘째 줄(`09:31:10 WARN …`)로 내려갑니다. `yy` 로 그 줄을 복사하고 `p` 로 붙여 넣습니다.
4. `[터미널]` `:wq` Enter 로 저장하고 나간 뒤 내용을 확인합니다.
   ```
   cat notes.txt
   ```

| 나오면 성공 |
|---|
| 2번에서 줄이 두 개로 줄었다가 `u` 로 세 개로 돌아왔다 |
| 4번의 `cat` 에 로그가 **네 줄**이고, `09:31:10 WARN` 줄이 두 번 연속으로 있다 |

### 실습 ④ 단어를 찾고 한 번에 바꿉니다

**할 일** — 파일에서 `WARN` 을 찾고, 전체를 `ERROR` 로 바꿉니다.

**왜 중요한가** — 긴 로그에서 원하는 단어를 눈으로 찾지 않고 `/` 로 찾습니다. 설정 파일 안의 주소나 포트 번호를 한 번에 바꿀 때도 `:%s` 를 씁니다.

1. `[터미널]` `notes.txt` 를 열고 `/WARN` Enter 를 입력합니다. 커서가 첫 `WARN` 으로 이동합니다. `n` 을 눌러 다음 `WARN` 으로 이동해 봅니다.
   ```
   vim notes.txt
   ```
2. `[터미널]` `:%s/WARN/ERROR/g` Enter 를 입력합니다. `WARN` 이 있던 줄이 모두 바뀝니다.
3. `[터미널]` 바뀐 것을 확인한 뒤 `:wq` Enter 로 저장하고 나갑니다. 내용을 확인합니다.
   ```
   cat notes.txt
   ```

| 나오면 성공 |
|---|
| 1번에서 `WARN` 글자 위로 커서가 움직인다 |
| 3번의 `cat` 에 `WARN` 이 하나도 없고, 같은 줄들이 `ERROR` 로 바뀌어 있다 |

## ⭐ 다 한 사람만 합니다

**왜 중요한가** — 서버의 설정 파일은 고치기 전에 복사본을 만들어 두고, 고친 뒤 무엇이 바뀌었는지 비교합니다. 잘못 고쳤을 때 복사본으로 되돌릴 수 있고, 바뀐 줄만 보면 확인이 빠릅니다.

`vim_practice` 폴더로 돌아가(`cd ../vim_practice`) 서버 설정 파일을 흉내 낸 `server.conf` 를 고칩니다. `pwd` 결과가 `…/vim_practice` 로 끝나는지 먼저 확인합니다. **그 위치가 아니면 `touch` 하지 말고 `cd` 로 먼저 옮깁니다** — `…/security-agent-toolkit` 으로 끝나면 `cd ../vim_practice`, 그다음 `pwd` 를 다시 칩니다.

1. `[터미널]` `touch` 로 파일을 만들고 `vim` 으로 열어 아래 네 줄을 입력한 뒤 `Esc`, `:wq` 로 저장합니다.
   ```
   pwd
   touch server.conf
   vim server.conf
   ```
   ```
   # server settings
   port=22
   allowed_ip=10.0.0.5
   log_level=info
   ```
2. `[터미널]` 고치기 전에 복사본을 만듭니다 (10/14 에 배운 `cp`).
   ```
   cp server.conf server.conf.bak
   ```
3. `[터미널]` `server.conf` 를 `vim` 으로 열고 두 가지를 고칩니다. `G` 로 맨 아래 줄로 간 뒤 `o`(아래에 새 줄을 만들고 입력 모드로 들어감)를 눌러 `blocked_ip=10.0.0.99` 를 입력하고 `Esc`. 이어서 `:%s/info/debug/` Enter. 마지막에 `:wq`.
4. `[터미널]` 복사본과 고친 파일의 차이를 봅니다.
   ```
   diff server.conf.bak server.conf
   ```

| 나오면 성공 |

> - 이 교시에서 하는 일: 「끊긴다」를 지연 · 지터 · 손실 세 숫자로 바꾸고, 내 PC 에서 직접 잽니다.
> - 끝나면 쓰는 것: **보고서 한 줄**(고객에게 보낼 답 한 문장)

### 왜 필요한가

1. 고객이 「인터넷이 느려요」라고 하면 무엇이 느린지 알 수 없습니다. 숫자로 바꿔야 원인을 찾을 수 있습니다.
2. 느린 이유는 세 가지입니다. ① **늦게 도착합니다**(지연). ② **도착 시간이 들쭉날쭉합니다**(지터). ③ **아예 도착하지 않습니다**(손실). 원인이 다르면 고치는 곳도 다릅니다.

### 5.1 세 가지 숫자

- **지연**(latency · 레이턴시)
  - 보낸 것이 도착할 때까지 걸린 시간. 실무에서는 갔다 돌아오는 왕복 시간(**RTT**: Round Trip Time · 알티티)을 잰다
  - 단위는 ms(밀리초, 1000분의 1초)
- **지터**(jitter · 지터)
  - 지연이 얼마나 들쭉날쭉한가. 이 수업에서는 **이웃한 두 값의 차이의 평균**으로 구한다
- **패킷 손실**(packet loss · 패킷 로스)
  - 보낸 것 가운데 응답이 오지 않은 비율(%)
  - 손실된 것은 재전송해야 한다(어제 10/15 오후 문제 5-2 에서 본 `tcp.analysis.retransmission`)
- 예: 응답이 `50, 52, 120, 48` ms 로 왔다면 평균은 67.5 ms 입니다. 평균은 나쁘지 않지만 세 번째 값만 120 입니다. 실시간 음성 · 화상회의는 일정한 간격으로 도착해야 해서, **평균이 좋아도 지터가 크면 끊깁니다.**
- 지연이 일정하게 큰 것은 조금 늦게 들리는 정도입니다. 끊기는 것은 지터와 손실 때문입니다.
- **회선**은 통신사에서 빌려 쓰는 인터넷 연결 하나입니다. 회사는 회선을 여러 개 쓰는 경우가 많아서 「어느 회선이 느린가」를 따로 봅니다. 오늘 표의 회선 X · Y · Z 와 회선 A · B · C 는 ping 을 잰 연결 하나씩입니다(예: 본사 인터넷, 지점 VPN, 무선).

**현실에서 마주치는 곳**

- **화상회의**(Zoom · Google Meet · Microsoft Teams)에서 말이 끊기거나 화면이 얼어붙으면 <mark>지터 · 손실</mark>을 의심합니다.
- **대용량 파일 내려받기**가 느리면 지연보다 <mark>전송량(대역폭)</mark>을 먼저 봅니다.
- **온라인 게임**에서 말하는 「핑 30」은 <mark>지연(RTT)</mark>이 30 ms 라는 뜻입니다. 오늘 `ping` 으로 재는 값과 같은 것입니다.

### ✍️ 문제 5-1 · 지연 · 지터 · 손실을 직접 계산하기

**📍 이런 상황이 있습니다**

- 지연 · 지터 · 손실 <mark>세 숫자</mark>를 따로 봐야 원인이 보입니다.
- 현업에서는 ping 요약이나 모니터링 도구가 이 값을 계산해 줍니다. 그래도 **계산 방식을 알아야** 도구가 보여 주는 숫자를 믿고 해석할 수 있습니다.

**🎯 할 일**

3. X 와 Y 의 <mark>지터</mark>를 구합니다. (이웃한 두 값의 차이를 모두 구해 그 평균을 냅니다. 5 개면 차이가 4 개입니다)

| 회선 | 1번 | 2번 | 3번 | 4번 | 5번 |
|---|---|---|---|---|---|
| X | 30 | 31 | 29 | 30 | 30 |

**계산 방법**

- 손실률: 못 받은 개수 ÷ 보낸 개수 × 100

**순서**

### 5.2 ping 으로 직접 재기

- `ping -n 10 주소` 는 신호를 10 번 보내고 응답 시간을 한 줄씩 보여 줍니다. (맥북은 `ping -c 10 주소`)
  - 줄마다 `시간=18ms` 처럼 응답 시간이 나옵니다(맥북은 `time=18.3 ms`)
  - 맨 아래 요약에 보낸 개수 · 받은 개수 · 손실 %와 최소 · 최대 · 평균이 나옵니다
- 응답이 없으면 `요청 시간이 만료되었습니다` 같은 줄이 나옵니다. 이것이 손실 한 번입니다.
- 글자가 깨져 보여도 `=18ms` 처럼 숫자와 `ms` 만 읽으면 됩니다. 응답이 없는 줄은 숫자가 없는 줄입니다.
- 이 명령은 10/12 오전에 한 것과 같습니다. 오늘은 열 개 응답 시간으로 **지터까지 구해 봅니다.**
  - 읽는 값: 응답 열 개의 시간(순서대로), 요약의 평균 · 손실
  - 대상: 구글이 운영하는 공개 DNS 서버 `8.8.8.8`

> - 끝나면 쓰는 것: **보고서 한 줄**(고객에게 보낼 답 한 문장)

### 왜 필요한가

1. 회선이 여러 개이고 측정값이 수백 개이면 하나씩 계산하기 어렵습니다. 5교시에서 직접 계산한 방법을 그대로 코드로 옮깁니다.
2. 계산한 숫자에 **기준**을 붙여야 이 회선을 쓸 수 있는지 판정할 수 있습니다. 오늘은 화상회의 기준으로 판정합니다.

#### 🐍 문법 상자 1 · `abs()` — 부호를 뗀 값

- `abs(수)` 는 **마이너스를 떼어 낸 값**(절댓값)입니다. 두 값의 차이를 구할 때 어느 쪽이 큰지 신경 쓰지 않게 해 줍니다.

```python
print(abs(5))
print(abs(-5))
print(abs(31 - 30))     # 큰 값에서 작은 값을 빼면 1
print(abs(29 - 31))     # 작은 값에서 큰 값을 빼도 2 (마이너스가 사라진다)

# 5
# 5
# 1
# 2
```

- 오늘은 이웃한 두 응답 시간의 **차이**를 구할 때 씁니다.

#### 🐍 문법 상자 2 · 독스트링 `"""…"""` — 함수가 하는 일을 함수 안에 적기

- 함수 이름 줄 **바로 아래**에 따옴표 세 개(`"""`)로 감싼 글을 쓰면, 그 글이 **함수 전체의 설명**이 됩니다. 이것을 독스트링이라고 부릅니다.
- `#` 주석은 **줄 하나**를 설명하고, 독스트링은 **함수 전체**(하는 일 · 받는 값 · 리턴하는 값)를 설명합니다.
- `help(함수 이름)` 을 치면 독스트링이 화면에 나옵니다. `#` 주석은 나오지 않습니다.

```python
def average(nums):
    """응답 시간 리스트의 평균을 구한다.

    입력: 응답 시간 리스트 nums
    리턴: 평균 값
    """
    return sum(nums) / len(nums)

print(average([30, 31, 29]))
help(average)

# 30.0
# Help on function average in module __main__:
#
# average(nums)
#     응답 시간 리스트의 평균을 구한다.
#
#     입력: 응답 시간 리스트 nums
#     리턴: 평균 값
```

**이 문제에 나오는 말**

- **`range(1, len(got))`**
  - 위치 번호 `1` 부터 `len(got) - 1` 까지 차례로 꺼냄(끝 숫자는 포함되지 않는다). 예: `got` 에 값이 5 개이면 `i` 는 1, 2, 3, 4 로 네 번 돈다. 0 번 값에는 「바로 앞 값」이 없어서 1 번부터 돈다
- **`got[i]` · `got[i - 1]`**
  - `got[i]` 는 i 번째 값, `got[i - 1]` 은 바로 앞 값. 둘의 차이가 이웃한 두 값의 차이다
- **`None`**
  - 「값이 없다」는 뜻. 응답이 없던 ping(손실)을 `None` 으로 적어 둔다
  - `x != None` 은 x 에 값이 있으면 `True`. 주어진 `measure` 가 응답을 받은 값만 고를 때 쓰고, 오늘은 읽기만 한다

   ```python
       jitter_value = jitter(got)            # 위에서 만든 jitter 함수에 got 을 넘겨 지터를 받는다
       loss = (len(data) - len(got)) / len(data) * 100   # 손실률 = 못 받은 개수 ÷ 보낸 개수 × 100

       print(name, "| 지연", round(delay, 1), "ms | 지터", round(jitter_value, 1), "ms | 손실", round(loss), "%")   # 한 줄로 출력한다

   for name in LINES:                        # 회선 이름을 하나씩 꺼낸다
   ```

   ```python
   # 3 개 회선의 ping 결과 10 번씩 (단위: ms). None 은 응답이 없었던 것(손실)이다
   LINES = {
       "회선 A": [22, 21, 23, 22, 21, 22, 23, 22, 21, 22],
       "회선 B": [18, 19, 95, 17, 18, 110, 19, 18, 92, 17],
       "회선 C": [40, 41, None, 42, 40, None, 41, 43, None, 40],
   }

   # 화상회의에 쓸 수 있는 기준 (이 수업에서 정한 값)
   MAX_DELAY = 150    # 평균 지연 150 ms 이하
   MAX_JITTER = 30    # 지터 30 ms 이하
   MAX_LOSS = 1       # 손실률 1 % 이하

   def measure(data):
       # 1. 응답을 받은 값만 got 리스트에 모은다
       got = []
       for v in data:
           if v != None:
               got.append(v)
       # 2. 평균 지연
       delay = sum(got) / len(got)
       # 3. 지터 = 이웃한 두 값의 차이의 평균
       total = 0
       for i in range(1, len(got)):
           total = total + abs(got[i] - got[i - 1])
       jitter = total / (len(got) - 1)
       # 4. 손실률
       loss = (len(data) - len(got)) / len(data) * 100
       return delay, jitter, loss

   for name in LINES:
       delay, jitter, loss = measure(LINES[name])

       # 5. 세 기준을 모두 지켰는지 ok 에 담는다. 여기를 직접 씁니다
       ok = False   # 이 줄의 False 를 「세 기준을 모두 지키면 True」가 되는 식으로 바꾼다
       # 6. 어느 기준에 걸렸는지 모은다 (이미 채워져 있음)
       reasons = []
       if delay > MAX_DELAY:
           reasons.append("지연")
       if jitter > MAX_JITTER:
           reasons.append("지터")
       if loss > MAX_LOSS:
           reasons.append("손실")

       # 7. 결과를 출력한다
       if ok:
           print(name, "→ 적합")
       else:
           print(name, "→ 부적합 (걸린 기준:", ", ".join(reasons) + ")")
   ```

### 7.1 tracert · 느려진 구간 읽기

- **tracert**(트레이스 라우트 · 줄여서 「트레이서트」 — trace route, 경로를 추적한다는 뜻)
  - 목적지까지 거치는 장비를 순서대로 보여 주고, 장비마다 걸린 시간을 보여 준다
  - 10/13 오후에는 `tracert` 로 **어떤 장비를 지나는지**를 봤다. 오늘은 장비마다 걸린 시간을 읽는 법을 더 배운다
- **홉**(hop · 홉)
  - 거치는 장비 하나하나. 1번 홉, 2번 홉처럼 센다
  - 장비마다 적힌 시간은 **내 PC 에서 그 장비까지 갔다 오는 데 걸린 시간**이다(앞 홉의 시간을 더한 값이 아니다)
- 읽는 법
  - 시간이 **처음 크게 뛴 홉**을 찾는다. 그 뒤 홉도 계속 크면, 그 홉과 바로 앞 홉 **사이 구간**이 원인이다
  - 한 홉만 크고 다음 홉에서 다시 작아지면, 그 장비가 **자기가 보내는 tracert 응답만 늦게 만든 것**이다. 지나가는 패킷은 빨리 넘기므로 실제 장애가 아니다
- **현실에서 마주치는 곳**
  - 내 PC 에서 `tracert google.com`(맥북은 `traceroute google.com`)을 쳐 보면 공유기 → 통신사 장비 → … → 서비스 순서로 홉이 나온다
  - 고객에게 「우리 구간은 정상이고 통신사 구간에서 늘어납니다」라고 말할 때 이 표를 근거로 보냅니다

### 정답 6-1

💻 **터미널에 입력합니다.**

```bash
python day05_6-1_measure.py
```
맥북: `python3 day05_6-1_measure.py`

**채운 함수**

```python
def jitter(got):
    """받은 응답 시간 리스트로 지터를 구한다.

    입력: 응답 시간 리스트 got
    리턴: 이웃한 두 값의 차이의 평균(지터)
    """
    total = 0
    for i in range(1, len(got)):
        total = total + abs(got[i] - got[i - 1])
    return total / (len(got) - 1)
```

**결과**

- (가) 위 함수(주석은 자유).
- (나) 채운 뒤에는 아래 세 줄이 나옵니다.
  ```
  회선 A | 지연 21.9 ms | 지터 1.1 ms | 손실 0 %
  회선 B | 지연 42.3 ms | 지터 54.3 ms | 손실 0 %
  회선 C | 지연 41.0 ms | 지터 1.7 ms | 손실 30 %
  ```
- (다) 리턴값은 **이웃한 값의 차이의 평균(지터)**입니다. `measure` 의 `jitter_value = jitter(got)` 줄에서 받아 `print` 에 지터 값으로 씁니다.

**왜** — 지터는 값 하나가 아니라 이웃한 값의 변화를 모두 모아야 구할 수 있으므로 반복문이 필요합니다. 함수로 만들면 다른 회선에도 같은 방법으로 씁니다.

**자주 틀리는 곳** — `abs()` 없이 `got[i] - got[i - 1]` 만 더하면 오르내림이 서로 상쇄되어 지터가 실제보다 작게 나옵니다. `total` 을 `len(got)` 으로 나누는 것도 틀립니다(차이는 한 개 적습니다). `return` 을 `for` 안에 쓰면 첫 차이만 더하고 끝납니다.

**관제에서는** — 회선 로그에서 지터를 구할 때도 같은 계산을 합니다. 값이 튀는 시각을 찾는 데 이 계산이 쓰입니다.

**자주 틀리는 곳** — `and` 대신 `or` 로 쓰면 하나만 지켜도 적합이 됩니다. 기준 비교를 `<` 로 쓰면 기준 값과 같을 때 부적합으로 나옵니다.

**관제에서는** — 어느 기준에 걸렸는지가 보고서의 첫 줄이 됩니다. 지터면 값이 튀는 구간, 손실이면 끊기는 구간을 찾습니다.

### 왜 필요한가

- 서버 · 업무 도구가 클라우드로 옮겨 가면서, 어디까지를 업체가 관리하고 어디부터를 내가 관리하는지가 서비스마다 달라졌습니다.
- 관리 범위가 좁을수록 내가 걸 수 있는 보안 설정도 줄어듭니다. 그래서 서비스를 만나면 **형태부터 구분**합니다.
- 직원이 집에서 SaaS 에 바로 접속하면 그 접속은 회사 방화벽을 지나지 않습니다. 보안팀이 볼 수 있는 것은 그 서비스가 남겨 주는 로그뿐입니다.

### 2.1 클라우드 서비스의 세 형태 — 어디까지 남이 관리하나

- **클라우드**(cloud · 클라우드)
  - 내 건물이 아니라 업체의 서버를 인터넷으로 빌려 쓰는 방식
- **IaaS**(Infrastructure as a Service · 아이아스)
  - 서버와 저장소, 네트워크만 빌린다
  - 운영체제 설치 · 패치 · 보안 설정은 **내가 한다**
- **PaaS**(Platform as a Service · 파스)
  - 운영체제와 실행 환경까지 업체가 관리한다
  - **코드와 데이터**만 내가 맡는다
- **SaaS**(Software as a Service · 사스)
  - 완성된 서비스를 계정만 받아 쓴다
  - **계정 · 권한 · 데이터**만 내가 맡는다

| 형태 | 내가 맡는 것 | 방화벽 규칙을 직접 걸 수 있나 |
|---|---|---|
| IaaS | 운영체제 · 보안 설정 · 코드 · 데이터 | 걸 수 있다 |
| PaaS | 코드 · 데이터 | 일부만 걸 수 있다 |
| SaaS | 계정 · 권한 · 데이터 | 걸 자리가 없다 |

- 위에서 아래로 갈수록 내가 쓸 수 있는 통제 수단이 줄고, SaaS 에서는 **계정과 권한**이 남습니다.

**실제 서비스로 보면**

| 형태 | 대표 서비스 | 회사가 하는 일의 예 |
|---|---|---|
| IaaS | **AWS EC2** · Google Compute Engine · Azure Virtual Machines | EC2 에서 가상 서버를 만들고, 운영체제(Linux · Windows)를 고르고, 웹 서버 프로그램을 설치한다. **보안 그룹**(클라우드의 방화벽)에서 443 만 열어 둔다 |
| PaaS | **Vercel** · Heroku · Azure App Service | 코드를 Vercel 에 올리면 서버 · 운영체제 관리 없이 웹사이트가 배포된다. 회사는 코드 · 환경 설정 · 데이터를 관리한다 |
| SaaS | **Google Docs**(Google Workspace) · Microsoft 365 · Slack | 직원 계정을 만들고 초대한다. 프로그램을 설치하거나 서버를 두지 않는다. 회사는 계정과 권한 · 공유 범위를 관리한다 |

- 한 회사가 **세 가지를 함께 쓰는 것**이 흔합니다.
  - 예: 회사 소개 웹사이트는 <mark>Vercel</mark>(PaaS), 사내 DB 서버는 <mark>EC2</mark>(IaaS), 업무 문서는 <mark>Google Docs</mark>(SaaS)
  - 고객사에서 사고가 나면 **어느 서비스에서 났는지**가 먼저 보고 항목이 됩니다.

**서비스 네 개**

- **서비스 A:** 클라우드에서 빈 가상 서버를 빌려, 운영체제 설치와 보안 설정까지 직접 해서 웹 서버로 씁니다. (예: **AWS EC2** 에서 만든 서버)

### 2.2 회사 방화벽을 지나지 않는 접속

- **예전 접속 경로**
  - 사내 PC → 사내망 → 회사 방화벽 → 인터넷
  - 모든 접속이 방화벽 한 곳을 지나서 거기서 기록하고 막을 수 있었다
- **재택근무 뒤의 접속 경로**
  - 집 PC → 인터넷 → SaaS 서비스
  - 회사 망 · 회사 방화벽을 거치지 않는다. 방화벽 로그에는 이 접속이 **남지 않는다**
- **가시성**(visibility · 비저빌리티)
  - 무슨 일이 일어나는지 보안팀이 볼 수 있는 정도
  - 접속이 회사 방화벽을 지나지 않으면 가시성이 떨어진다. 이때 볼 수 있는 곳은 **그 서비스의 로그인 기록**뿐이다
- **현실에서 마주치는 곳**
  - 직원이 집에서 <mark>Google Docs</mark> · <mark>Slack</mark> 에 로그인하면 회사 방화벽을 지나지 않는다
  - 그래서 보안팀은 방화벽 로그가 아니라 **서비스의 접속 기록**(Google Workspace 의 로그인 기록 등)을 본다
  - 퇴사자 계정이 새벽에 낯선 IP 로 로그인되는 것은 계정 도용을 의심하는 전형적인 모양이다

### 3.1 구성도를 읽는 순서

- **구성도**(diagram · 다이어그램)
  - 장비와 그 사이의 연결을 그린 그림
- **구역**(zone · 존)
  - 방화벽이 네트워크를 나눈 칸. 오늘은 `outside`(인터넷 쪽) · `DMZ` · `inside`(내부망) 세 구역을 쓴다
- **DMZ**(demilitarized zone · 디엠지)
  - 밖에 공개하는 서버만 따로 둔 중간 구역
  - 웹 서버가 뚫려도 내부 서버로 가려면 방화벽을 한 번 더 지나야 한다

- 구성도를 읽는 순서는 세 가지입니다.
  1. 방화벽이 어디에 있고, 어떤 구역들을 나누고 있는가
  2. 인터넷에서 오는 요청을 받는 **공개 서버**가 어느 구역에 있는가
  3. 지켜야 할 **내부 서버**가 어느 구역에 있는가
- 공개 서버가 내부 서버와 **같은 구역**에 그려져 있으면 DMZ 가 없는 구성입니다. 방화벽 개수만으로 정하지 않습니다.

**현실에서 마주치는 곳**

- 회사 홈페이지 서버 · 메일 서버처럼 <mark>인터넷에서 접속해야 하는 서버</mark>는 DMZ 에 두고, 직원 DB · 파일 서버는 <mark>내부망</mark>에 둡니다.
- 클라우드에서도 같은 생각입니다. 예: **EC2** 에 만든 웹 서버는 보안 그룹으로 443 만 열고, DB 서버는 인터넷에서 접근할 수 없는 곳에 둡니다.

> 📨 **오늘 들어온 일**
> 고객사 보안 담당이 보낸 메시지: 「요구사항대로 방화벽 규칙이 걸렸는지 확인해 달라는 요청입니다. 코드로 판정해서 알려 주세요.」

> - 끝나면 쓰는 것: **보고서 한 줄**(고객에게 보낼 답 한 문장)

### 왜 필요한가

- 고객이 「요구사항대로 방화벽 규칙이 걸렸나요?」라고 물으면, 눈으로 보는 것보다 **코드로 요청을 넣어 판정**해 보는 것이 정확합니다.
- 이 코드는 10/15 오후 7교시의 판정 코드와 같은 방식이고, 이번에는 **구역**(`outside` · `DMZ` · `inside`)으로 규칙을 씁니다.
- 오늘은 코드를 **읽고 설명하고, 도식으로 그리고, 함수를 직접 만들어** 봅니다. 쓰기만 하는 연습이 아닙니다.
- 현실에서도 같은 모양입니다. 사내 방화벽 장비의 규칙표, 그리고 **AWS EC2 의 보안 그룹**은 모두 <mark>출발 · 포트 · 허용</mark> 칸으로 씁니다. 오늘 코드는 그 구조를 가장 단순하게 옮긴 것입니다.

#### 🐍 문법 상자 · 값 두 개 리턴하기 · 튜플 꺼내기 `rule[4]` · `a, b = f()`

```python
rule = (1, "outside", "DMZ", 443, "permit")   # 값 다섯 개를 하나로 묶은 튜플
print(rule[0], rule[4])                        # 번호로 꺼낸다 (0 번부터 센다)
no, r_src, r_dst, r_port, action = rule        # 다섯 값을 한 번에 이름으로 꺼낸다
print(no, action)

def two():
    return "permit", 1                          # 값 두 개를 쉼표로 이어 한 번에 리턴한다

a, n = two()                                    # 리턴된 두 값을 a 와 n 에 나눠 담는다
print(a, n)

# 1 permit
# 1 permit
# permit 1
```

| 쓰는 것 | 뜻 |
|---|---|
| `rule[4]` | 튜플의 다섯 번째 값(번호는 0 번부터). 위 튜플에서는 `"permit"` |
| `no, r_src, r_dst, r_port, action = rule` | 튜플의 값 다섯 개를 이름 다섯 개에 한 번에 나눠 담는다 |
| `return a, b` | 함수가 값 두 개를 한 번에 리턴한다 |
| `x, y = f()` | 리턴된 두 값을 `x` 와 `y` 에 나눠 담는다 |

### ✍️ 문제 4-1 · 규칙 판정 코드 읽고 설명하기

**🎯 할 일**

1. 코드를 붙여 넣고 <mark>실행해서 출력 여섯 줄</mark>을 봅니다.
2. 함수 세 개(`default_policy` · `match_rule` · `judge`)가 <mark>각각 무엇을 하는지</mark> 한 줄로 적습니다.
3. `judge` 가 <mark>리턴하는 값 두 개</mark>와 그것을 만드는 줄을 찾습니다.
4. `for` 안의 `return` 이 <mark>왜 필요한지</mark> 설명합니다.
5. 기본 정책으로 판정된 요청이 <mark>몇 개인지</mark> 셉니다.

**💡 왜 중요한가**

- 방화벽 규칙을 판정하는 코드를 <mark>읽고 설명할 수 있어야</mark> 고객 구성을 점검할 수 있습니다.
- 함수마다 <mark>역할</mark>과 <mark>리턴값</mark>을 말할 수 있으면 코드를 <mark>고치거나 확장</mark>할 수 있습니다.
  - 오늘의 형식은 「쓰기」가 아니라 「설명하기」입니다.
- `for` · `if` · `return` 을 <mark>왜 그렇게 썼는지</mark> 말하는 연습입니다.

**이 문제에 나오는 말**

- **구역 규칙**

       (2, "DMZ", "inside", 445, "permit"),     # 규칙 2: DMZ 에서 내부망의 445 번을 허용한다
   ]

           return "permit"                      # 허용한다
       if dst == "outside":                     # 인터넷으로 나가는 통신이면
           return "permit"                      # 허용한다
       return "deny"                            # 나머지는 모두 차단한다

   def match_rule(rule, src, dst, port):        # 규칙 하나가 요청과 맞는지 알아보는 함수이다

       return default_policy(src, dst), 0       # 맞는 규칙이 없으면 기본 정책의 동작과 번호 0 을 리턴한다

- (나) **나 와 다 에 DMZ 가 있습니다.** 웹 서버가 내부 서버(`DB`)와 **다른 구역**(DMZ)에 있기 때문입니다. 가 는 웹 서버가 내부망 안에 `DB` 와 같이 있어 DMZ 가 없습니다.
- (다) 가 와 나 는 방화벽이 한 개씩이지만, 나 에서는 웹 서버가 **다른 구역**에 있습니다. DMZ 는 방화벽 개수가 아니라 **웹 서버가 어느 구역에 있느냐**로 판단합니다.
- (라) 구성도 가: **0 번**(같은 구역이라 방화벽을 지나지 않고 바로 닿음). 구성도 나: **1 번**(`FW`). 구성도 다: **1 번**(`FW2`, `FW1` 은 인터넷 쪽에 있으므로 지나지 않음).

**왜** — 공개 서버를 따로 둔 구조에서는 한 구역의 침해가 다른 구역으로 바로 번지지 않습니다.

**자주 틀리는 곳** — 방화벽이 하나뿐이라서 DMZ 가 없다고 답하는 경우가 많습니다. 구성도 다 의 `FW1` 을 지난다고 세는 것도 흔한 실수입니다. 웹 서버는 이미 `FW1` 안쪽에 있습니다.

**관제에서는** — 고객 구성도를 받으면 공개 서버가 어느 구역인지부터 확인합니다. 내부망 안에 있으면 그 서버가 뚫린 순간 내부 서버가 같은 구역에서 바로 보입니다.

### 정답 4-1

💻 **터미널에 입력합니다.**

```bash
python day05_4-1_zone_rules.py
```
맥북: `python3 day05_4-1_zone_rules.py`

**나와야 하는 출력**

```
outside → DMZ 443 : permit (규칙 1)
outside → DMZ 80 : deny (규칙 0)
inside → DMZ 443 : permit (규칙 0)
DMZ → inside 445 : permit (규칙 2)
DMZ → inside 3389 : deny (규칙 0)
outside → inside 445 : deny (규칙 0)
```

**결과**

- (가) `default_policy` 는 규칙에 맞는 것이 없을 때 **기본 정책**(같은 구역 · 내부망 출발 · 인터넷으로 나감은 허용, 나머지는 차단)을 알려 줍니다. `match_rule` 은 **규칙 하나가 요청과 맞는지** `True` / `False` 로 알려 줍니다. `judge` 는 **규칙표를 위에서부터 보며 요청을 판정**해 동작과 규칙 번호를 알려 줍니다.
- (나) 리턴값은 **동작(`permit` / `deny`)과 규칙 번호**입니다. 동작은 `rule[4]` 또는 `default_policy(...)`, 규칙 번호는 `rule[0]` 또는 `0` 입니다.
- (다) `return` 이 없으면 `for` 가 규칙을 끝까지 돌며, 맞는 규칙이 여러 개일 때 **위의 규칙이 아니라 마지막 규칙의 값**이 남을 수 있습니다. 방화벽은 **첫 번째로 맞는 규칙**을 쓰므로, 찾자마자 `return` 해서 함수를 끝내는 문법을 썼습니다.
- (라) 기본 정책으로 판정된 것은 **4개**(규칙 번호 0 인 줄)이고, 그 가운데 허용된 것은 `inside → DMZ 443` 하나입니다.

**왜** — 규칙표는 위에서부터 첫 번째로 맞는 것이 결정합니다. `return` 은 그 「첫 번째」를 코드로 만든 것입니다.

**자주 틀리는 곳** — `judge` 가 값을 하나만 리턴한다고 쓰는 경우가 많습니다. `return rule[4], rule[0]` 처럼 값 두 개를 쉼표로 이어 리턴합니다. 「인터넷에서 DMZ 80 이 차단된 것은 규칙 1 때문」이라고 답하는 것도 틀립니다. 규칙 1 은 443 만 허용하고, 80 은 맞는 규칙이 없어 기본 정책으로 차단됩니다.

**관제에서는** — 로그에 규칙 번호 0(기본 정책) 판정이 많으면 규칙이 부족하다는 신호로 봅니다.

### 정답 4-2

💻 **터미널에 입력합니다.**

```bash
python day05_4-2_allowed_ports.py
```
맥북: `python3 day05_4-2_allowed_ports.py`

**채운 함수**

```python
def allowed_ports(src, dst, ports):
    result = []
    for port in ports:
        action, no = judge(src, dst, port)
        if action == "permit":
            result.append(port)
    return result
```

**나와야 하는 출력**

```
[443]
[445]
[22, 80, 443, 445, 3389]
[]
```

**결과**

- (가) 한 예: `judge` 줄마다 주석 — 규칙 하나씩 꺼내기, 맞는지 확인, 맞으면 동작과 번호 리턴, 규칙이 끝나면 기본 정책 리턴.
- (나) 도식의 한 예:
  ```
  START
    │
    ▼
  [ take next rule ] ◄──────────┐
    │                           │
    ▼                           │
  [ match_rule ? ] ── no ───────┘
    │ yes
    ▼
  RETURN (rule action, rule no)

  (rules exhausted)
    │
    ▼
  RETURN (default_policy, 0)
  ```
- (다) 출력은 위 네 줄이고, 요구사항 표의 기대값과 같습니다.
- (라) `result = []` 를 `for` 위에 두어야 포트를 하나씩 보는 동안 **모은 값이 유지**됩니다. `for` 안에 두면 포트를 볼 때마다 리스트가 **비워져서** 마지막 포트 하나의 결과만 남습니다.
- (한 줄) 예: 「요구사항대로 인터넷은 DMZ 의 443 만, DMZ 는 내부망의 445 만 열려 있고 인터넷에서 내부망은 모두 막혀 있습니다.」

**왜** — 판정 함수를 포트 목록에 반복해서 부르면 「통과하는 목록」이 나오고, 이 목록이 요구사항과 같은지가 점검의 결과입니다.

**자주 틀리는 곳** — `if action == "permit"` 의 `==` 를 `=` 로 쓰면 에러가 납니다. `judge` 가 값 두 개를 리턴하므로 `action = judge(...)` 로 받으면 `action` 이 튜플이 되어 `"permit"` 과 같지 않습니다.

**관제에서는** — 규칙을 바꾼 뒤 같은 시험 요청으로 목록이 달라졌는지 비교하면, 의도하지 않게 열린 길을 찾습니다.

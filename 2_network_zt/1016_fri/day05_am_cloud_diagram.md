# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">2교시 (10:00–10:50) · 클라우드 · SaaS · 회사 방화벽이 못 보는 접속</mark>

### 왜 필요한가

- 서버 · 업무 도구가 클라우드로 옮겨 가면서, 어디까지를 업체가 관리하고 어디부터를 내가 관리하는지가 서비스마다 달라졌습니다.
- 관리 범위가 좁을수록 내가 걸 수 있는 보안 설정도 줄어듭니다. 그래서 서비스를 만나면 **형태부터 구분**합니다.
- 직원이 집에서 SaaS 에 바로 접속하면 그 접속은 회사 방화벽을 지나지 않습니다. 보안팀이 볼 수 있는 것은 그 서비스가 남겨 주는 로그뿐입니다.

### 2.1 클라우드 서비스의 세 형태 — 어디까지 남이 관리하나

- **클라우드**(cloud · 클라우드)
  - 내 건물이 아니라 업체의 서버를 인터넷으로 빌려 쓰는 방식
- **IaaS**(Infrastructure as a Service · 아이아스)
  - 서버와 저장소, 네트워크만 빌린다
  - 운영체제 설치 · 패치 · 보안 설정은 **내가 한다**
- **PaaS**(Platform as a Service · 파스)
  - 운영체제와 실행 환경까지 업체가 관리한다
  - **코드와 데이터**만 내가 맡는다
- **SaaS**(Software as a Service · 사스)
  - 완성된 서비스를 계정만 받아 쓴다
  - **계정 · 권한 · 데이터**만 내가 맡는다

| 형태 | 내가 맡는 것 | 방화벽 규칙을 직접 걸 수 있나 |
|---|---|---|
| IaaS | 운영체제 · 보안 설정 · 코드 · 데이터 | 걸 수 있다 |
| PaaS | 코드 · 데이터 | 일부만 걸 수 있다 |
| SaaS | 계정 · 권한 · 데이터 | 걸 자리가 없다 |

- 위에서 아래로 갈수록 내가 쓸 수 있는 통제 수단이 줄고, SaaS 에서는 **계정과 권한**이 남습니다.

### 2.2 회사 방화벽을 지나지 않는 접속

- **예전 접속 경로**
  - 사내 PC → 사내망 → 회사 방화벽 → 인터넷
  - 모든 접속이 방화벽 한 곳을 지나서 거기서 기록하고 막을 수 있었다
- **재택근무 뒤의 접속 경로**
  - 집 PC → 인터넷 → SaaS 서비스
  - 회사 망 · 회사 방화벽을 거치지 않는다. 방화벽 로그에는 이 접속이 **남지 않는다**
- **가시성**(visibility · 비저빌리티)
  - 무슨 일이 일어나는지 보안팀이 볼 수 있는 정도
  - 접속이 회사 방화벽을 지나지 않으면 가시성이 떨어진다. 이때 볼 수 있는 곳은 **그 서비스의 로그인 기록**뿐이다

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">3교시 (11:00–11:50) · 망 구성도 읽기 · DMZ</mark>

### 왜 필요한가

- 고객사 환경을 처음 받으면 가장 먼저 구성도를 봅니다. 어느 서버가 인터넷에 열려 있고, 어느 서버가 안쪽에 있는지가 구성도에 있습니다.
- 공개 서버(웹 서버)가 내부망 안에 있는지, 따로 떼어 둔 구역에 있는지가 사고 때 피해 범위를 가릅니다.
- 오늘은 **읽는 법**만 배웁니다. 직접 만드는 것은 4교시입니다.

### 3.1 구성도를 읽는 순서

- **구성도**(diagram · 다이어그램)
  - 장비와 그 사이의 연결을 그린 그림
- **구역**(zone · 존)
  - 방화벽이 네트워크를 나눈 칸. 이 과제는 `outside`(바깥, 인터넷 쪽) · `DMZ` · `inside`(안쪽, 내부망) 세 구역이다
- **DMZ**(demilitarized zone · 디엠지)
  - 밖에 공개하는 서버만 따로 둔 중간 구역
  - 웹 서버가 뚫려도 내부 서버로 가려면 방화벽을 한 번 더 지나야 한다

```
인터넷 ──── 방화벽 ──── DMZ  (웹 서버)
              │
              └──────── 내부망 (내부 서버)
```

- 구성도를 읽는 순서는 세 가지입니다.
  1. 방화벽이 어디에 있고, 어떤 구역들을 나누고 있는가
  2. 인터넷에서 오는 요청을 받는 **공개 서버**가 어느 구역에 있는가
  3. 지켜야 할 **내부 서버**가 어느 구역에 있는가
- 공개 서버가 내부 서버와 **같은 구역**에 그려져 있으면 DMZ 가 없는 구성입니다. 방화벽 개수만으로 정하지 않습니다.

### ✍️ 문제 3-1 · 구성도에서 구역과 서버 위치 읽기

**할 일** — networksim 의 연습용 구성도를 열어, 방화벽이 나눈 구역과 두 서버의 위치를 보고서에 적습니다.

**왜 중요한가** — 구성도에서 「공개 서버가 어느 구역인가」를 바로 읽을 줄 알아야, 사고가 났을 때 이 서버가 뚫리면 어디까지 위험한지 말할 수 있습니다.

**이 문제에 나오는 말**

- **Firewall 카드의 `3 zones · 0 rules`**
  - 이 방화벽이 구역을 3개 나누었고 규칙은 아직 0개라는 뜻
- **서버 카드의 `Server · DMZ`**
  - 그 서버가 DMZ 구역에 있다는 표시

**순서**

1. **[브라우저]** 크롬이나 Edge 의 주소창에 아래 주소를 입력합니다. 「현재 구성이 바뀝니다」 같은 확인 창이 나오면 `OK` 를 누릅니다.
   ```
   networksim.app/?task=web-dmz
   ```
2. **[networksim]** 화면 위쪽의 과제 설명을 읽습니다. 「웹은 HTTPS(443)로 닿아야 하고 내부망은 바깥에서 닿으면 안 된다」는 내용입니다. 방화벽이 지금 모든 것을 막고 있다는 설명도 있습니다.
3. **[networksim]** 가운데 그림에서 `Internet` · `FW` · `SW-DMZ` · `SW-LAN` · `WEB` · `Internal server` 여섯 장치를 찾습니다. `FW` 카드의 `3 zones · 0 rules` 를 확인합니다.
4. **[networksim]** `WEB` 카드와 `Internal server` 카드에 적힌 구역 이름(`Server · …`)을 봅니다.
5. **[networksim]** `FW` 를 **더블클릭**해 설정 창을 열고 `Zones & interfaces` 를 눌러, 어느 네트워크가 어느 구역에 묶였는지 읽습니다. 확인만 하고 `Cancel` 로 닫습니다.
6. **[보고서]** `day05_am_report.md` 의 `## 3교시` › `### 문제 3-1` 아래를 채웁니다.
   - (가-1) 그림에서 방화벽 장치 이름과, 방화벽이 나눈 구역 세 개의 이름을 적어 주세요.
   - (가-2) `WEB` 서버와 `Internal server` 는 각각 어느 구역에 있나요?
   - (나) 🔍 이 구성은 DMZ 가 있는 구성일까요, 없는 구성일까요? 그렇게 본 근거는 무엇인가요?

**💡 힌트**

1. 구역 이름은 `FW` 설정 창의 `Zones & interfaces` 에 `outside` · `inside` · `DMZ` 로 적혀 있습니다.

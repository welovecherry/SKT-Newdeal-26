# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">2교시 (10:00–10:50) · 클라우드 · SaaS · 회사 방화벽이 못 보는 접속</mark>

### 왜 필요한가

- 서버 · 업무 도구가 클라우드로 옮겨 가면서, 어디까지를 업체가 관리하고 어디부터를 내가 관리하는지가 서비스마다 달라졌습니다.
- 관리 범위가 좁을수록 내가 걸 수 있는 보안 설정도 줄어듭니다. 그래서 서비스를 만나면 **형태부터 구분**합니다.
- 직원이 집에서 SaaS 에 바로 접속하면 그 접속은 회사 방화벽을 지나지 않습니다. 보안팀이 볼 수 있는 것은 그 서비스가 남겨 주는 로그뿐입니다.

### 2.1 클라우드 서비스의 세 형태 — 어디까지 남이 관리하나

- **클라우드**(cloud · 클라우드)
  - 내 건물이 아니라 업체의 서버를 인터넷으로 빌려 쓰는 방식
- **IaaS**(Infrastructure as a Service · 아이아스)
  - 서버와 저장소, 네트워크만 빌린다
  - 운영체제 설치 · 패치 · 보안 설정은 **내가 한다**
- **PaaS**(Platform as a Service · 파스)
  - 운영체제와 실행 환경까지 업체가 관리한다
  - **코드와 데이터**만 내가 맡는다
- **SaaS**(Software as a Service · 사스)
  - 완성된 서비스를 계정만 받아 쓴다
  - **계정 · 권한 · 데이터**만 내가 맡는다

| 형태 | 내가 맡는 것 | 방화벽 규칙을 직접 걸 수 있나 |
|---|---|---|
| IaaS | 운영체제 · 보안 설정 · 코드 · 데이터 | 걸 수 있다 |
| PaaS | 코드 · 데이터 | 일부만 걸 수 있다 |
| SaaS | 계정 · 권한 · 데이터 | 걸 자리가 없다 |

- 위에서 아래로 갈수록 내가 쓸 수 있는 통제 수단이 줄고, SaaS 에서는 **계정과 권한**이 남습니다.

### 2.2 회사 방화벽을 지나지 않는 접속

- **예전 접속 경로**
  - 사내 PC → 사내망 → 회사 방화벽 → 인터넷
  - 모든 접속이 방화벽 한 곳을 지나서 거기서 기록하고 막을 수 있었다
- **재택근무 뒤의 접속 경로**
  - 집 PC → 인터넷 → SaaS 서비스
  - 회사 망 · 회사 방화벽을 거치지 않는다. 방화벽 로그에는 이 접속이 **남지 않는다**
- **가시성**(visibility · 비저빌리티)
  - 무슨 일이 일어나는지 보안팀이 볼 수 있는 정도
  - 접속이 회사 방화벽을 지나지 않으면 가시성이 떨어진다. 이때 볼 수 있는 곳은 **그 서비스의 로그인 기록**뿐이다

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">3교시 (11:00–11:50) · 망 구성도 읽기 · DMZ</mark>

### 왜 필요한가

- 고객사 환경을 처음 받으면 가장 먼저 구성도를 봅니다. 어느 서버가 인터넷에 열려 있고, 어느 서버가 안쪽에 있는지가 구성도에 있습니다.
- 공개 서버(웹 서버)가 내부망 안에 있는지, 따로 떼어 둔 구역에 있는지가 사고 때 피해 범위를 가릅니다.
- 오늘은 **읽는 법**만 배웁니다. 직접 만드는 것은 4교시입니다.

### 3.1 구성도를 읽는 순서

- **구성도**(diagram · 다이어그램)
  - 장비와 그 사이의 연결을 그린 그림
- **구역**(zone · 존)
  - 방화벽이 네트워크를 나눈 칸. 이 과제는 `outside`(바깥, 인터넷 쪽) · `DMZ` · `inside`(안쪽, 내부망) 세 구역이다
- **DMZ**(demilitarized zone · 디엠지)
  - 밖에 공개하는 서버만 따로 둔 중간 구역
  - 웹 서버가 뚫려도 내부 서버로 가려면 방화벽을 한 번 더 지나야 한다

```
인터넷 ──── 방화벽 ──── DMZ  (웹 서버)
              │
              └──────── 내부망 (내부 서버)
```

- 구성도를 읽는 순서는 세 가지입니다.
  1. 방화벽이 어디에 있고, 어떤 구역들을 나누고 있는가
  2. 인터넷에서 오는 요청을 받는 **공개 서버**가 어느 구역에 있는가
  3. 지켜야 할 **내부 서버**가 어느 구역에 있는가
- 공개 서버가 내부 서버와 **같은 구역**에 그려져 있으면 DMZ 가 없는 구성입니다. 방화벽 개수만으로 정하지 않습니다.

### ✍️ 문제 3-1 · 구성도에서 구역과 서버 위치 읽기

**🎯 할 일**

1. networksim 에서 <mark>연습용 구성도</mark>(`web-dmz`)를 엽니다.
2. 방화벽이 나눈 <mark>구역 세 개의 이름</mark>을 찾습니다.
3. <mark>웹 서버(`WEB`)와 내부 서버(`Internal server`)</mark>가 각각 어느 구역에 있는지 찾습니다.
4. <mark>DMZ 가 있는 구성인지</mark> 판단하고 근거를 적습니다.

**💡 왜 중요한가**

- 구성도에서 <mark>「공개 서버가 어느 구역인가」</mark>를 바로 읽어야 합니다.
- 그래야 사고가 났을 때 <mark>이 서버가 뚫리면 어디까지 위험한지</mark> 말할 수 있습니다.

**이 문제에 나오는 말**

- **Firewall 카드의 `3 zones · 0 rules`**
  - 이 방화벽이 구역을 3개 나누었고 규칙은 아직 0개라는 뜻
- **서버 카드의 `Server · DMZ`**
  - 그 서버가 DMZ 구역에 있다는 표시

**순서**

1. **[브라우저]** 크롬이나 Edge 의 주소창에 아래 주소를 입력합니다.
   ```
   networksim.app/?task=web-dmz
   ```
   - 확인 창이 나오면 <mark>`OK`</mark> 를 누릅니다
2. **[networksim]** 화면 위쪽의 <mark>과제 설명</mark>을 읽습니다.
   - 웹은 <mark>HTTPS(443)</mark> 로 닿아야 합니다
   - 내부망은 <mark>바깥에서 닿으면 안 됩니다</mark>
   - 방화벽이 지금은 <mark>모든 것을 막고 있습니다</mark>
3. **[networksim]** 가운데 그림에서 <mark>여섯 장치</mark>를 찾습니다.
   - `Internet` · `FW` · `SW-DMZ` · `SW-LAN` · `WEB` · `Internal server`
   - `FW` 카드의 `3 zones · 0 rules` 를 확인합니다
4. **[networksim]** `WEB` 카드와 `Internal server` 카드에서 <mark>구역 이름</mark>(`Server · …`)을 봅니다.
5. **[networksim]** `FW` 를 <mark>더블클릭</mark>해 설정 창을 엽니다.
   - `Zones & interfaces` 를 누릅니다
   - 어느 네트워크가 어느 구역에 묶였는지 읽습니다
   - 확인만 하고 `Cancel` 로 닫습니다
6. **[보고서]** `day05_am_report.md` 의 `## 3교시` › `### 문제 3-1` 아래를 채웁니다.
   - (가-1) 그림에서 방화벽 장치 이름과, 방화벽이 나눈 구역 세 개의 이름을 적어 주세요.
   - (가-2) `WEB` 서버와 `Internal server` 는 각각 어느 구역에 있나요?
   - (나) 🔍 이 구성은 DMZ 가 있는 구성일까요, 없는 구성일까요? 그렇게 본 근거는 무엇인가요?

**💡 힌트**

1. 구역 이름은 `FW` 설정 창의 `Zones & interfaces` 에 `outside` · `inside` · `DMZ` 로 적혀 있습니다.
2. 3.1 의 마지막 불릿을 봅니다. 공개 서버가 내부 서버와 같은 구역인지 다른 구역인지가 기준입니다.
3. 다 했으면 · 막히면 문서 맨 아래 「정답 3-1」에서 결과를 확인합니다.

### 3.2 시험으로 길을 확인하기

- networksim 오른쪽의 **Traffic Test**(트래픽 테스트)는 「이 장치에서 저 장치로 통신이 되는가」를 바로 확인합니다. 오늘 아침 과제에서 눌러 본 `Test traffic` 입니다.

### ✍️ 문제 3-2 · 시험으로 막는 장치 확인하기

**🎯 할 일**

1. <mark>인터넷 → 내부 서버</mark> 시험을 돌립니다.

**💡 왜 중요한가**

- 웹 서버는 밖에서 들어오는 서버라 <mark>가장 먼저 공격받습니다</mark>.
- 웹 서버가 뚫린 뒤에도 <mark>내부 서버로 가는 길에 방화벽이 있는지</mark>를 시험으로 확인할 수 있어야 합니다.
- 그래야 <mark>DMZ 가 제 역할을 하는지</mark> 말할 수 있습니다.

**순서**

1. **[networksim]** <mark>첫째 시험:</mark> 인터넷에서 내부 서버로 보냅니다.
   - `Source (from)` = `Internet (0.0.0.0/0)`
   - `Destination (to)` = `Internal server @ Internal LAN`
   - `Test traffic` 을 누릅니다
2. **[networksim]** 결과를 읽습니다.
   - 결과가 <mark>`BLOCKED`</mark> 인지
   - 그 아래 「stopped by …」 의 <mark>장치 이름</mark>
3. **[networksim]** <mark>둘째 시험:</mark> 웹 서버에서 내부 서버로 보냅니다.

   - `Destination (to)` 는 그대로 `Internal server @ Internal LAN`
   - `Test traffic` 을 다시 누르고 같은 방법으로 결과를 읽습니다
4. **[보고서]** `### 문제 3-2` 아래를 채웁니다.
   - (가-1) 두 시험의 결과(통과 · 차단)와 막은 장치 이름을 각각 적어 주세요.
   - (나) 🔍 `WEB` → `Internal server` 도 막힌 것은 무엇을 뜻할까요? 웹 서버가 해킹당했다고 가정하고 설명해 주세요.

**💡 힌트**

2. (나) 는 웹 서버가 공격자 손에 넘어갔다고 가정하고, 그 서버에서 내부 서버로 가는 길에 무엇이 있는지 봅니다.
3. 다 했으면 · 막히면 문서 맨 아래 「정답 3-2」에서 결과를 확인합니다.

**💡 왜 중요한가**


**구성도 나**

```
인터넷 ──── 방화벽 ──┬── DMZ    (웹 서버)

```

**순서**

**요구사항**

| # | 요구사항 | 규칙 |

| ③ | 웹 서버(`WEB`) → 내부 서버: SMB(`445`)**만** 허용 | 지금 쓴다 |
| — | 위에 없는 통신은 모두 막는다 | 방화벽 기본 동작(규칙 0개일 때와 같음) |

### 정답 4-1

**결과**

- (가-1) 규칙(`outside` → `DMZ` · `TCP` · `443` · `permit`)을 추가하고 `✓ Check` 를 누르면 `Solved!` 가 나옵니다. 시험 세 개의 결과는 다음과 같습니다.

  - 인터넷 → `Internal server` (TCP 445): **차단**
  - 인터넷 → `WEB` 의 다른 포트(80): **차단**
- (나) 허용한 규칙이 **443 하나뿐**이기 때문입니다. 80번은 허용 목록에 없어서 기본 차단에 걸립니다.

**왜** — 허용 목록 방식에서는 적은 것만 열리고 나머지는 모두 막힙니다.

**자주 틀리는 곳** — 도착 구역을 `inside` 로 고르는 경우가 있습니다. 웹 서버는 `DMZ` 에 있으므로 도착 구역은 `DMZ` 입니다. 출발과 도착이 바뀌어도 통과하지 못합니다.

**관제에서는** — 공개 서버에 열린 포트가 실제로 필요한 것뿐인지 확인합니다. 열린 포트가 하나 더 있으면 그만큼 공격받을 길이 늘어납니다.

### 정답 4-2

**결과**

- (가-1) 규칙 ② `inside` → `DMZ` · `22`, 규칙 ③ `DMZ` → `inside` · `445`.
- (가-2) 한 예입니다. 시험 (a) `Internet` → `WEB`: `Web (HTTPS)` 하나. 시험 (b) `Internal server` → `WEB`: `Remote admin (SSH)` 하나. 시험 (c) `WEB` → `Internal server`: `File sharing (SMB)` 하나.
- (나) 시험 (b) 에서 `Web (HTTPS)` 는 **차단**입니다. 내부망에서 웹 서버로 허용한 것은 SSH(22)뿐이고, 443 은 `inside` → `DMZ` 규칙에 없어서 기본 차단에 걸립니다.
- (다) 웹 서버가 해킹당하면 공격자가 웹 서버를 거쳐 **내부 서버의 모든 서비스**(관리 · DB 등)에 접근할 수 있게 됩니다. 445 하나로 좁혀 두어야 다른 서비스로는 번지지 않습니다.

**왜** — 요구사항의 「만」은 규칙의 포트를 하나로 좁히라는 뜻이고, 통과 목록에 서비스가 하나만 남아야 맞습니다.

**자주 틀리는 곳** — 규칙의 출발 구역과 도착 구역을 바꿔 쓰는 경우가 많습니다. `inside` → `DMZ` 는 내부망에서 DMZ 로 가는 방향입니다. 포트를 비워 두면 모든 포트가 열립니다.

**관제에서는** — DMZ 에서 내부로 가는 규칙은 서비스 하나(예: DB 포트)만 허용하는지 먼저 봅니다. 「DMZ → 내부 전체 허용」은 위험한 설정으로 보고합니다.

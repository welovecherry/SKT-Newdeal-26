# 아침 과제 10 · 파일 만들고 옮기고 지우기 — `touch` · `cp` · `mv` · `rm`

10월 14일 (수) · 아침 과제

**오늘 하는 일:** 10/7 에 마우스로 한 일 — 파일 만들기 · 이름 바꾸기 · 복사 · 지우기 — 을 **명령어로** 다시 해 봅니다. 마지막에는 파일을 고쳐 올리고, 고친 곳이 깃허브에서 어떻게 보이는지 확인합니다.

오늘 새로 쓰는 명령은 `touch` · `cp` · `mv` · `rm` 네 개입니다. 폴더를 만드는 `mkdir` 은 9/29 에 배웠습니다. 연습은 저장소 **바깥**에 만든 연습용 폴더 `mvcp_practice` 안에서 합니다. 저장소 폴더가 아니라서 실수해도 괜찮습니다.

**오늘 못 끝냈으면 오후 5시 이후에 마무리합니다.**

---

## 1. 왜 이걸 하는지 찾아봅니다

**왜 중요한가** — 보안 담당자가 서버에서 로그를 옮기고 백업하는 일을 먼저 알아 두면, 아래 네 가지 명령이 실무에서 어디에 쓰이는지 보입니다.

| 질문 | 검색어 예시 |
|---|---|
| 서버에는 마우스가 없습니다. 보안 담당자는 서버에서 로그 파일을 어떻게 옮기고 백업할까요? | `리눅스 파일 복사`, `리눅스 mv cp 차이` |

정답을 맞히는 과제가 아닙니다. **찾은 내용을 자기 말로 적는 것**이 과제입니다. 4번의 기록 파일 「찾아본 것」 칸에 적습니다.

---

## 2. 연습할 폴더로 갑니다

**왜 중요한가** — 연습을 저장소 바깥 폴더에서 하면 `rm` 으로 잘못 지워도 과제 파일과 깃허브 기록은 그대로 남습니다.

1. VS Code 에서 저장소 폴더 `security-agent-toolkit` 을 엽니다.
2. 왼쪽 목록의 **빈 곳**(폴더가 아닌 곳)을 오른쪽 클릭 › **Open in Integrated Terminal** 을 누릅니다. 터미널 오른쪽 위에 `bash` 가 보여야 합니다. `powershell` 이면 10/6 아침 과제의 방법으로 Git Bash 로 바꿉니다.
3. 지금 위치가 저장소 폴더인지 먼저 봅니다. 결과가 `…/security-agent-toolkit` 으로 끝나야 합니다. 아니면 `network_zt` 같은 하위 폴더에서 연 것이니 2번을 다시 합니다.
   ```
   pwd
   ```
4. 상위 폴더로 이동해 연습용 폴더를 만듭니다.
   ```
   cd ..
   mkdir mvcp_practice
   ```
5. 연습용 폴더로 들어갑니다. 이번에는 **Tab** 키를 씁니다 — `cd mvcp` 까지 치고 Tab 을 누르면 나머지가 채워집니다. 그다음 Enter.
   ```
   cd mvcp_practice
   pwd
   ```
   결과가 `…/Documents/mvcp_practice` 처럼 끝나면 됩니다. **경로 안에 `security-agent-toolkit` 이 없어야** 저장소 바깥입니다. 있으면 멈추고 강사를 부릅니다.

연습용 파일을 두 개 만듭니다. 하나는 내용이 있고, 하나는 비어 있습니다.

```
echo "2026-10-14 09:12:00 WARN failed login for admin" > a.log
touch memo.txt
ls
```

| 명령 | 하는 일 |
|---|---|
| `echo "글" > 파일` | 글을 담은 파일을 만든다. 같은 이름이 있으면 **내용을 덮어쓴다** |
| `touch 파일` | **빈 파일**을 만든다. 같은 이름이 있으면 내용은 그대로 두고 수정 시각만 바꾼다 |

VS Code 의 **New File** 과 `touch` 는 같은 일을 합니다. 서버에는 VS Code 가 없으니 `touch` 를 씁니다.

## 3. 여덟 가지를 해 봅니다

**왜 중요한가** — 서버에서는 로그 백업 · 정리를 이 네 명령으로 합니다. 덮어쓰기와 `rm` 삭제는 되돌릴 수 없어서, 증거 로그를 잃지 않게 하는 옵션을 여기서 찾아 둡니다.

**명령 이름만 알려 드립니다. 옵션은 직접 찾습니다.** 할 때마다 `ls` 로 결과를 봅니다.

| # | 하고 싶은 일 | 쓰는 명령 | 나오면 성공 |
|---|---|---|---|
| ① | `a.log` 를 복사해 `b.log` 를 만든다 | `cp` | `a.log` · `b.log` 둘 다 보인다 |
| ② | `b.log` 의 이름을 `c.log` 로 바꾼다 | `mv` | `b.log` 는 없고 `c.log` 가 보인다 |
| ③ | `backup` 폴더를 만들고 `c.log` 를 그 안으로 옮긴다 | `mkdir` · `mv` | `ls backup` 에 `c.log` 가 보인다 |
| ④ | `backup` 폴더를 안의 파일까지 모두 복사해 `backup2` 를 만든다 | `cp` + 옵션 하나 | `backup2` 안에도 `c.log` 가 있다 |
| ⑤ | `a.log` 를 `backup` 안으로 복사하는데, **같은 이름이 있으면 묻게** 한다 | `cp` + 옵션 하나 | 두 번째 실행 때 `cp: overwrite 'backup/a.log'?` 처럼 덮어쓸지 묻는다 — `n` 을 치고 Enter |
| ⑥ | `cat` 으로 `backup/a.log` 의 내용을 본다 | `cat` | 로그 한 줄이 보인다 |
| ⑦ | 빈 파일 `memo.txt` 를 지운다 | `rm` | `memo.txt` 가 안 보인다 |
| ⑧ | `backup2` 폴더를 안의 파일까지 모두 지운다 | `rm` + 옵션 하나 | `backup2` 가 안 보인다 |

- ②와 ③을 비교해 보세요. **`mv` 는 같은 명령으로 「이름 바꾸기」와 「옮기기」를 다 합니다.** 뒤에 적은 것이 파일 이름이면 이름이 바뀌고, 폴더면 그 안으로 옮겨집니다.
- ④ 폴더는 그냥 `cp` 로는 복사되지 않습니다. 「폴더 안까지 모두」를 뜻하는 옵션을 찾습니다.
- ⑤ `cp` 와 `mv` 는 같은 이름이 있으면 **묻지 않고 덮어씁니다.** 증거 로그를 덮어쓰는 사고를 막으려면 묻게 하는 옵션을 붙이는 습관이 좋습니다. ⑤를 두 번 실행해서 확인합니다.
- ⑦ ⑧ `rm` 은 **휴지통으로 보내지 않고 바로 지웁니다.** 되돌릴 수 없으니 지우기 전에 `ls` 로 이름을 한 번 더 봅니다. 폴더는 ④처럼 「폴더 안까지 모두」 옵션이 있어야 지워집니다. 그 옵션 **하나만** 씁니다 — 묻지 않고 강제로 지우는 옵션과 `*` 는 쓰지 않습니다. 지우기 전에 `pwd` 로 `mvcp_practice` 안인지 확인합니다.

「cp 폴더 복사 옵션」, 「cp 덮어쓰기 확인 옵션」, 「rm 폴더 삭제 옵션」처럼 검색하면 나옵니다.

## 4. 오늘 공부한 것을 기록하고 올립니다

**왜 중요한가** — 찾은 옵션을 내 말로 적어 두면 다음에 같은 일을 할 때 다시 검색하지 않고 꺼내 씁니다. 올리기는 10/12 에 배운 순서를 한 번 더 연습합니다.

1. 터미널을 저장소 폴더로 옮기고, 결과가 `…/security-agent-toolkit` 으로 끝나는지 봅니다.
   ```
   cd ../security-agent-toolkit
   pwd
   ```
2. VS Code 왼쪽 목록에서 `docs` 폴더를 오른쪽 클릭 › **New File** › 이름 `2026-10-14.md` 를 입력하고 아래 틀을 붙여 넣어 채웁니다.

```markdown
# 2026-10-14 (수)

## 찾아본 것
서버에서 로그를 옮기고 백업하는 방법:

## 오늘 새로 쓴 명령
touch, cp, mv, rm, Tab 자동 완성

## 찾은 옵션
폴더째 복사 -  / 덮어쓰기 전에 묻기 -  / 폴더째 지우기 -

## mv 의 두 가지 쓰임
이름 바꾸기:
옮기기:

## 막힌 것

## 다음에 확인할 것
```

3. 10/12 에 배운 순서로 올립니다. `git status` 의 빨간 목록에 `docs/2026-10-14.md` 하나만 보이면 다음으로 갑니다. `mvcp_practice` · `a.log` · `.env` 가 보이면 멈추고 강사를 부릅니다.

```
git status
git add .
git commit -m "Add 10/14 study note"
git push
```

## 5. 고친 곳을 깃허브에서 봅니다

**왜 중요한가** — 깃허브 커밋 화면을 읽을 줄 알면 언제 어느 줄이 바뀌었는지 확인할 수 있습니다. 설정 파일이 바뀐 곳을 찾을 때도 같은 화면을 봅니다.

방금 올린 `docs/2026-10-14.md` 를 조금 고쳐서 한 번 더 올립니다. 깃허브는 **무엇이 바뀌었는지**를 초록색과 빨간색으로 보여 줍니다.

1. `docs/2026-10-14.md` 에서 세 곳을 바꿉니다.

| 할 일 | 어디를 |
|---|---|
| 고치기 | 첫 줄 `# 2026-10-14 (수)` 를 `# 2026-10-14 (수) 아침 과제` 로 |
| 지우기 | 가운데 `## 막힌 것` 줄 하나 |
| 더하기 | 맨 아래에 `## 오늘의 한 줄` 과 그 아래 한 문장 |

2. 4번과 같은 순서로 올립니다. 메시지만 다릅니다.

```
git status
git add .
git commit -m "Edit 10/14 study note"
git push
```

3. 브라우저에서 내 `security-agent-toolkit` 저장소를 열고, 파일 목록 오른쪽 위의 **Commits**(시계 모양)를 누릅니다.
4. 맨 위의 `Edit 10/14 study note` 를 누릅니다. 바뀐 줄이 색으로 보입니다.

| 보이는 것 | 뜻 | 오늘 바꾼 곳 |
|---|---|---|
| 빨간 줄 `-` | 지워진 줄 — 옛 내용 | `## 막힌 것` |
| 초록 줄 `+` | 더해진 줄 — 새 내용 | `## 오늘의 한 줄` 과 그 문장 |
| 빨강 한 줄 바로 아래 초록 한 줄 | **고친 줄** — 옛 줄이 지워지고 새 줄이 더해졌다 | 첫 줄 |

git 은 「고쳤다」를 따로 기록하지 않습니다. **옛 줄을 지우고 새 줄을 더한 것**으로 기록합니다.

## 6. 확인합니다

**왜 중요한가** — 빠진 단계를 여기서 찾아 마무리합니다. 덮어쓰기 · 삭제 옵션을 못 찾은 채로 실제 로그 파일을 다루면 되돌릴 수 없는 사고가 납니다.

- [ ] `touch` 로 빈 파일을 만들고, `rm` 으로 파일과 폴더를 지웠다
- [ ] `cp` 로 파일을 복사하고, `mv` 로 이름을 바꾸고 폴더로 옮겼다
- [ ] 폴더를 안의 파일까지 모두 복사 · 지우는 옵션과 덮어쓰기 전에 묻는 옵션을 찾았다
- [ ] Tab 으로 긴 폴더 이름을 채워 봤다
- [ ] `docs/2026-10-14.md` 를 `git push` 로 올렸다
- [ ] 깃허브 커밋 화면에서 빨간 `-` · 초록 `+` · 고친 줄(빨강 + 초록)을 찾았다

연습한 `mvcp_practice` 폴더는 저장소 바깥에 있어서 깃허브에 올라가지 않습니다. 그대로 둬도 됩니다.

## ⭐ 다 한 사람만 합니다

**왜 중요한가** — `mv` 로 옮길 때도 같은 이름의 파일을 덮어써 잃을 수 있습니다. `git diff` 를 쓰면 올리기 전에 바뀐 줄을 터미널에서 미리 점검합니다.

`mv` 에도 「덮어쓰기 전에 묻는」 옵션이 있는지 찾아 `backup` 안에서 해 봅니다.

저장소 폴더에서 `docs/2026-10-14.md` 를 한 줄 더 고친 뒤, `git add` 하기 전에 터미널에 `git diff` 를 입력해 봅니다. 5번에서 깃허브에 보인 `-` · `+` 를 터미널에서 미리 볼 수 있습니다. 끝내려면 `q` 를 누릅니다.

### 2.1 URL 과 DNS 가 묻는 것 · 질문이 오가는 경로

**여기 나오는 말**

- **도메인 이름 (domain name)** (도메인 네임)
  - 사람이 외우는 **인터넷 이름**
  - 예: `example.com`
- **URL** (유알엘)
  - 웹 주소 전체
  - DNS 는 그 가운데 **도메인 이름만** 묻는다
  - 예: `https://example.com/news`
- **DNS (Domain Name System)** (디엔에스)
  - 이름을 **IP 주소로 바꿔 주는** 체계
- **재귀 리졸버 (recursive resolver)** (리커시브 리졸버)
  - 내 PC **대신 여기저기 물어** 답을 찾아 주는 DNS 서버
  - 예: 학원 · 통신사 DNS, 구글 `8.8.8.8`
- **`nslookup`** (엔에스룩업)
  - DNS 서버에 이름을 **직접 물어보는** 명령

`https://example.com/news/today` 를 주소창에 치면:

| 부분 | 이름 | DNS 가 묻나 |
|---|---|---|
| `https://` | 방식(scheme) — 암호화한 웹 | 아니요 |
| `example.com` | **도메인 이름** | **예 — 이것만 묻는다** |
| `/news/today` | 경로(path) — 서버 안의 어느 페이지 | 아니요 — IP 를 알아낸 뒤 웹 서버에 묻는다 |

```
내 PC  ──「example.com 의 IP 는?」──▶  DNS 서버(재귀 리졸버)  ──…──▶ 여러 네임서버
       ◀──「104.20.23.154 입니다」──
```

내 PC 가 어느 리졸버에 묻는지는 `ipconfig //all` 의 **DNS 서버** 줄에 있습니다(Git Bash 에서는 `/` 를 두 번 칩니다).

- 회사 DNS 서버는 위험한 도메인에 대한 질의를 막고, 어느 PC 가 어떤 이름을 물었는지 기록을 남깁니다.
- PC 는 DNS 서버가 준 IP 로 접속합니다. DNS 서버가 틀린 IP 를 답하면 PC 는 그 틀린 IP 로 접속합니다.

#### 명령 상자 · `nslookup` 결과 읽기

```
$ nslookup example.com
서버:    kns.kornet.net
Address:  168.126.63.1

권한 없는 응답:
이름:    example.com
Addresses:  2606:4700:10::ac42:93f3
          2606:4700:10::6814:179a
          172.66.147.243
          104.20.23.154
```

| 줄 | 뜻 |
|---|---|
| `서버` · `Address` (위 두 줄) | **내가 물어본** DNS 서버(리졸버)의 이름 · 주소 |
| `권한 없는 응답` | 권한 있는 네임서버가 아니라 리졸버가 **대신 조회해** 받은 답이라는 표시(3교시 3.2) |
| `이름` | 물어본 이름 |
| `Addresses` | 답. `:` 가 든 것은 IPv6(새 방식의 긴 주소), 숫자 네 개를 점으로 이은 것이 **IPv4** |

⚠ 위 두 줄의 `Address` 는 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">물어본 DNS 서버</mark>의 주소입니다. example.com 의 주소는 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">아래</mark> `Addresses` 입니다. 가장 많이 헷갈리는 곳입니다.

### 2.2 이름을 못 찾을 때 — NXDOMAIN

**여기 나오는 말**

- **NXDOMAIN** (엔엑스도메인)
  - 「**그런 이름은 없다**」는 DNS 의 답
  - 예: 화면에 `Non-existent domain` (맥북은 `NXDOMAIN`)
- **`socket`** (소켓)
  - 파이썬에 들어 있는 **네트워크 도구** 모음

#### 🐍 문법 상자 · `import socket` · `socket.gethostbyname()` — 파이썬으로 DNS 에 묻기

```python
import socket                             # import 는 파이썬에 들어 있는 도구 모음(모듈)을 불러온다. 네트워크 도구 모음 socket 을 불러온다
ip = socket.gethostbyname("example.com")  # 모듈이름.함수이름() 으로 그 모듈 안의 함수를 쓴다. gethostbyname() 은 내 PC 의 DNS 서버에 이름을 묻고 IPv4 주소 하나를 글자로 리턴한다. 그 주소를 ip 에 담는다
print(ip)                                 # 리턴받은 IPv4 주소를 출력한다
print(type(ip))                           # type() 은 값의 종류를 리턴한다. ip 가 글자(str)인지 확인해 출력한다

# 104.20.23.154     ← print(ip) — 실행할 때마다 다른 IPv4 가 나올 수 있다
# <class 'str'>     ← print(type(ip))
```

| 쓰는 것 | 뜻 |
|---|---|
| `import socket` | 파일 맨 위에서 한 번 불러온다. 빠뜨리면 `NameError: name 'socket' is not defined` |
| `socket.gethostbyname("이름")` | 이름을 DNS 에 묻고 IPv4 하나를 **글자로** 리턴한다. `nslookup` 과 달리 PC 의 DNS 캐시를 거친다 |
| 없는 이름을 물으면 | `socket.gaierror` 에러가 나고 프로그램이 그 줄에서 멈춘다 |

### ✍️ 문제 2-2 · URL 에서 이름을 꺼내 묻기 — 없는 이름이면

**할 일** — URL 에서 도메인 이름을 꺼내 IP 를 묻는 코드를 실행하고, 없는 이름을 적은 두 번째 파일 `day03_2-2_url_nowhere.py` 와 `nslookup` 으로 「이름이 없다」는 답을 확인해 보고서에 적습니다.

**왜 중요한가** — 접속 로그의 URL 에서 DNS 가 묻는 도메인 이름만 잘라 내는 연습입니다. 없는 이름에 DNS 가 어떤 답을 주는지 알아야 오후 5교시에 NXDOMAIN 이 급증하는 PC 를 찾을 수 있습니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `day03_2-2_url_example.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드 상자 안을 마우스로 끌어 선택하고 `Ctrl + C` 로 복사해 파일에 붙여 넣습니다. 실행하기 전에 **줄마다 주석을 읽어** 각 줄이 무엇을 하는지 이해합니다.
   ```python
   import socket                                 # import 로 네트워크 도구 모음 socket 을 불러온다
   url = "https://example.com/news/today"        # 주소창에 친 URL 글자를 url 에 담는다
   parts = url.split("/")                        # split("/") 로 URL 을 / 마다 잘라 리스트를 parts 에 담는다
   name = parts[2]                               # 리스트의 번호 2 칸(0 번부터 세어 셋째 칸)을 꺼내 name 에 담는다
   print(parts)                                  # 리스트 전체를 출력한다
   print(name, "→", socket.gethostbyname(name))  # name 과, gethostbyname() 이 DNS 서버에 물어 리턴한 IPv4 주소를 함께 출력한다
   ```
3. **[터미널]** 실행합니다. 터미널의 줄 위에 `…/network_zt` 가 보여야 합니다. 아니면 먼저 `cd network_zt` 를 입력합니다.
   ```bash
   python day03_2-2_url_example.py
   ```
   맥북: `python3 day03_2-2_url_example.py`
4. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `day03_2-2_url_nowhere.py` 를 입력하고 Enter 를 누릅니다.
5. **[VS Code]** 아래 코드를 파일에 붙여 넣고, 실행하기 전에 바뀐 줄(주석에 「달라진 줄」이라고 적힌 줄)을 첫 파일과 비교합니다.
   ```python

   url = "https://abc.nowhere-not-exist.com/login"  # 달라진 줄: 세상에 없는 이름이 든 URL 로 바꿨다. 첫 파일은 example.com 이었다

   name = parts[2]                                  # 리스트의 번호 2 칸(0 번부터 세어 셋째 칸)을 꺼내 name 에 담는다
   print(parts)                                     # 리스트 전체를 출력한다
   print(name, "→", socket.gethostbyname(name))     # name 과, gethostbyname() 이 DNS 서버에 물어 리턴한 IPv4 주소를 함께 출력한다
   ```
6. **[터미널]** 실행하고, 마지막 줄의 에러 이름을 읽습니다.

### 왜 필요한가

1. 세상의 모든 이름을 한 서버가 다 알 수는 없습니다. 도메인 이름은 **점으로 나뉜 계층**마다 관리하는 네임서버가 따로 있습니다.
2. 리졸버는 상위 계층부터 차례로 물어 **권한 있는 네임서버**(그 도메인의 레코드를 직접 관리하는 서버)를 찾아갑니다.
3. 공격자가 권한 있는 네임서버 정보를 바꾸면 도메인 전체를 가로챌 수 있습니다. 그래서 NS 레코드를 읽을 줄 알아야 합니다.

### 3.1 이름은 오른쪽부터 읽는다

**여기 나오는 말**

- **루트 (root)**
  - DNS 계층의 **최상위**
  - 도메인 이름 끝에 생략된 점 `.`
- **TLD (Top-Level Domain)** (티엘디)
  - 도메인 이름의 **마지막 레이블**(마지막 점 뒤의 부분)
  - 예: `com` · `kr`
- **레이블 (label)** (레이블)
  - 도메인 이름을 점으로 나눈 **각 부분**
  - 예: `www.example.com` 의 레이블은 `www` · `example` · `com`
- **네임서버 (name server)**
  - 도메인의 레코드를 저장하고 질의에 답하는 **DNS 서버**
- **권한 있는 네임서버 (authoritative)** (어소리테이티브)
  - 그 도메인의 레코드를 **직접 관리**하고 답하는 네임서버
  - 예: `hera.ns.cloudflare.com`
- **NS 레코드** (엔에스 레코드)
  - 그 도메인의 **권한 있는 네임서버**를 적은 레코드
  - 한 도메인에 보통 둘 이상 등록한다
  - `nslookup -type=ns 이름` 으로 묻는다

`www.example.com` 은 끝의 점이 생략된 `www.example.com.` 입니다. **오른쪽이 상위 계층**입니다.

| 계층 | 이 이름에서 | 관리하는 네임서버 |
|---|---|---|
| 루트 | `.` (마지막 점) | 루트 네임서버 — 세계에 13개 이름 |
| TLD | `com` | `.com` 을 맡은 네임서버 — `.kr` · `.net` 도 각각 |
| 2단계 도메인 | `example.com` | **권한 있는 네임서버** |
| 호스트 이름 | `www.example.com` | 위 권한 있는 네임서버가 함께 답한다 |

- TLD 의 권한 있는 네임서버도 같은 방법으로 봅니다 — `nslookup -type=ns kr.`(끝의 점은 루트를 나타냅니다. 점이 있어도 없어도 같은 결과입니다).
- `.kr` 처럼 국가 코드 TLD 는 계층이 하나 더 있습니다. `mail.google.co.kr` 은 `kr` → `co.kr`(회사용) → `google.co.kr` → `mail.google.co.kr` 순서입니다.

리졸버의 질문 순서:

```
리졸버 ─ ① 「com 의 네임서버는?」 ─▶ 루트          ─▶ 「com 의 네임서버는 ○○」
       ─ ② 「example.com 의 네임서버는?」 ─▶ com 네임서버  ─▶ 「hera.ns.cloudflare.com 이야」
       ─ ③ 「www.example.com 의 IP 는?」 ─▶ hera.ns.cloudflare.com ─▶ 「104.20.23.154」 ← 권한 있는 응답
```

#### 🐍 문법 상자 · 끝에서부터 세기 `[-1]` · 잘라 꺼내기 `[-2:]`

```python
parts = ["www", "example", "com"]  # 도메인 이름을 점으로 나눈 레이블 세 개를 리스트로 만들어 parts 에 담는다
print(parts[0])                    # 리스트[0] 은 앞에서 첫째 칸이다. 첫째 요소를 출력한다
print(parts[-1])                   # 리스트[-1] 처럼 번호에 - 를 붙이면 뒤에서부터 센다. -1 은 마지막 요소다. 마지막 요소를 출력한다
print(parts[-2])                   # -2 는 끝에서 둘째 칸이다. 그 요소 하나를 출력한다
print(parts[-2:])                  # 리스트[시작:] 은 시작 칸부터 끝까지를 잘라 새 리스트로 리턴한다. 끝에서 둘째 칸부터 끝까지를 출력한다

# www                    ← print(parts[0])
# com                    ← print(parts[-1])
# example                ← print(parts[-2]) — 요소 하나(글자)
# ['example', 'com']     ← print(parts[-2:]) — 대괄호가 있는 리스트
```

| 쓰는 것 | 뜻 | 결과의 종류 |
|---|---|---|
| `리스트[-1]` | 마지막 요소 하나 — 도메인 이름이면 TLD | 글자 하나 |
| `리스트[-2]` | 끝에서 둘째 칸 하나 | 글자 하나 |
| `리스트[-2:]` | 끝에서 둘째 칸부터 **끝까지** | **리스트** |

⚠ `[-2]` 와 `[-2:]` 는 콜론 하나 차이입니다. 콜론이 있으면 요소 하나가 아니라 리스트가 나옵니다.

#### 🐍 문법 상자 · `".".join()` 으로 다시 잇기 · `reversed()` 로 뒤집기

```python
parts = ["www", "example", "com"]  # 레이블 세 개를 리스트로 만들어 parts 에 담는다
print(".".join(parts[-2:]))        # "이을글자".join(리스트) 는 리스트의 요소 사이에 이을 글자를 넣어 하나의 글자로 리턴한다. 끝의 두 요소를 점으로 이어 출력한다
print(reversed(parts))             # reversed() 는 리스트를 뒤에서부터 꺼낼 준비만 한 값을 리턴한다. 그대로 출력하면 내용이 보이지 않는다
print(list(reversed(parts)))       # list() 로 감싸면 뒤에서부터 꺼낸 요소를 새 리스트로 만든다. 그 리스트를 출력한다
print(parts)                       # 원래 리스트를 다시 출력한다. reversed() 는 원래 리스트를 바꾸지 않는다

# example.com                              ← print(".".join(parts[-2:]))
# <list_reverseiterator object at 0x…>     ← print(reversed(parts)) — 내용이 안 보인다
# ['com', 'example', 'www']                ← print(list(reversed(parts)))
# ['www', 'example', 'com']                ← print(parts) — 그대로다
```

| 쓰는 것 | 뜻 |
|---|---|
| `".".join(리스트)` | 요소 사이에 점을 넣어 **글자 하나**로 잇는다. `split(".")` 의 반대 |
| `reversed(리스트)` | 뒤에서부터 꺼낸다. 내용을 보려면 `list()` 로 감싼다 |

### 3.2 권한 있는 응답과 권한 없는 응답

**여기 나오는 말**

- **권한 없는 응답 (Non-authoritative answer)** (논 어소리테이티브)
  - 리졸버가 권한 있는 네임서버에 **대신 조회해** 받은 답이라는 표시
  - 평소 `nslookup` 하면 거의 항상 보인다

| | 권한 있는 응답 | 권한 없는 응답 |
|---|---|---|
| 누가 답했나 | **권한 있는 네임서버**가 직접 | 리졸버가 **대신 조회해** 받은 답(또는 캐시에 저장해 둔 답) |
| 언제 보나 | 권한 있는 네임서버에 직접 물을 때(3-2) | 평소 `nslookup` 할 때 거의 항상 |

# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">4교시 (12:00–12:50) · DNS 레코드 · TTL · 캐시</mark>

### 왜 필요한가

1. DNS 는 IP 만 알려 주지 않습니다. **메일은 어느 서버가 받나 · 이 이름의 정식 이름(canonical name)은 무엇인가** 같은 정보도 **레코드**로 담고 있습니다.
2. 답은 매번 처음부터 찾지 않고 **잠시 저장(캐시)** 해 두고 씁니다. 얼마나 오래 쓸지는 **TTL** 이 정합니다.
3. 피싱 · 악성 코드 분석에서 「이 도메인의 메일 서버는? 별칭은? 언제 바뀌었나?」를 묻습니다. 레코드를 읽을 줄 알아야 합니다.

### 4.1 자주 보는 레코드

**여기 나오는 말**

- **레코드 (record)**
  - DNS 서버에 적힌 **기록 한 줄**
  - 이름 하나에 값 하나
- **A 레코드** (에이 레코드)
  - 이름 → **IPv4 주소**
- **CNAME (canonical name)** (씨네임)
  - **별칭(alias)** 레코드 — 이 이름의 정식 이름(canonical name)을 가리킨다
- **MX (mail exchanger)** (엠엑스)
  - 그 도메인의 **메일을 받을 서버**
  - 메일을 주고받는 회사 도메인은 보통 MX 가 있다. 메일을 받지 않는 도메인은 `-type=mx` 결과에 `mail exchanger` 줄이 없다
- **CDN (Content Delivery Network)** (시디엔)
  - 콘텐츠를 여러 지역의 서버에 복제해 두고 **사용자와 가까운 서버에서 전송하는** 서비스
  - 큰 사이트는 CNAME 레코드로 자기 이름이 CDN 의 이름을 가리키게 설정한다

| 레코드 | 담는 것 | 예 (실측 10/4) | `nslookup` 옵션 |
|---|---|---|---|
| **A** | IPv4 주소 | `example.com` → `104.20.23.154` | (기본) |
| **CNAME** | 별칭 — 정식 이름을 가리킴 | `www.naver.com` → `www.naver.com.nheos.com` | `-type=cname` |
| **MX** | 메일을 받을 서버의 이름 — 그 IP 는 이름의 A 레코드로 다시 묻는다 | `google.com` → `smtp.google.com` (우선순위 10) | `-type=mx` |
| **NS** | 권한 있는 네임서버 | `example.com` → `hera.ns.cloudflare.com` | `-type=ns` |

### ✍️ 문제 4-1 · 메일 서버와 별칭 — MX · CNAME

**할 일** — `google.com` 의 메일 서버와 `www.naver.com` 의 별칭을 묻고, 메일 서버 이름 · 우선순위 · 별칭 · 최종 이름을 보고서에 적습니다.

**왜 중요한가** — MX 레코드로 그 도메인의 메일을 받는 서버를 확인하고, CNAME 으로 큰 사이트가 CDN 이름으로 이어진 것을 봅니다. 피싱 메일을 분석할 때 보낸 쪽 도메인에 메일 서버가 있는지 보고, 오후 5교시에는 `akamaiedge` 같은 CDN 이름이 무작위처럼 보여도 정상일 수 있다는 근거로 씁니다.

**이 문제에 나오는 말**

- **`MX preference`** (엠엑스 프리퍼런스)
  - 메일 서버의 **우선순위**
  - 숫자가 작을수록 먼저 쓴다
- **`Aliases`** (에일리어시스)
  - `nslookup` 결과에서 **거친 별칭들**

**순서**

1. **[터미널]** 메일 서버를 묻습니다.

2. **[터미널]** `mail exchanger =` 뒤의 서버 이름과, 같은 줄의 `MX preference` 숫자를 읽습니다.


4. **[터미널]** `이름:` 줄의 최종 이름(정식 이름)과 `Aliases:` 줄의 별칭을 찾습니다. Windows 는 `Aliases:` 에 내가 친 `www.naver.com` 이 나옵니다.

### 4.2 TTL 과 캐시

**여기 나오는 말**

- **캐시 (cache)**
  - 받은 답을 **정해진 시간 동안 저장**해 두고 다시 쓰는 것
- **TTL (DNS 에서)** (티티엘)
  - 답을 캐시에 **몇 초 동안 둘지** — 권한 있는 네임서버가 정한다
  - 10/12 `ping` 의 TTL 과 이름만 같다

| | |
|---|---|
| **TTL** | 이 답을 **몇 초 동안** 저장해 써도 되는지. 권한 있는 네임서버가 정한다 |
| **캐시** | 리졸버와 내 PC 가 TTL 동안 답을 저장해 두는 곳 — 빠르고 DNS 서버 부담이 줄어든다 |
| 그래서 생기는 일 | 권한 있는 네임서버에서 IP 를 바꿔도 **TTL 이 지날 때까지는 옛 IP 로** 간다 |

내 PC 의 캐시는 `ipconfig //displaydns`(디스플레이 디엔에스)로 보고, `ipconfig //flushdns`(플러시 디엔에스)로 비웁니다.

⚠ `nslookup` 은 PC 의 캐시를 거치지 않고 DNS 서버에 바로 묻습니다. 그래서 <mark style="background:#ffcdd2; color:#1a1a1a; padding:0 4px; border-radius:3px">`nslookup` 으로는 캐시가 채워지지 않습니다.</mark> 캐시를 채울 때는 `ping` · 브라우저처럼 보통 프로그램이 쓰는 방식으로 접속합니다.

#### 🐍 문법 상자 · `<` 로 만료 시각과 비교하기 — 같을 때를 조심

```python
ttl = 300                     # 답을 저장해 써도 되는 초를 ttl 에 담는다
saved_at = 0                  # 답을 저장한 시각(초)을 saved_at 에 담는다
print(saved_at + ttl)         # 저장한 시각에 TTL 을 더하면 만료 시각이다. 만료 시각을 출력한다
print(299 < saved_at + ttl)   # a < b 는 a 가 b 보다 작으면 True, 아니면 False 를 리턴한다. 299 가 만료 시각보다 작은지 출력한다
print(300 < saved_at + ttl)   # 300 과 만료 시각이 같을 때 < 가 무엇을 리턴하는지 출력한다
print(300 <= saved_at + ttl)  # a <= b 는 a 가 b 보다 작거나 같으면 True 를 리턴한다. < 와 비교해 출력한다

# 300      ← 만료 시각
# True     ← 299 < 300
# False    ← 300 < 300 — 같으면 작지 않다
# True     ← 300 <= 300
```

| 쓰는 것 | 뜻 |
|---|---|
| `a < b` | `a` 가 `b` 보다 **작을 때만** `True`. 같으면 `False` |
| `a <= b` | 작거나 **같으면** `True` |
| 캐시에서는 | `지금 < 만료 시각` 이면 캐시를 쓴다. 만료 시각이 **되는 순간** 새로 묻는다 |

### ✍️ 문제 4-2 · 내 PC 의 DNS 캐시와 TTL

**할 일** — 내 PC 의 DNS 캐시를 보고 비운 뒤, TTL 이 지나기 전후를 가르는 코드를 TTL 두 값으로 실행해 보고서에 적습니다.

### 정답 2-1

💻 **터미널에 입력합니다.**

```bash
nslookup example.com
nslookup example.com 8.8.8.8
```

**결과**

- (가) 첫째는 위 두 줄이 학원 DNS 서버(`kns.kornet.net` · `168.126.63.1`)이고, `Addresses` 의 IPv4 주소(예: `104.20.23.154` · `172.66.147.243`)가 답입니다. 둘째는 위 두 줄이 `서버:    dns.google` · `Address:  8.8.8.8` 로 바뀌고 답의 IPv4 는 같습니다.(값은 바뀔 수 있습니다).
- (나) 위 두 줄은 「누구에게 물었나」라서 물어볼 서버를 바꾸면 바뀝니다. 아래 `Addresses` 는 example.com 의 답입니다. 서버를 적지 않으면 PC 에 설정된 DNS 서버(`ipconfig //all` 의 `DNS 서버`)에 묻습니다.
- (다) 회사는 사내 DNS 서버로 위험한 이름을 막고 기록을 남깁니다. PC 가 외부 DNS 에 직접 물으면 그 차단과 기록을 피해 가므로 확인합니다. PC 의 DNS 서버가 낯선 주소로 바뀌어 있으면 악성 코드가 설정을 바꿔, 은행 이름을 물어도 가짜 사이트 IP 를 받게 만들었을 수 있습니다.

**왜** — 위 두 줄은 물어본 DNS 서버, 아래 `Addresses` 는 물어본 이름의 답입니다.

**자주 틀리는 곳** — `서버:` 바로 아래의 `Address`(`168.126.63.1` · `8.8.8.8`)를 example.com 의 주소로 적는 경우가 많습니다. 그것은 물어본 DNS 서버의 주소입니다.

**관제에서는** — 의심 도메인이 가리키는 IP 를 확인해 방화벽 로그의 접속 IP 와 맞춰 봅니다. PC 의 DNS 서버가 회사가 정한 주소가 아니면 악성 코드가 설정을 바꿨는지 의심합니다.

### 정답 2-2

💻 **터미널에 입력합니다.**

```bash
python day03_2-2_url_example.py
python day03_2-2_url_nowhere.py
nslookup abc.nowhere-not-exist.com
```
맥북: `python` 대신 `python3`

**결과**

- (가) 첫 파일은 `['https:', '', 'example.com', 'news', 'today']` 와 `example.com → 104.20.23.154` 두 줄입니다(IPv4 는 실행할 때마다 다를 수 있습니다). 두 번째 파일은 `['https:', '', 'abc.nowhere-not-exist.com', 'login']` 을 출력한 뒤 마지막 줄이 `socket.gaierror: [Errno 11001] getaddrinfo failed` 로 멈춥니다(맥북은 `[Errno 8] nodename nor servname provided, or not known`). `nslookup` 은 `Non-existent domain` 이 든 줄입니다. 한국어 Windows 는 앞부분 문구가 한국어로 나올 수 있습니다(확인 필요). 맥북은 `NXDOMAIN`.
- (나) `/` 로 자르면 `https:` 와 `example.com` 사이의 `//` 에 글자가 없어 빈 문자열 `''` 이 한 칸 생깁니다. 그래서 0 번 `https:`, 1 번 `''`, 2 번이 도메인 이름입니다. 두 번째 파일은 DNS 서버가 「그런 이름은 없다」고 답해 `gethostbyname()` 이 IPv4 를 리턴하지 못하고 `socket.gaierror` 에러로 멈췄습니다.
- (다) NXDOMAIN 은 DNS 서버가 정상으로 답을 한 것이고, 그 답이 「이름이 없다」입니다. 연결이 끊겼다면 답 자체가 오지 않아 시간 초과가 납니다. 한 PC 에서 짧은 시간에 NXDOMAIN 이 급증하면, 악성 코드가 무작위로 만든 이름을 차례로 물으며 공격자 서버를 찾는 중일 수 있습니다(오후 5교시).

**왜** — DNS 가 묻는 것은 URL 가운데 도메인 이름 하나입니다. 없는 이름에는 DNS 서버가 「없다」는 공식 답(NXDOMAIN)을 리턴하고, 파이썬은 그 답을 에러로 알려 줍니다.

**자주 틀리는 곳** — 빈 문자열 `''` 을 빼고 세어 `parts[2]` 를 `news` 로 적는 경우가 많습니다. NXDOMAIN 을 「인터넷이 끊겼다」로 적는 것도 흔합니다.

**관제에서는** — 접속 로그의 URL 에서 도메인만 잘라 DNS 질의 기록과 맞춰 봅니다. 한 PC 의 NXDOMAIN 수를 세어 많이 튀는 PC 를 먼저 봅니다.

**왜** — 도메인 이름은 오른쪽이 상위 계층입니다. NS 레코드는 이 도메인의 권한 있는 네임서버를 알려 줍니다.

**자주 틀리는 곳** — `[-2:]` 를 끝에서 둘째 요소 하나(`co`)만 꺼내는 것으로 읽는 경우가 많습니다. `-type=ns` 결과의 `internet address` 줄 IP 를 네임서버 이름으로 적는 것도 흔합니다. 권한 있는 네임서버는 `nameserver =` 뒤의 이름입니다.

**관제에서는** — 로그의 도메인을 TLD 별로 묶어 셉니다. 도메인의 NS 가 갑자기 낯선 서버로 바뀌면 도메인을 빼앗긴 신호일 수 있어 확인합니다.

**자주 틀리는 곳** — `권한 없는 응답` 을 「틀린 답」으로 적는 경우가 많습니다.

**관제에서는** — 리졸버의 답이 의심스러우면 권한 있는 네임서버에 직접 물어 같은지 비교합니다.

### 정답 4-1

💻 **터미널에 입력합니다.**

```bash
nslookup -type=mx google.com
nslookup www.naver.com
```

**결과**

- (가) `google.com  MX preference = 10, mail exchanger = smtp.google.com` — 메일 서버 `smtp.google.com` · 우선순위 `10` 입니다. `www.naver.com` 은 `Aliases:` 에 `www.naver.com` 이 있고, `이름:` 줄의 최종 이름은 `www.naver.com.nheos.com` 입니다(값과 단계는 바뀔 수 있습니다).
- (나) MX 는 「메일을 받을 서버가 누구인가」를 담는 레코드라 서버 이름을 답하고, 그 이름의 IP 는 다시 A 레코드로 물어 알아냅니다. 큰 사이트는 사용자와 가까운 서버에서 콘텐츠를 전송하는 CDN 을 쓰므로, 원래 이름의 CNAME 레코드가 CDN 의 이름을 가리키게 설정하고 리졸버가 그 별칭을 끝까지 따라가 IP 를 받습니다.
- (다) 정상 회사 도메인은 메일을 받는 MX 가 있는 경우가 많습니다. 보낸 쪽 도메인에 MX 가 없거나 막 만든 낯선 서버를 가리키면 피싱용으로 급히 만든 도메인일 수 있습니다. 잘 아는 이름이 처음 보는 도메인으로 CNAME 레코드가 설정돼 있으면, 별칭을 끝까지 따라가 그 서버가 정상 CDN 인지 남의 서버인지 확인합니다.

**왜** — MX 의 답은 서버 이름이고 IP 는 A 레코드가 줍니다. CNAME 은 이 이름의 정식 이름을 가리키는 레코드라, 리졸버가 별칭을 따라가 마지막 이름의 IP 를 줍니다.

**자주 틀리는 곳** — MX 아래에 함께 나오는 IP 를 메일 서버로 적는 경우가 많습니다. 최종 이름을 `Aliases:` 의 마지막 줄로 적는 것도 흔합니다. 최종 이름은 `이름:` 줄입니다.

**관제에서는** — 피싱 메일의 보낸 쪽 도메인에 MX 가 있는지, 별칭이 어디로 이어지는지 확인합니다.

### 정답 4-2

💻 **터미널에 입력합니다.**

```bash
ping -n 1 example.com
ipconfig //displaydns
ipconfig //flushdns
ipconfig //displaydns
python day03_4-2_ttl_300.py
python day03_4-2_ttl_60.py
```
맥북: `ping -c 1 example.com` 뒤 `ipconfig` 세 줄은 건너뛰고, `python` 대신 `python3`

**결과**

- (가) 처음에는 `example.com` 아래 `TTL(Time To Live) . : ○○○` 이 보이고, `//flushdns` 뒤에는 `DNS 확인자 캐시를 플러시했습니다.` 가 나오며 `example.com` 항목이 사라집니다. 첫 파일은 `30 초: 캐시의 답을 쓴다` · `100 초: 캐시의 답을 쓴다` · `299 초: 캐시의 답을 쓴다` · `300 초: DNS 서버에 새로 묻는다`, 두 번째 파일은 `30 초: 캐시의 답을 쓴다` · `100 초: DNS 서버에 새로 묻는다` · `299 초: DNS 서버에 새로 묻는다` · `300 초: DNS 서버에 새로 묻는다` 입니다.
- (나) 만료 시각은 첫 파일이 0 + 300 = 300초, 두 번째 파일이 0 + 60 = 60초입니다. 100초는 300 보다 작아 첫 파일에서는 캐시를 쓰고, 60 보다 커서 두 번째 파일에서는 새로 묻습니다. 299 < 300 은 `True` 라 캐시를 쓰고, 300 < 300 은 `False` 라 새로 묻습니다. `nslookup` 은 PC 캐시를 거치지 않고 DNS 서버에 바로 물어 캐시에 남기지 않으므로, 보통 프로그램이 쓰는 방식인 `ping` 으로 채웁니다.
- (다) 리졸버와 PC 는 받은 답을 TTL 동안 저장해 두고 다시 묻지 않습니다. 그래서 권한 있는 네임서버에서 IP 를 바꿔도 만료 시각 전까지는 저장해 둔 옛 IP 로 접속됩니다. 이상한 주소로 계속 접속되는 PC 는 캐시에 옛 답이나 위조된 답이 남아 있을 수 있어, `//flushdns` 로 지운 뒤 다시 물어 새 답으로 확인합니다.

**왜** — 캐시는 만료 시각(저장한 시각 + TTL) 전까지만 씁니다. TTL 이 길수록 바뀐 IP 가 늦게 퍼집니다.

**자주 틀리는 곳** — 300초 줄도 캐시라고 적는 경우가 많습니다. 만료 시각과 **같으면** 새로 묻습니다. `ipconfig /displaydns` 처럼 슬래시를 하나만 치는 것도 흔합니다. Git Bash 에서는 `//` 두 번입니다.

**관제에서는** — 도메인의 IP 가 바뀐 직후에는 TTL 이 지날 때까지 옛 IP 와 새 IP 가 섞여 로그에 나옵니다. 이상한 주소로 계속 접속되면 캐시에서 그 이름의 IP 를 확인하고 `//flushdns` 로 비웁니다.

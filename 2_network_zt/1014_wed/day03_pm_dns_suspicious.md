# <mark style="display:block; background:#c8e6c9; color:#1a1a1a; padding:6px 12px; border-radius:4px">5교시 (14:00–14:50) · 의심 도메인의 특징</mark>

### 왜 필요한가

1. 악성 코드가 고정된 도메인 이름 하나만 쓰면 그 이름을 막으면 끝납니다. 그래서 공격자는 **이름을 매일 수백 개씩 자동으로 만들어** 그중 하나만 실제로 등록해 둡니다. 이것이 **DGA** 입니다.
2. 감염된 PC 는 그 이름들을 차례로 물어봅니다. 대부분 등록되지 않은 이름이라 **NXDOMAIN 이 많이 나옵니다.**
3. 또 하나는 **사칭**입니다. `naver.com` 을 `nav3r.com` 처럼 비슷하게 만들어 사람을 속입니다.

### 5.1 의심 도메인을 가르는 지표

**여기 나오는 말**

- **DGA (Domain Generation Algorithm)** (디지에이)
  - 악성 코드가 도메인 이름을 **정해진 계산식으로 자동 생성**하는 방식
  - 예: `kxq3vz9a.top`
- **C2 서버 (Command and Control)** (씨투 서버)
  - 공격자가 감염된 PC 에 **명령을 보내는** 서버
  - DGA 로 만든 이름 가운데 등록된 하나가 이 서버의 IP 를 가리킨다

| 특징 | 정상 도메인 | DGA 도메인 | 왜 |
|---|---|---|---|
| 레이블 길이 | 짧고 뜻이 있다 — `naver` | 길고 뜻이 없다 — `p0w8rk2mzq` | 계산식이 만든 문자열 |
| 숫자 | 거의 없다 | 여러 개 섞여 있다 | 무작위로 고르므로 숫자도 섞인다 |
| 모음(a · e · i · o · u) | 사람이 읽을 수 있게 섞여 있다 | **거의 없다** — `kxq3vz9a` | 발음할 수 없는 이름 |
| TLD | `.com` · `.net` · `.kr` | 등록비가 싼 `.top` · `.xyz` · `.tk` 가 많다 | 한꺼번에 싸게 등록 |
| DNS 응답 | NOERROR | **NXDOMAIN 이 많다** | 대부분 등록하지 않은 이름 |

**어느 레이블을 볼까:** `e6030.a.akamaiedge.net` 처럼 정상 서비스도 맨 앞 레이블은 무작위로 보입니다(오전 4.1 절의 CDN). 그래서 오늘은 **TLD 바로 앞 레이블**(2단계 도메인 · SLD — 회사나 서비스가 등록한 이름 부분 — `akamaiedge` · `naver` · `kxq3vz9a`)을 봅니다.

### 5.2 사칭 도메인과 NXDOMAIN 이 많은 PC

**여기 나오는 말**

- **타이포스쿼팅 (typosquatting)** (타이포스쿼팅)
  - 진짜 도메인과 **철자가 비슷한** 도메인을 등록해 사람을 속이는 사칭
  - 예: `nav3r.com` (`e` 를 `3` 으로), `g00gle.com` (`o` 를 `0` 으로)
- **피싱 (phishing)** (피싱)
  - 가짜 사이트 · 메일로 사람을 속여 계정 · 정보를 빼내는 공격

| 의심 신호 | 무엇을 보나 | 예 |
|---|---|---|
| 사칭 ① 철자 바꾸기 | 진짜 도메인과 한두 글자만 다른가 | `nav3r.com` · `g00gle.com` |
| 사칭 ② 낱말 붙이기 | 은행 · 로그인 같은 낱말을 붙여 진짜처럼 보이게 했나 | `bnk-secure-login.xyz` |
| NXDOMAIN 이 많은 PC | 한 PC 가 짧은 시간에 NXDOMAIN 을 몇 번 받았나 | DGA 이름을 차례로 묻는 감염 PC |

- 사칭 이름이 DGA 지표에 해당되는지는 6교시에서 점수로 확인합니다.
- 한 번의 NXDOMAIN 은 사람의 오타일 수 있습니다. **같은 PC 에서 여러 번**이 신호입니다.

#### 🐍 문법 상자 · `딕셔너리.get(키, 0) + 1` — 키마다 횟수 세기

```python
nx = {}                                                # PC 주소를 키, NXDOMAIN 횟수를 값으로 담을 빈 딕셔너리를 만든다
for pc in ["10.20.0.42", "10.20.0.42", "10.20.0.33"]:  # PC 주소를 하나씩 꺼내 pc 에 담아 반복한다
    nx[pc] = nx.get(pc, 0) + 1                         # .get(키, 0) 은 키가 있으면 그 값을, 없으면 0 을 리턴한다. 거기에 1 을 더해 다시 담는다
print(nx)                                              # 키마다 센 횟수가 든 딕셔너리를 출력한다

# {'10.20.0.42': 2, '10.20.0.33': 1}
```

| 쓰는 것 | 뜻 |
|---|---|
| `nx.get(pc, 0)` | `pc` 키가 있으면 그 값, **없으면 0** 을 리턴한다 — 처음 보는 키도 에러 없이 센다 |
| `nx[pc] = … + 1` | 그 키의 값을 1 늘려 다시 담는다 |

⚠ `nx[pc] + 1` 처럼 바로 꺼내면 처음 보는 키에서 `KeyError` 가 납니다.

### ✍️ 문제 5-2 · NXDOMAIN 이 많은 PC 찾기

**할 일** — DNS 로그에서 PC 마다 NXDOMAIN 을 몇 번 받았는지 세는 코드를 실행하고, 감염이 의심되는 PC 를 보고서에 적습니다.

**왜 중요한가** — 도메인 하나가 아니라 PC 별로 NXDOMAIN 을 세면 DGA 이름을 연달아 묻는 감염 의심 PC 를 찾을 수 있습니다. 관제에서 어느 PC 를 먼저 점검할지 정하는 기준이 됩니다.

**순서**

1. **[VS Code]** 왼쪽 목록에서 `network_zt` 폴더를 오른쪽 클릭 › **New File** › 이름 `day03_5-2_nx_count.py` 를 입력하고 Enter 를 누릅니다.
2. **[VS Code]** 아래 코드를 파일에 붙여 넣고, 실행하기 전에 **줄마다 주석을 읽어** 각 줄이 무엇을 하는지 이해합니다.
   ```python
   logs = [("10.20.0.15", "www.naver.com", "NOERROR"),    # DNS 로그를 (PC 주소, 물어본 이름, 응답) 튜플의 리스트로 만든다
           ("10.20.0.42", "kxq3vz9a.top", "NXDOMAIN"),    # 10.20.0.42 가 없는 이름을 물은 줄이다
           ("10.20.0.42", "p0w8rk2mzq.xyz", "NXDOMAIN"),  # 같은 PC 가 또 없는 이름을 물은 줄이다
           ("10.20.0.33", "nevar.com", "NXDOMAIN"),  # 다른 PC 가 철자를 틀린 이름을 물은 줄이다
           ("10.20.0.42", "zzx9q2lk.top", "NXDOMAIN"),    # 10.20.0.42 가 세 번째로 없는 이름을 물은 줄이다
           ("10.20.0.42", "qwrtpzkx7v.com", "NOERROR")]   # 10.20.0.42 가 마지막에 응답을 받은 줄이다
   nx = {}                                                # PC 주소별 NXDOMAIN 횟수를 담을 빈 딕셔너리를 만든다
   for pc, name, rcode in logs:                           # 튜플을 하나씩 꺼내 세 값을 pc · name · rcode 에 나눠 담아 반복한다
       if rcode == "NXDOMAIN":                            # 응답이 NXDOMAIN 이면 아래 줄을 실행한다
           nx[pc] = nx.get(pc, 0) + 1                     # 그 PC 의 횟수를 1 늘린다
   print(nx)                                              # PC 주소별 NXDOMAIN 횟수를 출력한다
   ```
3. **[터미널]** 실행합니다.
   ```bash
   python day03_5-2_nx_count.py
   ```
   맥북: `python3 day03_5-2_nx_count.py`

### 6.2 채점 — 오탐 · 미탐

**여기 나오는 말**

- **오탐 (false positive)** (폴스 포지티브)
  - 실제로는 정상인데 규칙이 **「의심」으로 잘못 고른** 것

  - 근거가 분명한 정상 도메인을 규칙에서 **빼 주는** 목록

| | 실제 정상 | 실제 의심 |
|---|---|---|
| **규칙이 「의심」** | **오탐** | 맞힘 |
| **규칙이 「정상」** | 맞음 | **미탐** |

**자주 틀리는 곳** — `x7q9pz2kd`(9글자)를 10글자 이상으로 세어 규칙 ① 을 더하는 경우가 많습니다. (다) 에서 오탐 위험을 빼고 규칙만 적는 것도 흔합니다.

**관제에서는** — 새 규칙은 먼저 지난 로그에 걸어 오탐 · 미탐을 센 뒤에 적용합니다.
